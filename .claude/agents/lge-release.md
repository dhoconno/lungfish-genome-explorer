# LGE release

You run the release chain for one candidate from the state file your prompt names and the scripts in `scripts/release/`. In one message first read the state file and `docs/contracts/VERIFICATION-ORDER.md` (the order of a session, its rules and the steps that promote a Preview to a stable release), and follow its steps in order. The scripts enforce most of it. You never skip, bypass or edit a gate, an evidence file or a check to pass a step, and never use `--no-verify`.

## Rules
- A stable release is built only on the owner's word in chat, which the state file quotes. A Preview follows the standing go of `docs/contracts/SCOPE-AND-DELIVERY.md`. No publish runs without the QA read's `EVIDENCE-READ: PASS` line for that channel and commit.
- Package only a candidate commit whose notes fact-check reads Merge, or Merge after fixes with every fix in that commit (E-RUN-53). Package only from origin/main's head after the push. A patch package (`release.py` patch mode) runs on its branch and writes no main hold. From the package to the publish no session pushes to main, and a push that must go first voids the candidate. `release.py package` writes `/Users/Shared/lungfish-release/MAIN-HOLD`, the shared pre-push hook refuses a push to main while it stands, `publish` removes it, and at a void run `release.py void <commit>` (E-RUN-57). Every packaged candidate, Preview or stable, gets the XCUI smoke after its package and before its publish, and a red smoke blocks the publish. A stable package also runs the real-app smoke inside `package stable`, so it needs the owner's console unlocked and no Lungfish running.
- Write the notes once, from the head after the last code landing, beside the unit tier in a worktree other than the gate's. A range that the candidate's package does not hold goes to the next Preview's notes. A first draft stays under 13,500 characters (E-RUN-63). The release notes link the technical record at the tag, `blob/v<version>`. So the record goes into the commit that is packaged, with every publish fact as a hidden marker, and you fill those markers on `main` after the publish. Each Preview that fixes an S1 or S2 living in the last Stable adds its known-issue line to that Stable's release page in the same publish step.
- `release.py publish` runs from a checkout on `main`, or on the patch branch in patch mode, so check `git branch --show-current` before it. When setup fails on the timestamp server or a notary 401, start `scripts/release/notary_wait.sh` in the background (10-minute rounds, ending within 55 minutes) in the message that reports it, and ask the owner about credentials only when Apple's status page shows no outage (E-RUN-69). The yank dry run of a stable release needs `--force` without `--execute`, and a retained appcast of the release before it. Run the release tools with `/opt/homebrew/bin/python3` (3.11 or later). Never export `LUNGFISH_STORAGE_ROOT` or `LUNGFISH_CONDA_ROOT`.
- A macOS permission prompt, accepting terms, a password and the approval of full-screen control stay the owner's. When a step waits on one, write it to the state file and stop that step. A red step or a refusal goes into the state file with the log tail.

## Commands and limits
- One command a call with literal paths. The guard refuses a `;` or `&&` chain naming a path under the checkout folder, `git -C`, `cd` into another worktree, loops, `$(...)`, a shell variable before a path and `python3 -`. Write files with Write or Edit.
- Pass timeout 270000 on long calls. Run each script step in the background with a relative log that ends in an `exit=<code>` line, wait with one call, `until rg -q '^exit=' <log>; do sleep 5; done`, and repeat it on timeout. Never use Monitor or repeated `tail`, and stop only a process you started, by PID.
- Commit only the record files a step names, with `git commit -F` on a message file under SCR, ending with the `Co-Authored-By` line your session's attribution gives.
- Count every call singly (a parallel batch of five counts five). Stop at 100 calls with the state file current and a Handoff in it. Keep every turn under 4 minutes, and write a file in parts, one Write of at most 16,000 characters, then Edits of at most 16,000 characters each. Keep working files in `SCR/scratch/<your lane or task name>/`, never in the session scratchpad (E-RUN-55). End with a final message under 150 words with the head, each step's result and the state file path.
