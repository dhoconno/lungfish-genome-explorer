# Lungfish 2026.10.23 technical notes

These are the full technical notes of Preview 2026.10.23, and the release notes are in `docs/release-notes/2026.10.23.md`.

Channel: Preview

Previous versioned release: v2026.10.22

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release is Preview 2026.10.23. It follows Preview 2026.10.22 and is the Stable candidate of Phase 2.14, so it becomes a Stable release only after the owner check list has passed. The sections below list what changed for a person who uses Lungfish Genome Explorer (LGE) or `lungfish-cli`. The release carries two kinds of change. The first is the work of the CHTC preprocessing program (C0 to C3, on main between f179dc769 and 949267f01), which changed every FASTQ import and which five narrowed reviews, a Linux tier run and a narrowed fact-check checked in this phase. The second is eleven lanes of Phase 2.14. They fix defects that the GUI walk of 2.13 and those reviews found, repair the probe of the Accessibility tests and add two agent guides.

## Reads and downloads

**Quality binning.** Every default import now bins quality scores with `illumina4`, which the import sheet and the help call Illumina (7-level). The seven levels are 0, 8, 13, 22, 27, 32 and 37. Since 20 is not a level, a base filter at Q20 can move bases across it. The change reaches imports of Illumina and Oxford Nanopore reads, SRA downloads into a bundle and `fastq ingest`. The two Oxford Nanopore barcode recipes do not bin, and the import sheet sets None for them. To keep every score, pass `--quality-binning none` to `import fastq`, `fastq import-ont` or `fetch sra download`, and `--binning none` to `fastq ingest`. A golden over FASTQ import payloads does not exist yet, and it is a Phase 3 row.

**VSP2 and wastewater recipes.** One recipe at `formatVersion` 2, `illumina-paired-cleanup`, replaces `vsp2.recipe.json` and `wastewater-metagenomics.recipe.json`, with two switches for duplicate removal and ribosomal RNA removal. Both presets run fastp with `--detect_adapter_for_pe -g --poly_g_min_len 10 -q 15 -u 40 -n 5 -l 15 -W 5 --cut_tail -M 20`, and duplicate removal adds `--dedup --dup_calc_accuracy 3` to the same call. At f179dc769 both recipes cut with `--cut_right` and named no poly-G flag, and the VSP2 call also carried `-A -G -Q -L`. VSP2 therefore changes in five ways (adapters, poly-G, the quality 15 read filter, the length 15 filter and tail cutting) and wastewater in three (duplicates, tail cutting and forced poly-G trimming). Ribosomal RNA removal is off for VSP2.

**Trim Galore.** The Trim Galore storage step counts the reads that it removes, and the import notice and the provenance record of the step say that it removes reads (decision O19). One check stays open, the words of the removal line and the way the row of a Trim Galore import ends.

**Import messages.** The out-of-memory message of a BBTools step tells you to close other apps or import fewer samples at a time. For the storage step, the message ends with a line that starts On the command line and names `import fastq --clumpify-heap-gb` with twice the heap that ran (`BBToolsOutOfMemory.swift:41-43`). A recipe step sizes its own heap, so its message names no option (`FASTQBatchImporter.swift:1981`, `:2105`). The unknown-recipe error lists every name from `resolvableRecipeNames()` (`BatchImportError.swift:23-25`), and the command's help reads the same list (`ImportFastqCommand.swift:316`, `:322-324`). The help also describes the default Java heap correctly. The Inspector records a duplicate or ribosomal RNA setting only for a recipe that has the switch, so it no longer lists such a setting as Not recorded. The recapture of the `cli-help` golden changed 8 lines in 2 files, and `golden.py compare --only cli-help` matches all 321 files.

**Chunked Oxford Nanopore import.** A chunked import of an ONT run folder says Import complete once, after the binning. The importer holds its last word back, `finish()` says it once at 1.0, and `Completed 2/2 barcodes` stays at 0.8. The doubled words appeared only in the program's own builds and in no Preview, so the release notes carry no line for them.

## Mapping

**Pooled runs.** Mapping several bundles in one pooled run now maps every read of every bundle. `MappingPooledInputs.swift` joins the execution files of an unbound pool, in input order, into one `pooled-<UUID>.fastq` (or `.fastq.gz`) in the run's `.lungfish-map-inputs` folder, and `MappingInputResolver.swift` calls it after the single-bundle plan block, so a bundle that binds R1 and R2 still sets paired mode first. The join streams in 4 MiB chunks through `ReadFileWriters` with a cancel flag, never touches an input bundle and removes its file and sidecar on any failure. A pool reaches minimap2 with `--frag=no` after `-x sr`, which only a pooled single-read stream gets, so every other command line is unchanged. BBMap with several inputs that are neither a bound pair nor a read set now stops with `MappingCommandBuilderError.unboundInputs`, where it mapped only the first bundle. A pool that mixes compressed and uncompressed bundles stops with `mixedCompression` and names the bundles. Before, bowtie2 and minimap2 with a long-read or assembly preset opened such a pool by content and ran it. A pooled record keeps one materialization step for each virtual bundle. The warning of the Map Reads window for a pooled run has new words.

## Classifiers

**Extract from the Collections drawer.** The Kraken2 sidebar route calls `displayTaxonomyFromDatabase`, which never set `onBatchExtract`, so the drawer's closure returned with one log line and no row. `TaxonomyViewController+Collections.swift` now takes the one picked sample, resolves its folder the way BLAST Verify does, loads its `ClassificationResult` in `Task.detached` and calls `onBatchExtract` back on the main actor. The silent return is an alert titled Could not extract reads, with the text `Lungfish could not find the classification result for the sample shown. Open the result again from the sidebar, then choose Extract.` When the table shows several samples, the text reads `Choose one sample, then choose Extract.` The extraction acts on the one sample shown, and an extraction of every sample was voted out. The row's command starts `lungfish-cli extract taxa-collection` and names that sample.

**Imported classifier results.** Every classifier import now goes to `Analyses/` through one destination function that both import routes call, the Tools menu NVD import included. NAO-MGS results already went there, so only the other kinds moved. A result folder whose name already carries the kind's prefix keeps one prefix, so a source folder named `esviritu-one-folder` imports as `esviritu-one-folder` (`MetagenomicsImportService.swift:1757`).

**EsViritu Identity.** The Identity column and the hover text of a segment row show percent. The export keeps the fraction as the shortest text that reads back to the same number at both export sites, so 0.99699 exports as `0.99699`, and a copied row writes the fraction too.

**NAO-MGS and NVD Operation Details.** The clear of the batch Operation Details and Source Samples now sits inside both display functions of `MainSplitViewController+ClassifierDisplay.swift`, and the batch route's two duplicate clears are gone, a net change of zero lines. A second change, the continuation of the first review, closes the same fault for an EsViritu or Kraken2 result that has no recorded configuration or whose database is still building. No Known limit remains for it.

## Viral Recon

**Preparing inputs.** The builder of the Viral Recon run leaves the main actor, and the wizard's Run is disabled while it prepares, with `Preparing inputs…` on the footer. A second press of Run while it prepares starts nothing, and a cancel at that point launches nothing, although the builder is not stopped, runs to its end and has its finished result dropped (`testCancelWhilePreparingLaunchesNothing`). The `firstFASTAChunk` read in `ViralReconWizardSheet.swift` stays on the audit list of Phase 3 task 3.1. A fast preparation can end before a screenshot shows Run disabled, so the disabled Run rests on `testSecondRunWhilePreparingStartsNothing` and the footer words rest on `testRunPressedTwiceWhilePreparingLaunchesOneRun`.

## Viewer images

**Bundles opened from the sidebar.** A reference bundle and a mapping result that you open from the sidebar resolved to the `other` kind, so File > Export > Image saved a screenshot of the pane with the whole-pane scope. `drawnReferenceBundle` now names the bundle that the viewer draws, and the pane state, the Scope list and the settings of the `bundle export-graphic` leaf read it. The Scope menu reads Tracks and Ruler and Tracks, and it adds Selected Region only after you select a region in the view. The Operations Panel shows an Export Image row, and the row's command is the argv that the transport ran. The row's bundle name comes from the manifest name, with the folder name as the fallback. An image of a mapping result draws its reads only for a window of at most 2 bases per point, and never a coverage curve.

## Known issues

The known issues of 2026.10.22 that this release does not change still apply, and `docs/reports/2026.10.22-technical.md` lists them. The limits below are new in this release. Each one ends with the Phase 3 task that covers it, with the words Phase 3 candidate when no plan row names one, or with the words No task applies for a fact about records or bundles that are already written.

Known limit. Quality binning rounds the stored scores and cannot be undone for an import already made, so choose None for quality binning before an import that needs every score. A golden over FASTQ import payloads is a Phase 3 row.

Known limit. A failed step of a legacy recipe still reads as an unknown recipe error. Phase 3 task BATCH-IMPORT-ERROR-WORDS covers this.

Known limit. A pooled run maps every read as a single read, so paired bundles lose their pairing in it. To keep pairs, map the bundles one by one. This is a Phase 3 candidate.

Known limit. A pooled run stops when it mixes compressed and uncompressed bundles, and it loses the pools of that kind that bowtie2 and minimap2 with a long-read or assembly preset ran before. This is a Phase 3 candidate.

Known limit. Extract in the Collections drawer needs one sample chosen, and a Kraken2 batch opens with every sample picked. This is a Phase 3 candidate.

Known limit. An EsViritu, Kraken2 or TaxTriage result that an earlier version imported stays in the project's Imports folder and does not open. Import it again to see it in the sidebar. No task applies.

Known limit. Copied rows and exported tables write the EsViritu Identity as a fraction from 0 to 1 while the table shows percent. This is a Phase 3 candidate.

Known limit. An image of a mapping result draws its reads only when the exported window is at most 2 bases per point, about 2,000 bases for a view 1,000 points wide, and a wider window gives an empty read track, and no image of a mapping result draws a coverage curve. When the viewer shows only one read track or only some samples of the result, the image still draws all of them. The image holds at most 75 rows of reads where the viewer can show more, and it can draw a track that the viewer has hidden. This is a Phase 3 candidate.

Known limit. Extract from a result that was renamed in the app, or whose project was copied or moved, uses the folder the result was made in. After a rename it stops with the message Classification result not found, and in a copied project it would read from and write into the original project. Extract works on a result you made in the open project and did not rename. It will be fixed before Stable. Phase 3 task OBS-W4 covers this.

Known limit. A ZIP dropped on the sidebar adds nothing to the project, though its row in the Operations Panel reads Completed. To import the bundle in a ZIP, use File > Import Center…. It will be fixed before Stable. Phase 3 task OBS-W8 covers this.

Known limit. A ZIP dropped on the sidebar that holds a link to a file outside the archive is refused without a message. Nothing is imported and no link is followed. The same ZIP imported with File > Import Center… shows the reason. It will be fixed before Stable. Phase 3 task OBS-W9 covers this.

Known limit. After a NAO-MGS result is shown, its Summary block (the sample, the virus hits and the top taxon) stays at the top of the Inspector for the next Kraken2 or TaxTriage result you open, above that result's own details. The table and the details below the block belong to the result you opened. It will be fixed before Stable. Phase 3 task OBS-W6 covers this.

Known limit. Selecting a tree in the sidebar can make the window taller than the screen, so its bottom edge sits below the screen. You can resize the window. This is unchanged since 2026.10.22. Phase 3 task obs-22 covers this.

Known limit. An image of a mapping result leaves out the mismatch marks that the viewer draws in the reads, so a base that differs from the reference in many reads does not show in the image. This is fixed before Stable. Phase 3 task OBS-W7 covers this.
