# Remediation implementation and verification

This is the implementation companion to the preserved [baseline audit](README.md) and [approved plan](../../superpowers/plans/2026-09-05-lge-audit-remediation.md). Work is on `codex/lge-audit-remediation`, from baseline `13e114087b1c0a994ad1d957ce7d71b963e5575d`. The user authorized implementation after reviewing the plan, with consistent tool, viewport and inspector behavior as the priority.

**Implementation is complete at source commit `9fffc8fbbf9c9a9e76b6de68a6dd24b288668b64`.** The final combined regression selection passed 860 XCTest cases and 95 Swift Testing cases, with zero failures or skips. Final Release app/UI-target compilation passed on the corrected source. This document distinguishes implemented behavior from release-environment verification; it does not certify a release.

## Implementation boundaries

The existing modules, SQLite storage, AppKit application, operation center, provenance model and release front door remain the authorities. Changes repair their contracts and migrate actual callers. There is no UI framework migration, scientific algorithm rewrite, biological tool tuning, database download or new general plugin system.

Root orchestrates three Astra implementation/review teams, serializes builds and shared-file adoption, reviews evidence, and owns commits. Each new behavior defect was first exercised by a failing regression where practical; original crashes, incomplete runs and subsequent diagnostic retries remain in local evidence. Source-only inventory tests are not counted as behavioral validation. The original audit describes its baseline and has not been rewritten to imply the repairs already existed.

## Consistent user experience

An explicitly scoped operation retains its original window and project through configuration and destination sheets. Closing that window does not redirect completion to another window with the same project. Project-only routes may still resolve an appropriate peer. Selection identity includes native record identity where URL alone is ambiguous.

Document parsing is separate from session registration. A late load cannot join the wrong session, overwrite a newer viewport, publish stale inspector details or hide another request's progress. Same-URL reloads refresh payload while retaining document identity. Background sidebar insertion preserves the user's selection. Unsupported content clears stale source details and explains the unsupported state.

Sequence and FASTQ exports use a shared ordered eligibility partition and disclose skipped items. Annotation export explicitly chooses a source when several are eligible. Matching loaded documents are captured as values; unrelated documents cannot lend their annotations to the selected sidebar row. Native and external records with the same apparent URL remain distinct. Multi-source sequence export preserves selected order, and GenBank annotations remain with their originating source.

Filesystem loss retains already displayed values while disabling new scoped writes and inspector actions. Retry/Locate validates the original directory, not merely its name. Recovery preserves native record IDs and rebases only paths inside the moved root. A replacement folder cannot silently become the old project while unavailable windows retain it.

“About Saving…” replaces inert document save commands and describes committed project changes, explicit draft application, window restoration and separate export. Dependency-free viewing is available before unrelated tool setup, while installer/storage reconciliation exclusion remains enforced.

Run Again supports bound terminal histories from imported local packages that fit the existing configuration controls without losing options. Operations and the durable **Open Previous Run…** chooser restore inspectable settings. **Check Configuration** refreshes the package registration, then validates retained bytes, runtime and destination off the UI actor. Missing-package Locate works even when enablement did not change. The final registration check retains the original window, project generation and write permission. Inspection is allowed without a writable owner; launch is refused. Each attempt owns a fresh runner and independent output/history paths. Cancellation drains before terminal acknowledgement, suppresses late results and does not open a failure dialog. Additional output leases reject overlapping ordinary or tree destinations in both arrival orders; availability queries use the same authority, and cancellation retains leases through worker drain; exclusive CLI reservations prevent merging with a raced foreign directory. Unsupported or unbound histories explain the supported alternative.

## Data integrity and reproducibility

Publication owns payload and provenance artifacts together. Observed ownership witnesses prevent rollback from overwriting a later writer's receipt. SQLite backup preserves committed WAL data and restores through retained handles without replacing the inode beneath existing readers. If database restoration is uncertain, existing receipt files and both recovery locations are retained for explicit recovery; coherence of the resulting database/receipt pair is not certified. Recovery errors report the original and restoration failures.

Copied scientific bundles preserve or rehydrate CLI receipts against the final stored payload. Captured GUI selections retain exact export bytes plus a selection manifest containing their source identity. Replay copies those retained bytes using an executable argument vector; it does not pretend that ephemeral UI state can be reconstructed. Historical unsupported GUI-only replay remains explicitly unavailable. Bash, Python, Nextflow and Snakemake retained-byte paths have small invented fixtures, including literal filenames with shell metacharacters.

`conda lock` is a compatibility command name for a versioned **requested environment specification**. It preserves supported requests, targets, channels, overlays and hook metadata; it is not a resolved external conda-lock inventory. Unsupported exact installation fails before a solver or destination mutation. Database catalog labels are separated from actual received archive and payload identity. No expected upstream digest was invented.

Final documentation review also corrected older workflow instructions that described controls or guarantees absent from the current implementation. Local workflow resource fields are not universal enforcement controls: the local Nextflow adapter does not impose CPU/memory ceilings from these fields, local Snakemake uses `--cores`, and the local runner does not enforce the accepted timeout field. The manual now states these limits. This remediation does not add engine scheduling or resource enforcement.

These mechanisms do not claim full multi-file crash atomicity or a distributed transaction against noncooperating cross-process writers. The revision/witness preflight can still race with a later writer before SQLite obtains its destination lock. An interrupted disposable SQLite probe verified the database boundary, not power-loss recovery of the entire application. Snapshot backups use system temporary storage and may be reclaimed by the OS, including across reboot; the reported recovery paths are not a permanent recovery archive.

## Responsiveness and simplification

The synthetic storage fixture contained 256 sequences of 16 KiB, 128 revisions and 10,000 variants. The old eager path loaded 256 sequences and showed about 437 ms open time with a 438 ms heartbeat delay. The actual asynchronous UI path loaded one selected sequence, with about 136 ms open time and a 36 ms heartbeat delay; a second open measured about 142/19 ms. The mutation worker reduced measured heartbeat delay from about 76 ms to below 1 ms.

The entrypoints and live window graphs differ, so these are availability observations, not an isolated speedup benchmark. Measured process RSS increased from about 127 MB to 244 MB; no memory reduction is claimed. Selected hydration wall time also did not demonstrate a speedup. Empty creation, metadata operations and some default folder scans remain synchronous.

`SidebarExportSelection` replaces the separate sequence/FASTQ selection helpers. `SequenceExportSourceResolver` captures source identity and asynchronously obtains native values without mutating UI selection. Controllers translate intent and present results; the existing publication transaction and retained-selection service own durable output. Dynamic source-string assertions were retired only after named regressions covered bookmark replay, captured mixed export and VCF manifest-after-receipt publication. Static contracts remain tested statically.

The 11 unchanged sequence/FASTQ selection test methods shared by the pre-consolidation inventory and final run took a summed 0.088 seconds before and 0.077 seconds after. These are timer-level observations from different checkpoints, not a meaningful speedup claim. Earlier mixed builds took 42.14 and 61.02 seconds; the preceding Run Again focused build took 24.43 seconds, while the earlier 951-case combined run reused that build. The final lock correction required a 34.35-second focused rebuild before the 955-case integration run. Different invalidation sets prevent a causal build-time comparison. The earlier 951-case checkpoint’s slowest XCTest cases were filesystem-watcher timing checks (about 7.1 seconds each), retained Snakemake byte replay (4.7 seconds), another watcher check (4.6 seconds) and the synthetic FASTQ collector performance case (4.3 seconds). No arbitrary test deletion or reduction percentage is claimed.

## Final combined validation

At source commit `9fffc8fbbf9c9a9e76b6de68a6dd24b288668b64`, root enumerated the compiled test inventory and verified every one of the 79 selected suite names plus the actual copied-import route case. Three explicitly named existing `seqkit` methods were excluded. The final command used anchored suite filters, those explicit exclusions and `--skip-build` against the unchanged focused-build source.

- **860 XCTest cases passed** in 81.712 seconds; **95 Swift Testing cases passed** in 0.197 seconds. Total command wall time was 83.38 seconds, including test-runner startup and discovery.
- **Zero failures and zero skips.** All 955 selected inventory entries are accounted for. This is a selected integration run, not the entire repository’s test suite.
- Optional Nextflow and Snakemake smoke/retained-copy cases, and the shell/Python retained-copy case, all executed and passed. No runtime was installed to make them pass.
- Original RED regressions, compilation errors, diagnostic retries and the test-isolation incident remain recorded; this final pass does not erase them.

The committed [validation evidence](evidence/implementation-validation.json) retains all 955 selected test IDs, suite declarations, exact exclusions and argv, source commit, results, build settings, package-lock identity and full-log hashes. Complete raw logs are local-only under the evidence directory below.

Fresh-context review identified one final defect: an ordinary operation could bypass an active additional output-tree lease. Four new regressions reproduced that gap before the existing owner map gained exact/tree scope. The repair passed 51 focused checks and independent rereview, then the complete 955-case selection. The pre-fix Release compilation was deliberately interrupted (exit 75) for this repair; it is not counted as a build pass.

## Validation limits and release requirements

The local environment is macOS 26.6.2 arm64, Swift 6.3.3. Root compiled the final Release app and XCUITest target in 297.19 seconds using a local ad-hoc test signature. Xcode reported `TEST BUILD SUCCEEDED`; package-lock SHA-256 stayed `a5604e675a3f80690f1b1ff39de43c92f75f54864323868eaf60960f914c5f86`. CLI embedding and bundled-tool sanitation were skipped for that compilation; it is not a distributable candidate. Application and test code were fixed at the recorded source commit; report/manual edits were uncommitted during validation and are committed separately. This is not clean-candidate release evidence. No live release was signed, notarized, packaged or published.

The real-app smoke refuses to run in the ordinary developer profile. It requires a clean disposable logged-in graphical account, validates candidate/source/runner identity and records the selected test results. Actual graphical interaction, installed-client channel recovery and schema compatibility across a corrective release remain required release-environment validation. Fake corrective-release fixtures verify feed/notes interruption and resume, not a real installed client's behavior. No real-data external-tool conformance run or end-to-end scientific pipeline was performed. Earlier broad CLI selections did run three existing `seqkit` extraction/search tests on tiny invented fixtures (`ScientificCLIProvenanceCoverageTests`); those passes establish only their fixture-level checks and are explicitly excluded from the final software-contract selection. Generic workflow engines, where available, were exercised only for tiny byte-copy replay fixtures.

The release engineer owns the remaining candidate-level checks: execute the real-app gate in the disposable logged-in `lungfish-release-qa` account (QR-04), confirm the current-commit CI run in its configured environment (QR-07), and demonstrate an installed-client corrective update plus schema compatibility (QR-09). Desktop QA and the adapter maintainers own the family-specific gaps in the journey matrix. Local compilation and fake corrective-feed tests do not close those checks. Actual packaging also requires the release front door’s clean-source and disk-space prerequisites; no packaging was attempted here.

**Test-isolation incident:** earlier AppDelegate lifecycle tests used the default saved-window store without a backup. Metadata-only inspection found the normal `Lungfish/window-state.json` modified during an earlier checkpoint. Touched lifecycle tests now inject a temporary store. The prior saved-window list cannot be certified as preserved; no contents were reconstructed or overwritten speculatively. This is a material limitation of the validation work, not a claim of isolated earlier execution.
