# Reconciliation of the 2026-09-05 and 2026-09-23 audits

**Scope.** This report compares the prior audit (baseline `13e114087`, 35 findings, remediation recorded as complete at `9fffc8fbb` and shipped as 2026.9.9) with the fresh audit (HEAD `a1f439076`, eight specialist reports). Every prior finding was re-checked in current source. The remediation record was treated as a claim to verify, not as evidence. `testing-ci.md` did not exist when this report was written, so it is not covered.

**Method.** Read-only. I read the prior README, the four specialist reports, the remediation plan, `implementation.md` and `journey-verification.md`, and all eight fresh reports. Four read-only sub-reviews checked the ARCH, WF, DATA and QR groups against current source. I re-verified their load-bearing claims myself: the lock API, the release contract, the backup-deleting mutation service, the MSA and tree `--force` paths, the AssemblyStatistics length rule and the retained-snapshot source policy. Dates come from `git blame` and `git log 9fffc8fbb..HEAD`. Nothing was built or run. 479 commits, +33K/-24K lines in `Sources/`, and 30 Preview or Stable releases have landed since the remediation.

**Limits.** "Fixed" means the named defect is gone from the traced source path. It does not mean the family has been verified end to end. Blame dates of 2026-06-01 usually mark the kernel-module `git mv` and not when the code was written. Where that matters, I say only that the code existed before 2026-09-05.

## Headline

- **Remediation mostly held where it was applied.** Of 35 findings, 19 are Fixed, 14 are Partially fixed and 2 are Regressed. None is fully Still open. All eight workflow findings (WF) held, and so did the project-storage fixes (ARCH-03, ARCH-09).
- **Every "Partially fixed" gap is in a sibling that the fix did not reach.** The named caller was repaired, but other callers of the same contract were not migrated. Examples: a second variant mutation service, other CLI commands with `--force`, other table exports, and other `OperationCenter.start` callers. Almost all of these siblings already existed on 2026-09-05. New code has rarely bypassed a repaired contract. Old code was never brought onto it.
- **Both regressions are in release assurance.** A parallel release redesign landed six hours after the remediation. It thinned the release gates and made the GUI smoke optional (`34548a699`). A CI edit on 2026-09-14 invalidated the workflow file (`821ca701a`). Twelve releases, including Stable 2026.9.28, shipped with no automatic CI signal.
- **All seven fresh P0 findings are in code that existed at the prior baseline.** The prior audit missed them because of its lens, not because the code is new. It deliberately excluded scientific algorithm review, and it verified contracts, not live user journeys. The remediation also deferred per-family desktop QA and adapter conformance to "future validation owners". There is no evidence that this work was ever done.

### 1.1 The lock question: `9fffc8fbb` versus ARC-04 and FEA-07

Both claims are true, at different layers.

- **What `9fffc8fbb` actually changed.** The commit touches only `OperationCenter.swift` and one test file. It unified the conflict *detection* rules. Before it, tree-scope overlap was checked only when the incoming request carried `additionalLockedBundleURLs`. Now each lock records an `exact` or `tree` scope, and `activeLockHolder(forCanonicalPath:requestedScope:)` treats either side's tree scope as overlapping ([OperationCenter.swift:381-455](Sources/LungfishKit/OperationCenter.swift:381)). "Enforce ... for every operation" means that every `start` call now consults the unified rule. The file has not changed since.
- **What it did not change.** Refusal is still expressed as a new `.failed` row ("Bundle is busy") plus a normal `UUID` return ([OperationCenter.swift:401-427](Sources/LungfishKit/OperationCenter.swift:401)). This return-a-failed-row shape predates the commit (see the removed lines in `git show 9fffc8fbb`). The regression tests assert only registry state (`canStartOperation`, `activeLockHolder`, the row's `.state`). They do not assert that the refused caller's work never ran ([OperationCenterAdditionalLockTests.swift](Tests/LungfishAppTests/OperationCenterAdditionalLockTests.swift)).
- **Callers that ignore the refusal at HEAD.** Annotation import from the Import Center ([AppDelegate+ImportCenter.swift:604](Sources/LungfishApp/App/AppDelegate+ImportCenter.swift:604)). Annotation drop on the sidebar ([MainSplitViewController+FASTQImport.swift:140](Sources/LungfishApp/Views/MainWindow/MainSplitViewController+FASTQImport.swift:140)). MSA export ([ViewerViewController+MSAExport.swift:42](Sources/LungfishApp/Views/Viewer/ViewerViewController+MSAExport.swift:42)), whose runner pre-flight checks only cancellation ([CLIMSAActionRunner.swift:352](Sources/LungfishApp/Services/CLIMSAActionRunner.swift:352)). Four MSA and tree actions in [ViewerViewController.swift:2011](Sources/LungfishApp/Views/Viewer/ViewerViewController.swift:2011), [:2099](Sources/LungfishApp/Views/Viewer/ViewerViewController.swift:2099), [:2223](Sources/LungfishApp/Views/Viewer/ViewerViewController.swift:2223) and [:2311](Sources/LungfishApp/Views/Viewer/ViewerViewController.swift:2311). None of the 67 `OperationCenter.shared.start(` sites calls `canStartOperation` on the line before it. Only 7 files call it at all.
- **When the unchecked callers were written.** All of them existed before the remediation: 2026-05-15 to 2026-09-03. The only `start` site added after 2026-09-05 is the WF-02 fix itself ([ReferenceBundleImportHelperLauncher.swift:233](Sources/LungfishApp/Services/ReferenceBundleImportHelperLauncher.swift:233), `cb6e9973c`), and it passes no target. Primer operations added on 2026-09-12 do check `state.isActive` after `start` ([MainSplitViewController+PrimerAnalysis.swift:91](Sources/LungfishApp/Views/MainWindow/MainSplitViewController+PrimerAnalysis.swift:91)). So nobody bypassed the contract after the fix. The API never forced existing callers to comply, and package 02's caller audit ("61 registration sites audited") checked terminal-state handling, not refusal handling.
- **One correction to FEA-07.** Annotation-drawer deletion does pre-check, in the same function before `start` ([ViewerViewController+AnnotationDrawer.swift:486](Sources/LungfishApp/Views/Viewer/ViewerViewController+AnnotationDrawer.swift:486)). FEA-07's third bullet is wrong. The other bullets hold.
- **Verdict.** ARCH-01's *cancellation* half is fixed. Its *ownership* half is advisory. Fix it the way ARC-04 and FEA-07 propose: a start API whose refusal cannot be ignored, all `targetBundleURL:` callers migrated, and a test that the refused caller's transport is never invoked.

### 1.2 Other notes the table cannot carry

- **Retained-snapshot exports do not checksum their true sources.** `RetainedSelectionExportSnapshot.publish` records only the retained payload and `selection.json` as inputs, unless the caller passes `preserveOriginalSources: true` ([RetainedSelectionExportSnapshot.swift:26-36](Sources/LungfishApp/Services/RetainedSelectionExportSnapshot.swift:26)). This limitation came from the remediation itself (`cb6e9973c`). `c2920e464` (2026-09-19) added the opt-in, and only one caller uses it ([AnnotationTableExportService.swift:85](Sources/LungfishApp/Services/AnnotationTableExportService.swift:85)). GFF3 and bookmark exports therefore record source paths only as option strings. This weakens DATA-01 and DATA-06.
- **Remediation deferred the journeys, and nobody did them.** `journey-verification.md` certifies none of the 16 families as a live GUI journey. It assigns them to "Desktop QA" and adapter maintainers. Its gaps include per-adapter options, "format/coordinate correctness" and "BAM/CRAM ... coordinate/filter semantics". There is no commit, report or release note since 2026-09-05 recording any of these runs. The `lungfish-release-qa` account appears only in scripts, tests and docs.

## 4. Meta-lessons

### 4.1 Patterns

1. **Named callers got fixed. Siblings did not.** Every partial fix has the same shape: a named caller was repaired, and its sibling with the same contract was not. Examples: `convert` but not `tree` and `msa`, `VariantDeletion` but not `VariantSampleMetadataMutation`, the GFF3 export but not the Kraken2 and BLAST exports, the document-load path but not the download importer. The plan's per-package "Files:" lists set the scope, and the implementers stayed inside those lists. The prior audit sampled one instance of each defect class and presented it as the instance.
2. **Contracts were enforced by convention, not by type.** `start` returns a UUID whether or not it refused. Scoped notifications default to accept. `publish` defaults to not recording sources. `write()` (destructive) still sits beside `writeAtomically`. When the safe path is optional, new and old callers alike take the default. The remediation strengthened the rules inside each authority but left their APIs permissive.
3. **Tests proved the registry, not the caller.** The lease tests assert `OperationCenter` state. The release tests assert that the gate evidence validator rejects bad manifests. Neither asserts the property the user needs: the refused work does not run, and a release without GUI evidence cannot ship. Unchanged source-text tests (about 107 files) also pin implementation shape, which makes sibling migration look riskier than it is.
4. **Concurrent remediation streams can cancel each other out.** The audit remediation and the release redesign landed on the same day with opposite goals: more assurance versus faster headless releases. Nothing reconciled them. The later commit won silently, and the remediation record still describes the earlier state.
5. **Deferred verification became no verification.** "Remaining release-environment validation" and "Desktop QA owns ..." had no owner, date or gate. Thirty releases later, none of it has run. The fresh audit's P0 and P1 findings sit mostly in exactly those deferred areas: per-adapter options, scientific conformance, and GUI reachability.
6. **The fixes that stuck share one trait.** All WF fixes, ARCH-03/07/09, DATA-03/05/08 and QR-01/02 held for 479 commits. Each one replaced a single authority that every caller already went through: one planner, one registry, one gate evaluator, one `replayArguments`, one Nx. Fixes that relied on many callers adopting a pattern are the ones that are now partial.

### 4.2 How to run the next implementation round

1. **Scope by contract, not by file.** For each finding, write a grep or AST query that enumerates *every* caller of the contract. Examples: `targetBundleURL:` sites, `removeItem(at: outputURL)` before staging, `content.write(to:` in export paths, `DocumentManager.shared.register`, `shouldAcceptScopedNotification`. Put the full list in the package. Record each caller as migrated or explicitly exempt, with a reason. Review the list, not a sample.
2. **Make the safe path the only path.** Change `start` to return a refusal the caller must handle (`Result` or `throws`). Deprecate the old overload with `@available(*, deprecated)` and ratchet the count to zero. Make scoped notifications fail closed. Delete `ScientificFileExportProvenance.write` or rename it `writeScratchUnprovenanced`. Make `preserveOriginalSources` default to true. Give `--force` handling in the CLI one shared `OutputPublication` helper, and write a lint rule that flags `removeItem(at: outputURL)` outside it.
3. **Write caller-level acceptance tests.** For every contract, add at least one test per caller *family* that asserts the user-visible property. Examples: a refused MSA export never invokes its transport, a failed `tree infer --force` leaves the old tree byte-identical, and a failed metadata restore leaves a recovery folder. Registry-only tests do not count toward closing a finding.
4. **Add ratchet gates to the fast CI job and the release contract.** Encode each contract as a counted grep in `scripts/` (raw `start(` without refusal handling, `Process()` outside the runner, `NSApp.keyWindow` in App, `testing*` outside `#if DEBUG`). Fail when the count rises. This is the cheap guard against pattern number 1.
5. **Keep one living ledger.** Carry the 35 prior IDs forward with the fresh IDs in a single ledger (this table is a start). Any change to `config/release-contract.json`, `.github/workflows/` or `test-catalog.json` must name the ledger rows it affects. A PR that loosens a gate a finding depends on must reopen that finding. That would have caught `34548a699`.
6. **Restore release assurance before new features.** Fix `ci.yml` (REL-02) and add `actionlint`. Have `release.py` refuse, or at minimum loudly warn, when CI on the candidate commit is not green. Make at least one real-app launch and a file-mode check (REL-01) mandatory for Stable. These are S-effort items that decide whether anything else sticks.
7. **Give deferred verification an owner, a date and a gate.** For each of the 16 families, run one scripted journey on a small invented fixture: open, configure, run, cancel, reopen, export. Run it through Computer Use per project rules, and record the result as a release-contract input. Start with the families where the fresh P0 and P1 findings cluster: FASTQ operations, variants and annotations, trees and MSA, and classifiers.
8. **Review science separately.** Give scientific correctness its own track with small oracle fixtures: multi-segment CDS, overlapping CDS, reverse-strand extraction, ONT qualities, paired subsample and IUPAC contigs. Include `ONTGenotyping`, which neither audit has reviewed for correctness.
9. **Verify skeptically and in fresh context, as both audits did.** Re-run this reconciliation after the next round. It should be run by a reviewer who did not implement the fixes, against HEAD source and not against the implementation record, and it should list the post-fix commits that touched each contract.
