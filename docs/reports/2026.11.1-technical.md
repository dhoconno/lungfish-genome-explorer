## The release

Preview 2026.11.1 is the first Preview of Phase 3.2, session 1 (the other viewer kinds, the sidebar registry and BLAST searches that come back). It builds on Stable 2026.10.29 (build 12045 from `e4f8f9860`), which is also the Stable baseline, and on `origin/main` at `ebe9373cf`, the head the session started from. It holds the 461 commits of the program branch `phase-3-2` between `ebe9373cf` and its head `d282a1d76983fbcc5fa6e85df95580ee7f67c56b`, counted with `git log --oneline ebe9373cf..d282a1d76`. The numbers below are counted at that head. The tool lock did not change since 2026.10.27, so the dependency set stays 2026.2, and the version is the highest `YYYY.M.PATCH` among the committed notes files, as `release_version()` in `scripts/release/release_version.py` names a release. The published package is build 12518 from `94266d11b`, which adds six commits to that head (the Detect Barcodes line of the notes in `12d957b4c` and five docs commits), and the facts of the publish are in the section The publish and the walk.

The session opened with step 0 of the plan, three result rows that the 3.1 walks left. BIO ruled READ-LAYOUT-PARTIAL-SCAN an S1 that cannot wait (a mixed FASTQ file of 50,000 or more pairs paired unrelated reads without a word), the lost negative-control flags of an imported TaxTriage batch an S1, and FASTA-READER-SHORT-READ an S1 that a person reaches by replacing the FASTA inside a reference bundle. The owner's O140 asked for two known-issue lines and a patch, and O141 reversed the patch half: the fixes blend into the session and reach a Preview within seven days of landing, which is why this Preview exists. The seven days ran from LAND-4 (2026-11-04), so the Preview was due by 2026-11-11. The session then landed the BLAST client that waits and comes back (BLASTNET and BLASTCOLLECT), the Unique Reads export, the TaxTriage control and import fixes, the words that replace beeps, and ten viewer kinds through `ViewportHost` (MHC, genotype, tree, MSA, assembly, VCF dataset, FASTA collection, Quick Look, FASTQ dataset, and reference with mapping result). The view-switch matrix now holds 22 kinds and 462 switches. ENDROUTE, the sidebar registry and BLASTDB stay for session 2.

The walk of the first packaged candidate (candidate-2, `ba127aee4`, build 12447) ran on 2026-11-05 and found W-34 (S1): a FASTA file of 20,000 records froze the candidate, which grew to about 404 GB in the macOS memory compressor and starved the release Mac until it was forced off at 14:07:45 (section The walk and the crash). The cause came in with `782dff647` on 2026-11-04, after Stable 2026.10.29, so no published build has it. The five walk votes sent the S1 and S2 rows to fix-now lanes, and LAND-26 to LAND-29 hold those fixes. The last walked candidate is built from `d282a1d76` (candidate-3, build 12512), and its walk (walk 2, 2026-11-05 19:38 to 20:15) left no S1 or S2 open. The package that is published is built from `94266d11b` (build 12518), which changes only docs after `d282a1d76`: the Detect Barcodes line of the notes and these records.

## The command line

- **`lungfish-cli build-db taxtriage <result folder> --force`** before you export an older TaxTriage result from the command line. The export (`TaxTriageExportLoader`) now refuses a stale database in words (`c61298baa`), and `--force` rebuilds it through the same core that the app's recount on open runs (the app's argv is `build-db taxtriage <dir> --force`, `LungfishCLIRunner.swift:180-183`, with no `--no-cleanup`, so a recount of a non-executor folder runs the legacy cleanup again). The command works for a result of 2026.10.27 and of 2026.10.29, also in the layout of a report at the top with sample folders beside it, because the core now reads the root and then the folders (`fe5c3d5e6`, the CLI line "Also read N sample folders beside the root report").
- **A refused rebuild.** A forced rebuild that would leave fewer samples than its database refuses before it writes (`fef6f9b05`), prints the "Parsed N rows" lines and the words "Lungfish did not rebuild taxtriage.sqlite because that would lose these samples", exits non-zero and, in JSON mode, sends a `failed` event with the same words. The old database stays as it was, and the failure record carries the reason (`25a9357f6`). The case is a sample whose organism report has no row and whose folder has no confidence table, once an earlier legacy build removed its `top/`, which is the shape of a clean negative control. Import the run's original folder again to keep that sample. Deleting `taxtriage.sqlite` ends the words and drops the sample.
- **`lungfish-cli fastq deinterleave <file>`** without `--unpaired` checks a file by reading it whole. A mixed file stops with its counts and writes nothing, and `--unpaired` splits it. `map`, `assemble` and the classifiers read the whole file before they pair by position (`c29845778`).
- **BLAST.** `lungfish-cli blast resume` (with `--once` for a short pass) advances a saved search file, `blast submit --park` lets a search wait and outlive its process, and `blast submit --judged-at` records the basis a verdict was judged at (the help golden was recaptured in `999367521`). The contact address lives under `<root>/blast/` and is never in argv, a project file, a record or the replay command (O132).
- **AI.** `lungfish-cli genotype ai-haplotyping` says that the quota is used up with the provider's own words and billing link, and no longer retries when only credits help (`1f0328f5e` pins the CLI route).
- **Words.** `build-db taxtriage` on a batch in which no sample wrote a taxonomy report builds no `taxtriage.sqlite`, and the CLI line promises that LGE builds it when the result opens, which cannot hold for that cause (TT-CLI-INDEX, S3, W1FIX review Backlog 1).
