## What landed

- **TaxTriage synonym rows** (`8e9d5350e`, `94d3c108a`, `9e6ffd093`). When a report row's name matches no gcfmap organism, `build-db taxtriage` reads `map/<sample>.merged.taxid.tsv` (TaxTriage's `append_taxid.py`) and links the row to the unclaimed references of its NCBI tax ID in the same sample, when they belong to one gcfmap organism and no other unmatched row of the sample has that tax ID (`taxTriageTaxIDGroups`). Exact-name matches and the displayed name are unchanged. Both cleanups now keep that one file of `map/` (`keptThroughCleanup`), so a rebuild of a cleaned result keeps the link. `organismAccessions` moved to `BuildDbCommand+TaxTriageReferences.swift` for the file-size ratchet.
  - Evidence: `BuildDbTaxTriageTaxIDSynonymTests` (red at the base) builds a synthetic `pilot` sample with two MAPQ 60 reads on `synthetic_ref` and checks the name, the link, 2 unique reads and both alignments; taxid 730 stays unlinked, and a rebuild after cleanup keeps the link. On a copy of the SRR24010784 pilot result with the taxid file restored, Haemophilus parainfluenzae (729) linked to `NZ_CP065991.1` with 1306 reads and 70 unique, and no other of the 700 rows changed.
  - A result whose `map/` an older build removed cannot be relinked.
- **RNA-seq macaque sets** (`bf870049d`). The catalog adds `rhesus/ensembl-116` and `cynomolgus/refseq-GCF_037993035.2`. The T2T assembly has no mitochondrial genome.
- **RNA-seq served salmon indexes** (`87c9b64ae`, `204b1f15e`, `28e388c96`, `5712c0c80`, `db6fc3f6f`, `e3a8b336e`). Each catalog entry names a prebuilt index in the public LGE LabKey area (`databases/rnaseq-index/`, four archives, `scripts/rnaseq/large-files.tsv`), on the owner's direction of 2026-11-27 (`docs/plans/2026-11-27-rnaseq-served-salmon-index.md`). `install-reference` downloads and adopts the archive through `SalmonIndexCache.adopt` when this Mac's salmon build and the set id match, and `SalmonIndexCache.adopt` refuses it unless the set's contents digest matches too. Otherwise, or with `--build-index`, it builds the index. A served install checks a count's memory. Progress falls back to the row's archive bytes when the server sends no length.
  - The Debug app's walk found that an in-app install refused every served index: the set manifest records the Lungfish version that built it. Each served row now pins the manifest's digest without Lungfish's own versions, and adopt checks that (`e3a8b336e`).
  - Evidence: two builds of the rhesus index were byte-identical; anonymous GETs of all four archives matched their sha256; a served rhesus install gave counts byte-identical to the local index's; the Debug app built from the adopt fix installed mouse from LabKey with an index byte-identical to the CLI's, and the row read Installed. The CLI's served install transcript is `complete-served.ndjson` (`00801f402`).
- **RNA-seq rows drawn like the database rows** (`0cb3ba0ce`). The sets are the last section of the Databases list, drawn with the Kraken2 row's frame. Each shows its disk space once installed (human 18.6 GB, mouse 15 GB, rhesus 10.9 GB, cynomolgus 13.5 GB, du on galah). Refusals sit on their row, an installed set reads Installed, and a second Download of an installed set downloads nothing. Shared layout is S3 DATABASE-ROW-SHARED-LAYOUT.
- **Manual nav** (`7a81a0c93`). The Read the Docs nav lists the five RNA-seq chapters, 02-sequences/06, 03-reads/09 and 08-workflows/04. Docs only.
