## S1 and S2 results of this round

BIO and UX rated the rows below, and severity is not voted (the plan, section Panel decisions). One S1 by effect was open at the start and the round closes it. ### EXTRACT-PREFIX-SCAN-NO-DATABASE, an S1 by effect with rare reach, closed as ruled

BIO's ruling (`SCR/meeting/M34-R1-BIO.md:63`) reads S1 by effect, rare reach, open. A TaxTriage result with no recorded path took the exact name first and then any `.bam` whose name starts with the sample id, in listing order. So sample `S1`, with `S1.x.bam` and `S10.x.bam` beside it, could extract the reads of `S10` with no word. That is a silently wrong result, and the CLI on a raw nf-core folder reaches it. Rare reach does not lower an S1, so decision C7 fixes it.

The EXTRACT lane (red `044a1d40c`, fix `7fc768ba2`) tries the recorded paths, then `minimap2/{S}.bam`, then `minimap2/{S}.{S}.dwnld.references.bam`. It scans the folder only when nothing is recorded and both exact names are absent. A name fits when it ends in `.bam` and continues the sample id with `.`, `_` or `-`, the pipeline's own name fits only its sample, and the listing is sorted by name. Two or more fits are refused with the typed error `ClassifierExtractionError.moreThanOneBAMFitsSample`. Its words name the sample, the folder and the files that fit and tell the person to keep only that sample's file, and the Extract sheet and the CLI show them. At the base the four new tests failed in six assertions.

The lane ran the fixed CLI on a clone of a real nf-core TaxTriage result with its database removed and read 220 reads with no refusal, and that run took an exact name, so no scan ran. BIO ruled that `docs/contracts/SCOPE-AND-DELIVERY.md:100` is met and that a second real run is no should-fix, because all 249 TaxTriage `minimap2/` BAM paths on the Mac carry the pipeline's names and a real result never reaches the scan. BIO closed the row as ruled (`SCR/reviews/EXTRACT-BIO.md`, rulings 3 and 4).

### EXTRACT-SCAN-EXTENDED-ID, a narrower sibling that stays open as a Known limit

BIO's own boundary rule leaves one hole (`SCR/reviews/EXTRACT-BIO.md`, Backlog 1 and ruling 3). With no recorded path, no BAM of its own for sample `S1` and one file such as `S1_2.bam` or `S1.5.dedup.bam` that belongs to another sample and has a name the pipeline does not give, `S1` reads that file with no word. A name rule cannot tell `S1` plus `_dedup` from `S1_2` plus `.bam`, and the lookup holds no list of the folder's sample ids. BIO rates it S1 by effect with a reach narrower than the closed row and ruled it a backlog row with words, not a second lane. BIO's side of check 2 of Phase 3 reads MET-WITH-NOTES for it only if the Known limit words ship in the notes (row 19 of the Known limits). The plan row C7 overstates the code in this corner.
