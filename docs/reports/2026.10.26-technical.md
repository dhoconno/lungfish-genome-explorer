## DEMUX-STATS-BEHIND (S1, BIO)

**What was seen.** On the published 2026.10.25, `Walk 88.lungfish`, SRR12486983 (9,639,520 reads) selected, then the uncounted derived bundle `Analyses/SRR24403534-lengthFilter-old` after a relaunch. The sidebar selected the bundle, while the summary cards, the reads list and the Inspector kept SRR12486983's 9,639,520 reads, Mean Q 4.9 and GC 43.7% for 22 s (17:20:39.4 to 17:21:01.2, AX poller `SCR/walk/rewalk-3-w4a-behind.txt`). The spinner and `Measuring the read statistics for SRR24403534-lengthFilter-old... n reads counted` sat behind the dashboard. Then the bundle's own 1,710,778 reads, 25.4 and 61.9% showed. After a click away mid-count the spinner stayed in the accessibility tree behind the next dashboard. The walk record is `SCR/walk/rewalk-log.md`, section "3 (continued)".

**Cause** (`SCR/rulings/BIO-DEMUX-STATS-BEHIND.md`). `progressOverlay` is added in `loadView`, before any content view, so every dashboard and viewer added later draws above it. `showProgress` only unhides it. Neither FASTQ load path (`displayDerivedFASTQDataset`, new in 2026.10.25 with lane DEMUX-STATS `da2107137`, and the plain `Computing FASTQ statistics...` path, already in Stable 2026.9.78) removed the previous content or the Inspector's dataset section first, and a cancelled request left the overlay unhidden. Every previous view but an empty viewer and a FASTA collection hid the spinner, including reference and mapping viewports, result viewers and previews. BIO ruled S1, a false number shown silently, and a block on Stable.

**Fix** (lane DEMUX-STATS-BEHIND, `lge-worker` on sonnet at effort max, report `SCR/lanes/DEMUX-STATS-BEHIND/DEMUX-STATS-BEHIND.md`).
- `ViewerViewController+FASTQLoadProgress.swift` adds `showFASTQLoadProgress(_:)`, which calls `clearViewport` and then `showProgress`, so every dashboard and viewer, the reference viewport included, goes before the overlay shows. Both FASTQ load paths clear the Inspector's selection and call it, and a new FASTQ request that cancels a running one hides the overlay.
- The FASTQ metadata section saves an unsaved edit to its own bundle before it clears.
- `FASTQMeasuringBehindTests` holds nine tests. The ruling's four were red at the base with 13 failures, and the two of the lane's metadata save and the three of the fold-ins were each red before their change. The lane's run of the related classes passed 382 tests with 3 skipped, and the landing's run passed 355 tests with 3 skipped and the review's six further suites and the metadata suites 141 tests, with no failure.
- BIO reviewed it (`lge-expert` on sonnet at effort max, `SCR/reviews/DEMUX-STATS-BEHIND-BIO.md`) as Merge after fixes, with no blocker. `clearViewport` takes down every content view of the ruling's route table, and no number of a cancelled count reaches another read set.
- Two fold-ins landed with the lane in landing 14 (`c39bd99b2` to `7e20c7fac`, report `SCR/land/land-14.md`), which also lowered the file-size baseline of `MainSplitViewController+GenomicsDisplay.swift` from 1122 to 1120. The metadata section now saves a pending edit to its own bundle before it changes bundle or moves its read-type targets, where an edit made in the last half second was dropped or, for a read type, also sent to the next bundle (S3). A read set with no FASTQ file now clears the viewer and the Inspector and says in the status bar `No FASTQ file in <name>. Wait for its import to finish, or import the reads again.`, where it left the previous read set's dashboard under the new selection with no words (S2, already in Stable 2026.9.78).

## Known limits

- **A metadata edit that cannot be written.** The metadata section writes its file with no error shown, so an edit to a read set on a read-only volume is lost with no words (review backlog, S3, already in Stable).
- **An open annotation drawer.** The viewport clear does not close an open annotation drawer, so beside a loose sequence document it can stay next to the measuring spinner. It holds annotations, never a read-set number (review backlog, S3, not walked).
- **A failed reassembly can name a stale line.** After a cancelled Reassemble, a failure in the same output folder names a line of the cancelled run's `spades.log`, such as `Mode: ONLY assembling (without read error correction)`, while `assembly.log` holds the real error (`ManagedAssemblyPipeline.swift` `failureDetail`, S3 REASSEMBLE-STALE-SPADES-LOG).
- The known limits of the 2026.10.25 technical notes still hold.
