# Lungfish 2026.11.21 technical notes

These are the technical notes of Stable 2026.11.21, and the release notes are in `docs/release-notes/2026.11.21.md`. The technical record of the Preview it is promoted from is `docs/reports/2026.11.20-technical.md`. The notes link this record at the tag `v2026.11.21`, so it is in the commit that is packaged and tagged. It was drafted before the full tier and the stable package, so each fact that only the full tier, the package, the smoke, the QA read or the publish can give is a hidden `PUBLISH-FACT` comment, filled on `main` after the publish. `SCR` is `~/lungfish-phase-records/release-2026-11-27`, and all times are CST on 2026-11-27 unless a line says otherwise.

## The release

Stable 2026.11.21 is the stable release that follows Preview 2026.11.20, on the owner's word in chat on 2026-11-27 at about 18:00: "Yes, the RNAseq testing is done. Merge both to main and make a new Preview and Stable release. Do not overengineer and only solve significant issues uncovered during testing. Add the others to the backlog." (`SCR cand/RELEASE-STATE.md`, section The owner's word). It is a promotion and not a candidate of its own (`docs/contracts/VERIFICATION-ORDER.md`, section Promoting a Preview to a stable release), so it adds no product change to Preview 2026.11.20, which `release.py package preview` packaged from P = `422e825c08e1475d7dbce03cb69f7da6ca5af211` on `main` from 18:49 to 19:07:43 with exit 0 (`SCR cand/RELEASE-STATE.md`, Log). The stable commit S adds the notes `docs/release-notes/2026.11.21.md` and this record to P, after `b13b47a05`, which filled the publish facts of `docs/reports/2026.11.20-technical.md`. Both paths are release-neutral (`docs/release-notes/**` and `docs/reports/**` in `config/release-contract.json`, as `docs/reports/2026.11.7-technical.md` line 19 lists them), so the gate records of P carry to S, and a record cannot hold its own hash, so the hash of S, its build and its tag are added on `main` after the publish. The notes file is the highest `YYYY.M.PATCH` among the committed notes, so it moves the release version from 2026.11.20 to 2026.11.21 (`release_version()` in `scripts/release/release_version.py`, as `docs/reports/2026.11.7-technical.md` line 21 says). Stable 2026.11.14 was cut from `v2026.11.7` and holds none of the work of Previews 2026.11.8 to 2026.11.13 (`docs/reports/2026.11.14-technical.md` line 15), so a user of Stable 2026.11.14 gets from this release the work of twelve Previews, 2026.11.8 to 2026.11.13 and 2026.11.15 to 2026.11.20. A user of Stable 2026.11.7 also gets the one fix of Stable 2026.11.14 (a sample of a large Cutadapt run left out), which `main` has carried since Preview 2026.11.13 (`docs/release-notes/2026.11.13.md` line 21, `docs/release-notes/2026.11.14.md` line 85).
