## The release

Stable 2026.10.29 is the Stable candidate of Phase 3.1, the view-switch and alert quality net, database identity for the classifiers and the start of the ViewportHost migration. The owner's O102 asks for one Stable by 2026-11-04. It builds on Preview 2026.10.28 (build 11807 from `471167711`, which is also `origin/main`) and holds the 184 commits of the program branch `phase-3-1` since that Preview, counted at `e7c29256d`. The numbers below are counted at that head, which lane DOCS4 started from. The last candidate is `e4f8f9860` (build 12045), 238 commits after that Preview, and it shipped. The version is the highest `YYYY.M.PATCH` among the committed notes files, which is how `release_version()` in `scripts/release/release_version.py` names a release, and `release.py` checks the notes of that version for the lines `Channel: Stable`, `Previous versioned release`, `Stable baseline`, `Dependency set` and the headings Included preview releases and Dependency versions. `v2026.10.28` is the Preview, so the next number is 2026.10.29.

The last gate chain then met the ruling BIO-12S-STALE-EXPORT, an S1 in BLAST and an S2 in Export from a 12S viewer that holds a replaced result, and lane STALE12S fixes both in LAND-33. ## Full wording of the shortened notes bullets

These bullets of `docs/release-notes/2026.10.29.md` were shortened, merged or removed so that the notes stay under the 15,000 characters that `docs/contracts/SCOPE-AND-DELIVERY.md:96` sets. ### NAO-MGS shares and BLAST checks

- **A paired-end NAO-MGS share is no longer doubled.** Since v0.4.0-alpha.1, a NAO-MGS result from paired-end reads showed each virus's share of its sample's hits at about twice its true value, so a share could pass 100%. Shares are now correct for results made before and after this release, and you only need to open a result again to see them right, with no new import. Do not reuse a share you noted from an earlier version for paired-end reads. Hits and Unique Reads count each mate of a read pair as one read, and hovering a column header in the NAO-MGS table now says what the column counts.
- **NAO-MGS Verify with BLAST… searches all of NCBI's core_nt database.** In every version from v0.4.0-alpha.1 to Preview 2026.10.28 it searched only records of the taxon being checked, so no read could contradict the taxon and the badge could read Supported when another organism matched better. A read whose best match is another organism, such as the host, now counts as contradicting the taxon, and the badge can read Mixed or Unsupported. The EsViritu, TaxTriage, Kraken2 and NVD checks searched everything already. Run Verify with BLAST… again on any NAO-MGS call from an earlier version that you rely on.
- **Verify with BLAST… judges a row at species level.** A read whose best match was filed under another name in the same species, such as Rotavirus A for a Human rotavirus A row or Canine respiratory coronavirus for a Human coronavirus OC43 row, counted as contradicting, so a correct call could read Mixed or Unsupported. On one Human rotavirus A row, seven reads at 100% identity read 5 supporting and 2 contradicting. Such a read now counts as supporting in NAO-MGS, EsViritu, TaxTriage, NVD and Kraken2 results. Run Verify with BLAST… again on any row that read Mixed or Unsupported, since a saved result keeps the badge it was given.
- **Verify with BLAST… reads both mates of a read pair.** EsViritu and TaxTriage sent both mates, kept NCBI's answer for the first and dropped the second with no word. A row could read Inconclusive with `No significant hit` when the second mate matched at 100%, and a dropped match to another organism could leave a badge at Supported. Now both are judged and the pair counts once, as one fragment, so a row can read `1 supporting, 0 contradicting (1 fragment, 2 reads)`. A pair whose mates match different organisms counts as neither and shows in the conflicting count. Run Verify with BLAST… again on any EsViritu or TaxTriage row from paired-end reads, since a saved result keeps the badge it was given.

### Saved BLAST results and the table you export

- **A saved BLAST result comes back.** In NAO-MGS, EsViritu, TaxTriage and NVD a saved BLAST result now comes back when you return to its row, and the BLAST Results pane stays as you left it, open or closed. A row shows the search sent from that row, in that result and sample, and a row with no search leaves the pane as it was, so read which taxon the pane names. In the Assembly and 12S viewers a result comes back when you return and select the same contigs, or open Unresolved in 12S with the same sequences showing. The pane opens by itself to show it and stays open until you leave the result. The table export works on a result that came back. A search of several contigs also comes back when the contigs are listed in another order.
- **The BLAST table you export says what each read means for the row.** Verdict says only whether a read's alignment passed the quality thresholds, so a read that contradicts the row can read `verified`. The new Queried Taxon and Taxon Check columns at the end of the table say what the read means for the row. A BLAST of a contig or a sequence asks no taxon question, so its Queried Taxon is empty and its Taxon Check reads `no taxon queried`. A table exported by an earlier version does not have these columns, so export it again before you rely on it. The other columns have not moved.
- **BLAST rows in Operations and checks with NCBI.** A finished BLAST row in Operations now gives the pane's counts, such as `0 supporting, 1 contradicting of 1 read`, where it said `1/1 verified`. Lungfish now asks NCBI about a running search once a minute, as NCBI requests, so a finished search can take up to a minute to appear.
- **A 12S result replaced on disk.** If a 12S result is replaced on disk while it is open, Export now stops and says so. BLAST stops and says so when the sequences in the result are no longer the ones on screen, so no wrong sequence goes to NCBI. If the unresolved sequences of a 12S result cannot be read, the Unresolved tab now says so, because an empty table there does not mean the result has none.
- **A moved, renamed or copied assembly result reads its own folder.** BLAST Contig, Copy FASTA, saved BLAST results and the Inspector's run details read the folder the assembly was first made in. If that folder was gone, BLAST Contig did nothing and showed no message. If it still existed, as in a copied project, a contig of the same name was read from there, so when the two differed, for example after a new run under the same name, the sequence sent to NCBI or copied was not the one on screen, and nothing said so. Every action now reads the result on screen, and you need no new import. A BLAST search you saved on a result before you renamed it in the sidebar does not come back, and a search saved after the rename does. If the contigs file of the open result can no longer be read, Extract, Export FASTA, Create Bundle and Run Operation now say so and do not run. If you ran BLAST Contig or Copy FASTA on a copied or moved assembly with an earlier version, run it again. This goes back to at least v2026.9.78.

### Reads you extract

- **NVD Unique Reads counts each read once.** A BAM with secondary or supplementary alignments made the column count a read more than once. On our small test file a count of 7 became 5. An NVD result imported with Stable 2026.10.27 or earlier keeps the Unique Reads it stored, so import it again to get the corrected number.
- **Extract Reads writes each read once.** From an EsViritu, TaxTriage, NVD or NAO-MGS row, an extraction wrote a read more than once when its alignment file held secondary or supplementary alignments. EsViritu, TaxTriage and NVD rows now write each read once, matching Unique Reads, and we have not checked this for a NAO-MGS row. In our test data no EsViritu extraction changes and one TaxTriage row writes 983 reads where it wrote 993. From an NVD result imported with Stable 2026.10.27 or earlier, an extraction can write fewer reads than the older Unique Reads it shows until you import the result again.
- **Extract Reads keeps both mates.** A pair that a run mapped as two single reads, as happens with reads downloaded from SRA, lost one mate in an extraction. Both mates are now kept when you extract from an EsViritu or TaxTriage result, by read ID from a BAM, from a region of the alignment viewer, and for selected reads by name from an alignment. Before, an extraction could come out a few reads short of the count shown, on our test data 1 to 5 reads and up to a third of a small selection, and nothing said so. Extract again to get the missing mates.
- **NAO-MGS reads are stored on the right strand.** Extract Reads from a NAO-MGS result wrote about half its reads reverse-complemented, and the reads view and the BAM file in the result folder showed those reads on the wrong strand as well. A result imported with 2026.10.28 or later writes each read as it was sequenced, and `lungfish-cli markdup --force` keeps the BAM files of a NAO-MGS result, where it replaced them with empty ones.
- **Older NAO-MGS results are refused, not extracted.** A NAO-MGS result imported with Stable 2026.10.27 or earlier stored the reads that map to the reverse strand the wrong way round, so those reads came out reverse-complemented when extracted and showed as false mismatches in the read panels, although counts and read IDs were right. The read panels now say so, and Extract Reads and the command line refuse with the same words and write nothing. Import the same NAO-MGS results file again in the Import Center, under NAO-MGS Results. The new result takes the name with -2 added, and the old one stays in the project until you remove it.

### Alignment counts

- **Mapped counts say what they count.** When an alignment's statistics hold no read counts, the Inspector and the mapping header label the numbers as alignments, since a read that aligned in more than one place counts once for each place. When the total number of reads is unknown, the header shows no percentage and says so, where it showed `N / N reads mapped (100.0%)`. The Inspector shows Not recorded for a track that holds no counts, where it showed 0.
- **The command line says the same.** `lungfish-cli bundle list` and `bundle info` label alignment counts, and `bundle info --format json` adds a `mapped_read_count_basis` entry that says what each alignment track's `mapped_read_count` counts. `lungfish-cli import bam` into a plain folder now counts reads the way the app does, so a BAM with supplementary alignments reports its reads and not its alignment records.

### Failures explain themselves

- **Failure alerts name the step and the next thing to try.** Alerts from the Import Center, the Inspector, the genotype and assembly views, sequence and table export, project opening and migration, annotation edits, primer exports and FASTQ barcode detection now say which step failed, what happened and what to try next. A message the app wrote about your own input, such as a BAM file opened as a document, a sample sheet with a missing column or a bundle that is read-only, stays in view with the next step beside it. The technical error is under Show Details.
- **A NAO-MGS, NVD or CZ-ID result that cannot be opened says which one.** The alert names the result and says what to try next, such as importing it again for a missing file or an older layout, and the technical error is under Show Details.
- **Verify with BLAST… says why it cannot start.** When NAO-MGS cannot start BLAST or cannot read the reads for it, or an EsViritu result records no alignment file for the sample, the results below the table say why instead of an alert. The refusals for an NVD contig without its sequence and for a Kraken2 result without its reads name the button Verify with BLAST….
- **A database archive that cannot be installed says why.** When it holds a link that leaves its own folder, the alert names the link, says that nothing was installed and says what to try. A ZIP dropped on the sidebar that holds such a link says the same. The official Kraken2 viral and EsViritu archives hold no such link and install as before.
- **A NAO-MGS result whose alignment file is missing says so.** The read panels name the file and tell you to import the same NAO-MGS results file again. They used to stay blank.

### Time limits

- **Analysis steps no longer stop at a fixed time.** Kraken2, Bracken, the mappers, read extraction, variant calling, human read removal, MAFFT alignment, assembly, the FASTQ tools, FASTQ import, demultiplexing, BAM import and filtering, duplicate marking, primer trimming, read orientation, Savont clustering, ONT genotyping, Freyja, the database builds and the FASTA and VCF clean-up steps run until they end or you press Cancel, which stops them at once. ### Limits you may meet

- **BLAST Verify.** It judges a row at species level when the NCBI Taxonomy database is installed, and for an EsViritu row the EsViritu database too. So it cannot tell strains, genotypes or host groups apart. A SARS-CoV-2 row is judged at its species, Betacoronavirus pandemicum, which includes SARS-CoV-1 and the SARS-related viruses of bats and other hosts, even though SARS-CoV-2 and SARS-CoV-1 are only about 80% identical across the genome. For Influenza A, Influenza B and Norovirus norwalkense, which have too many strains to list, it checks the line from the strain up to the species and the names on it, so a record named otherwise can count as another organism. Without those databases, a best match that is another virus of the same species, such as Bovine coronavirus for Human coronavirus OC43, counts as contradicting, and an EsViritu row is judged by names, so a record of another species that starts with the same word, such as a Rotavirus C record for a Rotavirus A call, can count as supporting. A read tied at one score counts as supporting when any of the five records NCBI returns for it is in the row's species, and the row shows a conflicting count. So it cannot tell a virus from a lab vector built from it, and a matching record NCBI did not return cannot help. NCBI can return a different five on another run, so the same reads can read Supported once and Unsupported the next time. A large row is sampled read by read, so some pairs send one mate. Look at each read's best match in the saved result before you rely on a badge. NAO-MGS Verify with BLAST… can also take longer than before, because the search is no longer limited to the taxon. Any search still in NCBI's queue after about 10 minutes stops and gives its request ID. About half of our test searches stopped this way, and those we followed finished at NCBI hours later. You can open a finished search on NCBI's site, but Lungfish cannot read it back or badge it, so send the row again later. In the Assembly and 12S viewers a saved BLAST result comes back only when you select exactly the contigs or sequences that were searched. No list of past searches exists there, so note which ones you sent.
- **NAO-MGS.** Older results need their results file again, and an import made with another minimum identity can give other counts. The note about a missing alignment file appears once Lungfish has tried to rebuild the file from the reads stored in the result. For results imported by recent versions that takes a few seconds, and an older result that still holds its reads is rebuilt first, which can take longer on a large result. Extract Reads and Verify with BLAST… keep their own words for a missing file. A window that this note stretched before the update can still open wider than your screen, so choose Window > Zoom once to fit it back.
- **Extract counts.** The count shown for a region or a selection in the alignment viewer is the number of alignment records. The file can hold fewer reads, one fewer for each selected record that has no sequence and for each extra record of one read that carries the same mate flag as another record of it, which is written once.
- **Time limits.** Only the commands named above offer `--time-limit`, and the app has no field for one, so press Cancel to end any other run.
- **12S results.** The screen does not refresh by itself when a 12S result is replaced. It keeps showing the old numbers until you select another item in the sidebar and then select the result again, and the same steps clear the message that Export and BLAST show. Export also stops when the result was written again with the same numbers, because it checks the files.

### Limits you may meet, continued

- **A BLAST search saved before you rename an assembly result.** A saved search goes with the result's name. After you rename the result in the sidebar, the earlier search stays on disk and does not come back. A search saved after the rename does, and renaming the result back to its old name brings the earlier one back.
