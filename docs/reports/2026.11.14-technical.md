## The fault it fixes

DEMUX-SHARED-NAME-GZIP (S1, BIO). Cutadapt 5.2 opens one writer for each adapter line and keeps the last writer of each name, and each earlier writer of a name ends a 20-byte empty gzip stream at the start of the shared file when it closes. So a run that writes two or more adapter lines under one name to gzip temporaries loses every read of each output that grows past about 202 KB of gzip, exits 0 and counts only the outputs that stayed whole (`DDBR/rulings/BIO-SHARED-NAME-GZIP.md:8` and `:28`). Cutadapt 5.2 on the pipeline's lines lost 100% of 50,000 reads on a built-in dual kit at Both Ends 0/0 (12 of 12 rows) and nothing on a control with one line a name (`:50-54`). One run of a single-index kit at a distance above 0 showed `Input reads: 4597, Assigned: 4597 (100.0%)` on 100,000 reads, so only the input file's own read count shows the loss (`:56-58`).

At the tag a single-index kit at a distance above 0, a built-in dual kit at a distance above 0 and a built-in dual kit or a `# kit:` definition at 0/0 reach the fault, as read and not run (`SCR/lanes/PORT.md:42-53`). The last is the default of the command line, the dialog and the plan of the Demux tab. The notes say nothing of Detect Barcodes, since QA ruled the draft sentence false at the tag (`SCR/coordinator-page-edit-2026-11-19/QA-page-lines.md`, C1).

The fix is one predicate. `writesPlainCutadaptOutputs(_:adapterFASTA:)` (`DemultiplexingPipeline+Scout.swift:505-513`) is true for the observed route of a Custom Definition, or when any first word of a `>` line of the adapter file the run wrote stands on two or more lines. `DemultiplexingPipeline.swift:156` reads it after the adapter file is written, `:161` writes plain temporaries when it holds or the run places mates, and `:228-230` gzips them after Cutadapt when the run places no mates. `runScoutCutadapt` does the same (`+Scout.swift:529-533` and `:567`). It is the code of `794ae5bff` on main without an offset check, which the tag lacks. A run whose lines repeat records `-o {name}.fastq`, keeps the same reads in other gzip bytes and counts the reads it holds, but it needs the disk of the plain reads and takes longer.

Red came first at the base source, with 5 tests and 10 failures, and test (a) alone failed at `red-a.log:327` on its first row with "trailing garbage ignored". With the fix all 5 pass, and the targeted run of the Demultiplex suites ends with 317 tests of LungfishWorkflowTests (2 skipped, 0 failures) and 32 of LungfishCLITests (1 skipped, 0 failures) (`SCR/lanes/PORT.md:25-40`). BIO merged it with 0 blockers, 0 should-fix items and 10 backlog lines (`SCR/reviews/PORT-BIO.md`).
