"Restore after" is the point after which a restored value cannot be overwritten. The rows of VS U1 are never restored in any view, and the column "Never" lists only what a view adds to them.

## Held outside the bundle today

Every one is written on the main actor, unbounded and never pruned (SWIFT F-S11). VS A10 (O4) moves the second and third into the store, each old key read as a starting value while the item has no store entry and never written back, and keeps the first.
- Filter profiles, `com.lungfish.filterProfiles.<manifest identifier>` (`LungfishApp/Views/Viewer/FilterProfileManager.swift:76-91`), shared by a reference and all its mapping results (ARCH F-A11). Named presets a person saved, so they stay in `UserDefaults`, out of scope.
- Haploid mode, `VariantHaploidMode.<id>` (`LungfishApp/Views/Viewer/AnnotationTableDrawerView+Columns.swift:679-695`, id from `:664`). A reading of the data, so it moves into the store in VS-MAP under VS B6.
- Metadata column layouts, `org.lungfish.metadata-column-layout.<table>:<result path>` (`LungfishKit/MetadataColumnController.swift:81`), which 59 test files restore (QA F3). They move into the store in VS-PARTS.
- Global view keys that are not per bundle (`ColumnConfigurationPopover.swift:53-67`, `BlastResultsDrawerTab.swift:231`, `GenotypeComparisonMatrixView.swift:357,1807-1809`, `GenotypeOutlineView.swift:487`, `ViewerViewController+FASTQDrawer.swift:53`) stay as they are.
- `window-state.json` keeps each window's sidebar item, active content URL and Inspector tab (`ProjectWindowStateStore.swift:18-48`). Its Inspector tab stays the fallback for an item with no store entry (VS U7, O6).
