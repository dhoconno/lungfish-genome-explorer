## What the design team found

Three Opus inventories read the code at `ddfe9b778`. Their fact bases are in the session notes and are summarized here.

| Finding | Consequence for the plan |
|---|---|
| A first provenance write is durable, but a rewrite, a signed write or a write with an observer has no fsync and renames the old record to `.provenance-displaced-<UUID>`, which nothing recovers | Writer durability stays the first lane, through `PortableRename.swap` on the anchored parent folder |
| Outside a project the store walks from `/` and refuses symlinks, so `conda offline-install` rolls back a verified install. The `/home` cost is one uncached `realpath` per path value | Anchor at the destination folder and memoize canonicalization per call |
| Dropping the 14 alias keys changes 35 golden records. The envelope decoder already reads version 2, so only `WorkflowRun` readers such as `ops stats` break | Readers land in wave 2 and the version 2 encoder in wave 3, closed by one golden recapture |
| No golden holds a parser defect. Moving the 11 `tool(named:)` callers fixes the dropped minimap2 build and changes two mapping goldens and the iVar header line | Parser fixes and export pins sit in the golden wave |
| 15 `lungfish*` folder kinds, 68 `"lungfishref"` literals, 105 files that decide a kind from the extension (25 of them case-sensitive) and eleven tables that disagree | A string-backed `BundleKindID` registry in IO, frozen by a parity test before any caller converts |
| Viewing a FASTQ dataset without cached statistics rewrites `<reads>.lungfish-meta.json`, which every demo FASTQ bundle covers with a record | The view-time write stops. What a recorded digest covers never changes |
| Walk F6 comes from the bundle writer recording its own record as an output, and the same mechanism records `manifest.json` and `.lungfish-meta.json` | F6 is fixed in wave 1. The general rule is written for new writes |
| CLIEvent is emitted by 11 of 138 command files, carries no version and has five exhaustive switches in the app. There are 15 private event formats | A `CLIEventLine` envelope with `schemaVersion` on every line, leaving the enum alone |
| Walk F7 comes from `WorkflowOperationExecutionService.swift:996`, which logs any stderr line that is not progress as a warning, while the 12S commands print their last line on stderr | The 12S final lines move to stdout in wave 1. The single warning rule is the spec rule and lands in 2.8 |

## Panel decisions

Settled by all five memos, or by every memo that addressed the point with no objection.

| Id | Decision |
|---|---|
| S1 | Rewrites, signed writes and observed writes publish through `PortableRename.swap` on the anchored parent descriptor, never the URL form that resolves from the working directory |
| S2 | `/home` canonicalization is memoized per call inside `CanonicalFilePath`, and every canonical path stays byte-identical |
| S3 | Schema version 2 drops all 14 alias keys from new records, and readers keep every alias |
| S4 | A fact a record never held is an optional shown as Not recorded, never a value from the reading Mac and never a sentinel |
| S5 | Escaped slashes go with the version 2 encoder in the one golden recapture. Signatures survive because signing reserializes the parsed object |
| S6 | Step parentage is a recorded `parentStepID`, plus the `.building-` heuristic for released records |
| S7 | Unpinned script exports are refused in the CLI and the GUI together, with `--allow-unpinned` and a confirm sheet before the save panel, and the override is recorded |
| S8 | The stderr rule (first 2,048 and last 8,192 characters) is public in Core and applied at init only, so reading an old record never cuts it again |
| S9 | `BundleKindID` is string-backed like `AnalysisToolID`, and an unknown kind decodes |
| S10 | Packages without a viewer keep walking, and `.lungfish12sref` is its own kind, not a genome reference |
| S11 | View state is declared app state inside the bundle, outside checksums and records, written only after a user change. Fields that shape an export, such as `genotypeLocusDisplayOrder`, stay recorded |
| S12 | The GUI search index is a derived cache with no record, and `universal-search reindex` keeps its record |
| S13 | A deleted built-in cohort is recorded in the sidecar settings, the seeding record names its cohorts, and Restore Built-In Cohorts brings them back |
| S14 | `buildDatabaseToken` and `outputStem` are fields on `AnalysisToolDescriptor`, after pins land on unchanged code |
| S15 | CLIEvent version 2 carries `schemaVersion` on every line, decodes through a `CLIEventLine` envelope that leaves the enum alone, keeps events on stdout and human text on stderr, and keeps `--format json` |
| S16 | Completed with Warnings follows today's rules in 2.6, with F7 fixed by moving the 12S final lines to stdout. Warning events as the only source is the spec rule and lands in 2.8 |
| S17 | The private shapes S2, S3, S8, S9, S15 and the 12S progress text are the ones that may migrate in 2.6. S1 waits for 2.7 |
| S18 | The CLI contract acceptance is a per-leaf table checked in the unit tier with transcripts captured from real runs, and its `.legacy` rows count the shapes left, so no new ratchet is needed |
| S19 | Kraken2 gains `kraken2 classify`, registering the same `ClassifyCommand` beside `conda classify`, and recorded commands keep `conda classify` until 2.7. Kraken2 gets a `classify` provenance policy entry |
| S20 | Bracken records 3.1 with source-build evidence, the lock stays at 1.0.0, and exports treat Bracken as unpinnable |
| S21 | Sidebar routing through the registry (lane B8) and the lowercased extension convergence move to 2.9, because those sites pick the BAM and VCF viewer and need a walk |

## Execution

Program branch `worktree-phase-2-6` in `.claude/worktrees/phase-2-6`, from main `ddfe9b778`. Lanes run with agent worktree isolation, first fast-forward to the program branch, run only targeted tests plus the serial, replay, storage, end-to-end and conformance suites they touch, and never edit `docs/architecture/MODULES.md`, `Package.swift`, a ratchet baseline, `scripts/full-suite-gate.sh` or `config/test-catalog.json`. A lane that fixes a defect shows its new test failing at its base first. A freeze commit passes at its base. A lane stops and reports any snapshot, golden, parity or routing diff it did not predict. At most four lane worktrees build at once. Experts review each lane in their field before it lands by cherry-pick. After each wave the manager regenerates the module map, adds catalog rows, lowers the baselines that fell, runs the unit tier once with the lanes idle and rewrites the continuation notes.

## Acceptance

- Every `provenance-compat` case decodes with equal facts, every signed record verifies, and the demo archive sweep reads 10 of 10 identically before and after any reader, finder, lineage, exporter or installer change.
- On APFS no injected fault empties a record name. On real ExFAT and under `--simulate` a decodable record remains after recovery. A 101-record bundle write issues one full flush.
- Version 1 and version 2 event transcripts decode under both decoders, and lines at a higher version with unknown keys, names and kinds never throw.
- The parity table and the routing safety net equal the frozen commit for every BAM, VCF and reference row.
- `golden.py compare` shows only the key paths G predicted, scientific payloads byte-identical.

The final candidate passes the unit tier, the replay suites, the golden compare, `exfat-tests.sh` on a real image and simulated, the serial suites the lanes touched, the demo sweep and a GUI walk or, with the screen locked, the Phase 2.4 substitutes.
