## What the design team found

Three inventories and five expert memos read the code at `7faa999d7` before any lane started.

| Finding | Consequence for the plan |
|---|---|
| R2 mixes two identity spaces. An analysis kind is a result type under `Analyses/` (21 ids in `AnalysesFolder.knownTools`). A managed tool is a lock entry (44 ids, 17 tools and 27 pack tools). They coincide for 12 strings and differ for `bbmap` and `bbtools`, `viralrecon` and `nf-core-viralrecon`, and six analysis kinds that have no lock entry | Two typed ids and two registries, joined by one unit-tier test. Only the managed-tool side is decoded from the lock |
| The lock carries no probe, display, family, icon or viewport facts, and any change to its bytes changes `manifestHash`, which drives the launch fast path, receipt checks, Debug to Preview tool sharing and two Python copies of the hash | The lock bytes and schema do not change tonight. Presentation facts live in Swift in IO, probe facts in one Workflow table keyed by lock id |
| Probe facts live in six tables with three parsers that disagree on real output (EsViritu read as `3.14` from its Python path, GATK `4.6.2.0` cut to `4.6.2`, primalscheme3 losing `+lge.5`) | One probe table tonight. The production parsers stay until their recorded values can move under a golden proof |
| Every BBMap mapping record names micromamba's error line, with the home path, as the mapper version and names a `bbmap` conda environment that does not exist. The run itself is correct, because it executes in `bbtools` | Fixed tonight with a faithful test double first. Renaming the environment alone would make PacBio mode record `0.40` |
| bwa-mem2 records `ERROR: unknown command '--version'`, vsearch records `10.7717` from its citation DOI, executed GATK runs record `4.6.2`, and FASTQ ingestion records the lock pin as observed when its probe fails | Deferred to 2.6, where recorded versions change under schema version 2 |
| The lock is hashed two incompatible ways. `ManagedToolLock.manifestHash` hashes a sorted re-encoding, and the release tooling hashes the raw bytes | 2.5 computes the raw-byte SHA-256 from the same read that decodes the lock. `manifestHash` keeps its jobs |
| Nothing refuses an unpinned export, and 26 genotype steps record `unknown` today | A compute-only version evidence type and a pure export pin assessment tonight. Refusal ships in 2.6 in the CLI and the GUI together |
| The sidebar snapshot fixture builds its input from `AnalysesFolder.knownTools.sorted()`, the code under test | The fixture becomes a literal list before any registry code |
| `AnalysesFolder.swift` is 792 lines under the 800-line rule, and `NativeToolRunner.swift`, `SidebarProjectScanner.swift` and `MappingProvenance.swift` sit at their baselines | New code goes in new files and those lanes shrink or stay line-neutral |
| Any test class whose name contains `Conformance` or a hazard suite name never runs in the unit tier | Every new pure test is named outside those lists, and real-tool tests carry `Conformance` |

## Panel decisions

Settled by all five memos, or by the memos that addressed the point with no objection.

| Id | Decision |
|---|---|
| S1 | `AnalysisToolDescriptor` and `AnalysisToolRegistry` are static Swift data in `Sources/LungfishIO/Analysis/`. IO never reads the lock, and nothing is generated |
| S2 | Facts are split. Provisioning facts stay in the lock, presentation facts in the IO registry, probe facts in one Workflow table keyed by lock id. No lock byte or schema change tonight, checked by an empty `git diff` of `Sources/LungfishWorkflow/Resources/ManagedTools` |
| S3 | Two string-backed struct ids, `AnalysisToolID` and `ManagedToolID`, each `RawRepresentable`, `Hashable`, `Sendable`, `CustomStringConvertible`, and coded as a bare JSON string. Neither is an enum or `ExpressibleByStringLiteral`, and unknown ids decode |
| S4 | `NativeTool` raw values, `nativeToolPolicies` keys, `native.<raw>` policy ids, analysis directory names and the metadata `tool` field keep their bytes. `NativeTool` gains an exhaustive `managedToolID` |
| S5 | The sidebar fixture becomes a literal list of the 21 ids, and today's display names, badges, icons and `NativeTool` probe argv are pinned, before any conversion |
| S6 | Every display name and icon keeps its exact value behind the registry. Display names double as CLI tokens (`build-db`), output folder stems and saved labels, so unification waits for token fields and a UX ruling |
| S7 | The lock hash is the SHA-256 of the bundled lock file's exact bytes, computed once from the same read that decodes `bundled`, nil when the file cannot be read, exposed as an API only. No record field and no default parameter carries it tonight |
| S8 | A compute-only version evidence type (observed, pinned but not measured, unknown with a reason) and a pure export pin assessment. No exporter refuses tonight |
| S9 | `ToolVersionConformanceTests` iterates the probe table in place, fails on a missing probe executable in require mode instead of skipping, and probes RiboDetector through `ribodetector_cpu`, the executable LGE runs |
| S10 | The BBMap record is fixed tonight. The environment comes from the lock entry and the version from the runner that executes BBMap |
| S11 | Left alone tonight: the Minimap2 environment pick (no production caller, deleted in 2.9) and `AnalysesMigration` (no production caller, deletion goes to the owner) |
| S12 | Deferred to 2.6: `tool(named:)` callers, CZ-ID batch routing, the search gaps for `kraken2-` folders and `type:kraken2`, the export pin output and refusal, the parser defects (bwa-mem2, vsearch, GATK, FASTQ ingestion's pin fallback). Deferred to 2.7: inherited `CONDA_*` values in records and merging the three parsers |
| S13 | A `tool-identity.sh` ratchet counts bare analysis-id literals used as decisions, `tool(named:)` lookups and `?? "unknown"` fallbacks, which may only fall |

Votes on the contested points. The tie rule was the option that loses no recorded information and can be verified tonight, then the smaller change.

| Id | Question | Ruling | Vote |

## Execution

Program branch `worktree-phase-2-5` in `.claude/worktrees/phase-2-5`, from main `7faa999d7`. A lane stops and reports on any snapshot diff, golden diff, parser result that differs from its pin, or `NativeTool` argv change. Experts review each lane before it merges. After each wave the manager rebases the lanes onto the program branch in order, regenerates the module map and lowers the baselines that fell.
