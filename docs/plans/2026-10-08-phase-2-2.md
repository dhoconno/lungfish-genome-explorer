Status is active. Sub-phase 2.2 of `docs/plans/2026-10-02-architecture-program.md`, finding R7 of `docs/reports/2026-10-02-architecture-review/REVIEW.md`. Delete this file when the program plan closes.

## Owner decisions of 2026-10-08

| Decision | Ruling |
|---|---|
| Where the primitive lives | LungfishCore, under `Sources/LungfishCore/Process/`, so Core and IO spawners can use it. NativeToolRunner, CondaManager and ProcessManager stay in LungfishWorkflow as adapters. |
| Scope of 2a in 2.2 | The primitive, adapters for the five runners (NativeToolRunner, CondaManager.runTool, ProcessManager, LungfishCLIRunner, CLISubprocessTransport), the spawners with known defects, and a ratchet that only falls. About 40 system-tool spawners (gzip, unzip, tar, zip) migrate in later sub-phases under the ratchet. |
| Depth of per-tool goldens | Tiered. Every tool that runs on a small fixture in seconds gets byte-exact stdout, exit code and output-file goldens through each runner that serves it today, plus a stdout case over 64 KB and an error-exit case. Heavy tools (flye, hifiasm, clair3, medaka, GATK, Nextflow pipelines) get exit code, version and one error-path golden. |
| Golden machine | The desktop Mac becomes a second release Mac with its own `~/.lungfish-stable`, copied from the laptop. The goldens stay machine-bound as the README describes. |

## Execution

Lanes follow `docs/contracts/VERIFICATION-ORDER.md`. A lane runs only targeted tests in its own worktree and never the unit tier. After each wave of at most three lanes merges into the program branch, the unit tier runs once in the primary checkout. Review fixes run targeted tests only. The final candidate runs the unit tier, the replay suites, the golden compare, the tool goldens under `LUNGFISH_REQUIRE_TOOLS=1` and one GUI walk on a Debug build, each once.

Program branch `claude/phase-2-2`, from main. Every Swift command sets `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, because this Mac's `xcode-select` points at the Command Line Tools. Opus lanes take the design and scientific work. Sonnet lanes take mechanical work, stop at any judgment call and report it. The manager reviews every diff before merge.

## Acceptance

- Tool goldens are byte-identical before and after every adapter lane, and the existing golden compare is unchanged.
- Cancelling a running Nextflow (TaxTriage) and a BBTools run leaves no java child, shown by a test and by one GUI cancel.
- A tool writing more than 64 KB to both streams never deadlocks, in every adapter.
- The process-spawn ratchet is at or below its baseline, and the baseline has fallen.
- The unit tier, the replay suites and the golden compare pass on the final candidate, and the Debug build passes the GUI checklist.
