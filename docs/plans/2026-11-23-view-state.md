## User outcome

A person who leaves a bundle and comes back, in the same run of the app or after a relaunch, finds its view as they left it: the locus and zoom, the selection, the scroll, the sort and filters, the visible tracks and columns, the embedding and colouring, and the open tab. A mapping result keeps its position, zoom and selected contig, as the owner asked. A bundle whose data changed opens clamped or at its starting view, with one line that says what was not kept, never at a wrong locus and never with a selection on other rows. Viewing writes nothing into a bundle or the project on any volume. The next Preview after 2026.11.17 carries this after a packaged walk (`docs/contracts/SCOPE-AND-DELIVERY.md:26`).

At the base:
- No viewport keeps anything across a switch. Each show builds a new controller and drops the old one (`LungfishKit/Surfaces/ViewportHost.swift:86-90,158-164`, SWIFT F-S1). `clearTransientViewportState()` clears only overlays (`LungfishApp/Views/MainWindow/MainSplitViewController.swift:513-519`), so the brief's first fact was wrong. The read block is the exception: its filters carry through a switch to another kind while its last bundle URL stays the same (`LungfishApp/Views/Inspector/Sections/ReadStyleSection+BundleConfidence.swift:25-32`), shown only in the Inspector.
- The reference viewer writes its locus into the bundle and never reads it back. The only route passes `restoreViewState: false` (`LungfishApp/Views/Results/Reference/ReferenceBundleViewportController.swift:818`), while the capture writes chromosome, origin and scale (`LungfishApp/Views/Viewer/ViewerViewController+BundleDisplay.swift:754-757`). So the owner's example fails today.
- That write runs on the main actor (`ViewerViewController+BundleDisplay.swift:717-723`, `LungfishCore/Bundles/BundleViewState.swift:288`), and it reaches a project opened read-only on a writable disk, since it never asks `isReadOnlyRecommended` (`LungfishApp/StateManagement/ProjectSession.swift:155-156`, `ViewerViewController+BundleDisplay.swift:729-737`).
- Relaunch already reopens each window's bundle and Inspector tab from `window-state.json` in Application Support (`LungfishApp/StateManagement/ProjectWindowStateStore.swift:103-157`), but not the bundle's place in it.
- Genotype is the one kind that remembers: view mode, layout and density, in a file inside the bundle (`LungfishIO/Bundles/GenotypeResultViewState.swift:18-27`).

## The mechanism (START items 2 to 5)

One mechanism in a new folder `LungfishKit/ViewMemory/`, in row 5, the lowest row every adopter reaches and the row that owns the slot (`AGENTS.md:31-46`; a leaf imports only Core, IO, Workflow and Kit, `docs/contracts/analysis-surface-checklist.md:35`). It adds no target and no dependency edge. The store imports Foundation, Core and IO only.

1. **State type.** `ViewMemoryState: Codable, Sendable, Equatable`, with a `kind` and a `schemaVersion`. Each view's struct sits beside its viewport and copies only the view fields of its injected `@Observable` model (`analysis-surface-checklist.md:36`). The store wraps it in a record with the kind, the schema, the data key (VS B1), the bundle folder's identity and the time it was last restored.
2. **Hook.** `ViewMemoryAdopting: ResultViewport` (`LungfishKit/Surfaces/ResultViewport.swift:69-102`) adds the item URL, the data key, `captureViewMemory()` and `restoreViewMemory(_:dataChanged:)`. The adopter owns the clamp or drop rule of each field, through the shared rules of VS B2 to B7, and the store never reads scientific data.
3. **Store.** `ViewMemoryStore`, one process default whose root sits under Application Support (VS A1, A4), or an injected root in tests (VS A6), with the layout and bounds of VS A9 and the writer of VS S1.
4. **Restore step.** `ViewportHost` takes the store. In `removeActiveViewport`, before `willDeactivate`, it captures the leaving view (`ViewportHost.swift:158-161`), and its `captureActive()` stores the installed view without removing it, at window close, project close and quit (VS S1). After `load` returns with its token current and before `commit` (`:127-133`), it hands the adopter its record, so the first frame is the restored view. An adopter whose own load runs on after install applies the record when that load commits, under its counter and only while the view still equals its starting view (VS A2). The host also serves Reset View, and it draws and clears the reset line (VS U2).
5. **Shared parts.** The table and split parts of Kit (`LungfishKit/BatchTableView.swift:75`, `LungfishKit/TrackedDividerSplitView.swift:6`), the metadata column layouts (`LungfishKit/MetadataColumnController.swift:81`, VS A10) and the sample picker state, a Core type (`LungfishCore/Models/ClassifierSamplePickerState.swift:35-36`), get one memory struct each in Kit, which a view's state embeds, so one part serves the nine table classes and six splits.
6. **Outside the host.** The FASTA document uses the same types, store and reset line through one App shim, and Status only holds nothing (`ViewSwitchKinds.swift:75,79`).
