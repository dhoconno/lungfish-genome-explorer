# PCR Primer Design

PCR Primer Design is an optional tool pack for sequence-based primer design. Install it from **Tools → Plugin Manager**, then open **Tools → PCR Primer Design**. The pack contains Primer3 and **PrimalScheme3-LGE (custom fork)** in separate managed environments. The custom fork uses a pinned Python wheel set inside its conda environment. It is distinct from upstream PrimalScheme3 and the older Bioconda `primalscheme` package. Its public source is [dhoconno/primalscheme3-lge](https://github.com/dhoconno/primalscheme3-lge).

## Inputs

Select sequence bundles or native `.lungfishmsa` alignments in the project, including alignments generated by MAFFT. The design dialog uses those selections and has no external input chooser or Refresh button. Full paths distinguish files with the same name. Numbered record choices distinguish repeated FASTA headers.

Full-length human and macaque MHC alignments provide development fixtures for class I, class II DP, DQ and DRB. The invocation interface contains no example shortcuts or assay presets.

Primer3 offers an explicit record checklist for FASTA. For each native alignment, choose the template row. The conserved-binding-site option excludes variable and gapped positions from primer and internal-probe binding sites. Coordinates refer to the chosen ungapped template. The source fingerprint is checked again when the run starts; changed inputs must be inspected and selected again.

PrimalScheme3 consumes each selected file as an alignment. Rows must have equal lengths and distinct FASTA identifiers. The workflow does not align unequal-length input on behalf of the user.

## Design settings

Primer3 supports product-size ranges, a target region, candidate-pair count, primer length, melting temperature and GC ranges. Target coordinates are **1-based and inclusive**. The adapter converts them to Primer3 coordinates and preserves the exact generated Boulder input.

Choose PCR primers, qPCR with an intercalating dye, or qPCR with an internal hydrolysis-probe candidate. Internal oligo sequence selection does not add fluorophores, quenchers or vendor modifications. The output represents design candidates.

PrimalScheme3 offers **one scheme per MSA** or a **combined scheme from selected MSAs**. Independent mode runs `scheme-create` separately for each alignment. Combined mode runs `panel-create` once with all selected alignments, using Equal mode by default. Amplicon size, pool count and minimum primer-variant frequency are explicit basic settings. Advanced controls include high-GC settings, CPU workers (up to four by default), and minimum overlap for independent schemes. The complete native configuration is retained with the outputs. Execution snapshots use unique filenames and safe row identifiers even when source filenames or allele names repeat across alignments. A hash-bound row map preserves the original allele names and row order; original source files remain byte-for-byte intact.

The GUI displays minimum primer-variant frequency as a percentage and passes the corresponding fraction to the existing `--min-base-freq` option. The default remains zero. This filters each distinct candidate sequence independently; it is not a cumulative cap on unmatched alignment rows and does not enforce a 5′ mismatch policy. Multiple individually rare alternatives may together account for many rows. Frequencies describe alignment observations, not read abundance or population allele frequency. The custom observed-only policy excludes uncovered terminal observations from the candidate denominator. The pinned fork does not provide a user-defined fraction of rows allowed to have 5′ mismatches. See the [pinned discovery implementation](https://github.com/dhoconno/primalscheme3-lge/blob/v3.3.0-lge.2/primalscheme3/core/digestion.py).

Advanced settings include an executable override. The chosen binary is identified before design and its actual path/version are recorded. The PrimalScheme3 adapter requires the explicitly versioned custom fork; a stock executable is rejected. Previously saved stock analyses remain readable.

The PrimalScheme3-LGE custom fork exposes **Treat uncovered alignment ends as missing observations**, enabled by default in LGE. LGE explicitly passes `--terminal-gap-policy observed-only`; disabling the option passes `legacy`. The fork's standalone CLI defaults to legacy for backward compatibility. Missing terminal observations do not count as matches; internal gaps remain distinct from missing ends. Compatibility among assessable sequences does not establish compatibility for unobserved alleles.

The observed-only policy uses patched Python discovery; legacy preserves upstream Rust discovery. The backend choice is recorded as `python-observed-only` or `rust-legacy` in native configuration and retained in provenance. Comparisons therefore involve a discovery-backend change as well as missing-data semantics. See [custom fork details](primalscheme3-lge-fork.md).

## Saved results and annotations

Name a new `.lungfishprimeranalysis` analysis in the current project. The analysis retains original input snapshots, selected templates, native outputs, logs, settings and provenance. Existing destinations are not overwritten. Tool execution records preserve exact argv, resolved settings, runtime identity, file hashes/sizes, exit status and timing, with output descriptors pointing to the published bundle.

Primer3 Overview and Results show each candidate independently on its saved design template: a product span and size, labeled forward and reverse binding sites, and the optional internal probe. Primer3 has no Binding inspection tab; that tab appears only for supported PrimalScheme alignment contexts. The Results view also shows candidate sequences and detailed coordinates. **Create Annotated Reference** creates a `.lungfishref` document containing the template and all candidate primer/probe features. Annotation qualifiers retain the analysis, result and input identifiers. This provides durable annotations for FASTA, which itself has no feature storage. The original sequences and saved analysis remain unchanged.

The PrimalScheme3 Results view lists primer pools and alternative primer records, shows selected binding sites on the saved reference, and resolves execution identifiers back to the original allele names. The Inspector's Files tab exposes the complete saved output inventory and can reveal a file in Finder. Its Provenance tab uses the standard LGE provenance interface for the analysis wrapper, native tool and derived ordering-sheet records. Saved analyses can be reopened without installing either design engine.

## Command-line workflows

The CLI uses the same pipelines and durable bundles as the graphical workflow:

```text
lungfish-cli primers design primer3 --fasta-record INPUT.fasta@0 --output OUTPUT.lungfishprimeranalysis
lungfish-cli primers design primer3 --msa-template INPUT.lungfishmsa@0 --output OUTPUT.lungfishprimeranalysis
lungfish-cli primers design primalscheme3 --msa FIRST.lungfishmsa --msa SECOND.lungfishmsa --grouping combined --output OUTPUT.lungfishprimeranalysis
lungfish-cli primers analysis inspect OUTPUT.lungfishprimeranalysis --json
lungfish-cli primers analysis annotated-reference OUTPUT.lungfishprimeranalysis --result-id RESULT_UUID --output-directory EXISTING_DIRECTORY
```

Record and row indices after `@` are **zero-based**; target coordinates are **one-based inclusive**. Repeat selection flags to design more than one template. Use each subcommand's `--help` for typed controls and managed-executable overrides. The PrimalScheme CLI accepts native alignments, including those produced by `lungfish-cli align mafft`. The annotated-reference action currently supports Primer3 results with linked annotation artifacts.

## Interface references

The sequence-context and explicit-selection approach draws on the [Geneious primer interface](https://manual.geneious.com/en/latest/Primers.html). Engine contracts are based on the [Primer3 manual](https://primer3.org/manual.html) and the [PrimalScheme3 project](https://github.com/artic-network/primalscheme3).


## Project-owned design and ordering review

The GUI saves each named analysis under the originating project's `Analyses` directory. There is no external destination chooser or example shortcut in the design dialog. Unsafe names, existing destinations and symbolic-link escapes are rejected; completed bundles appear in that project's sidebar.

PrimalScheme results include pool-organized oligos, native 5′–3′ sequences, synthesis lengths, reference binding spans and GC/ambiguity information. Newly generated results include an `ordering-v1.csv` worksheet inside the custom `.lungfishprimeranalysis` bundle. Every native oligo and alternative stays separate; order specifications remain blank for the user. The derived worksheet has independent LGE workflow provenance and is covered by bundle checksums. Older bundles remain readable without a worksheet.

Basic settings expose **minimum, target and maximum amplicon sizes**. For example, a nominal target of 200 bp can use an inclusive 150–250 bp range. The bounds describe the saved reference amplicon span, including both primer sites. Alternative primer combinations and alleles with insertions or deletions can have different product sizes. The target initializes the default bounds; it does not rank candidates by closeness to that size. Each bound follows changes to the target until the user edits it independently.

The GUI always passes explicit bounds to the custom fork. CLI users can set `--amplicon-size-min` and `--amplicon-size-max`; supplying either selects the `reference-span` metric and an omitted bound resolves from 90% or 110% of the target. Invocations without either flag retain the older `legacy-pairing` metric. Native configuration and LGE provenance record the metric, requested bounds and resolved bounds. Before publishing a new reference-span analysis, LGE verifies both the engine configuration and every saved amplicon interval against the requested limits. Combined-panel pairing now respects both bounds.

Advanced settings expose dimer score, mispriming database, independent-scheme overlap/backtracking/unknown-base handling, combined-panel equal/entropy selection and optional panel/per-alignment amplicon limits, alongside CPU count, high-GC and missing-terminal-observation settings. Offline reports remain enabled and coordinates map to each alignment's first row.

## Operations and visual review

Primer3 and PrimalScheme runs appear immediately in the shared Operations Panel. Before input snapshots are captured, the selected managed engine is checked and, when necessary, installed or repaired through Plugin Manager’s pinned installation service. Other engines are left alone. Failed repair restores the previous environment; failed or cancelled preparation cannot publish an analysis. A lease keeps the selected environment stable through execution, and its captured location is used in command and provenance records. Waiting for a busy runtime is cancellable; readiness probes finish within their existing tool timeouts. Explicit CLI executable overrides keep their own identity and skip managed preparation. The configuration dialog uses LGE's standard dataset-operation shell and closes on launch. Operations retain project routing, progress messages, cancellation, failure details and saved-result links independently of the sheet lifetime.

Overview reports per-reference geometric coverage from the union of saved amplicon spans, with reference-length denominators, uncovered bases and separate primer tracks. Zero-coverage references remain visible; absent amplicon evidence is unknown. Primer3 candidates are reviewed individually and are never unioned as if all alternatives formed a scheme. These displays describe saved design coordinates rather than experimentally established amplification success.

Click an amplicon or primer in Overview or Results to inspect its size, pool, reference coordinates and associated oligos. Selection follows the same target between those tabs. PrimalScheme uses the exact saved amplicon identity, reference and pool to retain all forward and reverse alternatives; matching alternative suffixes do not establish individual pairs. Its size is the saved reference span including primers, which can differ from individual products or alignment rows. Primer3 displays the explicit candidate's product size on the saved template, including its linked probe when present, and labels it as a candidate pair. Inconsistent or missing native membership is shown as unavailable while standalone primer inspection remains accessible.

Context-click a primer or amplicon to inspect that specific record, open its alignment binding site, or copy names, coordinates and FASTA. Multi-record FASTA copies retain alternative oligos with distinct record identifiers and source metadata. Stored reverse primers are already in 5′–3′ synthesis orientation and are not reverse-complemented during copying or export. Associated-primer and whole-pool actions retain their original scope.

Contextual save actions create a native `.lungfishref` in the originating project's Analyses folder. Primer exports retain a plain `primers.fasta`; reference amplicon extraction takes the saved forward-reference interval including primers and shifts its primer annotations into the extracted coordinate system. It does not reconstruct products from alternative primer combinations or predict allele-specific product sequences. The bundle retains exact selection metadata, source evidence and provenance. Progress and cancellation use Operations; staging is published exclusively after validation and a final project write check. No external destination chooser is offered by these contextual actions.

For PrimalScheme outputs with verified alignment/reference mappings, Binding inspection reuses the native MSA canvas, consensus display and annotation tracks in read-only mode. Selecting a primer focuses its footprint and adds a pinned primer sequence track above the consensus. Matching concrete alignment bases appear as dots within that primer’s mapped columns; differences remain letters. The toggle restores all original letters. Bases outside the footprint remain unchanged. Reverse primers are displayed in reverse-complement orientation on the ascending reference axis; the original synthesis sequence remains available below. The per-row comparison table highlights known mismatches at the mapped site. Purple ruler marks indicate variable MSA columns, orange overview marks indicate gap-bearing columns, and underlines identify saved primer footprints. These marks are distinct from primer mismatch evidence. The legend and comparison menus follow the active primer track. Missing terminal data, internal gaps and ambiguous target bases are shown as unresolved rather than matches. Comparisons run on demand for the selected primer, and every row remains accessible. Primer3 MSA binding inspection is not yet supported; its normalized candidate/reference review remains available.
