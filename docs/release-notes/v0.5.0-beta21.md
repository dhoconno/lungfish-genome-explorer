# Lungfish 0.5.0-beta21

Previous release: v0.5.0-beta20

## Standalone Savont clustering

This release adds Savont as a standalone clustering tool for FASTQ data. It is
available beside pbAA under **Tools → Clustering** and does not require a guide
reference. Analysts can choose the output name, thread count, quality cutoff,
minimum cluster size, and optional read-length limits, then receive a FASTA
whose record headers report how many reads support each consensus cluster.

The app now checks that the managed Savont runtime is ready before starting a
long job and gives a direct setup message when it is not. The CLI and app agree
on the exact planned output path, accept both project-level and derived FASTQ
provenance, and validate that the resulting FASTA and its provenance describe
the same successful run before importing it. Empty-cluster results and retry
fallbacks are reported clearly instead of being mistaken for successful data.

Standalone Savont runs retain the reproducibility record required for
scientific outputs: tool and runtime versions, exact command and resolved
options, input and output paths, checksums and sizes, elapsed time, exit status,
and useful failure details. Cleanup is also recorded so an interrupted or
failed run does not silently leave an ambiguous result.

## A more useful FASTA result view

Savont results and other FASTA files now open in the standard FASTA collection
view rather than a minimap presentation that did not add useful information for
cluster consensus sequences. Selecting one or more rows shows the corresponding
FASTA records in the lower pane, including complete headers and wrapped
sequences that can be reviewed or copied without leaving the result.

## Compact and editable miSeq haplotypes

The miSeq genotype matrix now presents each locus compactly as the two effective
haplotype labels, while the lower pane reuses the same manual haplotype editor
as full-length MHC genotyping. Selecting a sample column opens the editor;
leaving no column selected leaves the otherwise unhelpful lower pane empty.
Workflow-generated calls and analyst edits remain synchronized with the
haplotype view, workbook publication, annotations, and audit history.

Analysts can now clear either haplotype slot independently and explicitly mark
it as not called. Clearing H1 no longer clears or copies H2, and the empty state
remains visible after saving and reopening. A **Restore Workflow Call** action
returns only the selected slot to the pipeline result. These changes preserve
the distinction between an unedited workflow call, an analyst-entered label,
and an intentional empty call.

## Release reliability

The repository now contains a reusable release skill that inventories and
integrates active release branches, derives the next version from the most
recent versioned GitHub release, runs the release gates, and verifies signing,
notarization, Sparkle publication, and cleanup. The skill is linked from the
repository so its instructions stay current with the release scripts. This
release also tightens the preflight checks for GitHub authentication, Apple
signing identity, notarization credentials, Sparkle tooling and build-number
ordering before any release tag is created.

## Notes

This remains a beta prerelease. It is distributed as a signed and notarized
Apple Silicon DMG through GitHub and the Sparkle beta update feed. The same
signed update entry is published to the legacy alpha bridge so older alpha
installations can move onto the beta channel.
