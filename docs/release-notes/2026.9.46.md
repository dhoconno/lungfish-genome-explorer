This release explains why a varVAMP primer scheme covers less of an alignment than expected, and updates the attribution and public links shown in the app.

## varVAMP coverage explained

- **Each varVAMP scheme now states the consensus threshold it used, and whether varVAMP chose it automatically.** For an alignment with few sequences, the note gives the threshold as the number of sequences that must agree. For six sequences, every value from 0.84 to 1.00 requires all six to agree, so an automatic 0.99 can reject most primer sites in a variable gene.
- **Warnings that varVAMP writes to its own log now appear on the scheme**, for example its low-coverage warning and suggested fixes.
- **A tiled scheme with gaps now explains that varVAMP keeps only its longest unbroken chain of amplicons.** Regions it cannot link are left uncovered rather than tiled separately. Wider amplicon size bounds, a lower consensus threshold or more allowed ambiguous bases usually close these gaps.
- The `lungfish-cli primers design varvamp` command prints the same notes after a run.
- Saved varVAMP analyses from earlier releases show the stored threshold. Run the analysis again to see the sequence counts and native warnings.
