# Lungfish 2026.11.7

Channel: Stable

Previous versioned release: v2026.11.6

Stable baseline: v2026.10.29

Dependency set: 2026.2

This Stable release brings the work since Stable 2026.10.29, which is Previews 2026.11.1 to 2026.11.6. It corrects results that Stable 2026.10.29 could show or make, such as TaxTriage read counts, Kraken 2 totals, the Mean Q of a merged FASTQ bundle and a few reads that Demultiplex Barcodes gave to the wrong sample. Some numbers and files change, so read What works differently before you compare with old results.

## What works differently

### Reads, pairs and counts

- **A FASTQ file that holds read pairs together with merged or single reads is read in full before it is paired.** With 50,000 or more pairs, `fastq deinterleave`, `map`, `assemble` and the classifiers could pair unrelated reads silently. A mixed file now stops `fastq deinterleave` with its counts, so split it again with `--unpaired` and rerun any analysis of it or of its R1 and R2 files. Imported reads need no new import.
- **Read pairs named like SRR123.1.1 and SRR123.1.2 now run as pairs.** They ran as single reads, so a Kraken 2 total was about double the number of pairs, a map showed no paired reads and a third file of unpaired reads was left out. Import and run such a sample again. Pairs named _1 and _2 still run as single reads.
- **A NAO-MGS read pair's second mate could be counted at the first base of a reference without being placed,** so Unique Reads read low. New imports are right. Import the original results file again and remove the old result.
- **Unique Reads showed 1 for rows that were never counted, and a dash now means not counted.** EsViritu and NVD exports write Unique Reads right after Read Count (Mapped Reads in NVD), empty where the table shows a dash, and NVD also writes Aln Length, so columns after them move right. Update a script that reads them by column number.
- **Kraken 2 and NAO-MGS counts.** With several samples picked in a Kraken 2 batch, the bar under the table and the sunburst gave a row's share of all their reads, and now give its own sample's. A sample with no total of its own showed the batch's total as its own, and now shows its own reads with no percent. A NAO-MGS result's Taxa count counts each taxon once, not once for each sample that has it.
- **A FASTA list's GC Content counts every base,** where it averaged its records. A protein record shows a dash for GC. A short peptide such as MKTAYGHSSRV now opens as protein, and a protein record with U, B, Z, J or O opens instead of stopping the whole file.
- **The Mean Q of a merged FASTQ bundle or an older Nanopore import in chunks is one figure for all its reads.** It averaged the Phred scores of the files, which could read 9 to 16 Phred units too high when one file was poor. It is now labeled Mean Q (error rate), so read it with Q20 and Q30.
- **Bundles of several files are read once and as pairs.** Mapping, classifying or running EsViritu on several files of one bundle counted each file as the whole bundle, so read counts and depth came out multiplied. A bundle that `lungfish-cli extract reads --by-id` makes from two `--source` files is now read as a pair, and operations that read one file refuse it in words, where they read the R1 file alone, so run them again on one file of the bundle.

### TaxTriage

- **TaxTriage read counts are corrected.** Since April 2026, a row could read 0 or too few Reads for an organism with more than one reference sequence, such as the eight segments of Influenza A, so a negative control could look clean. Reads now show TaxTriage's own count (# Reads Aligned). Open each result once in a project you can edit, which recounts it, and export again any table made from it. Extract Reads and BLAST Verify then use every reference of the organism, and Extract Reads skips duplicates, so it can write fewer reads than Reads shows. If a clean control with no organism has lost its report, Lungfish says so and hides the old counts, so import the run's folder again.
- **A TaxTriage result says when a negative control cannot be read as clean.** If a control failed, is missing, had a step the pipeline skipped after an error, or shares a name with another sample once spaces and symbols are removed, the viewer notes it, the organism matrix and results table say Not checked, not No or a blank cell, and the batch report says what to try. A control named like NTC 1 or Water (blank) keeps its flag. Export an earlier result again to correct it.
- **An imported TaxTriage run keeps its negative controls, run settings and database name.** A run imported by an earlier version reads Not recorded above its table, so import its folder again and export again anything made from the old import, which may say No for contamination.
- **A sample whose reads file has a symbol in its name now runs in TaxTriage,** where it stopped with no result. Two samples whose reads files shared a name in folders with a space in the path were both analyzed on the second file. Run such samples again.
- **Extract Reads on a raw TaxTriage result takes a sample's own BAM file,** not the reads of a sample whose name only begins the same way, such as S1 and S10. On the command line, for a result Lungfish has not opened, if the own BAM is not found it reads the one `minimap2` file whose name fits and says which. If two fit, it stops and names both. The limit is under Things to know.

### BLAST Verify

- **BLAST Verify asks NCBI for up to 500 records per read, not 5, when it judges by species.** A perfect match no longer reads Unsupported because its first five hits were lab vectors, and a row whose supporting reads all match other records equally well, such as a vector, reads Not specific, not Supported. Send a saved row again to refresh its badge.
- **A verdict showed under the wrong row.** Unless a Kraken 2 or FASTA list search is running, the pane shows the row's own search or nothing, and a late verdict names its sample.
- **Verify with BLAST in the Kraken 2 viewer and `lungfish-cli blast verify` ask NCBI for core_nt,** where the viewer asked for nt. NCBI already searched core_nt then, so no result changes.

### Demultiplex Barcodes

- **It no longer gives a few reads to the wrong sample.** With Cutadapt and a single-index kit or a custom barcode list, it moved a read to another barcode when the bases after its barcode looked like a second barcode, about 1 read in 120 with 12 barcodes of 8 bases and about 1 in 14 with 96. ONT Rapid Barcoding, ONT 16S Rapid Amplicon and M13 Universal Primers are unchanged.
- **A run that finds no barcode above chance now stops,** where earlier versions made sample files from chance matches. A lone real sample typically needs about 0.3% of ten thousand reads to stand above chance. A barcode that falls short is named in the summary as a possible chance match. If an earlier run of this kind sent most reads to Unassigned, run it again.
- **It splits reads whose index sits only in the read names,** as bcl2fastq and BCL Convert write it, with at most one mismatch in each index and both reads of a pair kept together, by itself when the names carry the indexes of two or more of the kit's barcodes, or when you choose Read Names. A read whose index matches two barcodes, differs in two or more bases, or has its i5 in the other orientation than most of the file goes to Unassigned. `lungfish-cli fastq demultiplex` with no engine named chooses this search from the read names, where it always used Cutadapt.
- **Detect Barcodes counts every read of a custom barcode list,** where it counted only the few that also held the barcode's reverse complement, and it reads the index in the read names of Illumina and Element files.
- **It records the bundle you picked.** For a subsample, a trimmed set or other derived reads, the record named a deleted temporary copy of the reads, no barcode bundle linked back to your bundle, and the command in the row showed `-o '<derived>'`, which cannot run. The record now names your bundle, each barcode bundle links back to it, and the command can be run again. Keep that bundle, since its barcode bundles read their reads from it.
- **A subset of ONT reads keeps its platform.** A bundle made by Subsample by Count, Quality Trim or another FASTQ operation lost its reads' ONT platform, so Demultiplex Barcodes started on the TruSeq Single Index Set A kit and Map Reads and Assemble could start on short-read settings for reads of 600 bases or fewer. All three now start on ONT settings.

### Viewer and figures

- **An exported figure counts depth under the window's cutoffs.** Its Depth strip counted every read and base whatever mapping-quality and base-quality cutoffs the window had set, so its depth could be larger than the window's. It now counts depth, and draws reads, under the cutoffs, and a line under the strip says which. With Hide high-gap sites on, a figure still draws those sites, and its row ends Completed with Warnings.
- **Opening another reference or alignment starts its read filters and consensus settings at their defaults,** where the Minimum alignment confidence and the other settings you made for one stayed set for the next, so reads showed pale and depth changed under a setting made elsewhere.
- **A result you open from the Operations panel, an import, an Inspector link or an accessibility tool now shows in the viewer,** where the viewer could keep the old result's numbers.

## What's new

- **A BLAST search stuck at NCBI no longer fails or holds up your work.** It waits on its row in the Operations Panel and its result comes back on its own, also after you reopen Lungfish. When NCBI is not taking new searches, the row and the BLAST pane say so and give the retry time.
- **The Results button opens a finished Call Variants run and a finished BLAST search,** and for a search saved in a Kraken 2 result it selects that result.
- **The Demux tab has a Demultiplex… button** that opens Demultiplex Barcodes with the plan's table, where you press Run.
- **Failures explain themselves.** Most commands that beeped say what is missing and what to try, failed runs and saves name the sample, and files and results that cannot be opened say what is wrong.
- **A classifier result dragged to another project keeps its record,** and Reassemble in a copied project uses the reads inside it.
- **A used-up AI quota says so** in Settings > AI Services, the AI Assistant and `lungfish-cli genotype ai-haplotyping`, with the provider's own words and billing link. This answers GitHub issue 35.
- **Illumina Amplicon Merge keeps only merged reads** and drops every pair that does not overlap. An import that dropped pairs ends as Completed with Warnings.
- **Smaller changes.** You can install `lungfish-cli` as a symbolic link on your PATH, and sorting or filtering the mapped contigs keeps your zoom.

## Things to know

- **A Kraken 2 sample with no total.** The percent columns of an exported table, and the percent column when you select several samples together, still read 0.
- **A bundle you imported.** Its Demultiplex still makes separate barcode bundles with no link back to it.
- **Platform records.** A barcode bundle that Demultiplex Barcodes makes keeps no platform in its own record, and `lungfish-cli fastq platform` shows none for it or for an earlier build's bundle. The Workflow Operations window reads only that record, so there such a bundle with ONT reads of 600 bases or fewer can start on Illumina settings.
- **Exported figures.** A figure still draws the reads of every read group, where the window draws the groups you selected, and draws a Depth strip and a reads track for each alignment track of a bundle, where the window shows one. Each strip is exact for its own track.
- **The mapped contig list.** The viewer can still return to the whole contig a few seconds after a mapping result opens, when the list has finished counting its reads, and when you change the alignment track in the Inspector.
- **The Results button.** For a BLAST search started from any other result or submitted directly, it selects the search's own folder, which has no viewer, so the viewer and the Inspector stay on the result you were looking at.
- **The ONT import sheet.** Total size adds the unclassified folder's files, and the Fluidigm and PacBio recipes read every FASTQ under the run folder, the unclassified folder included.
- **A sample's own BAM file is gone.** When Lungfish opens a TaxTriage result it builds its database. If a sample's own BAM is missing, the database takes a `minimap2` file whose name holds the sample's name followed by a dot, underscore or hyphen (`S1_2.bam` or `S1_2.S1_2.dwnld.references.bam` for S1). If that file is another sample's, S1 shows that sample's reads in the alignment view, Unique Reads and Extract Reads, with no warning. The Inspector names the file on its BAM line. A result Lungfish made with several samples is not affected. Put the BAM back, delete `taxtriage.sqlite` and select the result again.
- **BLAST Verify.** On an EsViritu result without NCBI Taxonomy, such as an imported one, each read is judged by organism names alone, so a read can count for or against the row by a name it shares with another virus. A read tied at one score counts as supporting when any record tied with it is in the row's species, and NCBI returns a sample of the tied records, so a read can show 100% on one run and 99.3% on the next, or read Unsupported.
- **Demultiplex Barcodes.** A barcode not in your pool can still pass as a sample, in about one run in 1,000 for each one and more often in amplicon files, and the summary and the Operations Panel say so.
- **Earlier notes.** The limits in the 2026.10.29 notes still apply, apart from the known issues about mixed FASTQ files, imported TaxTriage results and TaxTriage negative controls, the sentences about reads tied at one score and the sentences about a search that stops after about 10 minutes. The technical record lists the other limits that still hold.

## Included preview releases

Includes the six Previews 2026.11.1 to 2026.11.6. Stable promotion adds no product change.

- 2026.11.1 pairs mixed FASTQ files correctly, recounts TaxTriage reads and lets a stuck BLAST search wait.
- 2026.11.2 drops the GC percent of protein records and marks partly checked TaxTriage controls Not checked.
- 2026.11.3 corrects Demultiplex Barcodes and Mean Q and splits reads by the index in their names.
- 2026.11.4 shows a result chosen with an accessibility tool and warns of a barcode that could pass by chance.
- 2026.11.5 gives a previewed PDF its own Inspector and a TaxTriage sample its own BAM file.
- 2026.11.6 corrects a Kraken 2 total, figure depth and a NAO-MGS Taxa count, and keeps the platform of ONT subsets.
