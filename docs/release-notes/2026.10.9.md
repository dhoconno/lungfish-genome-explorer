# Lungfish 2026.10.9

Channel: Preview

Previous versioned release: v2026.10.8

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release changes several results. 12S amplicon matching now counts each DNA fragment once, demultiplexing keeps the two reads of a pair in the same barcode, and primer removal also trims a primer that a read runs into at its far end. It also checks SRA downloads more strictly, stops imports from replacing each other, and fixes Kraken2 runs whose files mixed compressed and plain FASTQ.

## 12S amplicon matching counts fragments

Before this release, 12S matching counted every read on its own. For an unmerged pair this counted one fragment twice, once as a species read and once as an unresolved read, because only one of the two reads faces the direction the matcher reads.

12S matching now counts fragments. A merged read counts once. An unmerged pair counts once when both of its reads give the same call, with the second read turned to face the same direction as the first. A pair whose reads disagree counts toward no species and is reported in a new `discordant_pairs` column of `samples.tsv`, in `read-fate.json` with the reason, in the run's provenance, in the command-line output and in the 12S viewer. On a test sample of four merged reads and four unmerged pairs, the counts changed from 12 reads (5 human, 1 dog, 6 unresolved) to 8 fragments (3 human, 1 dog, 2 unresolved, and 2 pairs left out). Results from merged reads alone are unchanged.

- The 12S viewer and Inspector name the counts fragments when a run read unmerged pairs, and keep "reads" for merged reads alone, so earlier results read as before. Exported tables keep their "Exact Reads" and "Reads" column names.
- A read without a mate whose name marks it as the second read of a pair (ending in `/2`, or with a Casava ` 2:` comment) is now turned to face the same direction as the first read before matching, so it can match its species. This includes every read of a second-read file named on its own.
- A FASTQ file named inside a bundle, such as `SampleA.lungfishfastq/merged.fastq`, is read alone, not with the rest of its bundle. Two inputs with the same sample name are refused before anything is written.
- Unmerged pairs whose names end in `.1` and `.2`, or carry no mate number, are read as pairs, as other tools read them.
- `lungfish-cli fastq 12s-match --force` keeps the earlier result until the new one is complete, puts it back if the new one cannot be written, and says where it waits if it cannot be put back.

## Demultiplexing keeps pairs together

Demultiplexing used to assign each read on its own, so the two reads of one pair could land in different barcodes, or one in a barcode and the other in Unassigned. Both reads of a pair now follow one call. A pair goes to a barcode when both reads carry it or when only one read carries a barcode. A pair whose reads carry different barcodes goes to Unassigned whole. On a 15-pair test file the barcodes and Unassigned held 14, 5 and 11 reads, with 9 pairs split between bundles. They now hold 16, 6 and 8 reads, with every pair whole.

- Demultiplexing a derived bundle counted 48 input reads where the file held 30, and returned no reads at all when the pairs were named `/1` and `/2`. It now counts 30 and gives the same reads as a full run.
- With Trim Barcodes off (`--no-trim`), derived barcode bundles still lost their barcodes (60-base reads came out at 52), and nanopore kits that are matched at both ends lost the adapter and barcode. Every read is now kept whole.
- A demultiplexing run that fails or is cancelled no longer leaves barcode folders that a later command could read as finished results.
- `lungfish-cli fastq demultiplex --replace` now refuses before it deletes anything, and keeps the earlier results until the new ones are complete.

## Primer removal trims read-through primers

When a read runs past the end of its amplicon, its far end holds the reverse complement of the other primer, and primer removal used to leave it there. Primer removal with bbduk now runs a second pass. Paired reads are trimmed where the two reads overlap, which is exact. Single reads, including merged reads, lose a primer's reverse complement that ends within their last bases. On the test reads, read-through reads went from 110 to 88 bases, read-through pairs of a tiled scheme from 88 and 82 to 60 and 60, and full-length reads from 387 to 359 bases. Forward reads keep their length.

- A read the second pass trims below 10 bases, such as a primer dimer, is dropped with its mate.
- Known limit. A short single-end read of a tiled scheme can lose 11 to 36 real bases when another amplicon's primer sits in its last bases (for 150-base reads, 3 to 8% of ARTIC and Midnight amplicon orientations, 45% for VarSkip vss1 and 7% for QIAseq). Paired reads are not affected.
- `lungfish-cli fastq primer-remove` now uses a k-mer size of 15 by default, the value the Primer Removal dialog has always used. The old default of 23 was longer than every bundled scheme's shortest primer, so such runs stopped inside bbduk or quietly left the shorter primers in place. A `--kmer` longer than the shortest primer is refused with a message, and every recorded command now names `--kmer`. A command recorded earlier without `--kmer` ran with 23 and now replays with 15.

## SRA downloads

- Every file downloaded from ENA is checked against the size and MD5 checksum ENA lists. A file that does not match is never imported, and the SRA Toolkit fetches the run from NCBI instead.
- A run downloads whole or not at all, in the SRA window and in `lungfish-cli fetch sra download`. A single mate of a run that ENA or NCBI lists as paired fails the run. If ENA lists only one mate of a paired run, the SRA Toolkit fetches it.
- A third read file of a run (`_3`) is never imported, and both the window and the command line now say so. A run whose layout neither archive could report, and that arrived as a single mate, imports as single-end reads with a warning.
- `fetch sra download` takes one run accession and refuses an experiment or study accession, where it used to download only the first run. A run that neither archive can serve fails with one line naming both reasons. A refused run exits with status 64 and a cancelled one with 125, and `--format json` now prints only JSON on standard output.
- The window and `fetch sra download` record the same provenance for the same run.
- `scripts/deps/run-pipelines.sh` uses `fasterq-dump --split-3`, as the app does.

## FASTQ import

- `lungfish-cli import fastq --force` no longer lets one sample of an import replace a bundle that an earlier sample of the same import wrote, or failed to write. A run's third file that the import leaves out can no longer replace its pair's bundle.
- The Import FASTQ sheet now groups files with the same rules as `lungfish-cli import fastq`. An SRA or ENA run's three files import as one bundle with the reads whose mate is missing, and a single file named like one mate keeps its full name.
- The two reads of a pair are matched inside their own folder first. Files in two folders pair only when no other file has either name, so a delivery with `R1` and `R2` folders pairs, while two sample folders that use the same file names are never mixed. When a shared name keeps two files apart, the import says so. The Import Center, the sheet, explicit files and `import fastq --recursive` all follow this one rule.
- This changes `import fastq --recursive` for some layouts. A delivery with `R1` and `R2` folders now imports as one paired bundle where 2026.10.8 made two single-end bundles, and a run's file of reads without a mate in another folder now joins its pair. A `--recursive` command recorded by 2026.10.8 can therefore make different bundles.
- A run's bundle that holds pairs and reads without a mate now shows "Pairs and single reads" with both counts in the Inspector.
- Cancelling an import now stops it during the join of a run's third file and during storage optimization, and leaves no workspace behind. Storage optimization of a file that mixes pairs and single reads needs less temporary disk.

## Read sets and combined bundles

- Merge into New Bundle keeps the counts of pairs, merged reads and reads without a mate, so tools plan a combined bundle the way they planned its inputs.
- An operation output that holds pairs and reads without a mate is now labelled by its counts, even when those reads lie deep in the file.
- Merging reads in the FASTQ Operations dialog records the merged reads as merged, so an assembly of the output passes them to SPAdes as merged reads.
- MAFFT alignment of a FASTQ bundle with several files now aligns the reads of every file, where it used to read only the first, and the dialog's sequence count matches.

## Kraken2

- Kraken2 runs whose two read files mixed gzip-compressed and plain FASTQ classified nothing, or one unreadable read, and still finished. They now classify every read.
- Extracting the reads of a taxon now works for pairs named `x.1` and `x.2`.
- `lungfish-cli conda classify` no longer deletes its own input when that input sits in a folder it would clear, and a run refused before it starts leaves the earlier run's provenance record as it was.

## Safer replacements

`lungfish-cli bundle extract-annotations`, `bam annotate-best` and `bam annotate-cds-best` with `--replace` now run every check before they replace anything, refuse an input that sits inside the output, and keep the earlier output until the new one is complete.

## Dependency versions

Dependency set 2026.2 and all managed tool, optional pack, pipeline, database, and bootstrap versions are unchanged from v2026.10.8.
