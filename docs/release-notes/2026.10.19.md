# Lungfish 2026.10.19

Channel: Preview

Previous versioned release: v2026.10.18

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release is a hot fix of the SRA download preparation of Lungfish Genome Explorer (LGE) on top of Preview 2026.10.18. It fixes an SRA download from the Database Browser that could stay at Preparing for hours with no way to cancel it. The owner downloaded SRR36291587 in 2026.10.18 (build 9035), and the row stayed at Preparing for more than three hours while the Actions menu offered no Cancel. It is the only change a user can see since 2026.10.18. The owner check list under Checks still to run blocks a Stable promotion, and this release adds rows 57 to 59 to it.

## Downloads

**SRA downloads.** In 2026.10.18, the browser closed its sheet after the run metadata lookup and before it found a window for the import settings, and with no key or main window it logged `No window available for config sheet presentation` and returned without ending the row. The row also had no Cancel, because its cancel action was installed only after the import settings were confirmed. The import settings (the `Import FASTQ` sheet) now open on the project window that opened the Database Browser, even when another window is in front. While the row prepares, its detail and its View Log show `Looking up SRA run metadata...` and then `Waiting for SRA import settings...`. When neither archive returns the run's metadata, the log records `Could not detect SRA import settings: <reason>. Choose the settings manually.` and the import settings still open so you can choose them yourself, and when one archive fails and the other answers, the log keeps one line that names the archive that failed. When no window can show the import settings, the row ends Failed with `Cannot show SRA import settings because the download window is unavailable. Open the database browser again and retry.` in place of running on. Cancel is offered from the moment the row appears, during the lookup and while the import settings wait, as the row's Cancel in the Operations Panel (Cmd-Shift-P), as Cancel in the Actions menu of the panel's inspector and as Selected Operation > Cancel Selected Operation. That Actions menu now offers Cancel as soon as a row can be cancelled, where it used to wait for the row's state to change. Cancel during the lookup stops it and shows no import settings, and Cancel while the settings wait closes them and starts no download. Cancel in the import settings, or closing them another way, ends the row Cancelled, where 2026.10.18 ended it Failed with `Cancelled by user`, and closing the project window during the lookup or while the settings wait cancels the row. After you click Import, the download runs the same `lungfish-cli fetch sra download ... --bundle` command as in 2026.10.18, and the key `DatabaseBrowserSRARowRoute` still selects the earlier route.

## Known issues

No known issue is new in this release, and the known issues of 2026.10.18 still apply as below.

Known limit. A cancelled or failed EsViritu run keeps its working files in its folder under Analyses. The notes of 2026.10.17 named a partial BAM and the trimmed reads among them and put them at about 15 GB for a sample of 25 million reads. If the Operations Panel lists the stopped run when you next open the project, Remove Partial Output… on its row deletes the folder after a confirmation.

Known limit. A large sample rich in one virus can take an EsViritu run several hours, and the run has no time limit, so it goes on until it ends or you cancel it. The rising count in the log shows that it goes on, and Cancel in the Operations Panel stops it.

Known limit. The TaxTriage launch from the Tools > Classification menu still runs in the app, and Copy CLI Command on its row still copies a `lungfish-cli taxtriage` command whose `--output` is the app's own result folder, so running it writes into that folder again. Change `--output` to a new folder before you run it. A row for several samples offers no command. A later release moves this launch onto the command and changes the recorded command of a TaxTriage row.

Known limit. The record that the app writes for a TaxTriage sample still names `count/`, `fastp/` and `top/` files that LGE removes after the database build, so some names in it point at files that are gone. The record at the top of an app run of several samples also still files the classifier choice and the sample count as options you chose, and its sample steps carry no Nextflow version and no pipeline source. A later release moves the app's launch onto the shared record. The record of a `lungfish-cli taxtriage run` result keeps `top/`. Until then, read a `count/`, `fastp/` or `top/` name in such a record as a file that the database build removed. For a record that keeps the top report, run `lungfish-cli taxtriage run --project` in Terminal.

Known limit. A Viral Recon run keeps an unsigned copy of its record in its results folder on purpose, and the record in the run bundle holds the digest of that folder. `lungfish-cli provenance verify` on the results folder ends with exit status 64 and prints `Workflow execution failed: Signature artifact is missing` with the path of the missing `.lungfish-provenance.json.signature.json`, and it does not say that the copy is unsigned on purpose or name the bundle. When the run had a signing key, `lungfish-cli provenance verify` on the run bundle prints `Signature valid`, so check the run there.

Known limit. When Docker has to start, the Viral Recon row's detail reads `Docker daemon ready` for the rest of the run, because the command's start line carries no message that replaces it. View Log on the row lists the run's progress lines, so follow the run there.

Known limit. A Viral Recon run into a results folder that an earlier run used can leave that run's files beside its own. Give each run a new results folder.

Known limit. When `lungfish-cli bam adopt-mapping` fails after it has attached a mapping, it still deletes the BAM that it moved into the bundle. A second adopt into the same bundle overwrites the bundle's shared `alignments/mapped/mapping-provenance.json`, so that record no longer describes the first track. Keep a copy of the mapping result until the command ends with exit status 0, and copy that `mapping-provenance.json` before a second adopt into the same bundle.

Known limit. A signing key does not sign every record yet. With `LUNGFISH_PROVENANCE_SIGNING_KEY` or `LUNGFISH_PROVENANCE_SIGNING_KEY_FILE` set, the records of `sequence annotate-orfs` and `sequence delete-track`, the log that Add Annotation appends to, and the record of a cancelled alignment workflow, consensus or read extraction stay unsigned. A run with no key that writes into a bundle whose record is signed leaves that record unsigned, on every route, so the record no longer shows that its earlier history was signed. If your lab signs records, set the key for every run that writes into a signed bundle.

Known limit. In Inspector > Provenance, the Command row of a Kraken2 result's `gzip` step, and of a few other steps that run a shell command, can drop the program and show one path in full, for example `/bin/sh -c 'Analyses/…/classification.kraken'\'' > '\''/Users/…/classification.kraken.gz'\'''`. The record is correct. Copy Command, the tooltip and provenance exports carry the full command, `/usr/bin/gzip -c …`.

Known limit. After a Kraken2 run opens its result, the Inspector can still show the item that was selected before the run, such as the input FASTQ's summary and its import record in Provenance. Click another item in the sidebar and then the result to show the result's own details.
