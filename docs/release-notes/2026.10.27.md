# Lungfish 2026.10.27

Channel: Stable

Previous versioned release: v2026.10.26

Stable baseline: v2026.9.78

Dependency set: 2026.2

This Stable release brings the work since Stable 2026.9.78. Paired reads reach every tool as pairs, many counts, statistics and quality scores that were wrong are now right, long runs are no longer cut off, and most work you start in the app runs a `lungfish-cli` command you can copy. Some numbers change, so read What works differently before you compare with old results.

## What's new

### Reads and imports

- **Every read reaches the tool, and pairs stay pairs.** Every file of a bundle is read, and a bundle's pairs reach mapping, assembly, classification and genotyping as pairs. A bundle recorded as Oxford Nanopore or PacBio is read as single reads.
- **The platform is found at import.** Nanopore, PacBio, Element and MGI reads are told apart by their read headers, and reads that match no platform are recorded as unknown.
- **Nanopore run folders and ZIP files import.** The ONT Run Folder card takes the folder MinKNOW writes, its fastq_pass folder or one barcode folder. A ZIP of a read bundle dropped on the sidebar adds the bundle, and a ZIP that cannot be imported says why.

### Downloads, drives and Linux

- **SRA downloads are checked.** Choose Prefer ENA or Prefer NCBI in the search filters. Each ENA file is checked against its listed size and MD5, a run downloads whole or not at all, and Cancel works as soon as the row appears.
- **External drives work.** Analyses saved to an ExFAT drive no longer fail at the last step.
- **Plans for a Linux machine.** The Plan for a Linux Machine card writes a plan that cleans up reads on an x86-64 Linux machine, and the Linux Run Result card checks and imports what comes back. The wastewater preset asks for 12.14 times the size of the reads in disk.

### Alignments and trees

- **A distance matrix under each alignment.** It opens under the alignment, and View > Hide Distance Matrix (Control-Command-M) hides it. It shows every pair of sequences as Identity, p-distance, Jukes-Cantor, Kimura 2-parameter or Poisson distance.
- **Build Tree with IQ-TREE** is in Tools > Alignment & Phylogenetics, with a model choice, branch support, an outgroup to root on and a recorded seed. Trees are saved in the Analyses folder.

### Menus, windows and runs

- **A reorganized Tools menu** with a Variant Calling submenu. Searches of NCBI, SRA and Pathoplexus moved to File > Search Online Databases, and genotype review to the Selection menu, where Command-Z undoes a review mark.
- **The app runs the command you can copy.** Most work, from mapping to primer design, runs a `lungfish-cli` command, so Copy CLI Command copies what ran. Twenty `lungfish-cli fastq` commands now refuse `--compress`, so drop it from scripts.
- **Cancel stops the whole run**, every program it started included.
- **Long steps are not cut off.** EsViritu, PrimalScheme3, Olivar, varVAMP, GATK and the bundled FASTQ tools no longer stop at a fixed time.

### Classification

- **Extract and BLAST read the right reads.** Extract uses the result's own folder, so a renamed, moved or copied result extracts where you expect, and Extract in the Collections drawer works. Both stop with words when the reads were replaced after the run. A TaxTriage row opens only its own sample's reference.

### Genotyping, viewers and records

- **Genotype exports carry analyst edits.** The command-line CSV, TSV and LabKey exports carry overrides and manual haplotype assignments, and the haplotype band shows an ambiguous call as its tokens and says No haplotype and Not assayed in words.
- **Images are drawn from the bundle's files.** File > Export > Image of a bundle or mapping result draws the tracks, the Depth track, mismatch marks and a line that names the contig and range.
- **Variants and annotations.** The variant table uses the genetic code and reading frame a coding feature names, SnpEff and VEP annotations split into fields, and a Variants export fills Gene / Protein, Consequence and AA Change for every coding variant.
- **Viewers.** Generate Consensus saves into the project.
- **Records.** Provenance records name the tool version that ran, a script export asks before it writes a tool the lock does not pin, and viewing an item no longer changes a result or a record in the project.

## What works differently

### Quality scores

- **Scores are read as Phred+33.** BBTools no longer guesses the encoding. A short read with a score of about Q55 or more, such as Element UltraQ, quality-filtered or short PacBio HiFi reads, could make an import or a BBTools step fail, hang or store every later score 31 too low with no warning. Import such reads again and repeat BBTools steps on them from the original files.
- **New imports store scores in steps of five.** Q5 steps (8-level) is the default on every platform. A score never moves across Q10, Q20 or Q30, so the Q20 and Q30 percentages stay as sequenced, but it can move by up to 2 inside a step, and Q35 and above is stored as Q37, so a HiFi read set shows a mean quality of about 37. Choose None (keep every score) to keep every score. The Illumina (7-level) scheme stored Q18 and Q19 as Q22, so its Q20 share could read 85% where the reads held 45%. Import such reads again.
- **Two more score faults are fixed.** With Optimize storage on, None stored every score above Q50 as Q50, and it now keeps scores up to Q93. A file whose first read holds only scores of Q31 or above showed its mean quality, Q20 and Q30 too low. If you imported it with None, import it again from the original.
- **Old Phred+64 files are refused.**

### Counts

- **Kraken2 counts fragments.** A pair counts once, so the totals of a paired bundle halve, and older results are labelled as counted per read. In a table of several samples, Clade % and Direct % are a percent of each row's own sample. A run whose files mixed gzip and plain FASTQ classified nothing, so run it again.
- **12S matching counts fragments.** A test sample went from 12 reads (5 human, 1 dog, 6 unresolved) to 8 fragments (3 human, 1 dog, 2 unresolved and 2 discordant pairs left out).
- **Demultiplexing keeps pairs together and reads every read.** On a 15-pair test file the barcodes and Unassigned went from 14, 5 and 11 reads to 16, 6 and 8. A virtual bundle was demultiplexed and genotyped from its 1,000-read preview, and a derived bundle counted 48 reads where it held 30. With Trim Barcodes off, 60-base reads came out at 52 and are now kept whole. The TruSeq and Nextera XT kits, which stopped with "Adapter sequence is empty", now run, and a kit with two indexes runs at Both Ends only.
- **Primer removal keeps the read.** The primer trim removed everything after a 5' primer, so every read that started with a primer was lost. A second pass now trims a primer that a read runs into at its far end, so read-through reads went from 110 to 88 bases and full-length reads from 387 to 359. `lungfish-cli fastq primer-remove` uses a k-mer of 15 where it used 23, also for a recorded command without `--kmer`. Run primer removal again.

### Mapping, genotyping and imports

- **Mapping and genotyping keep pairs.** Mates of a mixed bundle map as pairs, so proper-pair flags and mapping qualities change. A pooled map maps every read of every bundle and keeps pairs, where it mapped only the first bundle or lost the pairs, and a pool that mixes pairs with single reads stops first. A paired bundle is genotyped as one sample named for the bundle, so sample names in reports change. Taxa extracted from an interleaved sample are recorded as pairs, so map or assemble them again.
- **Import recipes and storage.** VSP2 and wastewater are presets of one recipe, so the same reads can keep a different read count. Optimize storage reorders every short-read import, so the stored order changes and the read count does not. `import fastq --recursive` pairs R1 and R2 folders into one bundle where it made two.

### Classifier and mapping numbers

- **EsViritu and TaxTriage count each read once.** Reads and Unique Reads counted every alignment record. In our test data three TaxTriage rows drop by 1 to 10 reads, for example 993 to 983. A classifier database built earlier keeps its old counts until you build it again.
- **An EsViritu virus row measures its whole genome.** RPKMF and Coverage of a segmented virus could read several times too high. High Island virus moves from RPKMF 6.9 to 1.2 and Coverage 2.5x to 0.4x, and the confidence badge can drop. Identity shows as a percent, 99.7% where it read 1.0%, and copies and exports keep the fraction.
- **Mapped reads count reads.** The contig table, the Inspector and `bundle info` counted alignment records, and four columns could read 0.0. For one test mapping Mapped Reads moves from 172,596 to 172,166, Mean Depth from 0.0 to 84.6, and Total Unmapped reads 576.
- **NAO-MGS.** When samtools rejects one of a sample's last reads, that sample now gets no BAM, where it got a BAM cut short.

### Read statistics

- **Statistics are measured.** A Nanopore barcode showed 383,349 bases for reads that hold 1,735,173, and 0 for lengths, N50, GC and quality. Demultiplexed bundles could show GC 0% and Mean Q 0. The median of an even count is the lower middle length. An older demultiplexed, trimmed or filtered read set is counted the first time you open it in each launch, about 13 seconds for each million reads. The viewer shows `Measuring the read statistics for <name>...` with a running count of reads, then the read set's own numbers.
- **A read set with no FASTQ file says so.** The viewer clears and the status bar says to wait for its import to finish or to import the reads again, where it kept the previous read set's numbers on screen.
- **Sample metadata stays with its sample.** An edit you have just typed, or a read type you have just chosen, is saved to its own sample when you select another read set.

### Alignments, trees and genotypes

- **Distances.** Ambiguity codes such as N, R and Y count as missing data, so Identity and p-distance change for alignments that hold them.
- **Tree defaults.** UFBoot and SH-aLRT support at 1000 replicates, one thread, a recorded seed, the alignment's own tip names and a root on the outgroup you tick are the defaults, so a new tree can differ from an older one.
- **Genotype calling rules move to version 5.** Tied references count once in the locus total, so in one test the total fell from 2,015 to 1,015 reads and a 15-read allele rose to 1.48%. A zero-read row no longer makes a haplotype call, and duplicate rows collapse to one. Full-length calls take their locus from the reference record, so percents of locus typically fall between 5 and 50 percent and older full-length exports are not comparable. Review a saved full-length revision again. The LabKey `cohort_id` is now an id that does not change, so a list keyed on row numbers needs a fresh import.
- **Translations and variants.** A clipped reverse-strand gene is translated in its own frame, so one tested protein reads `QYGS` where it read `SVR*R`, and residues count in the whole protein. Import annotation tracks and variant files again to get the frame and the split SnpEff and VEP fields. A compressed VCF with more than 512 contigs, or with records on contigs its header leaves out, now imports every record, so import it again with replace.
- **Assembly and genotyping.** MEGAHIT on Apple silicon runs on one thread. A hifiasm run with no contig graph, and a genotyping run whose minimap2 step failed, now fail where they looked complete.

### Exports

- **Export again.** A mapping image left out the reads that began before the first base shown, and an image of a bundle opened from the sidebar was a screenshot. A GFF3 export keeps each Note and lists such as `Parent=mRNA1,mRNA2`, with a dot in the source column. An EsViritu or Kraken2 export of several samples fills each row's metadata from its own sample.
- **Viral Recon.** A run on a reference bundle with no GFF3 file now passes the bundle's annotations, so iVar merges codons and SnpEff runs. A run that finished on an ExFAT drive under an earlier release cannot be shown, so run it again.

## Things to know

### Limits you may meet

- **Quality scores.** Binning cannot be undone once the original files are gone, and in-place imports of downloaded files and single-file imports offer no choice, so use the Import FASTQ sheet or `lungfish-cli import fastq --quality-binning none` to keep every score. Any BBTools step stores a base called at Q0 or Q1 as Q2.
- **IDT for Illumina UD Indexes is off.** Choose Custom Definition and enter the i7 and i5 sequences from your index sheet.
- **Cancel does not ask**, so a click on a row that moved under the pointer can stop the wrong run. An Extract with no reads ends Failed although nothing went wrong.
- **Some steps keep a limit.** kraken2 stops at 2 hours, Bracken at 1 hour, the human-read filter of a scrub at 2 hours, a recipe's deduplication at 1 hour, and the mappers, MAFFT and assembly at up to 24 hours. An EsViritu run has no limit, and a stopped one keeps up to about 15 GB of working files until you choose Remove Partial Output… on its row.
- **MEGAHIT can crash** on Apple silicon (exit -11 or -6). Run it again or use SPAdes or SKESA.

### Extract, images and older results

- **Extract.** A Kraken2 batch opens with every sample picked, so choose one sample first. Extract and BLAST compare read names and lengths, not bases. A classifier result that an earlier version imported stays in the Imports folder, so import it again.
- **Images.** An image leaves out base letters at single-base zoom and the Depth track above 1,000 bases per point, and it draws at most 75 rows of reads.
- **Older results.** NVD Unique Reads can still count a read more than once. Nanopore bundles imported earlier are measured again when opened. A region extracted to a new bundle keeps no annotations.
