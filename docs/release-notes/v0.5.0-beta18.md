# Lungfish 0.5.0-beta18

Previous release: v0.5.0-beta17

## Reliable partial-reference DRB candidate naming

This release fixes a second large-cohort MHC-DRB failure that appeared only
after all 192 samples had finished processing. The affected raw clusters
published the same observed DRB sequence and agreed on the closest reference,
the two-base deletion, and every other biological interpretation. They were
nevertheless assigned different provisional names because alignments with
slightly different endpoints counted substitutions in sequence beyond the
last coding exon actually present in the amplicon.

Canonical SNP counts, identity, and comparable-base totals are now calculated
only from mapped reference bases whose candidate coordinates fall within the
observed sequence that Lungfish publishes. This is especially important for
partial class II amplicons: bases aligned before the first observed coding exon
or after the last observed coding exon remain available in diagnostic evidence,
but they no longer change the identity or provisional name of the published
allele. The rule is applied in stored sequence coordinates for both forward and
reverse alignments.

The fix was checked against the complete 192-sample DRB cohort that exposed the
problem. The run completed candidate aggregation and produced the result
bundle, workbook, evidence BAMs, candidate files, and successful provenance.
The formerly conflicting sequence was consolidated into one candidate while
retaining all source-cluster and sample-level evidence.

Failure reports for any future genuine interpretation conflict are also more
useful. They now show the classification, locus, provisional name, reference,
SNP and indel counts, extension interpretation, and naming ambiguity for each
raw cluster. Provenance records the exact published-sequence comparison scope
on the canonicalization step, and regression tests cover partial CDS crops in
both forward and reverse orientations.
