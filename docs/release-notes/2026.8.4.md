# Lungfish 2026.8.4

Channel: Stable

Previous versioned release: v2026.8.3

Stable baseline: None (bootstrap aggregation baseline: v0.5.0-beta29)

Dependency set: 2026.2

Lungfish 2026.8.4 is the first Stable CalVer release. These notes aggregate
the complete product delta from the recorded bootstrap baseline
`v0.5.0-beta29` through this release rather than describing only the commits
since the previous Preview.

This is a fresh Stable-channel rebuild of the `v2026.8.3`-tested baseline plus
the channel-identity implementation. It does not relabel or reuse the Preview
tag, app, DMG, signature, or Sparkle item: the Stable name and feed are baked
into the app before signing.

## Included preview releases

- `v2026.8.1` — published as the first CalVer Preview, then its defective DMG
  was withdrawn after verification found upstream build paths in bundled
  micromamba. The immutable tag and notes remain in the release ledger.
- `v2026.8.3` — published Preview containing the corrected, independently
  verified portable build. It superseded the withdrawn 2026.8.1 artifact and
  is the tested product baseline rebuilt here for Stable.

`v2026.8.2` is recorded separately as an unpublished preparation tag. Its
pre-signing portability check stopped the build; no 2026.8.2 GitHub release,
Sparkle item, signed or notarized DMG, or distributed artifact was created.

## Stable and Preview channels

The Stable app is displayed as **Lungfish Genome Explorer** (short name
**Lungfish**) and polls `sparkle-stable/appcast-stable.xml`. The public Preview
app is displayed as **Lungfish Genome Explorer Preview** (short name
**Lungfish Preview**) and polls `sparkle-beta/appcast-beta.xml`.

There is no in-app channel toggle. To opt into Preview, install a Preview DMG;
to return to Stable, install a Stable DMG. Both channels use the literal
`Lungfish.app` wrapper, the same bundle identifier, preferences, and document
associations, so installing one replaces the other rather than creating a
side-by-side app. An installed Preview remains on the Preview feed until it is
manually replaced with Stable.

Preview is publicly downloadable as a GitHub prerelease and carries this
caveat:

> “Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.”

## Highlights

### Keep analysis tools current from Lungfish

Lungfish now compares installed environments with its bundled dependency
manifest and prepares an explicit update plan. The new **Update Tools** sheet
appears when required or optional work is available, shows affected tools and
databases, estimates the download, and distinguishes required work from
updates that may be deferred.

The command line exposes the same engine:

```bash
lungfish-cli tools update --plan
lungfish-cli tools update --apply --yes
```

Automation can request the plan or apply operation as JSON, restrict work to
blocking updates with `--required-only`, and distinguish pending updates from
failure through exit status 10. `lungfish-cli conda db install-managed` and
`conda db update` use the same manifest-backed database paths as the app.

Updates compare complete conda package specifications, including build
strings, and write incremental receipts so interrupted operations can resume.
Only previously installed optional tools are reconciled, and environments
that Lungfish does not own are not removed. Plugin Manager can check for tool
updates and apply supported managed-database updates from its Databases tab.

### Dependency set 2026.2

This release ships dependency set 2026.2, including updated managed tools,
pipelines, databases, bootstrap components, Sparkle, and the resolved SwiftPM
graph. The upgrade path was rehearsed against a clone of a real installation
containing 57 conda environments, including hand-created environments; no
unrelated environment was selected for removal, applied work completed, and a
dependency-set 2026.2 receipt was produced.

Some unchanged tool versions use new conda builds, so cutadapt, flye, LoFreq,
WhatsHap, and pysam may reinstall when upgrading a representative 2026.1
installation. This is intentional: Lungfish now verifies the full build
identity rather than only the displayed version.

### Bracken on Apple Silicon

Fresh Metagenomics pack installations build Bracken 3.1 from a
checksum-pinned source archive with a pinned Python 3.11/C++/OpenMP toolchain.
This supplies the real `bracken` and `bracken-build` programs on Apple Silicon,
including domain-level profiling and special-database build support.

Working existing Bracken environments are preserved during `tools update`,
including source builds without conda metadata. Lungfish remains compatible
with older Apple Silicon environments containing the driverless bioconda
package by detecting the synthesized `est_abundance.py` launcher and using its
supported argument form. That legacy launcher reports its supported ranks
instead of failing obscurely when domain-level profiling is requested.

### Safer Kraken2 and classifier workflows

Kraken read indexes are portable with their bundles instead of depending on
machine-local SQLite state. Lungfish recognizes missing write-ahead-log
sidecars, falls back safely when an index is unusable, and keeps fallback
diagnostics out of scientific result data.

Read estimates and extraction selections are scoped per sample, overlapping
counts are avoided, and the classifier choice is retained in provenance. This
prevents taxa selected for one sample from leaking into another sample's
extraction and preserves the exact classifier-row selections used to create an
extracted-read bundle.

### Parser, pipeline, and storage reliability

- EsViritu and SeqKit parsing is header-driven, tolerates additive columns,
  and surfaces malformed input instead of silently dropping parser failures.
- Kraken reports use explicit columns, and samtools flag statistics use JSON
  while retaining category order.
- TaxTriage 3.3.8 receives its required Kraken2 database explicitly, and
  EsViritu resolves its installed database through the same catalog used by
  installation checks.
- Ultra-low-memory imports preserve `skip_variant_info=true` even when a VCF
  contains no variants.
- Conda environment mutations are serialized to reduce collisions between
  installs, updates, and repairs.
- Database replacement is staged and checksum-verified, recovers interrupted
  swaps, and supports managed storage on external volumes.
- Offline pack imports preserve their transaction state when interrupted.
- Special-database recipe versions survive archive/import migrations.
- Genotype workbook revision resolves pinned openpyxl through Lungfish's
  managed Python environment rather than relying on system `PATH`.

## Reproducibility and provenance

Scientific provenance records dependency set 2026.2 as part of runtime
identity and presents it alongside app, executable, conda, plugin-pack, and
container identities.

Dependency reconciliation writes resumable receipts and operation provenance.
Managed Bracken source builds record the source archive and checksum, pinned
toolchain, commands, resolved defaults, paths, outputs, validated runtime, exit
status, wall time, and useful stderr. Bracken preflight records the invocation
form and any supported substitutions.

Classifier read extraction records the complete per-selection structure—sample,
accessions, and taxids—in workflow parameters and bundle creation options. ONT
demultiplexing resolves provenance tool descriptors from the same authoritative
manifest used for installation. The new dependency-reconciliation, managed
Bracken, and classifier-extraction workflows record their operation identity,
arguments and resolved defaults, runtime identity, input/output paths,
checksums, sizes, status, timing, and useful diagnostics.

**About Lungfish** and `lungfish-cli version --tools` read the shipped manifest
dynamically and report dependency set `2026.2 (2026-08-18)` with the current
managed and bundled tool identities.

## Platform and release infrastructure

Lungfish targets Apple Silicon on macOS 26 and builds with the Swift 6.2
package toolchain. Release automation uses one suffix-free `YYYY.M.PATCH`
sequence across channels, validates the candidate against both immutable tags
and GitHub releases, and orders Sparkle updates with a monotonically increasing
`CFBundleVersion`.

The release builder now sanitizes vendored Mach-O build paths before signing
and scans hidden and gitignored files in the complete packaged app. It permits
only the standard `/private/tmp` runtime-root constant while continuing to
reject concrete paths beneath `/private/tmp/`. Publication checks cover tag and
commit identity, DMG digest, signed Sparkle enclosure, narrative notes, baked
feed, and channel-specific bundle identity. A full Stable GitHub release
triggers the heavy build/smoke and toolset-conformance board through the
`released` event; it is not manually dispatched.

## Known issues and compatibility notes

- Preview and Stable cannot be installed side by side; install the desired
  channel's DMG to switch the one shared application installation.
- The 20260626 Kraken2 indexes display species-level taxid 3418604 as
  `Betacoronavirus pandemicum`. Classification identifiers are unchanged, but
  searches or notes relying on the former SARS-CoV-2 display name should be
  checked.
- The Apple Silicon bioconda Bracken compatibility package has no real driver
  and does not support domain-level profiling through its synthesized
  launcher. Fresh installs receive the managed Bracken 3.1 source build;
  existing working environments are preserved.
- `bioconda::bwa-mem2=2.3=hda5e58c_0` self-reports 2.2.1 because of an upstream
  packaging defect. Lungfish verifies that pin from conda package metadata.
