# Lungfish 2026.10.16

Channel: Preview

Previous versioned release: v2026.10.15

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release carries Phase 2.9. Lungfish Genome Explorer (LGE) now runs every Kraken2 and EsViritu launch from the Tools menu through `lungfish-cli kraken2 classify` and `lungfish-cli esviritu detect`, with the in-process route and its hidden setting gone, and a Kraken2, EsViritu or TaxTriage launch with no project open shows the No Project Open sheet. The bar of a TaxTriage row now moves while Nextflow runs, a cancel stops and removes the run's Docker containers, and LGE refuses a TaxTriage pipeline that its tool lock does not pin. `lungfish-cli taxtriage run` now runs the way `kraken2 classify` and `esviritu detect` do, with `--project`, `--batch` and `--format json`, and it cancels on SIGTERM with exit status 125. TaxTriage records name their Nextflow version and pipeline source, a Bracken profile that stops below its read threshold says why, Viral Recon and local workflows cancel with a 6 second grace, the sidebar lists results outside Analyses, and a full disk leaves no partial joined read file. The owner check list under Checks still to run blocks a Stable promotion.

## Classification

**One route for Kraken2 and EsViritu.** Kraken2 and EsViritu runs that you start from the Tools > Classification menu now always run through `lungfish-cli kraken2 classify` and `lungfish-cli esviritu detect`, and Copy CLI Command copies the command that ran. The in-process route that 2026.10.15 kept behind a hidden setting is gone, and the app no longer reads that setting. A value that you wrote with `defaults write` for `ClassifierLaunchRoute.kraken2.single`, `ClassifierLaunchRoute.kraken2.batch`, `ClassifierLaunchRoute.esviritu.single` or `ClassifierLaunchRoute.esviritu.batch` has no effect. The rows, their labels, the results and the Provenance tab look as they did in 2026.10.15.

**No project open.** Starting Kraken2, EsViritu or TaxTriage from the Tools > Classification menu with no project open now shows the No Project Open sheet, which reads `Open or create a project before running <tool>. LGE saves its results in the project's Analyses folder.`, with the tool's name in place of `<tool>`. The sheet starts nothing. In 2026.10.15 a Kraken2 or EsViritu run with no project open ran inside the app, on the route that this release removes.

**A Bracken profile below its threshold.** When you ask for a Bracken profile and no taxon at the chosen rank has as many reads as the Bracken threshold (10 reads unless you set another), LGE no longer runs Bracken only for it to fail. The run still ends Completed with Warnings, and the warning now says in plain words that no taxon reached the threshold and how many reads the largest one had. The result's record states the reason as `belowThreshold`. A result saved this way opens in 2026.10.15 and later but not in 2026.10.14.

## TaxTriage

**A progress bar that moves.** The bar of a TaxTriage row now moves while Nextflow runs. It follows the tasks that Nextflow has finished and rises from 10 percent to at most 86 percent, and the row, the log and the viewer's overlay name each task once as `Running <process> (<tag>)`, or `Running <process>` when the task has no tag. Before, the row stayed at `Starting TaxTriage pipeline...` and 10 percent until the engine ended. LGE counts 29 tasks for each sample, which is right for the app, because the app runs one sample at a time. A pooled `lungfish-cli taxtriage run --output` over several samples also counts 29 tasks for each sample but starts fewer, so its bar stops lower, at about 73 percent for two samples, and the step that collects the output files then takes it to 90 percent. The bar never moves back.

**Cancelling removes the run's containers.** When you cancel a TaxTriage run that uses Docker, LGE now stops and removes the Docker containers that the run's tasks started, once Nextflow and its programs on the Mac have stopped, and nothing of the run is left in `docker ps -a`. In two real runs, cancelled at the first tasks, the last container of the run was gone 2.2 seconds after the cancel from the command line and 2.7 seconds after the app's own cancel. Before, containers that ignored the stop signal outlived the cancel by about 10 seconds, and the ones that stopped stayed in `docker ps -a` as exited containers. LGE finds the containers of the run by the mounts of the run's own work folder and touches no other container. The row reads `Cancelling...` and then Cancelled with `Cancelled by user`, as in 2026.10.15. The viewer's overlay now reads `Cancelling...` with the row from the cancel on, where it kept the last Nextflow line or showed a task line that the engine reported while it stopped.

**A cancel while Docker Desktop starts.** When Docker Desktop is not running, the TaxTriage row reads `Docker daemon unavailable. Launching Docker Desktop...` while LGE starts it and waits up to 90 seconds for it. A cancel in that wait now ends the wait at once, and the row reads Cancelled with `Cancelled by user` within the 10 seconds that the Operations Panel allows. Docker Desktop goes on starting, because LGE asked it to start before the cancel. In 2026.10.15 such a cancel could take longer than those 10 seconds, and the row was then forced to Cancelled with a warning that the worker did not respond within 10s. That warning also said that a bundle stayed locked, though a TaxTriage row locks no bundle, and it no longer says so for a row that holds no lock.

**An unpinned pipeline is refused.** LGE refuses to run a TaxTriage pipeline that its tool lock does not pin, in the app and in `lungfish-cli taxtriage run`. The refusal reads `LGE's tool lock has no pinned version of TaxTriage, so LGE will not run it.`, and it comes before LGE waits for Docker. `lungfish-cli taxtriage run` also refuses before it makes any folder, but the Tools menu launch has already made its empty result folder in the project's Analyses folder, where it stays hidden from the sidebar. LGE no longer falls back to the pipeline's `main` branch when the lock names no revision.

## Viral Recon and local workflows

**Cancelling.** Cancelling a Viral Recon run or a Local Workflow run now sends its command a stop signal and gives it 6 seconds to stop before LGE ends it, inside the 10 seconds that the Operations Panel waits. A cancel that arrives before the command starts launches nothing. A Local Workflow now shows a Cancel button on its first run as well as on a replay. A cancelled first run ends `Cancelled by user`, and the command records the run as cancelled in the workflow's bundle.

## The sidebar

**Results outside Analyses.** The sidebar now lists an alignment or folder that carries LGE's analysis metadata outside the Analyses folder, such as an alignment that `lungfish-cli align mafft --output` wrote into another project folder or a result you copied out of Analyses. Earlier versions hid it. A copied result shows as a plain folder. A failed or cancelled run whose output folder is outside the Analyses folder now appears in the Operations Panel for review, as runs inside it already did.

**Results in folders you named.** A Kraken2 or EsViritu result in a folder you named yourself, such as a command line `--output` folder, now opens in its viewer after LGE builds its index, where earlier versions did nothing. A sample whose name starts like a tool, such as `esviritu_ctrl`, now opens as that sample of its batch, and a folder that only has such a name no longer opens as a result of that tool.

## Interrupted writes and external drives

**Joined read files.** When LGE joins the several files of a read set into one file, such as the reads that TaxTriage and EsViritu join from a bundle, it now writes the joined file to a hidden stage file in 4 MiB pieces and publishes it whole when the write ends. A full disk, or any other write error, now ends the join with an error that names the path, and LGE removes both the joined file and its lineage sidecar, so no partial file is left. The bytes of a join that succeeds are the same as before.

## Provenance records

**TaxTriage records.** A TaxTriage record now names the Nextflow version of a real run on Nextflow 26, which it reads from the line that TaxTriage prints, such as 26.04.6. Each TaxTriage step also says where the pipeline came from, as `snapshot` when Nextflow ran LGE's exported copy of the pinned release and as `remote` when it fetched the pipeline with `-r`, and a cancelled step says it too. The classifier choice is filed among the resolved defaults and not among the options you chose. The sample count, and the samples whose interleaved file LGE split into R1 and R2, are filed among the resolved defaults too, because LGE sets them and you do not. A database's identity is described with one of three words, pinned, unpinned or a live snapshot, and the words that earlier releases wrote read as the nearest of the three, so no earlier record changes. The Kraken2 database of a TaxTriage run still reads unpinned.

**The export fallback.** File > Export > Provenance with nothing selected now puts a one-sample TaxTriage run's database identity, read set plan and classifier choice among the resolved defaults, as the saved record does. Before, it put them among the options you chose. The values were already right, and only their place in the record changes.

## Command line

**`taxtriage run` works like the other classifier commands.** `lungfish-cli taxtriage run` now runs the way `kraken2 classify` and `esviritu detect` do. It takes `--project`, which makes the result folder under the project's Analyses folder as the app does and runs one Nextflow run for each sample, and `--batch`, which also runs one Nextflow run for each sample, each in a folder of its own. A plain `--output` keeps the one pooled run of earlier releases, in which one Nextflow run processes every sample. On real data, a pooled `--output` run and a `--project` run with one Nextflow run for each sample gave the same organism report and top report for each sample, byte for byte, which answers the comparison that 2026.10.15 listed as a known limit. The JSON copy of the report, `all.odr.json`, differs in bytes between any two runs, even two runs of one sample, so it is not part of that comparison. Give `--project` or `--output`, and not both. Giving both, or neither, is refused with exit status 3 before any folder is made. A `--project` result is indexed as part of the run, so it has its database when the run ends, and the cleanup that follows keeps `top/` and records what it removes as a step. The step names each removed file with the digest that a record of the run already holds, computes no new digest, and leaves a file unnamed when no record names it. A plain `--output` folder gets no database and no cleanup.

**Events and exit statuses.** Under `--format json`, `taxtriage run` prints version 2 events on standard output, and in text mode its failures and warnings go to standard error, as `kraken2 classify` and `esviritu detect` do. The header, the `[pct%]` progress line and the results table of text mode are as before. A SIGTERM cancels the run within 6 seconds, records `cancelled`, prints `TaxTriage was cancelled.` and exits 125. In 2026.10.15 a SIGTERM ended the command by the signal, exit status 143 in a shell, and left no `cancelled` record. A failed run exits 64, a pooled `--output` run included, where the pipeline's error ended the command with 1. The root record of a failed pooled run says exit status 64, and its `taxtriage` step keeps the 1 that Nextflow returned. A run that the command refuses before it starts exits 3 and leaves no folder, and the refusal for a tool lock with no pinned version exits 126. A run typed as `lungfish-cli taxtriage --input ...`, without the word `run`, now records the command as typed.

**Refusals.** `taxtriage run` refuses an `--input` folder whose loose files hold a mate pair with `The folder <folder> holds paired reads, such as <R1 file> and <R2 file>. Use --samplesheet to pair them.` and exit 3. A folder of `.lungfishfastq` bundles is never refused, because a bundle is not a mate. A blank `--revision` is refused with `--revision is blank. Name a TaxTriage commit or tag, or leave out --revision to run the pinned version.` and exit 3. Without `--revision` the run uses the commit that the tool lock pins. `lungfish-cli taxtriage run --help` says this in its own words now. It describes `--project` as `The .lungfish project the run belongs to. The result lands in its Analyses/taxtriage-batch-<timestamp>/ folder, where the app's TaxTriage runs put it`, `--batch` as `Run each sample alone, in its own Nextflow run and folder of one batch result`, and `--output` as `Output directory for results`, with a line below it that begins `Without --project or --batch, one Nextflow run processes every sample`. It describes `--revision` as `The TaxTriage commit or tag to run. Without it, LGE runs the commit its tool lock pins`, and it no longer prints a default commit for `--revision`, because the tool lock names the commit.

## Known issues

Known limit. The TaxTriage launch from the Tools > Classification menu still runs in the app, and Copy CLI Command on its row still copies a `lungfish-cli taxtriage` command whose `--output` is the app's own result folder, so running it writes into that folder again. Change `--output` to a new folder before you run it. A row for several samples offers no command. A later release changes the recorded command of a TaxTriage row.

Known limit. On that route, a sample that fails in a run of several samples still gets a completed TaxTriage entry, with the batch summary, in its source bundle's manifest.

Known limit. The record that the app writes for a TaxTriage sample still names `count/`, `fastp/` and `top/` files that LGE removes after the database build, so some names in it point at files that are gone. The record at the top of an app run of several samples also still files the classifier choice and the sample count as options you chose, and its sample steps carry no Nextflow version and no pipeline source. A later release moves the app's launch onto the shared record.

Known limit. The batch folder of a `lungfish-cli taxtriage run --project` run of several samples holds no aggregate `taxtriage-result.json`, which the app's own batch run writes and which the viewer and the row read. A later release settles that with the move of the app's launch onto the command.

Known limit. `build-db taxtriage --force` on a result that `taxtriage run --project` made still runs the earlier cleanup, which deletes the kept `top/` and replaces `taxtriage.sqlite` after the record named it, so the record then names a top report that is gone and the old digest.

## For contributors

This release carries Phase 2.9. `docs/plans/2026-10-12-phase-2-9.md` holds its plan.

The new target, the contract and the test helpers:

- `LungfishOperations` is a new library target for the services of the app that need no window. Its 69 Swift files, 67 of them moved from `Sources/LungfishApp/Services` and 2 new, are tested by `LungfishOperationsTests`, which holds 30 test files that moved from `LungfishAppTests`. `LungfishApp` and the app test targets import it, and `LungfishCLI` does not. `Sources/LungfishOperations/AGENTS.md` and the layering table of `AGENTS.md` say where it sits.
- `docs/contracts/ADDING-A-NEXTFLOW-WORKFLOW.md` is one contract for a Nextflow workflow. A workflow is one `NextflowWorkflowDescriptor`, and its repository and commit come only from the managed tool lock. TaxTriage is the first instance. `NextflowViralReconFitTests` shows that nf-core/viralrecon fits the same descriptor, although it still launches through its own request.
- `NextflowStandInEngine` in `Tests/Support/LungfishTestSupport` is the one stand-in Nextflow for tests. It prints either Nextflow 26's plain log lines or the 25.04 progress lines, and `TaxTriageStandInEngine` is now a short wrapper around it.
- `LiveNextflowRun` in the same folder is the helper for tests that run the real engine. A live class begins with `LiveNextflowRun.begin()`, which runs only when `LUNGFISH_LIVE_NEXTFLOW_ROOT` names an absolute root, or when `LUNGFISH_REQUIRE_TOOLS=1` is set with an absolute `LUNGFISH_STORAGE_ROOT`. It checks the managed Nextflow and `docker info`, never starts Docker Desktop, and at teardown removes the containers whose mounts hold its work folder. Name such a class with `Conformance`, so that it stays out of the unit tier.
- `TestDefaultsSuite` in the same folder gives a test a defaults suite named by a path in the temporary folder, so the test leaves no file in `~/Library/Preferences`. Nine test classes use it, and a tenth tests the helper itself.

Gates:

- `scripts/testing/preferences-leaks.py`, called by `scripts/full-suite-gate.sh`, takes a snapshot of `~/Library/Preferences` before each tier and fails the tier when a new UUID-named preference file appears whose prefix a test builds. `scripts/testing/preferences-leaks-allowed.txt` lists the test files that still build a suite by hand, and the list can only shrink.
- The `native-tool-runner-in-app` ratchet, `scripts/ratchets/native-tool-runner-in-app.sh`, counts the Swift files under `Sources/LungfishApp` that name `NativeToolRunner` outside comments. It started at 10 and stands at 7 after the move to `LungfishOperations`, and its baseline can only fall.
