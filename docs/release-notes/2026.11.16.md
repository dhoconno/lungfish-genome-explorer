# Lungfish 2026.11.16

Channel: Preview

Previous versioned release: v2026.11.15

Stable baseline: v2026.11.14

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

In this Preview, views and dialogs show the controls, the data and the facts true of this result, and each general explanation is one click away, behind an info button beside the control it explains. The button is a small i in a circle. Click it, or press Space when it has keyboard focus, to read the explanation, and press Esc to close it. Its hover text gives the short form, and VoiceOver reads it as "About" and the thing it explains. This Preview also fixes seven faults of Stable 2026.11.14. TaxTriage, Classification and EsViritu could join two FASTQ bundles of two specimens into one sample. In paired and batch runs of loose read files, Classification and EsViritu could pair reads from two folders, and all three could leave out the extra reads of a longer file or pair reads that were out of order. Mapping, assembly, Viral Recon, FASTQ import and plans for the Linux executor could also pair the reads of two files that were out of order, and some of them could leave out the extra reads of a longer file. LGE refused the reports CZ ID writes, and a tab copy of one imported with 0 reads. Viral Recon results made with another caller or from Nanopore reads could show no variant track, consensus or lineage tables.

## What works differently

- **The cell map carries less text.** The general explanations beside the plot now sit behind info buttons beside the controls they explain, such as Embedding and Colour by, and two new buttons, About the colour scale and About selecting, explain the legend's scale and how to select cells. The facts of this map and the short lines that must stay in view stay under their controls. The map's record lines, such as the result it came from, are in the Inspector. The control column is narrower, so the plot takes more of the window. On the walk's test map the words beside the plot fell from 193 to 54.
- **The Demultiplex Barcodes dialog carries less text.** The words on the three engines sit behind an info button beside Engine, and the words on a Custom Definition behind one beside the barcode source. With Cutadapt and a built-in TruSeq kit the pane shows 11 words beside its controls where it showed 71.
- **The pseudobulk and Workflow panes carry less text.** In the pseudobulk pane the captions of the single-cell result and of Result name are hover text, and an info button beside the selection line explains the selection-versus-rest test. The footer now says before Run when the result folder already exists. The six Workflow cards show one-line subtitles, and the rest of each card's words is its hover text, in the Library panel too.
- **The single-cell and bulk result views carry less text.** The rank plot's sentence, the two commands of the cell map line and the colour sentence of the Correlation tab sit behind info buttons beside them. The rank plot's heading reads "Cells ranked by UMIs", and VoiceOver names the plot the same way.
- **The Inspector names an open RNA-seq result.** With a bulk, single-cell or cell map result open, the Bundle tab lists the result and its facts, where it said No Bundle Loaded.
- **The operations dialogs carry less text.** Each dialog shows one readiness line, in the footer beside Run. Sections with no control, repeated Overviews and the line under the dialog's title are gone. Advanced settings shows only for a tool that has such a setting, each tool card's summary is its hover text, and section headings are in sentence case.
- **Genome Assembly and Viral Recon inside the FASTQ Operations dialog** show no Readiness section now. Their reason, failure or warning is the footer line beside Run, and a warning shows in orange. Viral Recon's line names the setting that keeps Run off, such as "Select a SARS-CoV-2 primer scheme."
- **The alignment viewer's coverage label and reads stay clear of the right band.** The label "max: … mean: …" now ends inside the data area, so its last digit and unit show whole. Reads no longer draw under the label gutter on the left or into the right margin, and a click in the gutter selects no read. An exported graphic is unchanged.
- **Viral Recon shows the results of every caller.** A run that sets another variant caller or consensus caller in Extra parameters, such as `--variant_caller bcftools`, or a run on Nanopore reads, now shows its variant track, consensus, lineage tables, alignment and coverage. Before, LGE read only the default folders, with no message. A run with another variant caller showed no variant track, consensus or lineage tables. A run with only another consensus caller kept its variant track but showed no consensus or lineage tables. A Nanopore run showed none of these, and no alignment or coverage either. A default Illumina run, with iVar variants and a BCFtools consensus, was not affected. The run's own files stayed in its results folder. When a sample lacks a variant, consensus or lineage output, the Inspector names it in one line, such as "Too few reads were left to call variants." The variant track names its caller, such as "BCFtools variants from Viral Recon". The fault was rated S2, a common task that fails with no words, in Stable 2026.11.14, and that page now lists it. LGE reads these outputs when a run ends, so a result made by an earlier version stays as it was. Run Viral Recon again with this version, or read the consensus and lineage tables in the run's results folder.
- **Each FASTQ bundle runs as its own sample in TaxTriage, Classification and EsViritu.** Before, these tools joined two FASTQ bundles whose names differ only by an ending such as _1 and _2, or _R1 and _R2, into one paired sample, with no message. So two files named like Swab_1 and Swab_2 from two specimens ran as one sample named Swab, with the organisms of both mixed in one result, a negative control mark lost, and the extra reads of the larger bundle left out. Now each bundle runs as its own sample under its whole name, such as Swab_1 and Swab_2, and no bundle is left out. When two bundles are named like the two reads of one sample, all three dialogs say, in their sample section, that they run as two samples, and that to run them as one you import both read files together as a pair. TaxTriage pairs only loose read files. It labels them "R1 ·" and "R2 ·", with R1 the file named R1, and says "Paired by filename as two reads of one sample. To run them as two samples, import each file separately." The fault was rated S1, a silently wrong result, in Stable 2026.11.14, and that page now lists it. A result made by an earlier version stays as it was. If you ran one of these tools on bundles named this way, run it again with this version.
  - A lone bundle whose name ends like a mate, such as Sample_1, now keeps its whole name as its sample name in TaxTriage, Classification and EsViritu, where before it became Sample.
  - In a command line batch, a loose X.fastq beside X_1.fastq and X_2.fastq is no longer left out. All three run as their own samples.
  - In TaxTriage, a launch whose bundles are all marked as controls no longer fills the Exclude host taxa field with 9606, the human taxon, by default, since the dialog now reads each bundle's role. The Exclude host taxa field shows the setting.
- **Two loose read files given as a pair are checked before a run or import starts.** Three faults of such pairs are fixed. Each was rated S1, a silently wrong result, in Stable 2026.11.14, and that page now lists it. A result made by an earlier version stays as it was. If you ran or imported two loose read files as a pair, or ran a command line batch of read files from several folders, run it again with this version.
  - **Folders.** A command line batch of Classification or EsViritu given read files from several folders pairs R1 and R2 only within one folder. Before, a mixed list could pair reads of two specimens, such as R1 from one folder with R2 from another. R1 and R2 in two different folders now run as two single-read samples. Where the old pairs were right, a batch of folders, one folder searched with `--recursive` and a shell glob pair the same files as before. Samples of one file name in several folders now number _1, _2 in the order of their folder paths, letter by letter, so `--batch b a`, folders such as run2 and run10, and folders whose files differ in compression can number them in another order than before.
  - **A short second file.** A paired run of two loose read files whose read counts differ now stops before it starts, with a message that names both files and both counts. Before, the run went ahead with no warning, and the reads past the end of the shorter file could be left out.
  - **Reads in a different order.** A paired run of two loose read files whose reads are not in the same order, by their read names, now stops with a message. Before, it ran with mismatched mates and no warning. This happens when one file was sorted or subsampled on its own.
  - **Where the check runs.** The read counts and read names of the two files are checked in TaxTriage, Classification and EsViritu, in mapping and assembly (their windows and the command line), in Viral Recon runs from your own sample sheet, in FASTQ import with a recipe (in the app and on the command line), in `fastq interleave`, which now writes nothing, and in RNA-seq plans of two files on this Mac. The plain FASTQ import with no recipe, in the app and with `lungfish-cli import fastq`, now reads both files once before its first step, shown as "Checking which reads are mates...", and refuses a pair out of step by name. This is how most pairs enter a project. Plans for the Linux executor are checked on this Mac when the reads are here, and on the node before the first step. In the runs above, a pair of FASTA files is checked the same way. A pair whose file names are not FASTQ or FASTA, such as .fastq.bz2, is now refused with a message in TaxTriage and in Viral Recon sample sheets, as mapping, assembly, Classification and EsViritu already refused it.
- **CZ ID reports import with their true read counts.** On the command line and in the CZ-ID import window, LGE now reads the taxon reports CZ ID writes, the Report Table and the bulk Sample Taxon Reports, as CSV files or tab copies. Each taxon gets its reads, and a genus's count includes its species, so no read is counted twice. Taxa with no rank keep their reads. Before, LGE refused the CSV with a wrong reason, and a tab copy imported with every taxon at 0 reads and rank U, with no warning. A report with no taxon ID, name or read count column, or a row with no taxon ID or name, is now refused, and nothing is imported. When you pick the file itself, the message names what is missing. The fault was rated S1, a silently wrong result, in Stable 2026.11.14, and that page now lists it. An import made by an earlier version stays as it was. Import the report again with this version.
- **Old results that these faults could reach carry a warning.** A result made by Preview 2026.11.15 or earlier, Stable 2026.11.14 included, now shows a warning line in the Inspector and above the viewer that says what to do, when it is a TaxTriage, Classification, EsViritu, assembly or Viral Recon result, a mapping of two loose files, a FASTQ bundle imported or planned from two loose files, or a CZ ID import.
- **Words that stated a wrong fact are corrected.**
  - In Demultiplex Barcodes, the kit's hover text says that Cutadapt searches for the kit's barcodes at both read ends in both orientations, and the caption of a long-read kit says that both ends must carry the same barcode only when the kit puts barcodes at both ends. Otherwise one barcode at either end is enough.
  - The Exact Bare Barcode refusal names what that engine accepts, the built-in Fluidigm Access Array kit or a Custom Definition of plain barcodes. The help and the run note of `lungfish-cli fastq demultiplex` state the same kit rule.
  - On the cell map, a sample with fewer than 10 selected cells reads "Pseudobulk omits <sample>'s <k> selected cells (under 10), so that sample has no selected column." About selecting says that a click on a legend row selects cells only when you colour by labels or Sample.
  - The hover text of the pseudobulk's Result name says that .lungfishrnaseq is added only when the name does not end with it. The 12S Amplicon Matching card says that it matches without substitutions, and the ONT genotyping card says that its matches allow indels.

## Things to know

The limits in the 2026.11.15 notes still apply, and so do the earlier limits that those notes keep.

## Updating

Choose Check for Updates… in the app menu to install this release. It adds no tool to install on the Mac.
