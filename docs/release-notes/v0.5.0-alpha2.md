# Lungfish 0.5.0-alpha2

This alpha focuses on making specialized workflows installable, inspectable,
and easier to run from real Lungfish projects. It also fixes several rough
edges from recent internal testing around plugin-pack status, FASTQ
demultiplexing, sidebar file handling, and mapping result display.

Changes since v0.5-alpha1:

## Workflow Library

- Added a Workflow Library for optional and specialized workflows, separate
  from the Plugin Manager.
- Registered existing built-in operations as Core tools and added ONT
  Genotyping as the first Specialized workflow.
- Added user workflow package import support for `.lungfishflowpkg` packages.
  Imported workflows can describe Lungfish bundle inputs and valid Lungfish
  bundle outputs.
- Added example three-step Nextflow and Snakemake workflow packages that use
  `.lungfishref` and `.lungfishfastq` inputs and write `.lungfishref` outputs.

## ONT Genotyping

- Added a first-class `lungfish fastq ont-genotyping` CLI workflow for mapping
  multiple FASTQ bundles to a reference, filtering exact aligned regions with
  indels allowed, and reporting per-bundle genotype support.
- Added the GUI workflow operation for ONT Genotyping so selected sidebar
  FASTQ bundles are used directly as inputs.
- Added pysam to the required Third-Party Tools pack for BAM filtering used by
  the genotyping workflow.
- Writes filtered minimap2 mapping bundles and a single CSV report into an
  `Analyses/ONT genotyping results` folder.

## FASTQ Operations

- Made exact bare-barcode demultiplexing operate directly on multi-file
  `.lungfishfastq` bundles instead of first materializing a giant temporary
  FASTQ.
- Added chunk-level parallelism for exact bare-barcode demultiplexing. In the
  barcode8 test dataset, a 4.98M-read demultiplex run dropped from roughly
  155 seconds to about 60 seconds with 8 workers.
- Preserved deterministic output ordering when parallel demultiplex shards are
  merged.
- Fixed a copy-on-write accumulator slowdown that caused excessive memory use
  during large demultiplex runs.

## pbAA Amplicon Clustering

- Added a container/Nextflow-backed pbAA FASTQ clustering operation that can
  use a project `.lungfishref` or filesystem FASTA guide sequence and output a
  `.lungfishref` bundle with provenance.
- Improved pbAA launch behavior, output discovery, and raw-output provenance.
- Removed the noarch conda pbAA plugin-pack path from the release flow because
  the packaged binary cannot execute on macOS.

## Plugin Packs And Operations

- Exposed conda plugin-pack install, verification, completion, and failure
  details through the Operations Panel.
- Moved less mature workflow packs such as Wastewater Surveillance, Variant
  Phasing, and GATK Core behind Experimental Features visibility.
- Improved readiness checks for managed tool packs and added pysam verification.

## Sidebar And Project Files

- Made sidebar scanning package-aware before recursing into directories, so
  `.lungfishfastq`, `.lungfishref`, `.lungfishmsa`, `.lungfishtree`,
  `.lungfishprimers`, and CZ-ID bundles are consistently shown as bundles.
- Made arbitrary project files visible in the sidebar, including unknown
  extensions, extensionless files, and ordinary `.json` files.
- Continued hiding known internal sidecars, indexes, provenance files,
  manifests, staging directories, and in-progress outputs.
- Fixed CSV/TSV-style report visibility so generated workflow reports appear in
  the project sidebar.

## Settings And UI Polish

- Adjusted Settings tab layout so available tabs are visible before the
  overflow control, following standard macOS tab/toolbar behavior.
- Added Workflow Library and Workflow Operations menu entries and accessibility
  identifiers for regression testing.
- Improved mapping result summaries and reference-paired detail display for
  filtered mapping outputs.

## Known Alpha Notes

- Workflow Library user package import is intended for early workflow authors.
  Package schemas and validation may still evolve before a stable public
  workflow authoring contract.
- pbAA remains specialized and should be treated as an alpha scientific workflow
  while additional real datasets are tested.
- Missing provenance remains a release-blocking defect for new scientific
  outputs; historical project data may still need backfill when opened.
