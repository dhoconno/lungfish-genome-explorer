# Lungfish 2026.9.9

Channel: Preview

Previous versioned release: v2026.9.8

Stable baseline: v2026.9.4

Dependency set: 2026.2

This Preview improves project ownership, background operations, import/export reliability, and workflow recovery. It includes the engineering remediation assessed after 2026.9.8.

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

## Predictable windows, tools and inspectors

Background loads and tool results retain their originating project and window. A late result cannot replace a newer viewport or publish stale Inspector details. Project opening, restoration and selected native-record loading move substantial storage work away from the interface thread.

Read-only projects are checked before writes, and incompatible project versions require explicit migration. If a project folder becomes unavailable, its windows show that state and disable new writes. Retry and Locate validate the original folder identity and preserve each window's selection.

## Safer operations and publication

Cancellation stays in progress while a worker drains and cleans up. Cancelled work does not publish a successful result, and its output reservations remain protected until it finishes. Overlapping output-directory reservations are enforced consistently across operations and availability checks.

Import and mutation publication preserve earlier payloads and provenance when recovery is possible. SQLite recovery retains committed WAL data and existing reader handles. When recovery cannot be completed confidently, the app reports retained recovery locations instead of claiming a successful rollback.

Managed database installation receipts now record the observed runtime version and resolved invocation. Older database installations without matching provenance must be refreshed before validated use.

Native bundles remain atomic through file panels, drops and supported ZIP imports. Copied bundles and attachments retain provenance for their final stored payloads. Sequence, FASTQ and annotation export actions use the selected sources consistently, disclose skipped items, and keep captured export data with reproducibility records.

## Workflow recovery and clearer controls

Workflow Library registrations remain available when their files move or become invalid, so they can be repaired. Supported imported local workflows can reopen a completed, failed or cancelled run through **Run Again…** or **Open Previous Run…**. The saved configuration is checked against retained inputs, package identity, the current runtime and a fresh destination before another attempt. Unsupported histories explain why they cannot be repeated.

**About Saving…** replaces inactive Save commands with an explanation of committed edits, drafts, window restoration and export. Viewing a project does not require installing unrelated tools. CLI and viewport sequence summaries now share boundary and overflow handling.

Menu validation tolerates early application startup without an active window. About Saving also works without a project window through a retained, nonblocking information window.

Credential edits persist reliably. The AI assistant provides a local preview of the context and possible recipients before submission. The environment export historically named `conda lock` now explicitly describes its requested, unresolved specification; unsupported exact reconstruction fails before environment changes.

## Validation and limits

Storage fixtures now isolate ambient environment overrides and reject cleanup outside their temporary roots. UI fixtures isolate persisted preferences. Suites with measured shared-state or startup-timing constraints run in the existing serial integration tier, and temporary-directory cleanup tests verify only the directories they own.

A file reader now consumes its already-validated descriptor directly, preserving ownership and line parsing while avoiding a second lookup through `/dev/fd`. Real-window fixtures also guarantee teardown when an operation throws.

The remediation passed 955 selected software regression cases and Release app/UI-target compilation. A separately assembled Debug app passed relocation/resource checks and a brief interactive check of windows, Operations, Inspector visibility, Workflow Library, an empty temporary project and normal quit. These checks do not certify every scientific workflow or replace release-candidate gates.

The user manual now states the local runner's existing resource limits accurately: not every retained CPU/memory field is enforced, and the accepted local timeout field is not enforced. Recovery snapshots may use temporary storage and are not a permanent archive. Full multi-file power-loss atomicity and noncooperating cross-process writers remain outside the guarantees of this release.
