# Lungfish 2026.11.6

Channel: Preview

Previous versioned release: v2026.11.5

Stable baseline: v2026.10.29

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview corrects a Kraken 2 total, the depth of an exported figure and a NAO-MGS Taxa count, keeps the platform of a subset of Oxford Nanopore (ONT) reads, and makes Demultiplex Barcodes record the bundle you picked.

## What's new

- **A Kraken 2 sample with no total of its own no longer takes the batch's total.** Before, in a Kraken 2 result of several samples, a sample that had no total of its own in the result's saved database (one made by hand or only half rebuilt) showed the whole batch's total, and the batch's count of unclassified reads, as its own. Now it shows its own reads and no percent of a total it does not have, and the hover card of a taxon leaves out a "% of total" or "% of classified" line when that total is not known, where it showed 0%. The limit that remains is under Things to know.
- **An exported figure counts depth under the window's cutoffs.** Before, a figure counted every read and every base in its Depth strip, whatever mapping-quality and base-quality cutoffs the window had set, so its max, mean and covered share could be larger than the window's. Now the figure counts depth, and draws reads, under the window's cutoffs, and a line under the Depth strip says which, such as "Depth counts reads with mapping quality 30 or more and bases with quality 20 or more." The figure's record holds the same cutoffs. With no cutoff set, nothing changes.
- **The Taxa count of a NAO-MGS result counts each taxon once.** Before, the Taxa count in the result header counted a taxon again for each sample that has it, so a taxon found in three samples counted three times. Now it counts each taxon once, however many samples have it, and follows the samples you select.
- **A subset of ONT reads keeps its platform.** Before, a bundle made by Subsample by Count, Quality Trim, Filter by Read Length or another FASTQ operation lost the platform of the reads it came from. Demultiplex Barcodes then started on the TruSeq Single Index Set A kit, and Map Reads and Assemble could start on short-read settings when the ONT reads were 600 bases or fewer, as in an amplicon run. Now the bundle keeps the platform, so all three start on ONT settings. Bundles that earlier builds made resolve the same way, by the record of the bundle they came from, and need no redoing. The limits are under Things to know.
- **Demultiplex Barcodes records the bundle you picked.** Before, when you demultiplexed a subsample, a trimmed set or other derived reads, the run's record named a temporary copy of the reads that the run had deleted, no barcode bundle linked back to the bundle you picked, and the command in the row and in Copy CLI Command showed `-o '<derived>'`, which cannot run. Now the record names the bundle you picked, each barcode bundle links back to it and records its pairing, and the command can be run again, also for a run that fails. The reads and pairs were right before and are the same now, with every pair whole. For a bundle you imported, the record now names the bundle and not the file inside it.
- **An exported figure says what it leaves out.** With Hide high-gap sites on in the Inspector, an exported figure still draws those sites. The export now says so. The row ends Completed with Warnings, and its Log and the figure's record say that the alignment track still shows the high-gap sites, because Hide high-gap sites applies in the window only. A figure zoomed out past 2 bases per point draws no reads, so it carries no such warning. The note in the Log for a zoomed-out figure now says that the track left out reads at this zoom, where it said that the track drew a summary.
- **Extract Reads on a TaxTriage result says which BAM file it read.** When a sample's own BAM file is not found, Extract Reads reads the one file in the `minimap2` folder whose name fits, such as `S1_2.bam` for sample S1. Before, it said nothing about this. Now it says "Sample S1's own BAM was not found, so Lungfish read S1_2.bam, the one file in the minimap2 folder that fits its name. If that file belongs to another sample, put S1's own BAM back and try again." The words show in the Operations Panel Log for a file or bundle extraction and on the command line, and the record of an extracted bundle holds them.
- **Sorting or filtering the mapped contigs keeps your zoom.** Before, a sort or a filter that kept the selected contig in the list sent the viewer back to the whole contig. Now the zoom and the reads stay. The limit that remains is under Things to know.
- **The Results button finds a BLAST search saved inside a Kraken 2 result.** Before, Results said "Unable to show results" while the files were there. Now it selects that Kraken 2 result in the sidebar.
- **The ONT folder import sheet counts the barcode folders and says what it leaves out.** Before, the sheet counted the unclassified folder among the barcode directories and said nothing about it, and a finished row read "1 barcode bundles". Now the count leaves the unclassified folder out ("Found 6 barcode directories."), the sheet says "Without a processing recipe, the import leaves the unclassified folder out." when the run folder holds one, and the row reads "1 barcode bundle" for one.

## What works differently

- **Keep the bundle you picked for a Demultiplex.** The barcode bundles of a demultiplexed subsample or other derived bundle now read their reads from the bundle you picked, where they were separate copies before. Keep that bundle.

## Things to know

- **A Kraken 2 sample with no total.** For such a sample, the percent columns of an exported table, and the percent column when you select several samples together, still read 0.
- **A bundle you imported.** A bundle you imported is not a derived bundle, so the barcode bundles of its Demultiplex stay separate copies with no link back to it, as before.
- **Platform records.** A barcode bundle that Demultiplex Barcodes makes keeps no platform in its own record, and `lungfish-cli fastq platform` shows no recorded platform for it or for a bundle that an earlier build made. The Workflow Operations window (Tools > Workflows) reads only a bundle's own record, so there such a bundle with ONT reads of 600 bases or fewer can still start on Illumina settings.
- **Exported figures.** A figure still draws the reads of every read group, where the window draws the groups you selected. A figure of a bundle with several alignment tracks draws a Depth strip and a reads track for each track, where the window shows one strip. Each strip is exact for its own track.
- **The mapped contig list.** The viewer can still return to the whole contig a few seconds after a mapping result opens, when the list has finished counting its reads, and when you change the alignment track in the Inspector.
- **The Results button.** For a BLAST search started from any other result or submitted directly, Results selects the search's own folder, which has no viewer, so the viewer and the Inspector stay on the result you were looking at.
- **The ONT import sheet.** Total size still adds the unclassified folder's files. The Fluidigm and PacBio recipes (Apply processing recipe after import) read every FASTQ under the run folder, the unclassified folder included.
- **A sample's own BAM file is gone.** If a sample's own BAM is gone, and another sample's name starts with this one's followed by a dot, underscore or hyphen (S1 and S1_2), Extract Reads can take the other sample's BAM when it has a name the pipeline does not give. It now says which file it read, but only after the output is written. If that file is not the sample's own, put the sample's own BAM back and run it again. Keep every sample's BAM file in the folder.
- **Earlier notes.** The limits in the 2026.11.5 and 2026.11.4 notes that this list does not change still apply.
