# Lungfish 0.5.0-alpha24

Previous published release: v0.5.0-alpha23

## Release Notes

This alpha introduces the first AI-assisted haplotyping workflow for genotype
result bundles. Until now, Lungfish haplotyping has been definition-driven: a
fixed set of haplotype rules is applied deterministically and the analyst
reviews the resulting workbook. That path remains available, but this release
adds a second route for cases where the most useful first pass is closer to how
a human analyst works through the genotype matrix: inspect the observed calls,
look for coherent sample-level patterns, explain ambiguous evidence, and
propose provisional haplotype assignments that can be reviewed before use.

The genotype result view now exposes AI Discovery and AI Refinement actions.
AI Discovery starts from the raw genotype calls and asks the selected model to
propose haplotype labels and supporting rationale without relying on the
existing deterministic definitions. AI Refinement starts from the current active
analysis, including deterministic calls, manual revisions, and overrides, and
asks the model to improve or qualify those calls using the same bundle evidence.
Both modes publish finalized haplotype calls into the bundle as versioned
revisions, the same way a manual revision becomes the current working file.

The AI path uses the existing Lungfish AI settings and keychain storage for
OpenAI and Anthropic credentials. The CLI also supports the workflow through
`lungfish-cli genotype ai-haplotyping`, with API keys read from environment
variables rather than command-line arguments. Prompts are versioned and hashed,
evidence is chunked through a registry, and model responses must satisfy a
strict structured schema before they can become bundle state. Invalid labels,
placeholder calls, malformed patches, and unsafe retain-current operations are
rejected before publication.

AI-generated haplotype calls are intentionally treated as reviewable scientific
outputs, not silent automation. Each AI revision writes the proposed calls,
discovered provisional definitions, evidence registry, validation report, and a
dedicated provenance record under the bundle's AI haplotyping artifacts. The
manifest and sidecar are updated only after those artifacts are complete, and a
failed publication rolls back to the original bundle state. The provenance
captures the model provider, model name, prompt template identity, resolved
workflow options, input and output file descriptors, and final manifest/sidecar
state while avoiding raw API keys and raw prompt text.

This release also improves the active haplotype resolver used by the app and
CLI. Persisted AI and manual analyses now take precedence over stale sidecar
definition settings, while deterministic definitions are still recomputed when
they are the active analysis. That keeps the visible workbook, manifest, and
review sidecar aligned as analysts move between deterministic calls, manual
edits, and AI revisions.

The prompt infrastructure is deliberately iterative. Prompt templates have
stable identifiers and versions, evidence registries preserve exactly what the
model saw, and the validation layer records why model output was accepted or
rejected. This gives future releases a place to add richer domain context,
calibration examples, disagreement handling, and analyst feedback without
changing the bundle revision model.

## Notes

- This release remains a prerelease build for testers.
- AI haplotyping calls must still be manually reviewed before downstream use.
- The release was validated with focused AI haplotyping regressions, broader
  genotype/app/CLI provenance sweeps, the full Swift test suite, signing,
  notarization, DMG packaging, and Sparkle appcast publication.
