# Lungfish 2026.11.3

Channel: Preview

Previous versioned release: v2026.11.2

Stable baseline: v2026.10.29

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview brings the work since Preview 2026.11.2. It fixes several wrong results that earlier versions, Stable 2026.10.29 included, could show or make, such as a Mean Q too high on a merged FASTQ bundle and a few reads given to the wrong sample by Demultiplex Barcodes with Cutadapt. Demultiplex Barcodes now also splits Illumina and Element reads by the index in their read names, and stops in words when no barcode turns up above chance. Read What works differently before you compare with old results.

## What works differently

### Demultiplex Barcodes

- **It splits reads whose index sits only in the read names.** It reads the index as bcl2fastq and BCL Convert write it, allows at most one mismatch in each index and keeps both reads of a pair together. It does this by itself when the names carry the indexes of two or more of the kit's barcodes, and the Read Names choice of the engine asks for it. Read Names works at 5' End and 3' End as well as Both Ends, so a dual-index kit whose indexes are in the names no longer has to run at Both Ends. It reads each file of a multi-file bundle on its own, so files that write the second index in opposite directions split correctly. A read whose index matches two barcodes, differs in two or more bases, or has its i5 in the other orientation than most of the file goes to Unassigned.
- **A run that finds no barcode above chance now stops.** When no barcode of the kit turns up in more reads than chance gives, Demultiplex Barcodes stops and makes no sample files, where earlier versions made sample files from chance matches. A Read Names run whose read names carry no index of the chosen kit also stops and says so, where it put every read in Unassigned. If an earlier version split such reads and sent most of them to Unassigned, its sample files hold chance matches, so run Demultiplex Barcodes again on this version.
- **Chance matches are judged on the reads of your own file.** Demultiplex Barcodes now judges chance matches (the demultiplexing chance floor) by the first bases of the reads in your own file that carry no barcode, so a file with no barcodes in its reads rarely gets sample files made from chance matches. A lone real sample typically needs about 0.3% of ten thousand reads, or about 0.4% of a million, to stand above chance, and more in an amplicon file. A barcode that falls short is named in the summary as a possible chance match, and its file is kept. On runs with more than 200,000 reads that carry no barcode, the demultiplexing chance floor now measures chance on all of those reads, not only the first 200,000, so a barcode that is not in your pool rarely passes as a sample there. This step reads every such read once, so it takes longer on runs with millions of them.
- **It no longer gives a few reads to the wrong sample.** It no longer moves a read to another barcode when the bases just after its barcode look like a second barcode. With Cutadapt and a single-index kit or a custom barcode list, earlier versions gave about 1 read in 120 to the wrong sample (12 barcodes of 8 bases at error rate 0.15), and more with more barcodes or shorter barcodes (about 1 in 14 for 96 barcodes of 8 bases). The ONT Rapid Barcoding and ONT 16S Rapid Amplicon kits and the M13 Universal Primers kit are unchanged.

### Detect Barcodes and the command line

- **Detect Barcodes counts every read of a custom barcode list.** Detect Barcodes now counts every read that starts with the barcode of a custom definition with one barcode a sample, such as a GBS or ddRAD key, the way Demultiplex Barcodes splits them. Before, it counted only the few reads that also held the barcode's reverse complement later in the read, often under 1% of them, and could mark barcodes that are in the file as rejected.
- **With no engine named, `lungfish-cli fastq demultiplex` chooses the search from the read names.** Before, it always used Cutadapt. Name `--engine cutadapt` to force the search of the read bases.

### Results and the sidebar

- **A result you open from the Operations panel, an import or an Inspector link now shows in the viewer.** Before, when a result viewer such as the TaxTriage table had the keyboard focus, the sidebar and the Inspector could move to the new result while the viewer kept the numbers of the old one. Now the sidebar and the Inspector always name the result the viewer shows.

### FASTQ statistics, bundles and mapping

- **The Mean Q of a merged FASTQ bundle is now one figure for all its reads.** A merged bundle (several single-end FASTQ files shown as one) and an older Nanopore import in chunks now show one Mean Q for all their reads together. Before, the card averaged the Phred scores of the files, which could read 9 to 16 Phred units too high when one file was poor. The statistics card and the Inspector now call the figure Mean Q (error rate), and the Inspector row has a hover tip that says what it is. Read it with Q20 and Q30, since a few very poor bases pull it down. A read in the alignment Inspector now says Mean Phred score.
- **A bundle made from an R1 file and an R2 file is read as a pair.** A bundle that `lungfish-cli extract reads --by-id` makes from two `--source` files with `--bundle` now shows both mates on its dashboard card, exports both, and counts both when `extract reads` reports how many reads it extracted. An operation that reads one file, such as `fastq materialize` or `fastq length-filter`, or Exact Bare Barcode demultiplexing, now refuses such a bundle in words and writes nothing, where it read the R1 file alone and said nothing.
- **Mapping, classifying or running EsViritu on several files of one bundle reads the bundle once.** Before, each file counted as the whole bundle, so mapping three chunks of a bundle of 12 reads gave 36 reads, and read counts and depth came out multiplied. The log now says when inputs of one bundle were collapsed.

### Other changes

- **A short peptide whose letters are all nucleotide codes now opens as protein.** A peptide such as MKTAYGHSSRV opens as protein and shows a dash for GC in the FASTA list. A protein record with U (selenocysteine), B, Z, J or O now opens instead of stopping the whole file.
- **Opening a different alignment starts the consensus settings at their defaults.** The high-gap masking, gap threshold, minimum depth, masking depth, caller mode and IUPAC codes start at their defaults, so the consensus track, the read display and a consensus export no longer use values set on another alignment.
- **`lungfish-cli provenance verify` on a record with no signature now says so and exits with 3.** It exited with 64 before. It says that the record carries no signature, so there is nothing to verify, and for the unsigned copy in a Viral Recon results folder it names the bundle that holds the signed one. A valid signature still exits 0 and a signature that does not hold still exits 64.

## What's new

### FASTQ operations

- **The Demux tab has a Demultiplex… button.** It opens Demultiplex Barcodes with the plan's table, and you press Run there. The names you type become the names of the outputs, with spaces, commas, quotes and slashes turned into underscores, and the new Output Name column shows each result before you run. A sample with no reads makes no output. The run keeps a copy of the table in its result folder, and its record names that copy. The status line of the tab wraps to three lines, and its tooltip holds the whole message.
- **Detect Barcodes reads the index in the read names.** It reads the index in the read names of Illumina and Element files, as bcl2fastq and BCL Convert write it. It reads the index the way Demultiplex Barcodes does, and accepts a barcode only when more of the names read carry it than chance gives. It says the counts came from the read names, says when a file holds one sample, and the plan it fills splits by the read names. It cannot search Ultima or MGI kits, or a file whose read names hold no index, and says so. For barcodes inside the reads, use Demultiplex Barcodes with a Custom Definition. The way out that Detect gives for a kit it cannot search no longer sends you back to Detect.

### Operations panel

- **The Results button opens a finished Call Variants run and a finished BLAST search.** For a Call Variants run it takes you to the bundle that holds the new variant track. For a finished BLAST search it selects the search's folder in the project list. The table and verdicts still open from the BLAST Results button of the result you ran the search from.
- **A FASTQ import that finishes with a warning says what the warning is.** The cause now starts the line under the import's name in the Operations panel. Hover over the line, or open the Log, to read all of it.

### Command line and batches

- **You can install `lungfish-cli` as a symbolic link on your PATH.** `taxtriage run` and the other Nextflow workflows now find their tool lock through the link, where they refused with exit code 126 and said that the tool lock had no pinned version.
- **The README of a staged batch says more.** It now covers how to check the staged reads before the submit, how to copy results home through a host that needs `ssh -F`, what the adopt does, and when the staging folder can be cleaned.

## Things to know

### Demultiplex… and its plan

- **A plan that fits.** Demultiplex… needs the dataset inside a project, a plan of one step and one barcode for each sample, and says what to change when the plan does not fit. For other plans, use Demultiplex Barcodes with a kit, which names the outputs by barcode.
- **Settings the Demux tab shows and the run ignores.** Allow Indels, Min Overlap and Search reverse complement show in the Demux tab and do not reach a Demultiplex… run. They have no effect on a Read Names run. On a search of the read bases, a person who cleared Allow Indels gets indels allowed, and the record shows it. Editing the 5' or 3' Sequence cell of a kit barcode shows in the table, and the run uses the kit's sequence.
- **A PacBio kit and a custom kit.** A plan on a PacBio kit passes Demultiplex… and Run then stops with "Combinatorial kits require explicit sample barcode assignments." A plan on a custom kit writes no `# kit:` line, so a one-sample plan whose index is only in the read names stops in the words about chance.
- **Reruns and empty samples.** A recorded command of a Demultiplex… run, run again with `--replace` into the same output, is refused because the copy of the table sits inside the output, so give a replay a new output folder. A sample with no reads has no bundle and no row in the manifest, so a negative control's 0 is not shown.

### Detect Barcodes and Demultiplex Barcodes

- **Detect and its plan.** A 6-base kit does not accept a sample under about 0.9% of 10,000 names, so Detect shows it and marks it rejected. The plan that Detect fills makes outputs only for the accepted barcodes, so the reads of a rejected barcode, or of the one barcode of a one-sample file, go to Unassigned.
- **The default engine and a multi-file bundle.** With the default engine, the files of a multi-file bundle are joined before their read names are read, so in a bundle whose files carry the second index in opposite directions the reads of the other files go to Unassigned. Choose Read Names as the engine, which reads each file on its own, or put such files in separate bundles.
- **Very short barcodes.** For a custom kit with so many short barcodes that about half of all random read starts would match one, such as a 384-sample plate of barcodes of 4 and 5 bases, Demultiplex Barcodes cannot tell a pool from a file with no barcodes. It judges chance as if every base were equally likely, can make sample files from chance matches, and says so in the Operations Panel and in the summary of the command line. No built-in kit is that short.
- **Exact Bare Barcode.** It does not check for chance matches, and says so when chosen and when it makes sample files. On reads without the chosen barcodes, such as reads whose index is only in the read names, it can make sample files from chance matches. Use it only on reads that carry them.

### Bundles and results

- **Operations run by earlier versions on a bundle of two files.** A FASTQ operation (trim, filter, subset, orientation, demultiplex) run by an earlier version on a bundle that `lungfish-cli extract reads --by-id` made from two `--source` files with `--bundle` read the R1 file alone. Run it again on this version, on one file of the bundle by name or on one interleaved FASTQ file of the pair, since this version refuses such a bundle in words.
- **Map Reads and `analyze stats` on such a bundle.** Map Reads in the FASTQ operations window on a bundle of an R1 file and an R2 file stops, and its words name an option the window does not have. `lungfish-cli analyze stats` refuses a read bundle folder with exit code 5 and "Could not detect format for file", so give it the FASTQ file inside the bundle.
- **The Results button of a BLAST search.** For a search started from a Kraken 2 result, Results may say "Unable to show results". Open the search from that result's BLAST Results button instead.

### Statistics and FASTA

- **Mean Q.** A bundle whose statistics a build from before 2026-09-27 saved may still hold the plain average of its Phred scores until its QC summary is refreshed. The statistics card shows the new label without a hover tip.
- **Peptides and short primers.** A record with fewer than 70% A, C, G, T, U or N among its letters is read as protein, so a short degenerate primer, motif or restriction site with many ambiguity codes other than N, such as the six-letter site RGATCY, shows as protein with a dash for GC. Peptides under 9 residues, or rich in A, C, G, T and N, can still open as DNA.

### Command line and other limits

- **A link to `lungfish-cli`.** The bundled micromamba may still refuse through a link. This has not been tried.
- **The README of a batch of reads on the Mac.** It does not yet have the points of the staged batch README.
- **Earlier notes.** The limits in the 2026.11.2 notes still apply, apart from the lines about the FASTQ drawer and about a protein whose letters are all nucleotide codes, which this Preview changes.
