# Lungfish 2026.8.1

Channel: Preview

Previous versioned release: v0.5.0-beta29

Stable baseline: None (bootstrap aggregation baseline: v0.5.0-beta29)

Dependency set: 2026.2

Lungfish 2026.8.1 introduces automatic, manifest-driven dependency updates,
ships dependency set 2026.2, and begins Lungfish's calendar-versioned continuous
release train.

This is the first release named with `YYYY.M.PATCH`. Preview and stable status
now belong to Sparkle channels instead of alpha or beta suffixes.

## Highlights

### Keep analysis tools current from Lungfish

Lungfish now compares installed environments with its bundled dependency
manifest and prepares an explicit update plan. The new **Update Tools** sheet
appears when required or optional work is available, shows affected tools and
databases, estimates the download, and distinguishes work required before
analysis from updates that may be deferred.

The same engine is available from the command line:

```bash
lungfish-cli tools update --plan
lungfish-cli tools update --apply --yes
```

Automation can request the same plan or apply operation with `--json`, limit
the work to blocking updates with `--required-only`, and distinguish
"updates are available" from failure through exit status 10. Managed database
installs are also exposed through `lungfish-cli conda db install-managed`, so
the GUI and command line share one manifest-backed installation path.

Updates use an incremental receipt, so an interrupted run can resume instead
of repeating completed work. Lungfish compares full conda package
specifications, including build strings, rather than treating a matching
version number as sufficient.

Plugin Manager can now check for tool updates and apply supported database
updates directly from the Databases tab. Database replacement is staged and
checksum-verified, with recovery for interrupted swaps and support for storage
on external volumes.

Only previously installed optional tools are reconciled. Environments that
Lungfish does not own are not removed.

### Dependency set 2026.2

This release moves 31 pinned tools, pipelines, databases, and bootstrap/app
components, along with 20 SwiftPM package upgrades. The update path was
rehearsed against a clone of a real installation containing 57 conda
environments, including hand-created environments: no unrelated environment
was selected for removal, all applied items completed, and a dependency-set
2026.2 receipt was produced.

Some unchanged tool versions use new conda builds. Those environments may
reinstall because Lungfish now verifies the complete build identity. This
affects cutadapt, flye, lofreq, whatshap, and pysam on a representative 2026.1
installation.

### Bracken now works correctly on Apple Silicon

Fresh Metagenomics pack installations now build Bracken 3.1 from a
checksum-pinned source archive using a pinned Python 3.11/C++/OpenMP toolchain.
This provides the real `bracken` and `bracken-build` programs on Apple Silicon,
including domain-level profiling and special-database build support.

Existing working Bracken environments are preserved during `tools update`,
including source-built environments without conda metadata. Remove the
`bracken` environment and reinstall the Metagenomics pack only if you
deliberately want Lungfish to replace it.

Lungfish also remains compatible with older Apple Silicon environments
containing the driverless bioconda Bracken package. It detects whether it is
invoking the real driver or the synthesized `est_abundance.py` launcher and
constructs the appropriate command. The synthesized launcher reports its
supported taxonomic levels instead of failing obscurely when domain-level
profiling is requested.

### Safer Kraken2 workflows

Kraken read indexes are now portable with their bundles instead of depending
on machine-specific SQLite state. Lungfish recognizes missing write-ahead-log
sidecars, falls back safely when an index cannot be used, and keeps fallback
diagnostics out of scientific results.

Read estimates and extraction selections are scoped per sample, overlapping
counts are avoided, and classifier choice is retained in provenance. These
changes prevent cross-sample taxa from leaking into a batch extraction and
preserve the exact classifier-row selections used to create an extracted-read
bundle.

Kraken2's 20260626 indexes use NCBI's current taxonomy name
`Betacoronavirus pandemicum` for species-level taxid 3418604. Classification
identifiers are preserved, but saved searches or notes that rely on the
previous SARS-CoV-2 display name should be checked.

### More robust parsers and pipelines

- EsViritu and Seqkit parsing is header-driven, tolerates additive columns, and
  surfaces malformed input instead of silently discarding parser failures.
- Kraken reports use explicit columns, and samtools flag statistics use JSON
  while preserving category order.
- TaxTriage 3.3.8 now receives its required Kraken2 database explicitly.
- EsViritu resolves its installed database through the same catalog logic used
  by installation checks.
- Ultra-low-memory imports preserve `skip_variant_info=true` even when a VCF
  contains no variants.
- Conda environment mutations are serialized, reducing collisions between
  installs, updates, and repairs.
- Offline pack imports preserve their transaction state when interrupted.
- Genotype workbook revision resolves its pinned `openpyxl` runtime through
  Lungfish's managed Python environment instead of depending on a compatible
  Python being present on the system `PATH`.

## Reproducibility and provenance

Scientific provenance now records dependency set `2026.2` as part of the
runtime identity. The provenance inspector displays that value alongside the
app, executable, conda, plugin-pack, and container identities.

Dependency reconciliation writes resumable receipts and operation provenance.
Managed Bracken source builds record the pinned source archive, checksum,
toolchain, commands, outputs, and validated runtime. Bracken preflight records
the actual invocation form and any supported substitutions.

Classifier read extraction records the complete per-selection structure—sample,
accessions, and taxids—in both workflow parameters and bundle creation options.
ONT demultiplexing provenance resolves its tool descriptors from the same
authoritative manifest used for installation.

**About Lungfish** now reads the bundled manifest dynamically. It reports
`Dependency set: 2026.2 (2026-08-18)` and the current bundled and managed tool
pins, including the bundled micromamba version and the source-built Bracken
overlay where applicable. `lungfish-cli version --tools` reports the same
dependency-set identity. Future dependency-set releases therefore update these
displays from the shipped manifest rather than from manually duplicated text.

## Release and maintenance changes

The release system now derives canonical versions from the local release month
and authoritative remote tags and GitHub releases. It rejects suffixes,
leading-zero months, future-dated histories, tag collisions, and attempts to
replace an existing versioned release outside an explicit recovery operation.

Sparkle preview and stable status are represented by feeds rather than version
suffixes. Sparkle continues to order updates by the monotonically increasing
`CFBundleVersion`; release tooling verifies that the planned build number
exceeds the live preview feed before building.

Publication checks now verify the versioned tag and commit, DMG identity and
digest, appcast contents, Sparkle signature, narrative notes, preview feed, and
legacy feed bridge. The fast push gate remains responsive for routine pushes
and preview releases. Publishing a full stable release automatically triggers
the heavier Swift build and toolset-conformance board through GitHub's released
event; release agents do not dispatch that board manually.
