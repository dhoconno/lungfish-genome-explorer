# Lungfish 0.5.0-beta17

Previous release: v0.5.0-beta16

## Reliable large-cohort DRB candidate reconciliation

This hotfix addresses a failure seen only after a large full-length ONT MHC-DRB
analysis had finished processing all 192 samples. Several raw clusters reduced
to the same observed DRB sequence after UTR trimming, but the final cohort-wide
merge rejected them because individual samples had described that sequence
using different, equally compatible partial-reference names. Small runs did
not necessarily contain enough of those observations to expose the conflict.

Lungfish now consolidates those sequence-identical observations into one
partial-extension candidate when the partial-extension evidence already lists
each reference name as an exact compatible match. All source cluster IDs,
sample observations, per-source read counts, reference names, and the selected
representative evidence remain traceable. When more than one compatible allele
name remains possible, the provisional naming is explicitly marked ambiguous
instead of choosing an unsupported unique name or failing the completed run.

The correction does not relax the underlying sequence checks. Candidates must
still have the same published sequence and locus, use genomic references, and
have no inserted, deleted, or skipped internal bases. A novel interpretation
cannot introduce an additional reference name unless a partial-extension
record already identified that allele as compatible; ordinary cDNA extensions,
different loci, different sequences, and genuinely SNP-different references
remain separate or are rejected as conflicts.

Reproducibility metadata now records the exact reconciliation rule and points
to the retained canonicalization-input artifact containing the original raw
biological interpretations. Regression coverage includes both the valid
multi-reference DRB case and rejection of an unrelated novel reference, along
with preservation of observations, read totals, and raw input identities.
