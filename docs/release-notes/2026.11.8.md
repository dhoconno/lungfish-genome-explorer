# Lungfish 2026.11.8

Channel: Preview

Previous versioned release: v2026.11.7

Stable baseline: v2026.11.7

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview corrects results that Stable 2026.11.7 could make wrong without a word. A trim could leave the wrong adapter on reads, a Viral Recon run could give a sample another sample's lineage tables, iVar could hide a change at 30%, and a grouped FASTQ operation, Demultiplex Barcodes among them, could read only the first of several datasets. Some numbers and files change, so read What works differently before you compare with old results. Each bullet says what to redo.

## What works differently

### Trims and read order

- **A trim of read pairs no longer lets fastp choose its adapter from the first reads in the file.** The import clumps similar reads together, so the head of the file could lead fastp to the wrong adapter and leave adapter bases on some reads. Lungfish now gives fastp the pairs in a fixed random order, with mates together. Trim the original reads again, or name your adapter in the trim dialog, and redo any mapping or variant calling that used the trimmed reads.
- **A trim of single reads no longer guesses its adapter.** With no adapter named, it uses TruSeq Read 1 and a list of five known adapters. Before, fastp guessed from the reads it saw first, and the guess changed with the order the reads were stored in. Trim the original reads again, or name your adapter in the trim dialog.
- **The trim of a processing recipe names its adapter,** where it let fastp guess. VSP2 target enrichment names the Nextera pair of Illumina RNA Prep with Enrichment. Wastewater metagenomics and the base recipe name the TruSeq pair. If you exported reads from a Lungfish bundle and imported them with a recipe, import them again with this version.

### Viral Recon and variant calls

- **Viral Recon gets its read pairs in a fixed random order.** Its fastp guessed the adapter from the clumped head of the file. On one real run (SRR36291587) it left one A on 2,309 reads and moved an allele frequency from 0.868 to 0.418. Run Viral Recon again on the same samples and compare the variant table and the consensus.
- **A Viral Recon sample takes only its own lineage tables.** A sample whose name began with another sample's name and a dot, such as S1.1 beside S1, put its Pangolin and Nextclade tables into S1's lineage files, so the Inspector could show the lineage and clade of S1.1 under S1. Run the batch again.
- **iVar no longer joins two changes of one codon into one record at the lower frequency.** On influenza PR8 (SRR5428776) it merged 469 C>A at 29.6% and 470 C>A at 9.5% into one record shown at 9.5%, so no row held the 29.6% change, and a 10% cut removed the only row left. Two small changes of one codon could also leave no record. A same-codon group now merges only when every change is above the consensus frequency, and any other change is its own record with the frequency and depth iVar measured. Call variants again with this version.
- **Viral Recon refuses inputs that share a sample name, before it stages any read.** Two bundles with one sample name, such as barcode01 from two runs, two NTC bundles, or a bundle and its copy, ran as one sample, and each result showed the joined reads. Names that differ only in letter case count as one. Rename one sample in its metadata. Two Nanopore samples that resolve to one barcode are refused for the same reason. A batch that repeats a name in another letter case (Sample_1 and sample_1) now takes the next folder name, where both used one folder and the second sample read the first one's results.
- **Viral Recon refuses a sample name with a space before it launches.** viralrecon refuses such a name, and the whole run failed after Nextflow started. The words now name the sample and say what to rename it to. Halves split from an interleaved file replace each space in the file name with an underscore.

### Demultiplex Barcodes

- **Grouped Result of two or more datasets now runs every dataset.** It ran one command that named the first dataset only, so the reads of the others were left out and the row ended Completed with no words. That was so for Demultiplex Barcodes and for every other FASTQ operation that offers Grouped Result, a length filter among them. Each dataset now runs its own command and writes its own folder, and the Demultiplex Barcodes row names every input. If you chose Grouped Result for more than one dataset, run the operation again on all the datasets with this version, then delete the old result.
- **The kit IDT for Illumina UD Indexes (96 pairs) is refused by every route.** Lungfish's built-in table for it holds 24 rows with 8 different i5 sequences, not the kit's 96 pairs, so reads could sit under the wrong sample or in Unassigned. The Demux tab plan, Detect, `fastq scout`, a run, and a definition that holds the table's pairs now stop with words and run nothing. Choose Custom Definition (on the command line, pass `--kit` with your own barcode file) and enter the i7 and i5 sequences from your index sheet. Run again any plan that you made in the Demux tab with this kit in 2026.11.3 to 2026.11.7. The kit stays in the lists until its table is checked, and using it gives these words.
- **The chance-match notice reaches every route.** When you demultiplexed several datasets with one command each, the Operations Panel row and its Log left out the within-chance line and the limit about a barcode not in your pool. They now show, and name the input of each barcode.
- **A file inside a multi-file bundle is read as the whole bundle.** `lungfish-cli fastq` subcommands, `demultiplex` among them, that were given one chunk of an ONT import or a merge counted the reads of part of the run, with no word. They now join the bundle's files and say so on stderr. If you ran one on a chunk, run it again on the bundle.

### Other results

- **EsViritu reads two inputs of one file name as two files.** When a folder in the input or output path held a space, Lungfish linked the inputs by file name alone, so two inputs of one name (reads.fastq.gz from two run folders, or a barcode sequenced on two runs) became one link to the second file. A pair was read as mate 2 twice, and an unpaired sample counted its second file's reads twice and its first file's not at all. Run such a sample again.
- **A saved BLAST search shows only on the row it belongs to.** A search saved from a FASTA list could show as the verdict of a TaxTriage row that held no BAM owner, taxon or accessions. A row that names no sample, taxon, contig or query now shows no saved search.
- **A varVAMP or Olivar design keeps its scheme when an amplicon is a few bases outside the size range.** varVAMP takes the range as a target, and on a real SARS-CoV-2 design it wrote amplicons of 354 and 444 bp against a range of 360 to 440. Lungfish refused the whole design. It now keeps the scheme and shows a warning on the result card and on the command line that names each amplicon, its length and the two bounds.
- **Copy takes the selected bases in a reference bundle view.** Command-C said "The viewer holds no sequence" while the bases showed. Copy now takes the selected bases, or the visible region when nothing is selected, and Edit > Copy works there. With nothing to take it says "No bases are selected" and asks you to select the bases you want, then try again.
- **A stopped run says why.** When the Mac ends a tool by SIGKILL or exit status 137, the words now say it stopped, most likely for memory, with the peak it reached, on the routes that share the new words. Lungfish also cancels its own work when it alone is using half of the Mac's memory. It says why in the Log of each cancelled row and once in an alert, and the row's detail still reads Cancelled by user. `lungfish-cli` stops at the same point with a message and exit status 1.

## What's new

- **A result made by a version with a known fault says so.** A note above the viewer and a line under Warnings in the Inspector give the fault and what to do, until the result is made again by an unaffected version. It shows for TaxTriage, Kraken 2, EsViritu, NAO-MGS, NVD and assembly results. It does not show yet for Viral Recon, Call Variants, trimmed reads and Demultiplex results, so use the redo lines above for those.
- **Two datasets with one name each get their own output folder.** A FASTQ operation run on two datasets with one name, such as `reads.lungfishfastq` in two folders, failed every time with words that the output folder already held items, in Per Input and in Grouped Result. The second dataset now writes to a folder numbered `-2`.

## Things to know

- **A single-read library with another adapter.** A library whose adapter is not TruSeq Read 1 or one of the five known adapters keeps its adapter on the reads, and nothing says so. Name your adapter in the trim dialog. The unpaired reads of a mixed file still get a single-read trim that names no adapter.
- **Viral Recon on single-end Illumina reads.** viralrecon's own fastp still guesses the read 1 adapter from the head of the staged file. Its effect on a result is not settled.
- **Wastewater metagenomics on a Nextera-based kit.** Its trim names the TruSeq pair, so on an Illumina DNA Prep, RNA Prep or Nextera XT library it removes adapter by mate overlap only. On two public Nextera runs that left adapter on 0.02 to 0.04% of reads. For such a library choose VSP2 target enrichment and turn on Remove ribosomal RNA reads, which runs the same steps with the Nextera pair.
- **Illumina amplicon genotyping.** Two sample IDs that share a file stem make the pair merge write one file for both, so the first sample's genotype is called from the second sample's reads, with no words. Give each sample ID its own file stem.
- **Merge AF distance.** The field in the Call Variants dialog and `--ivar-merge-af-threshold` no longer decide a merge, and their help still says they do.
- **Copy with nothing selected** takes the visible region at any zoom. Zoomed out on a long chromosome it can put a very large sequence on the pasteboard. Zoom in or select the bases first.
- **Memory stops.** Some routes, among them conda installs and mapping, still word a run that was stopped for memory as the tool's own failure. A status of 137 or the word Killed most likely means memory.

The limits in the 2026.11.7 notes still apply.
