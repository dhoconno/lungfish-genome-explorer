# Lungfish 0.5.0-beta23

Previous release: v0.5.0-beta22

This release is the result of a comprehensive review of the entire application, aimed
at fixing bugs, improving responsiveness, and making tool behavior consistent across
the app. It began with a report that merging two GenBank-derived reference bundles
failed, and grew into a full pass over correctness, performance, and every
user-triggerable action in Lungfish.

## Merging reference bundles now works as expected

Merging two or more reference bundles into a new bundle previously failed whenever
either bundle carried annotations, which is the normal case for anything imported
from GenBank. The merge now succeeds and keeps every source bundle's annotation
tracks, whether you are merging two GenBank imports, a GenBank import with a FASTA
import, or two FASTA imports. Duplicate sequence names are now caught and reported
before the merge starts rather than causing a confusing failure partway through, and
if part of a merge cannot be completed (an unreadable source file, for example) you
now get a clear warning explaining what was skipped instead of a silent gap. Merging
variant calls or alignments together is still not supported and now says so plainly.

## Running a tool on multiple selections is now consistent

Every wizard that can accept more than one selected bundle now offers the same
choice: run the tool once per bundle and get one result per bundle, or combine
everything into a single run. Mapping and short-read assembly (SPAdes, MEGAHIT,
SKESA) default to running once per bundle, which also fixes a real problem: mapping
multiple samples together previously produced one BAM file whose read-group tags
all pointed to the first sample, silently mislabeling everyone else's reads. Each
sample's reads are now correctly attributed. Tools that only make sense as a single
combined run, like MAFFT alignment, clearly say so and explain why. Tools that already
handled multiple selections correctly (TaxTriage, Kraken2, EsViritu, the Savont and
PBAA clustering tools) now describe their existing behavior honestly instead of using
generic wording that didn't match what actually happened.

## Bundles behave consistently in the sidebar

Right-clicking a bundle in the sidebar now shows the right actions for that bundle's
type. Previously, MHC amplicon reference bundles and five other bundle kinds fell
through to a bare-bones menu missing options like Open Bundle, Show Package Contents,
and Get Bundle Info, even though those actions worked fine once triggered another
way. Exporting sequences from a mixed selection no longer silently drops the items it
can't handle. It tells you which ones were skipped, or disables the export entirely
if nothing in the selection qualifies.

## Broad correctness and stability fixes

A wide sweep across the whole app turned up and fixed a long list of smaller issues
that could cause crashes, data loss, or confusing behavior:

Two different code paths could hang indefinitely if a background tool (samtools, or
tar during a conda package export) wrote enough error output to fill an internal
buffer. Both are now fixed. A rare SQLite memory-safety bug that could corrupt
annotation data on write has been closed everywhere it occurred. Interrupted database
writes, such as a disk running out of space mid-import, now fail loudly and leave the
database in a state that can be safely retried, instead of silently reporting success
over missing data. Importing a malformed BED file with mismatched block counts could
crash the app; it now falls back gracefully. Using `lungfish convert --force` to
overwrite a file could delete that file before checking whether the conversion itself
was even possible, permanently losing your data on a failed conversion; validation
now happens first. Extracting overlapping reads, canceling a mapping run, and several
other operations that used to fail silently now show an error when something goes
wrong.

Barcode assignment during ONT genotyping demultiplexing could silently assign a read
to the wrong sample when two samples' barcodes were ambiguous; this is now caught and
reported as an error naming both samples involved.

## Faster and more responsive

Several places where Lungfish would pause or stutter have been addressed. Opening a
project scans the sidebar in the background now instead of blocking the window.
Importing annotations, building reference bundles, and loading provenance information
in the inspector no longer freeze the interface while they work. The sequence viewer's
tooltip lookups and the genotype comparison matrix's search filter are noticeably
smoother on large datasets. The FASTQ operations dialog opens instantly rather than
scanning the project synchronously first.

## Under the hood

This release also includes substantial internal cleanup: shared components for
warning dialogs and byte/count/duration formatting, a single source of truth for
which actions a given bundle type supports, and a large source file in the ONT
genotyping pipeline split into more manageable pieces with no behavior change. None
of this is visible day to day, but it should make future updates land faster and with
fewer surprises.

## Notes

This remains a beta prerelease. It is distributed as a signed and notarized Apple
Silicon DMG through GitHub and the Sparkle beta update feed.
