# Lungfish 2026.10.23

Channel: Preview

Previous versioned release: v2026.10.22

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview is the Stable candidate of Phase 2.14. New FASTQ imports now store quality scores in 7 levels unless you choose None, and VSP2 and wastewater imports now share one recipe that gives different reads than before. Extract in the Collections drawer works on a Kraken2 result opened from the sidebar, imported classifier results appear in the sidebar, pooled mapping maps every read, and the image of a bundle opened from the sidebar is drawn from the bundle's files. Several messages, tables and Inspector rows are also corrected.

## What's new

### Classifiers

- **Extract from the Collections drawer.** Extract in the Collections drawer of a Kraken2 result that you open from the sidebar now starts an extraction, where before nothing happened. It extracts the reads of the sample shown, and the row's command names that sample. If Lungfish cannot find the result of that sample, an alert titled Could not extract reads says so. When the table shows several samples with none alone, the alert asks you to choose one sample first.
- **Imported results in the sidebar.** Imported EsViritu, Kraken2, TaxTriage and NVD results now appear in the sidebar's Analyses folder, where run results show. A NAO-MGS result is not part of this change and stays where it was.

### Mapping

- **Pooled mapping.** Mapping several bundles in one pooled run now maps every read of every bundle. Before, BBMap mapped only the first bundle, bwa-mem2 stopped on two bundles, and minimap2 stopped on three and also skipped the extra reads of the longer of two bundles. A pooled run maps the reads as single reads, so read the limits under Things to know before you pool paired bundles.

### Viral Recon

- **Preparing inputs.** Starting a Viral Recon run no longer blocks the window while Lungfish prepares the inputs. Run is disabled and the footer reads Preparing inputs… until the run starts, and a second click on Run starts nothing.

### Viewer images

Export Image of a genome bundle or a mapping result that you open from the sidebar now draws the image with `lungfish-cli bundle export-graphic`. This covers a reference bundle, a mapping result and a bundle with no tracks. The Scope menu now reads Tracks, Ruler and Tracks, and Selected Region, where these two routes offered one whole-pane choice, and the image holds the viewer's tracks and not the whole pane. The Operations Panel shows an Export Image row, and Copy CLI Command on that row copies the command. The 2026.10.22 notes described this, but these two routes still saved a screenshot of the pane. The other differences between the image and the viewer, such as track heights, spacing, colours and fonts, are listed in the 2026.10.22 notes and still apply.

## What works differently

### Reads and downloads

- **Quality binning.** New FASTQ imports now store quality scores in 7 levels, which the import sheet calls Illumina (7-level), to save space. This rounds the stored scores. Because 20 is not one of the levels, a base filter at Q20 can keep or drop different bases than it did on the original scores, which matters for low-frequency variant work. To keep every score, choose None for quality binning in the import sheet, or pass `--quality-binning none` to `lungfish-cli`, where the default is `illumina4`. The change reaches imports of Illumina and Oxford Nanopore reads, SRA downloads into a bundle and `fastq ingest`.
- **VSP2 and wastewater.** The two are now presets of one recipe, `illumina-paired-cleanup`, and ribosomal RNA removal is off for VSP2. VSP2 imports now trim adapters and poly-G tails, filter reads at quality 15 and length 15, and cut low-quality bases from the end of a read. Wastewater imports now remove duplicate reads by default, cut low-quality bases from the end of a read and always trim poly-G tails. The end cut is fastp `--cut_tail`, where both recipes used `--cut_right` before. The same reads can therefore give a different read count than they did with 2026.10.22.
- **Trim Galore.** The Trim Galore storage step now counts the reads that it removes, and its step, its notice and its record say that it removes reads.
- **Memory messages.** Import FASTQ now tells you to close other apps or import fewer samples when a sample runs out of memory. The `--clumpify-heap-gb` option comes last, under the command line.
- **Recipe messages.** `lungfish-cli` now lists every recipe name in its unknown-recipe error and describes the default Java heap correctly. The Inspector no longer lists the duplicate and ribosomal RNA settings as Not recorded for a recipe that has no such setting.

### Classifiers

- **EsViritu Identity.** The EsViritu Identity column and the hover text of a segment row now show percent (99.7%, not 1.0%). Copied rows and exported tables keep the fraction as the tool wrote it (0.99699).
- **NAO-MGS and NVD results.** A NAO-MGS or NVD result no longer shows the Operation Details or Source Samples of an earlier Kraken2 batch that you looked at before it.

## Things to know

### Reads and downloads

- **Binned scores cannot be recovered.** The 7 levels are a rounding, so choose None for quality binning before an import if you need every score. A file you imported with the earlier setting keeps the scores it stored.
- **A changed recipe changes counts.** A VSP2 or wastewater import made with this release can keep a different number of reads than the same reads did in 2026.10.22, because the recipe now trims, filters and cuts differently. Compare read counts only between imports made with the same release.
- **Failed legacy recipe steps.** A failed step of a legacy recipe still reads as an unknown recipe error.

### Mapping

- **Pooled runs map single reads.** A pooled run maps every read as a single read, so paired bundles lose their pairing in it. To keep pairs, map the bundles one by one.
- **Mixed compression is refused.** A pooled run stops with a message that names the compressed and the uncompressed bundles when you pool both kinds. bowtie2 and minimap2 with a long-read or assembly preset ran such a pool before this release. Compress or decompress the bundles so they match, or map them one by one.

### Classifiers

- **Extract needs one sample chosen.** When the table shows several samples at once, which is how a Kraken2 batch opens, Extract asks you to choose one sample first.
- **Results imported earlier.** An EsViritu, Kraken2 or TaxTriage result that an earlier version imported stays in the project's Imports folder and does not open. Import it again to see it in the sidebar.
- **Identity in copies and exports.** Copied rows and exported tables write Identity as a fraction from 0 to 1 while the table shows percent.

### Viewer images

- **Reads need a close view.** An image of a mapping result draws its reads only when the exported window is at most 2 bases per point, about 2,000 bases for a view 1,000 points wide. A wider window gives an empty read track and no coverage curve. Zoom in before you export.
- **Every read track and sample.** When a mapping result's viewer shows only one of its read tracks, or only some of its samples, the exported image still draws all of the result's read tracks and samples. The image holds at most 75 rows of reads where the viewer can show more, and it can draw a track that the viewer has hidden.

### If you repeat earlier work

- **Imports.** A FASTQ import made with this release stores binned quality scores unless you choose None for quality binning, and a VSP2 or wastewater import trims, filters and cuts differently. Read counts can differ from those of the same reads imported with 2026.10.22, so compare counts only between imports made with the same release.
- **Mapping.** A pooled run that stopped, mapped only the first bundle or dropped reads in 2026.10.22 can be run again, and it now maps every read as a single read. Map paired bundles one by one to keep their pairing.
- **Classifier results.** Import again an EsViritu, Kraken2 or TaxTriage result that an earlier version put in the Imports folder, so that it appears in the sidebar and opens.
- **Images.** Export again an image of a bundle or a mapping result that you opened from the sidebar, because the earlier file is a screenshot of the pane and not a drawing of the bundle's files.

### Everything else

The limits under Things to know in the 2026.10.22 notes still apply, except where a change above says otherwise.

## Updating

Choose Check for Updates… in the app menu, and Sparkle offers this release, installs it and relaunches the app. The tool lock adds no new tool in this release. The Ribosomal RNA Removal Data is no longer inside the app, so Lungfish downloads it on demand, about 10 MB.

## Dependency versions

Dependency set 2026.2 is unchanged from v2026.10.22. Two entries of the tool lock changed. The Ribosomal RNA Removal Data (deacon-ribokmers) moved from a payload inside the app to a pinned download of 10,107,947 bytes with SHA-256 f88286f607bc062ef872b55cac9aff1d447f7106068cafefef72a3ba8e49ede6, built with deacon 0.16.0 on one thread from BBMap's ribokmers.fa.gz. The Human Read Removal Data (deacon-panhuman) gained a pinned SHA-256 and a size of 3,279,263,603 bytes, and its source link now points to github.com/bede/deacon. A new file, `third-party-tools-lock.linux-64.json`, holds the tools of the Linux tier and does not change the Mac tools. No other pinned tool or pipeline moved.
