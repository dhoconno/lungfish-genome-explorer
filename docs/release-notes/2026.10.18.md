# Lungfish 2026.10.18

Channel: Preview

Previous versioned release: v2026.10.17

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release moves more of Lungfish Genome Explorer (LGE) onto `lungfish-cli`, so that a launch from the app and the same command in Terminal run one code path. Map Reads, Reassemble, the in-place FASTQ ingest, the ONT import, four Inspector alignment workflows, Update Tools, pack installs, database updates, and every download of the Database Browser and of Help > Demo Projects now start the command and show its Operations row, with a Cancel that stops the command and a Copy CLI Command that copies what ran. The release also changes the words of several classifier rows and logs, stages an annotation for Viral Recon runs on a freshly fetched reference, adds an Environment row to the Provenance tab for new classifier results, and corrects what several records say. Sequence export, region extraction, reference import, bundle merge, GATK variant calling and the TaxTriage launch from the Tools menu keep their in-app routes until 2.11. A hidden key keeps each earlier route for one release and 2.11 deletes the keys. Set one with `defaults write com.lungfish.browser.preview <key> legacy`, where `com.lungfish.browser.preview` is the identifier of this Preview, and delete it with `defaults delete com.lungfish.browser.preview <key>`. The owner check list under Checks still to run blocks a Stable promotion, and this release adds rows 27 to 50 to it.

## Reads and downloads

**Map Reads and Reassemble.** Map Reads (Tools > Mapping) and Reassemble… (the sidebar's context menu) run `lungfish-cli map` and `lungfish-cli assemble` by default, and Copy CLI Command on the row copies that command. The keys `ReadsLaunchRoute.mapping` and `ReadsLaunchRoute.assembly` keep the earlier route. With `--format json`, `map` prints `CLIEvent` lines in place of the `r5-map-report` document, so a script that read the document reads the `complete` line, and `assemble` prints its events on standard output. The record of a Map Reads run names `lungfish-cli map` in its `argv` and `reproducibleCommand`, a run with materialized inputs no longer records a `durableReplayArgv` for the mapper, and a BAM track's import row names the app's version and not the host's. A Reassemble run names its bundle as the record's output.

**FASTQ ingest.** When LGE copies a raw FASTQ file into a project, the ingest runs `lungfish-cli fastq ingest --delete-originals --format json`. The command writes the output, its sidecar and a record that names the digest of the original, and it removes the original last. A cancel exits with status 125 and leaves the original. When the input sits in a project, the command stages its hidden folder under the project's `.tmp` folder, so the project's automatic cleanup removes what a killed run leaves, and it reads the output once before it publishes. Its help says where the folder sits. On 4,983,047,591 bytes and 20 cores, the record's step for the ingest fell from 49.98 s to 0.13 s with that one read moved before the publish.

**ONT import.** Importing a dropped or chosen ONT run folder runs `lungfish-cli fastq import-ont --format json`, and Copy CLI Command copies the command that ran. The row has Cancel with a 6 second grace and ends Cancelled with no sheet and no bundle left. The failure sheet shows the import's own words in place of the error's dump, and the expanded row lists each stage word once. The key `ReadsLaunchRoute.ontImport` keeps the in-process import for one release, and the app reads it each time an import starts.

**Database Browser downloads.** With a project open, the Database Browser (File > Search Online Databases) downloads by running the command. Genome rows run `lungfish-cli fetch genome`, nucleotide and virus rows run `fetch ncbi --bundle`, Pathoplexus rows run the new `fetch pathoplexus`, and SRA rows run `fetch sra download --bundle`. Each Operations row shows the command's stages and a bar that does not step back, Copy CLI Command copies the command, and Cancel ends the row Cancelled with no alert and removes the command's staging folder. A genome downloaded from a genome row now carries the command's provenance record, which the in-process route did not write. A nucleotide bundle's one sequence is named with its version and a Pathoplexus bundle's with its INSDC accession and version. A restricted Pathoplexus record fails with `Record X is restricted and cannot be downloaded`. The reference that a VCF import downloads when no bundle is open runs `fetch genome --into-bundle` in the same way, and its GenBank fallback names the sequence as the VCF's CHROM with its title. The keys `DatabaseBrowserGenomeRowRoute`, `DatabaseBrowserNucleotideRowRoute`, `DatabaseBrowserPathoplexusRowRoute`, `DatabaseBrowserSRARowRoute` and `VariantOnlyReferenceDownloadRoute` keep the earlier routes. Under `--format json`, `fetch ncbi` and `fetch sra download` print events in place of their result documents.

**Demo Projects.** Help > Demo Projects… downloads by running `lungfish-cli demo fetch <id> --dest <folder>`, with `--force` for a replace. The byte bar moves, then the row shows Verifying, Unpacking and Installing. Cancel ends the row Cancelled with no alert and no folder left, and a replaced copy goes to the Trash only after the new one has verified. `demo fetch` on SIGTERM prints `Fetch cancelled`, exits with status 125 and leaves no hidden `.lge-demo-staging-` folder. This is the one moved route with no hidden key. `demo fetch --format json` prints events, and `demo info <id> --format json` prints the project record.

## Alignments, bundles and variants

**Inspector workflows.** In the Inspector's Analysis tab, Create Filtered Alignment and Convert Mapped Reads to Annotations always run `lungfish-cli bam filter` and `bam annotate`, and Mark Duplicates in Bundle Tracks and Create Deduplicated Bundle run `bundle mark-duplicates` and `bundle deduplicate-alignments` by default. The key `InspectorDuplicateWorkflowRoute` keeps the in-process task for the last two. These four commands, `bam filter`, `bam annotate`, `bundle mark-duplicates` and `bundle deduplicate-alignments`, print `CLIEvent` lines and one JSON document with the counts in `complete` under `--format json`, in place of their private shapes. Exit status 3 is a refusal, 64 a failure and 125 a cancel. The bundle record of a filter or an annotation is signed when a signing key is set.

**Consensus and tracks.** The new `lungfish-cli bam consensus` writes the viewer's consensus. Its `--region` is `contig:start-end`, 1-based and inclusive, a consensus that is N at every position exits with status 3 before anything is written unless `--allow-all-low-depth` is given, and a taken output exits with status 3. The new `lungfish-cli bam remove-track` removes a derived alignment track and its files after it writes the record of the removal, at `provenance/removals/<track>.lungfish-provenance.json` in the bundle, and it refuses a source alignment with exit status 3. A SIGTERM during either command ends it cancelled with exit status 125 and a record that says so.

**Extract reads.** With `--index`, `lungfish-cli extract reads --by-region` and `--by-id --bam` read the alignment through that index and publish one `.lungfishfastq` bundle at `--output` with its record. `--min-mapq`, `--exclude-flags` and `--read-group` choose the reads of a region. Under `--format json` the command prints `CLIEvent` lines on standard output and its text on standard error.

**Annotations and variants.** `sequence add-annotation` and `sequence attach-track` are new leaves and their `failed` events carry the refusal. The attach rows have a Cancel that works and a Copy CLI Command that names `--format json`, and the Add Annotation row shows a refusal when the bundle is busy. The new `variants delete <bundle> (--all | --variant-id <track-id>:<row-id> ...)` and `variants import-sample-metadata <bundle> <file> [--metadata-format csv|tsv]` run from the variant table's Delete Selected Variant…, Delete All Variants… and Import Metadata…. A Cancel on the import leaves the bundle as it was, within one chunk of the file's hash.

**Genotyping.** `genotype export-labkey` refuses a bundle in which two smart cohorts share a `cohort_id`, with exit status 3 and before any file or folder exists. The sentence ends `To export, keep one cohort of each id above and delete the others in Lungfish. A cohort you save again from its filter gets an id of its own.` `genotype list-cohorts` prints each cohort's id as a last column headed `id`.

## Tools and packs

**Update Tools, packs and databases.** Update Tools, the Plugin Manager's pack install and reinstall, and the database update run through `lungfish-cli` by default. The key `ManagedToolsRoute` keeps the in-process route for one release. `tools update --apply --yes --only <id>` and `conda install --pack <id> --reinstall` are new, `tools update --apply --format json` and `conda db update --format json` print `CLIEvent` lines, and `tools update --plan --format json` keeps the plan document. A pack whose smoke test fails now exits with status 126 where it exited 0. Each pack and database run writes a record under `provenance/packs` and `provenance/databases`. A cancelled run stops micromamba and the tools and rolls back, and a database that cannot be updated in place ends in a failure alert and a failed row. An Update Tools run with an empty selection runs `tools update --apply --yes --required-only --format json`, and its row reads Required updates. A failed or cancelled pack run records every requirement that did not finish, and every conda requirement of such a run, as not succeeded, with the run's failure text. The two broken lines of `tools update --help` are joined.

## Classifiers

**Words in rows and logs.** The build lines of a classifier row's View Log, which `lungfish-cli build-db` writes, now end `Built kraken2.sqlite with 14 rows.` where they ended `Built database at /…/kraken2.sqlite with 14 rows`, and one row reads `1 row.` The line `Cleanup complete. Freed Zero KB` is gone, and a cleanup that removed files reads `Removed intermediate files (1.2 MB).` A run on a virtual FASTQ shows `Writing the reads to a FASTQ file…` as its detail, overlay and log line, and `kraken2 classify` and `esviritu detect` print it in text mode. An EsViritu row of one virus in one family reads `1 virus detected in 1 family`. A Kraken2 run of one sample into a project shows `Building Kraken2 database…`, and an EsViritu run of one sample shows `Writing the EsViritu summary…`, where a `--batch` run keeps `Writing the EsViritu batch summary…`. `lungfish-cli esviritu detect` in text mode prints the log tail of a failed single run under `EsViritu log (last lines):`. A TaxTriage result summary reads `Ignored task failures: 1 across 1 sample`, and `lungfish-cli taxtriage check-prerequisites` prints `Nextflow: not installed` and `Container runtime: not available (<detail>)` where either is missing.

**Viewer index and Bracken.** A viewer index that cannot be built reads `The viewer index could not be built (<error>). LGE builds it when the result opens.` in the Operations log of every classifier run, without a doubled period. A Kraken2 run of one sample into a project now reads Completed with Warnings when its index fails, as a batch, an EsViritu run and a TaxTriage run already did. A Bracken profile that fails shows Bracken's last line in the row's detail and its warning, where it showed the whole traceback. The run's record keeps the same line as `profileMessage`, and the Bracken step keeps Bracken's whole standard error.

**A killed EsViritu run.** A run that exits with 137 reads `EsViritu was stopped before it finished, most likely because the Mac ran out of memory (exit code <n>). Deduplicate or subsample the reads, or run the sample on a Mac with more memory.`, with the tail of the standard error as the failure detail.

**Demultiplexed group bundles.** `kraken2 classify` and `conda classify` on a demultiplexed group bundle now refuse with exit status 3 and `Demultiplexed group bundles are container-only; select an individual demultiplexed FASTQ bundle for classification.`, before they look at the database, so an unknown or missing database no longer hides the refusal. They exited with status 64 before. An unreadable input still exits with status 64.

**Extract Reads on a link.** When the BAM of a classifier result is a link to a file outside the result folder, Extract Reads says that the BAM is a link to a file outside this result folder, that LGE extracts reads only from BAM files inside it, and to replace the link with a copy of the file, where it said the result might be corrupted. A missing BAM keeps the old words.

**No Project Open.** Choosing Tools > Classification > Kraken2…, EsViritu… or TaxTriage… with no project window open shows an app-modal alert titled No Project Open, with the text `Open or create a project before running Kraken2. LGE saves its results in the project's Analyses folder.`, one OK button, and writes nothing. A menu item for a classifier with no window only beeped before.

**The FASTQ operations dialog.** Launches of Kraken2 and EsViritu from the FASTQ operations dialog run `lungfish-cli kraken2 classify` and `esviritu detect` through the dialog's runner, with one Operations row for each. A run whose output a child process kept open shows the shared warning `The output of <label> is incomplete because a child process kept it open after <label> exited, so LGE stopped it.`

**Rows that run through `lungfish-cli`.** The bridge between a row and its command now holds the Operations bar and logs the command's progress once. The bar of a variant calling row no longer falls from 88 percent to 10 percent when the SQLite import starts, the expanded rows of alignment, tree, import and MSA action runs list the command's steps, a blank line from MAFFT no longer blanks the row's detail, and a classifier row lists `Building <Tool> database…`.

**TaxTriage on the command line.** `lungfish-cli taxtriage run` takes `--input` more than once. Each input is one sample or a folder of samples, named after its file or bundle behind `--sample`, and an input named twice runs once. `--negative-control <sample>` repeats and refuses a name that no sample has before any folder exists. A bundle whose sample role is negative control or extraction blank marks its sample, and the platform that a bundle records wins over `--platform`. A plain `--output` whose samples record different platforms is refused, and `--batch` runs each sample alone. The batch root of a `--project` or `--output --batch` run now holds `taxtriage-result.json`, with every sample in request order, and a failed sample is listed so that the batch reads Completed with Warnings. `build-db taxtriage` keeps `top/` and records its build on every completed result, so `--force` on a `--project` result completes and the record keeps naming the top report. The result of each completed `--project` sample shows in its bundle's Analyses section of the Inspector as TaxTriage Classification, with the sample's summary and no runtime. Samples named `S.1`, `S 1` and `S__1` run in the folders `S_1`, `S_1-2` and `S_1-3`. A plain `--output` run ends on `[100%] TaxTriage pipeline complete`, and a `--project` run keeps the engine's closing message on `[90%]` and ends on `[100%]`.

**TaxTriage in the app.** A sample that fails in a run of several samples no longer gets a completed TaxTriage entry in its source bundle's manifest. The app's route scales the runner's progress onto the first nine tenths of the bar, so a batch's bar keeps moving through its last sample. It reaches 90 percent when the engine stage ends, moves to 95 percent at `Building TaxTriage database…` and reaches 100 percent when the row completes.

## Viral Recon and Nextflow

**Annotation.** A Viral Recon run on a reference bundle that holds no GFF3 file exports the bundle's annotation database as a GFF3 file, passes it as `--gff`, and prints an information line that begins `Exported the annotation database`. A run on a freshly fetched reference now gets iVar's codon merges and SnpEff without a hand-placed GFF3. A reference bundle with no annotation gives `The reference bundle <name> has no annotation, so viralrecon runs without --gff. iVar merges no codons, and SnpEff and the variants long table are skipped.` The command prints that line with the warning label, and the app row sees an information event that leaves the row Completed. Every LGE GFF3 export now lists a parent before its children, so SnpEff names the spike gene S and not its CDS on a Viral Recon run of a fetched reference. The GenBank sidecar and a bundle merge write the same order, and no line changes besides the order.

**The row's label.** The Viral Recon row's final label now comes only from the warning events of the command, so a line on standard error no longer turns a completed run into Completed with Warnings. The command's progress lines are logged once.

**Docker and cancel.** A run whose Docker wait fails ends failed with exit status 65. `logs/stderr.log` holds `Docker Desktop is not running or daemon is unreachable. Start Docker Desktop and retry.`, and the command prints `Docker daemon unreachable. Nextflow pipelines (Viral Recon, TaxTriage) run through Docker Desktop; start Docker Desktop and retry.` A cancelled run reads cancelled with exit status 125 in the run bundle's manifest and provenance, which stayed running before, and `logs/stderr.log` holds `Workflow cancelled`. A cancel during the Docker wait or the read splitting is recorded in the same way. A record that cannot be written prints `Could not record the cancelled run: <reason>` on standard error.

**The pinned release and the logs.** The About window's credit for Viral Recon reads `Pinned 3.0.0 (395079f1d2)`. The pin in the managed tools lock is now the commit `395079f1d24dce731ac22e03d7a5e71f110103fc`, with the release version still 3.0.0. The manifest names `nextflowLogPath`, and a run from the app leaves five logs in its `logs` folder, `stdout.log`, `stderr.log`, `nextflow.log`, `lungfish-cli.stdout.log` and `lungfish-cli.stderr.log`.

**Records of a run.** A run that exported the annotation database records the exported GFF3 (path, digest, size and the role `input`) as an input of its first step and in the record's file list. Nextflow is launched with `AGENT`, `CLAUDECODE` and `NXF_AGENT_MODE` set to `false`, so a run from an agent shell records `nextflowVersion` and `resolvedCommit` as a run from the app does. `workflow run nf-core/viralrecon` prints the command that the engine got, and `--prepare-only` still prints the preview. The manifest of a Viral Recon or local workflow run bundle names Lungfish's version and build.

## Records and the Provenance tab

**Environment and termination.** The Provenance tab of a Kraken2, Bracken or EsViritu result recorded by this release shows an Environment row under Command in the disclosure of each tool step. It reads `Empty, with HOME, MAMBA_ROOT_PREFIX, PATH and TMPDIR set`, which names the variables that LGE sets for the tool and never their values, and an EsViritu step adds ESVIRITU_DB. A Termination row follows Exit Status and an Output row follows Wall Time only when the step ended in an unusual way, such as a Termination of `Cancelled (signal 15, SIGTERM)`. Output reads Incomplete when an output was cut short and Not recorded only for a step that ran and did not exit 0, and a step stopped by its idle limit reads `Timed out at its limit of <duration> without output`. A result recorded by an earlier release shows none of these rows. The Kraken2, Bracken and EsViritu steps of a record now carry an `observation` of their own launch, which holds how it ended, the stop, whether the output is complete, the environment with `MAMBA_ROOT_PREFIX` shown as `<tool-root>`, and the stage. A launch whose PATH does not end with the inherited one is recorded with `pathReplaced: true` and the whole PATH in `pathPrefix`, and older records read as not replaced.

**Step Tools.** Step Tools in the Run Summary reads the pipeline of a TaxTriage record as its release and the first 7 characters of its commit, such as `taxtriage v3.3.8 (e10bfeb)`, and a commit never reads with a `v` before it in the tab or in an export. Step Tools leaves out LGE's own helper steps, a copied command quotes a project folder whose name holds a space, and the status line's help shows only beside a Run Status row.

**Signing.** With `LUNGFISH_PROVENANCE_SIGNING_KEY` or `LUNGFISH_PROVENANCE_SIGNING_KEY_FILE` set, Map Reads onto a reference bundle keeps the signature of its analysis record, which the viewer publication used to remove. The records of a Reassemble's reference bundle, an attached annotation track, an annotation edit or deletion, a variant deletion, an imported variant sample metadata file, a removed alignment track, a consensus bundle, an extracted-reads bundle and a fetched NCBI, Pathoplexus or SRA bundle are now signed too.

**Other record changes.** `bam adopt-mapping` refuses a `mapping-provenance.json` that it cannot decode, before it attaches anything, with `Mapping result has a mapping-provenance.json that cannot be read as a mapping record at <path>`, and leaves the mapping result as it was. A grouped FASTQ operation's record names its run and steps `Lungfish Grouped FASTQ Operation`, and with a mixed FASTA and FASTQ group each step lists the files its own command made. Older records with the old label still read. A record without an embedded run lists each run output on the step that produced it, and the last step takes only the outputs that no step lists, so `lungfish-cli provenance` and script export stop crediting the last step with an earlier step's file. A sidebar rename, move, duplicate or copy of a plain folder in a project rebinds the provenance records inside it to the new paths. A FASTQ metadata sidecar (`<file>.lungfish-meta.json`) and every derived bundle manifest that holds FASTQ statistics write the quality histogram in ascending quality order in one flat shape, so two runs of the same input write the same bytes, and files written before still read. An EsViritu record files the read format that ran under `resolvedDefaults`, an explicit `--read-format` other than `auto` stays explicit, and Kraken2 and EsViritu write the read set plan once, under `resolvedDefaults`.

**Records of the database build.** In a Kraken2 classification record, the removal of the raw output depends on the index and gzip steps that read it and the sidecar step depends on the kraken2, index and gzip steps, and on a failure exit the record gains the removal steps that explain deleted halves. `build-db kraken2` keeps a sample folder whose classifier record names the raw output, the result sidecar or the old raw index, with one information line, and its own record names at run level only files on disk. `build-db esviritu` names the BAM and its index in `bams/` at run level with the digests of the files there. A cancelled or failed `build-db` core puts the earlier database back by rename, so a stop loses no database, and the markdup loop ends on a cancel in place of one warning for each BAM. A stderr kept in a record no longer starts with the tail of a line that a capture lost, and a captured stderr over 4 MiB loses its first, cut line.

**Processes.** BLAST's gzip stream and archive unzip and the FASTQ export's compressor run through the shared tool runner, so a cancel stops them and leaves no process behind.

## Command line help

Leaves whose output is plain text no longer list a `--format` option in their help, because the option did nothing there, and the leaves among them that read the thread count name the global `--threads` option. With `--format json`, `convert`, `translate` and `extract sequence` print the JSON result alone on standard output. `translate` and `extract sequence` refuse `--format json` without `-o`, with exit status 3 and the sentence `--format json prints the JSON result on standard output, so the FASTA needs a file. Add -o <file>, or leave out --format json to print the FASTA.`, because the FASTA needs a file. The commands that the app launches are unchanged, and nothing the app reads from standard output moved.

## Known issues

Known limit. A cancelled or failed EsViritu run keeps its working files, for example a partial BAM and the trimmed reads, in its folder under Analyses. They came to about 15 GB for a sample of 25 million reads. If the Operations Panel lists the stopped run when you next open the project, Remove Partial Output… on its row deletes the folder after a confirmation.

Known limit. A large sample rich in one virus can take an EsViritu run several hours, and the run has no time limit, so it goes on until it ends or you cancel it. The rising count in the log shows that it goes on, and Cancel in the Operations Panel stops it.

Known limit. The TaxTriage launch from the Tools > Classification menu still runs in the app, and Copy CLI Command on its row still copies a `lungfish-cli taxtriage` command whose `--output` is the app's own result folder, so running it writes into that folder again. Change `--output` to a new folder before you run it. A row for several samples offers no command. Release 2.11 moves this launch onto the command and changes the recorded command of a TaxTriage row.

Known limit. The record that the app writes for a TaxTriage sample still names `count/`, `fastp/` and `top/` files that LGE removes after the database build, so some names in it point at files that are gone. The record at the top of an app run of several samples also still files the classifier choice and the sample count as options you chose, and its sample steps carry no Nextflow version and no pipeline source. Release 2.11 moves the app's launch onto the shared record. The record of a `lungfish-cli taxtriage run` result keeps `top/`.

Known limit. The results folder of a Viral Recon run holds a copy of the run's record that LGE writes unsigned on purpose, and the signed record in the run bundle holds its digest. `lungfish-cli provenance verify` on the results folder ends with exit status 64 and prints `Workflow execution failed: Signature artifact is missing` with the path of the missing `.lungfish-provenance.json.signature.json`. It does not say that the copy is unsigned or name the bundle. `provenance verify` on the run bundle itself prints `Signature valid`.

Known limit. When Docker has to start, the Viral Recon row's detail reads `Docker daemon ready` for the rest of the run, because the command's start line carries no message that replaces it.

Known limit. A Viral Recon run with no trace gives a false failed-sample line from BCFtools, a reused results folder can hold an earlier run's files, and an ignored caller task names its sample in both of its lines.

Known limit. A cancelled attach of an annotation track that came through the import menu counts as a failed file in the import batch tracker, which shows Import Completed with Errors, as a cancelled configuration sheet does today.

Known limit. A demo download runs in a child process that writes to `~/Documents/LGE Demo Projects`, so a macOS privacy prompt for that folder would name `lungfish-cli` and not Lungfish.

Known limit. After a failure, `bam adopt-mapping` still deletes the moved BAM, and a second successful adopt overwrites the shared `alignments/mapped/mapping-provenance.json`, so the record of the first track goes stale. Deleting a bundle also leaves its `<bundle>.read-names.txt` file behind.

Known limit. A run with no signing key writes its record unsigned, on every route, so a record that stood signed and is merged by such a run no longer says that the history it carries was signed.

Known limit. A cancel that reaches a `lungfish-cli` command in the instant that it finishes no longer ends the command with a crash in place of its status, because the command waits up to 250 ms for the cancel's handler before it restores the earlier action. A SIGTERM that begins its delivery in the moment of that restore, after an earlier cancel went untaken for 250 ms, can still end the command by SIGBUS.
