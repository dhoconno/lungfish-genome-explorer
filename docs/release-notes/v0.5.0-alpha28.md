# Lungfish 0.5.0-alpha28

Previous release: v0.5.0-alpha27

## Summary

Alpha 28 fixes the FASTQ storage path used by MCM amplicon genotyping. Recent
projects could grow unexpectedly large because Lungfish wrote generated
sample-prefixed FASTQ files into the genotyping result bundle before mapping.
Those files repeated information that was already present in the imported
deduplicated FASTQ bundles, where duplicate support is encoded directly in read
headers as `size=N`.

This release keeps the deduplicated FASTQ representation as the durable payload
and streams any sample-prefixing needed for mapping directly into `minimap2`.
The generated sample-prefixed reads are now transient process input, not files
kept inside the `.lungfishgenotype` bundle.

## FASTQ Storage

Lungfish now treats counted FASTQ as the canonical representation for these
sample-split amplicon workflows. If a deduplicated record says `size=42`, that
single record is stored once and contributes 42 reads to downstream support
counts. Lungfish no longer persists a second expanded or sample-prefixed FASTQ
copy just so a downstream mapper or counter can see the same evidence.

The older ONT Fluidigm sample materialization path was also tightened to write
counted per-sample FASTQs with `size=N` headers instead of one physical record
per assigned read. This keeps the same policy across related sample-splitting
code paths: raw reads remain recoverable from the original input data, while
Lungfish stores compact, counted scientific payloads after collapse.

## Genotyping

Amplicon genotyping now feeds sample-prefixed reads to `minimap2` over standard
input. The mapper still sees sample-qualified read names, but the output bundle
does not retain `*.sample-prefixed.fastq` intermediates. Provenance records the
durable source FASTQ paths and marks the mapping transport as
`stdin-sample-prefixed-fastq`.

The retained-demux genotype and sample tables are expected to be unchanged for
existing data. The genotype support calculation reads the `size=N` token from
FASTQ/SAM query names and uses that value as the number of reads supporting a
genotype, rather than requiring physical duplicate records.

## Release Quality

The release adds focused coverage for weighted `size=N` counting, stdin mapping
without stored sample-prefixed FASTQs, counted Fluidigm sample materialization,
and byte-for-byte parity of the 32271 retained-demux genotype outputs in local
release verification.

This remains a prerelease build for alpha testers.
