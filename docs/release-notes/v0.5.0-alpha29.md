# Lungfish 0.5.0-alpha29

Previous release: v0.5.0-alpha28

## Summary

Alpha 29 fixes classification result browsing and project size growth in recent
TaxTriage runs, while carrying forward the zipped `.lge` import handling that
landed after alpha 28.

## Classification Browsing

MiniBAM read context menus now offer both FASTQ and FASTA copy actions. FASTQ
copy preserves the existing four-line read record with quality scores; FASTA
copy writes the selected read name and sequence only.

TaxTriage SQLite-backed batch results now validate their split-pane layout after
the result view is attached to a window. This fixes the empty initial viewport
that could appear until the Panel Layout preference was changed.

## Project Size

TaxTriage serial batch database builds now apply post-build cleanup inside each
sample result directory. Large pipeline intermediates such as per-sample
`get/assembly_summary_refseq.txt`, raw `count/` FASTQs, raw `fastp` FASTQs, and
other transient Nextflow directories are removed after the durable SQLite
database and retained reports are written.

This keeps new TaxTriage project bundles focused on the files Lungfish needs for
browsing, extraction, reports, and provenance instead of retaining duplicated
pipeline scratch data.

## Imports

The zipped Lungfish project import fix from the post-alpha28 mainline is included
in this release.

This remains a prerelease build for alpha testers.
