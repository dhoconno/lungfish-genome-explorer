## SRA downloads survive an incomplete ENA mirror

Bulk SRA downloads could fail for individual runs with a fastp error about an
invalid gzip header. The ENA portal advertised both mate files for those runs,
but the ENA HTTP mirror did not hold the second mate. The mirror answered that
path with a redirect and then an HTTP 200 directory listing, and Lungfish
staged the HTML page as the mate-2 FASTQ before handing the pair to fastp.

Every FASTQ file fetched from ENA is now checked before import. A body that is
an HTML page, that lacks the gzip signature under a `.gz` name, or whose size
differs from the size the ENA portal advertised is rejected. When the portal
advertised more files than the mirror served, the ENA download fails as a
whole instead of continuing with one mate.

Both download paths recover automatically. The command-line download falls
back to the SRA Toolkit through the existing prefetch and fasterq-dump path,
and the in-app bulk importer discards the partial pair and fetches the run
through the SRA Toolkit before running the import pipeline. The operation
detail names the run and explains that the ENA mirror is missing files.

Regression coverage reproduces the directory-listing response for a paired
run and verifies that the ENA download rejects it, leaves no partial files
behind, and triggers the toolkit fallback exactly once.
