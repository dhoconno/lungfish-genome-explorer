# Lungfish 0.5.0-beta24

Previous release: v0.5.0-beta23

This release brings two independent pieces of work together: results from multi-dataset
tool runs are now organized into a single tidy folder, and the minimap2 reference
viewer is fixed and considerably more capable. If you map or assemble across many
samples at once, or if you inspect mapped reads against a reference, this is a
worthwhile update.

## Multi-sample runs now produce one results folder, not a scatter

When you run a tool across several datasets at once, Lungfish now writes a single
`<tool>-batch-<timestamp>` folder under Analyses, with one clearly named result per
source bundle inside it, instead of scattering a separate timestamped folder for every
sample at the top level. This matches how classification batches have always been
organized, and it now applies everywhere a tool fans out over multiple inputs:
mapping, short-read assembly (SPAdes, MEGAHIT, SKESA), and the Savont clustering
workflow. The most visible symptom this fixes was short-read assembly of many samples
burying the Analyses list under dozens of sibling folders. The sidebar shows each
batch as a single expandable group, so a twenty-sample run is one row you can open
rather than twenty rows to scroll past. Runs that were never scattered in the first
place, and tools that only ever produce a single result, are unchanged.

## The minimap2 reference viewer loads again

Opening a minimap2 mapping result to view its reference sequence had stopped working:
every mapping bundle failed with a "not a safe bundle-relative path" error and showed
no reference at all. A security hardening added in an earlier release had begun
rejecting the reference symlink that mapping viewer bundles legitimately create to
point at their source reference, so the reference silently failed to load. Mapping
bundles open and display their reference again. The fix is deliberately narrow: the
viewer will only follow such a link into a reference bundle that lives in the same
project and matches the expected identity, so the protection against bundles that try
to reach files elsewhere on your disk stays fully in place.

## Clearer, more capable read inspection in the mapping viewer

With the reference loading again, a few related improvements come with it:

The reference selector and the reference track now show the reference bundle's name,
for example "SARS-CoV-2 (Wuhan-Hu-1)", instead of the raw internal contig identifier
like "NC_078297". The contig identifier is still shown alongside it and is still used
everywhere it matters for analysis, such as coordinates, region strings, and exported
file headers, so nothing about your data changes, only what is easier to read.

Aligned bases that match the reference are shown as dots again, so the mismatches you
actually care about stand out. This had quietly regressed: when the reference failed
to load, every base was drawn as a full letter with no way to tell agreement from
disagreement. Reference matching is now also more correct at the edges, handling
ambiguity codes and unknown bases in the reference sensibly rather than painting them
as false mismatches. When a BAM genuinely has no reference available, the viewer now
says so plainly instead of misleadingly showing everything as a mismatch.

You can now select one or more reads in the mapping viewer and act on them. Right-click
a selection to copy the reads as FASTA in their aligned orientation, or to extract the
original reads to a new FASTQ file. The two actions are labeled and described so it is
clear which one you are getting: the copy gives you exactly what is aligned (useful for
a quick BLAST), while the extract recovers the original sequenced reads. The same
extraction is available from the command line via `lungfish extract reads --by-id --bam`.
