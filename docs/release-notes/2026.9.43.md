# Lungfish 2026.9.43

Channel: Preview

Previous versioned release: v2026.9.42

Stable baseline: v2026.9.28

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release fixes four problems with classification results, found while the user manual's classification chapters were rebuilt around a sample from the Kraken 2 tutorial paper. If you checked a Kraken 2 result with BLAST, or read TaxTriage scores, in an earlier release, please read the first two sections.

## BLAST verification gives the right answer

- **BLAST checks of a Kraken 2 taxon on paired reads could report the wrong verdict.** LGE compared BLAST's organism names with the taxon's name only, so a species with a newer formal name, such as *Simplexvirus humanalpha1* for herpes simplex virus 1, was marked "Unsupported" even when every read matched it at 100%. Hits now count when their taxonomy ID falls inside the selected taxon, or when their name matches any member of it.
- **The reads sent to BLAST are now a fair random sample.** Before, the choice favoured reads near the start of the file and could send the same few reads every time.
- **For each pair of reads, LGE now sends the mate that carries the classification.** Before, it could send a low-quality first mate that matched nothing.
- The Operations panel and the BLAST Results drawer now report the same supporting and contradicting counts.
- `lungfish-cli blast verify` now reads compressed FASTQ files, takes `--seed`, and writes JSON with `--format json`.

## TaxTriage scores

- **TaxTriage results showed a TASS score of 0 for every organism.** The current TaxTriage version writes its scores to a new report file that LGE did not read. LGE now reads it, and a result made with an earlier LGE is rebuilt with the real scores the first time you open it. On the command line, `lungfish-cli build-db taxtriage <result folder> --force` does the same.

## Kraken 2 results

- **A Kraken 2 result reopened from the sidebar showed Bracken's species estimates in place of Kraken 2's own report.** The reopened table could lose rows, such as strains below species, and its percentages did not use all reads. A reopened result now shows the same tree and numbers as right after the run, with Bracken's estimates in their own column. Older results are rebuilt the first time you open them.
- The Sample column and the sample filter show the sample's name instead of a file name such as `classification.bracken`.
- Reopening a result no longer replaces the record of how the classification was run. Where an earlier release had already replaced it, LGE rebuilds the record from the result's saved settings and marks it as rebuilt.
- The Inspector shows the database, tool versions and settings of a reopened single-sample result.
- Reads extracted from a paired sample are now recorded as pairs, so later tools treat them as pairs.

## User manual

- The online manual shows its screenshots and illustrations again. They had been missing from the web version since the images moved to a separate store.
- The Kraken 2 chapter now works through a real sample from the Kraken 2 tutorial paper (Lu et al. 2022, Nature Protocols): a human corneal infection with herpes simplex virus 1, classified against the Viral and Standard-16 databases.

## Dependency versions

Dependency set 2026.2 and all managed tool, optional pack, pipeline, database, and bootstrap pins are unchanged from v2026.9.42.
