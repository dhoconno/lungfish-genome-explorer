# Lungfish 0.5.0-beta16

Previous release: v0.5.0-beta15

## Class II and partial-amplicon MHC genotyping

This release substantially improves how Lungfish interprets class II data when
the sequenced amplicon covers only part of a longer genomic reference. Valid
DRB names that use the established `W` nomenclature are now accepted as named
alleles. Lungfish also keeps high-quality incomplete observations in the
genotype review workflow instead of dropping them merely because exon 1,
intron 1, or another terminal reference region was not sequenced.

Zero-SNP matches across the complete observed amplicon are now reported as
**partial extensions** when the candidate and genomic reference do not share
the same ends. These rows use `_partial_ext` labels so they remain distinct
from ordinary `_ext` cDNA extensions and from provisional `_nov` sequences.
The relationship is determined only from the bases that were actually
observed: missing reference sequence is not imputed, and internal
substitutions, insertions, deletions, or skipped reference segments prevent a
zero-SNP partial-extension classification.

GenBank and EMBL candidate records explain which terminal reference regions
were not covered. Novel class II candidates continue to be compared over the
region shared with the closest reference, allowing a genuine internal SNP to
remain visible even when the assay cannot establish a full-length IPD allele.
Candidate canonicalization also preserves the raw source identities and
reconciles identical published sequences without duplicating their read
support.

## Complete candidate evidence in the genotype matrix

Partial extensions and provisional novel sequences now flow through the same
matrix, workbook, FASTA, GenBank, and EMBL presentation paths as other MHC
candidates. Their support remains associated with the originating samples,
and the candidate schema records the classification rules and reconciliation
counts in reproducibility provenance.

The schema-5 bundle loader now understands that a genomic partial extension
can name the compatible reference without requiring cDNA-extension evidence.
Previously, valid schema-5 candidate JSON could be rejected as malformed,
causing the app to show only conventional named calls. Existing affected
bundles do not need to be regenerated; reopening them with this release loads
their candidate rows.

Candidate-only full-length MHC analyses also open directly in the native
genotype matrix rather than falling back to an Excel preview. This keeps
provisional calls, read support, annotations, comments, sequence details, and
manual review tools available even when no conventional named genotype was
called.

## Faster navigation and focused matrix review

The project sidebar now preserves its scroll position and selection during
filesystem refreshes instead of jumping back toward the top while files and
analyses are being added. In the genotype matrix, selecting an allele row now
offers a contextual action to show only samples with read support for that
allele. The action uses the same visibility model as the Inspector, so it can
be reset without altering genotype calls.

## More flexible read import

Unmapped BAM files can now be used as Oxford Nanopore read inputs. Lungfish
converts the BAM records to a temporary compressed FASTQ and then uses the same
import and processing recipes as ordinary ONT FASTQ data. Provenance retains
the original BAM identity, conversion command and tool versions, resolved
options, checksums, sizes, final stored payload, elapsed time, and exit status;
temporary conversion files are cleaned up after success or failure.

PacBio-barcode demultiplexing now resolves repeated sample names before the
expensive import begins. Unique names remain unchanged, while every occurrence
of a repeated name receives a deterministic `_1`, `_2`, `_3`, and subsequent
suffix in sample-sheet order. Conflicting generated names and
case-insensitive filesystem collisions are rejected immediately.

## Verification and compatibility

The release adds regression coverage for partial DRB naming and ranking,
partial-extension classification and exports, candidate canonicalization,
schema-5 loading, sidebar refresh behavior, selected-row sample filtering,
candidate-only viewport routing, BAM conversion provenance, and duplicate
sample-name handling. Existing full-length class I behavior, conventional
cDNA extensions, genotype-only review, workbook projection, and legacy bundle
loading remain supported.

## Notes

This remains a beta prerelease. It is distributed as a signed and notarized
Apple Silicon DMG and through the Sparkle beta update feed.
