# Lungfish 2026.11.13

Channel: Preview

Previous versioned release: v2026.11.12

Stable baseline: v2026.11.7

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview opens RNA-seq results in their own viewer. A result of bulk or single-cell RNA-seq counts now opens from the sidebar, and the Import Center, the Tools menu and `lungfish-cli` gain the steps that make one. It also fixes faults of Demultiplex Barcodes with Cutadapt that put reads in the wrong sample, left a sample empty or gave a sample reads that matched by chance. It closes the known issue of 2026.11.12 about older results from a custom list of dual indexes. It also closes two more faults of Demultiplex Barcodes with a Custom Definition of dual indexes, one at 5' End or 3' End and one at Both Ends. Older results that these faults touched now show a warning.

## What works differently

- **A Custom Definition of dual indexes is searched only at the read ends.** At Both Ends with no sample sheet, a read now needs both barcodes of a pair, one at each end, so a read that carries no barcode almost never lands in a sample by chance, and the run no longer needs Keep Unchecked Samples. If your barcodes sit some bases in from the ends, as they do inside a longer adapter, set 5' Distance and 3' Distance in Demultiplex Barcodes to that many bases (`--max-distance-5prime` and `--max-distance-3prime` on the command line), or trim the adapter from the reads first. The same two distances serve both strands, so if the two sides differ, use the longer one for both. A setup that needs more than 6,000 Cutadapt search lines, such as 96 pairs with both distances at 5, is refused in words that say so. Results of this kind made by Preview 2026.11.11 or an earlier version now show a warning in the Inspector.
- **Demultiplex Barcodes reads the secondary sequence of a Custom Definition the way your reads carry it.** At Both Ends with no sample sheet, a Custom Definition of dual indexes may list each secondary sequence as it appears at the end of the read or as the i5 primer's barcode. The run checks the first 10,000 reads, uses the form they carry, and the Operations Panel says which. Before, it looked for each secondary sequence only as written, so when a definition listed the i5 primer's barcodes and two rows had first barcodes that matched and secondary sequences that were reverse complements of each other, each within the error rate, those two samples could get each other's reads with no warning. If the reads fit both forms, or some rows carry one form and others the other, the run now stops before it makes any sample file and names the rows. Older results that may hold such swapped samples show a warning that says what to do.
- **Demultiplex Barcodes stops a Custom Definition of dual indexes at 5' End or 3' End.** Before, it left one barcode of each pair free to match anywhere in the read, so reads from the reverse strand stayed in Unassigned and sample files could hold reads that matched by chance, enough in an amplicon pool to fill a sample. The run now stops before it makes any sample file and says why. Choose Both Ends (`--location bothends` on the command line), and if your barcodes sit some bases in from the read ends, set 5' Distance and 3' Distance to that many bases (`--max-distance-5prime` and `--max-distance-3prime`). Older results made at 5' End or 3' End show a warning that says what to do.
- **Demultiplex Barcodes with the engine Cutadapt checks each read it placed when 5' Distance or 3' Distance is above 0.** Before, a read could land in the wrong sample with no warning, because another sample's barcode sat a few bases further in and outscored the right one. This held for TruSeq Single Index Set A and B, TruSeq HT Dual Index, Nextera XT Index Kit v2 and a Custom Definition. The run now keeps a read in a sample only when that sample's barcode fits it better than any other sample's, both within your distances and up to 4 bases past them. A read that two or more samples fit equally well, or that another sample fits as well or better just past your distance, goes to Unassigned. The Operations Panel, the Log and the command line say how many reads that was and what to try, and the counts still add up. Runs with both distances at 0 are not checked this way and do not change.
- **Demultiplex Barcodes keeps every sample of a large run.** Before, a sample whose output file grew past about 200 KB compressed could come out empty, the run still ended without an error, and the counts showed only the reads it kept. This could happen on single-end reads with TruSeq HT Dual Index, Nextera XT Index Kit v2, or a Custom Definition made on one of them or on IDT for Illumina UD Indexes, at any distance, and with a single-index kit when 5' Distance or 3' Distance is above 0. The run now writes such outputs uncompressed and compresses them at the end, so it needs free disk space for the uncompressed reads and takes a little longer. Older results of these two changes, made from version 2026.8.1 up to Preview 2026.11.12, show a warning that says to run them again.

## What's new

- **RNA-seq results open in their own viewer.** Select an RNA-seq result, a folder that ends in `.lungfishrnaseq`, in the sidebar. It opens with its name, modality, origin, route and sample count, then the bulk or the single-cell view. Neither view counts anything itself or edits a file of the result.
- **The bulk view** has a tab for each count table, then Quality and Correlation. A count reads as `counts/genes.counts.tsv` prints it, with each gene's name, biotype and not-host flag beside it and Not recorded where the result has none, and the search box keeps the genes whose id or name holds your text. Quality and Correlation show the numbers of `lungfish-cli rnaseq quality`.
- **The single-cell view** shows the cell summary that the import wrote (each sample's cells, features and entries, and the tool and its version), the quality table, a plot of the cells ranked by UMIs, histograms of UMIs, genes and not-host UMIs per cell, and a table of the cells with each cell's not-host counts and flag. The flag reads viral RNA above ambient or bacterial RNA above ambient, as the import wrote it, and no cell is called infected.

Four more changes make an RNA-seq result or read its quality numbers.

- **Import Center cards for counts.** RNA-seq Counts imports salmon quant folders, or one count table of genes by samples, as one RNA-seq result. Single-cell Counts imports Cell Ranger outs folders or STARsolo run folders as one single-cell result. Each opens a sheet that asks for what the import needs, such as the unit of a count table, a sample sheet and a reference set, and says what is wrong with your inputs before it offers Import. A refusal shows in the command's own words on the Operations row and in the sheet, and a cancel leaves no result.
- **Plan sheets for a Linux machine, and a card for their result.** RNA-seq Plan for a Linux Machine and Single-cell Plan for a Linux Machine write the plan folder that a Linux machine runs. A sheet counts nothing and submits nothing, so copy the folder to the machine yourself, and Check runs every check without writing a folder. A barcode list that you choose is checked by SHA-256 and recorded as supplied by you, and the introns preset is never called a match for Cell Ranger 7. RNA-seq Linux Run Result adopts a plan or batch folder that came back, after you copy the files in each sample's `result/` folder into that sample's folder, next to `plan.json`. It checks all of it before it writes anything, refuses a folder that the introns preset returned, needs an open project that can be written, and selects the adopted result in the sidebar.
- **Three RNA-seq tools in the Tools menu.** Quantify RNA-seq Reads… makes one result for the FASTQ bundles you choose, from a reference set, and needs the rna-seq pack that holds salmon. Export RNA-seq Counts… writes the counts with R scripts for DESeq2, edgeR, limma voom and dream. Pseudobulk RNA-seq Cells… sums the cells of a single-cell result by label into a bulk result and leaves out groups of fewer than 10 cells and cells with no label. Each runs its `lungfish-cli rnaseq` command, and its Operations row records that command.
- **`lungfish-cli rnaseq quality` prints the quality numbers of a bulk result.** It checks each file against the sha256 in the manifest and writes nothing. `--table samples` gives each sample's library size, mapping rate, library type, rRNA share and not-host share, and `--table correlation` gives Pearson r of log2(CPM + 1) between samples. `--format` takes text, json and tsv.

## Things to know

- **Two rows of a Custom Definition that read alike both ways.** At Both Ends with no sample sheet, Demultiplex Barcodes cannot tell which sample a read belongs to when every row that has reads in the file is in a pair of rows with first barcodes that match and secondary sequences that are reverse complements of each other, each within the error rate. The run then stops before it makes any sample file and names the rows. If one row of a pair is not in your pool, remove it from the definition and run again.
- **Barcodes that sit in from the read ends.** With 5' Distance and 3' Distance at 0, the default, Demultiplex Barcodes with the engine Cutadapt looks for each barcode only at the very start or end of a read. A barcode that sits a few bases further in is out of reach. The read's first or last bases can then happen to match another sample's barcode, and the read goes to that sample with no warning. If your barcodes sit some bases in from the read ends, set 5' Distance and 3' Distance to that many bases and no more.
- **A result that 2026.11.12 made from a custom list of dual indexes with Keep Unchecked Samples shows no warning.** Check its samples against your sample sheet.
- **The RNA-seq viewer is new.** The Inspector's Document tab has no RNA-seq block yet. The rank plot leaves out the barcodes outside the cells, since the result keeps no list of them, and the globin share reads Not recorded, since no rule names the globin genes yet. Quantify RNA-seq Reads… shows no progress bar and has no name field, so each result carries the name `RNA-seq counts`.

The limits in the 2026.11.8, 2026.11.9, 2026.11.10, 2026.11.11 and 2026.11.12 notes still apply, except the known issues about a Custom Definition of dual indexes, which this version closes.
