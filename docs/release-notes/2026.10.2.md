# Lungfish 2026.10.2

Channel: Preview

Previous versioned release: v2026.10.1

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release sends paired reads to every tool as pairs, infers the sequencing platform at import, and fixes several defects that read the wrong reads or trimmed too much. Some results change because the reads that reach a tool are now the right ones. The sections below say where.

## Read pairs

- **Unmerged pairs reach each tool as pairs.** A bundle that holds merged reads beside unmerged pairs used to send every read to a tool as single-end. Each tool now gets its pairs as pairs and its merged or single reads beside them, in the same run where the tool allows it.
- **Kraken2 classifies pairs as pairs.** Merged reads are classified beside the pairs in the same run. Counts are now fragments, so a pair counts once and a merged read counts once. The totals of a paired bundle therefore halve. Results made before this release are labelled as counted per read. `lungfish-cli conda classify` gains `--unpaired` for a separate file of single reads, plain or gzip.
- **Mapping keeps mates paired.** minimap2, BWA-MEM2, Bowtie2 and BBMap map the unmerged pairs of a mixed bundle as pairs, so proper-pair flags and mapping qualities now reflect the mates.
- **Assembly uses each read in its role.** SPAdes, MEGAHIT and SKESA take pairs as pairs and merged reads as merged reads. Flye runs in its PacBio HiFi or CLR mode for PacBio reads instead of its nanopore mode.
- **EsViritu, TaxTriage, Viral Recon and genotyping read every read of a bundle.** TaxTriage paired merged reads with R1 and dropped R2, and paired two ONT chunks while dropping the rest.

## Reads that were wrong

- **Primer removal no longer cuts the read after the primer.** The bbduk primer trim removed the 5′ primer and everything after it, so every read that started with a primer was lost. Mates now stay together.
- **A demultiplexed virtual bundle is genotyped from all its reads.** It was genotyped from its 1,000-read preview. The FASTQ Operations dialog also genotypes a paired bundle as one sample named for the bundle, not as an R1 sample and an R2 sample, so sample names in its reports change.
- **Read extraction and BLAST checks of a Kraken2 result read both mates and the merged reads.** Reads whose names end in `/1` or `/2` are found.
- **An ONT barcode bundle of several files is genotyped as one sample** from the FASTQ Operations dialog, with its files joined in order.

## Pairs that were lost

- **A virtual subset of a merged or deinterleaved bundle reads the merged reads,** not the raw mates of the import, and a large merged bundle is never paired by position.
- **Deduplicate keeps the pairs of a mixed file whole.**
- **A paired BAM sorted by position imports as pairs.** Its mates are grouped by read name first, where they imported as single reads.
- **An operation output that keeps only the unmerged pairs of a merged bundle stays paired.** The Inspector shows it as interleaved, where it showed single-end, and every tool runs it and the outputs of later operations on it as pairs.
- **Filter by Read Length and Correct Sequencing Errors keep the mates of a mixed file together.** The length filter judged each record alone and left some pairs with one mate, and error correction wrote its reads out of order.

## Operations that failed

- **Demultiplex Barcodes from the FASTQ Operations dialog writes its barcode bundles again.** Since 2026.9.53 every such run stopped before writing any, because its staged input sat in the output folder.
- **SRA searches and downloads continue when ENA is unavailable.** A search shows the run from NCBI, the download uses the SRA Toolkit, and an archive's error page no longer fills the message.
- **An SRA download keeps the reads whose mate is missing.** ENA serves some paired runs as three files, the third holding spots with one read. The window imported only the pair, and `lungfish-cli import fastq` skipped the third file. Both now import the three files as one bundle, the pairs as pairs and the third file's reads as unpaired reads. A run like this imported with a recipe stops with a message, because a recipe reads only pairs or only single reads.

## Sequencing platform

- **The platform is inferred at import and shown with its evidence.** Nanopore reads with SAM tags, PacBio Revio and Sequel IIe, Element and MGI reads imported as Illumina when no platform was given. Reads that cannot be identified are recorded as unknown, never as Illumina.
- **The platform only chooses defaults.** Mapping and assembly run on any read type. A setting that does not suit the reads gives a warning instead of a refusal, and settings you choose are always used. `lungfish-cli map` and `assemble` choose their default preset and assembler from the read type.
- **`lungfish-cli fastq platform` shows, checks and corrects a bundle's platform label.** The Inspector offers the same correction for a bundle whose label disagrees with its reads.

## Recorded commands

- No Operations panel row shows a command that would not reproduce its run. A row whose operation has no `lungfish-cli` command yet shows none.
- A FASTQ Operations dialog row shows the command that ran, with its real output path, once the run finishes.
- `lungfish-cli blast verify --source` can be repeated and accepts a bundle.

## Under the hood

The read pairing every tool follows and the rule that every operation records a command that reproduces it are now written contracts, checked before each push. The FASTQ dataset view's in-app derivative path, which release builds could not reach, is deleted.

## Dependency versions

Dependency set 2026.2 and all managed tool, optional pack, pipeline, database, and bootstrap versions are unchanged from v2026.10.1.
