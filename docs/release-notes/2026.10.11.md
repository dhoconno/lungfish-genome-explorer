# Lungfish 2026.10.11

Channel: Preview

Previous versioned release: v2026.10.10

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release fixes crashes while drawing sequence letters under heavy load, stops some annotation edits from being undone by a clock change, and makes new Preview releases much faster to cut.

## Coordinate ruler crash

Under heavy load the app could crash while drawing the coordinate ruler above a sequence, for example while many other programs kept the Mac busy. macOS sometimes returned no font for the ruler's monospaced labels, because the ruler created those fonts on every redraw and released them again. The ruler now creates its fonts once and keeps them, and it falls back to the system's fixed-pitch font, with a log entry, if the monospaced font cannot be found.

## Crashes while drawing sequence letters

The same font lookup could fail in other views that draw monospaced letters. These include the read track's insertion labels, the translation track's amino acids, the mini pileup, base letters on loaded sequences, the multiple sequence alignment's consensus and residue rows, the error correction preview, the search and demultiplex previews, and the known-allele overview's nucleotide strip. Each of these views now keeps its fonts instead of creating them on every redraw.

## Annotation edits and provenance timing

Deleting or editing an annotation could fail and roll back a change that had succeeded, when the Mac's clock stepped back by a few milliseconds during the edit. Every operation that records its start, end or duration in provenance now measures the run on a steady clock, so a recorded end never comes before its start and a recorded wall time is never negative.

## For contributors

- `docs/contracts/VERIFICATION-ORDER.md` sets the order of verification in a session and which evidence carries forward, so no check runs twice on the same code.
- A passing unit-tier run covers its own commit and any later commit that changes only documentation listed as release-neutral, such as release notes. The pre-push hook and `release.py package` reuse it, from any worktree of the repository. `python3 scripts/release/gate_evidence.py unit-evidence --root . --commit HEAD` says whether evidence covers a commit.
- `release.py package` compiles the candidate while its gates run, runs the unit tier itself when no evidence covers the commit, refuses code whose newest unit-tier run failed, pins the commit before compiling, and writes the receipt only after every gate passed. When the build fails or the run is interrupted, it stops each gate's whole process tree, including `swift test`.
- The release notes file now declares the version. Packaging stamps the newest `docs/release-notes/<version>.md` into the app after compiling, so a release changes no Swift source, project setting or managed-tools lock, and the Release build reuses its compiler cache.
- `python3 scripts/release/prune-release-cache.py` lists stale release compiler caches and removes them only with `--apply`. It keeps two namespaces by default, one per channel.
