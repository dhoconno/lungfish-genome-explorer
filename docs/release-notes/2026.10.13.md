# Lungfish 2026.10.13

Channel: Preview

Previous versioned release: v2026.10.12

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release changes genotyping results and exports, and it shows live progress for more commands in the Operations Panel. Full-length calls now take their locus from the reference record, so their percents of locus change and older full-length exports are not comparable. A cluster tied between references counts once in its locus total, a genotype row with zero reads no longer counts toward a haplotype call, duplicate rows collapse to one, and zeros that a reviewable row catalog lists can be reviewed in the matrix. The command-line CSV, TSV and LabKey exports now carry analyst overrides, and the haplotype band and the Inspector say more in plain words. The Plugin Manager also shows experimental packs as soon as you turn them on. Provenance records now keep the end of a long error log and the read-pairing plan of Kraken2 runs started in the app, more copies keep a cancelled status, and selecting an older EsViritu batch or TaxTriage result no longer writes a rebuilt record into the project.

## Genotyping results

**Calling rules.** The calling rules move from version 3 to version 5, so the app recomputes a saved deterministic analysis from older rules when its bundle opens. A saved AI or manual revision keeps its calls. A revision saved on a full-length result before this release was made while every accession call read 100 percent of its locus, so review it again. Calls change only where a tie, a zero-read row or a duplicate row was involved, and full-length calls can also change through the new loci and the dropout thresholds below.

**Tied references.** In full-length results, a cluster that matches two references equally gives each reference its own call with the full cluster reads. Calls of one animal at one locus that name each other as tied in the `ambiguous_with` column and carry the same reads now count once in the locus total, the sample total and the evidence pane. Each tied call keeps its full reads, and allele percents at that locus rise to their true values. In a test with a 1,000-read cluster tied between two MHC-A references and a 15-read allele, the locus total is 1,015 reads and not 2,015, so the 15-read allele reads 1.48 percent and passes a 1 percent locus threshold. Each tied reference then reads 98.5 percent of the locus, so the percents of a locus with a tie can add up to more than 100.

Known limit. When haplotypes are matched, each tied reference still counts as its own observed allele, so a tie between diagnostic alleles of two haplotypes can still read as both haplotypes.

**Zero-read rows.** A genotype row with zero reads no longer counts toward a haplotype call, although the matrix still shows the zero for review. In a test, an animal whose MHC-A call was `M2A` from a single zero-read row now reads `ERR: NO HAP`. A locus where no animal in the run has a single read now reads `Not assayed` for every animal.

**Duplicate rows.** Two rows of the long summary for one animal, locus and allele can come only from an edited or combined table, because the pipelines write one row per animal and reference. The app now keeps the row with the most passed unique reads, then the most alignments, then the first in the file, and it never adds rows together. In every bundle type, a warning in the Inspector's Genotype Display section counts the rows it collapsed and asks you to check the sample sheet and the long summary. Before, the matrix cell showed the row with the most reads, the cell shading and the detail pane used the first row, and the Samples and Total Reads columns and the locus total added both.

**Catalog zeros.** A run's reviewable row catalog records some cells as zero reads. In real bundles those zeros never reached the matrix, so "Mark False Negative" stayed disabled on them. They now reach the matrix, also where a reference's sequence ID is an accession, and "Mark False Negative" works on them, as the workbook already allowed. A false negative imported with the command line is drawn, and the workbook lists each allele once.

**Catalog-only animals.** Where a catalog names an animal that no sample row names, the animal now appears as a matrix column. The prevalence filter then keeps the same rows in the window and in the workbook's Filtered sheet, and "Export to Excel" works with the default columns. Bundles from current pipelines do not name such an animal.

## Full-length genotyping

**Gene loci.** A full-length call whose reference is named by an IPD accession, such as `NHP01270`, carries that accession as its genotype. The app read the accession as a locus of its own, so every such call read 100 percent of its locus and every accession became its own locus column. A check on a real full-length bundle with 96 libraries and 471 reference accessions showed both. Each call now takes its locus from its reference record. The record's allele name, cut at the first `*`, names the gene group, and the record's gene is the fallback.

A1 to A6 pool as MHC-A, and AG1 to AG6 pool as MHC-AG. B with its pseudogenes, and B11L, B16, B17 and B22, pool as MHC-B. I, J, G, E, F and K stay apart. Known and candidate reads now share one total at each locus, and the evidence that AI refinement reads uses the same loci. Percents of locus divide by the whole gene group and typically fall between 5 and 50 percent, so older full-length exports are not comparable. The new loci do not change MiSeq calls.

A call whose record names no allele or gene keeps its old locus, and a warning says that each such call is its own locus with a percent of locus of 100. A result with no reference records at all gets a warning that asks you to run the genotyping again. A record whose allele and gene name different loci uses the allele and shows a warning. A new run publishes its reference record store, with its provenance step, before its own haplotype analysis, so the run never works on per-reference loci.

Known limit. The locus rule removes only the Mafa, Mamu and Mane species prefixes, so a record named for another species keeps its prefix. An allele that begins `Mafu-A1`, a Japanese macaque name, gets the locus `MHC-MAFU-A1` and does not pool with the other A genes as MHC-A.

**Older analyst edits.** Matrix reviews, comments and styles saved at an old per-reference locus now show, clear and change at the gene locus, and clearing one also removes the entry saved at the old locus. Call overrides, and the highlights, comments and status flags of haplotype call cells, saved at an old locus no longer apply, because one old slot cannot be mapped to one slot at the gene locus. They stay in the annotations file as saved, and the Inspector counts them in a warning.

**Dropout thresholds.** A full-length run applies haplotype dropout thresholds, but until now it did not record them in its stats file. The app then recomputed calls with no thresholds, and the command line used a fallback of 50 reads and 1 percent of the locus that no run chose, so one bundle could show three sets of calls. A new run now records its four threshold values, as the barcode pipeline does. A bundle that never recorded them takes them from the command that made it, and a run whose command carried no threshold flag used no dropout filter, so its recomputed calls use none. The fallback is gone, and the app, the command-line exports and the Excel export now show one set of calls.

**Candidate reads in a run's own totals.** A new full-length run now counts candidate-cluster reads in the locus total of its own haplotype analysis, as the app and the command line already did when they re-read a bundle. Before, a known allele near the locus percent threshold could be kept by the run and dropped by the app. A bundle written before this release keeps its own workbook.

**Failed candidate files.** When a full-length bundle declares candidate files and any of them fails validation, the app loads none of them, so locus percents and haplotype calls count known alleles only and can differ from the run's own workbook. The app now says so. The Inspector's candidate warning leads with a sentence about it, and the four `genotype` export commands (`export`, `export-xlsx`, `export-pivot-xlsx` and `export-labkey`) print that sentence once on standard error. The Percent basis row of the workbook's Export Metadata sheet states the known-alleles-only basis. A workbook for any other bundle keeps its earlier text.

## Genotype exports

**CSV, TSV and LabKey.** `lungfish-cli genotype export` in CSV or TSV form without `--view-projection`, and `genotype export-labkey`, now carry analyst overrides and manual haplotype assignments, as the Excel workbook does. Before, the CSV and TSV tables took their H1 and H2 columns from the active haplotype analysis without the analyst's overrides or manual assignments, so one command reported different haplotype calls depending on the file format. The LabKey `haplotype_calls.csv` took the latest override of each slot whatever analysis it came from, and it never read manual assignments. Both exports now take their calls from the same resolution as the workbook's Haplotype Calls sheet. In the LabKey file, `called_haplotype` is the Effective H1 or H2 value, `is_override` is true when the analyst chose it, and an override saved against an earlier analysis of a MiSeq result no longer replaces the pipeline call.

**Full-length CSV and TSV.** A full-length result with no haplotype analysis now exports every allele under its gene locus, in `<locus> allele 1`, `<locus> allele 2` columns ordered from the most reads to the fewest. Other results keep the H1 and H2 columns. On the same real bundle, the table went from one pair of H1 and H2 columns for each of 471 accessions to 43 allele columns over six gene groups, and its 1,810 cells match the 1,810 unique calls. The Exporting Genotypes chapter of the user manual describes the columns.

In the Excel workbook:

- Only a single haplotype name gets a colour. Ambiguous calls such as `M1A|M2A`, the unresolved mark `?`, `Not assayed` and error calls such as `ERR: NO HAP` are plain, where they were filled like named haplotypes.
- The filter context prints its three percent thresholds, the global minimum, the matrix minimum and the prevalence, exactly as applied. A minimum of 0.125 used to print as 0.1 there, while the Export Metadata rows said 0.125.
- An Excel export whose haplotype analysis names an animal that no sample row or call lists is refused before the save panel opens, and the Inspector says so in a plain sentence. Current pipelines never write such a bundle, and a hand-edited one used to get an extra column.

## The haplotype band and Inspector

**Haplotype band.** The expanded band drew an ambiguous call, a locus with no haplotype and a locus that the assay did not cover all as a dash, so three different states read as nothing called. An ambiguous call now shows its tokens the way the workbook writes them, for example `M4|M7 • M1`. A locus whose two slots both carry `No haplotype` or `Not assayed` says so in words, like the existing `Too many haplotypes` and `Too many genotypes`. When an analyst overrides one slot, the band shows the override beside the pipeline's own value for the other slot, for example `B9 • ERR: TMG`. A dash now means only that a slot has no value.

In the Inspector:

- A tied call shows a "Shares reads with" row in the Selected Item details, naming the other references that share its reads, so a tie no longer reads as a heterozygote.
- A full-length call whose reads carry inserted or deleted bases shows a "Review flag" row. It gives the number of bases and asks you to check the alignment before relying on the call. The Running Amplicon MHC Genotyping chapter of the user manual describes it.
- Warnings read as plain sentences. A candidate warning used to begin with its raw code, such as `candidate-artifact-missing`. Every warning line now gives the warning's detail and the file it names, with the code as help text.
- An Excel export that would not match the matrix is refused with one plain sentence that asks you to report it. An export started while annotations are still saving says to wait for the save and export again.
- Reload in the manual and effective haplotype editors now redraws the changed cells, recomputes calls when a review changed, refreshes the review menus and tells the Inspector. Before, these stayed out of date until the next click.

## Live progress in the Operations Panel

Twelve more `lungfish-cli` commands that the app runs showed no progress in the Operations Panel until they exited, because the command held its event lines in a buffer on a pipe. Each now flushes every event line. The commands are:

- `bam primer-trim` and `variants call`
- `tree infer iqtree`, `tree reroot` and `tree extract-subtree`
- `fastq platform`
- `msa annotate add`, `msa annotate project`, `msa export`, `msa extract`, `msa distance` and `msa discriminating-sites`

In a test of `tree infer iqtree` on five SARS-CoV-2 genomes with 1,000 bootstraps, all eight events used to arrive together when the command exited. The start and the first three progress events now arrive at 2 seconds, and the other four arrive when IQ-TREE ends, 79 seconds later.

`workflow run` has the same fix. The app runs it for Viral Recon, and "Preparing workflow", the "Read pairing" lines, "Created run bundle" and the progress of the interleaved split, which can take minutes, reached the panel together when the command exited. They now appear as they are printed. In a test that splits 500,000 pairs, "Preparing workflow" appeared at 0.09 seconds and the "Read pairing" line after the split at 6.0 seconds, where every line used to arrive at the end, 8.3 seconds in. `workflow run-headless` and `workflow` without a subcommand share the change.

## Experimental packs in the Plugin Manager

The Plugin Manager is one window that loaded its pack list only when it opened or when you changed tab. Turning on "Show Experimental Features" in Settings therefore left GATK Core, Variant Phasing and Wastewater Surveillance hidden until you switched tab or relaunched. The window now reloads its pack list when the setting changes, and turning the setting off hides those packs again.

## Provenance records

A provenance record is the file that says how a result was made, so that you can check it and run it again. This release keeps more of what happened in each new record, and the operations that still wrote the older record shape now write the standard one.

**Cancelled runs.** A record now stores its run status itself, so a cancelled run stays cancelled in the record that Lungfish Genome Explorer (LGE) writes for each of the run's outputs and in the copy LGE makes when you copy a result in the sidebar, import one from another project or import a FASTQ operation's output. Before, such a copy of a Kraken2 run cancelled while Bracken was being prepared could read as completed, because its last finished step had exited normally. Records rebuilt by FASTQ ingestion and batch or copy import, annotation import, mapping viewer publication, duplicate marking and the lineage export can still lose the status until a later release, and a cancelled `lungfish-cli conda classify` run still records failed. The Provenance tab does not show a run's status yet.

**Long error logs.** When a tool writes a long log to its error stream, the record now keeps the first 2,048 and the last 8,192 characters, with a line reading `... [truncated] ...` where the middle was left out. Tools print their version at either end of the log and their errors and summaries last, and the record used to keep only the first 10,240 characters. The Provenance tab shows this text in a step's stderr row under Lineage. Steps of a FASTQ processing recipe, human read scrubbing, and EsViritu, Kraken2 and TaxTriage batch records still keep only the start of the log until a later release.

**Kraken2 read pairing.** The read-pairing plan of a Kraken2 run started in the app, which counts the fragments sent to Kraken2 as pairs and the reads sent as single reads and gives the reason, now sits in the record's options whenever the run did more than send plain pairs or plain single reads. The Provenance tab shows it under Invocation & Options. A `lungfish-cli conda classify` record gains it in a later release.

**Fewer record shapes.** New records no longer carry a nested `legacyWorkflowRun` block. Variant calling, phasing, sample extraction and queries, Freyja, GATK, SRA downloads and imports, BAM adoption, conda lock files and offline packs, project migration and container export wrote the older shape and now write the standard record that most operations write. Records already in your projects read as before, and new records keep the top-level keys, such as `status`, that earlier LGE versions and scripts read.

**Reading provenance no longer writes.** Selecting an older EsViritu batch or TaxTriage result no longer changes the project, and exporting its provenance writes only the export you save. Before, selecting an older EsViritu batch or TaxTriage result could save a record rebuilt at that moment, naming the app version that read it rather than the one that ran it, and could rewrite a real TaxTriage record with an extra step and without its signature. An older EsViritu batch or TaxTriage result without a record of its own now shows Missing provenance.

Correction of 2026-10-10. These notes first said that selecting any result no longer changes the project. The GUI walk of this release found three writes that opening, selecting or viewing still makes, all older than this release. Opening a project rewrites its search index record, `.universal-search.db.lungfish-provenance.json`. The first selection of a haplotyped genotype result adds the four built-in smart cohorts to its `annotations.json` and writes a record and a lock file for that, and switching between Haplotype Calls and Genotype Matrix saves the choice in the same file with a new record. Viewing a reference bundle saves the viewer's place in a hidden `.viewstate.json` inside the bundle, which no checksum covers. No genotype call or workbook changes. On a genotype result annotated with `lungfish-cli genotype apply-annotations`, though, the cohort write replaces that command's record of `annotations.json` and leaves three more of its records with a checksum that no longer matches the file. The next release keeps the built-in cohorts in memory until the first real edit, and the search index and view switch writes are scheduled for a later release.

**Raw JSON.** The Raw JSON block of the Provenance tab now shows the record file's own text, and its Copy button copies that text. It used to show LGE's reading of the record written out again, which could differ from the file. The block shows only the start of a long record, so use its Copy button to see all of it.

- `LungfishGenotypeUI` moved 65 secondary types into files named for them. `GenotypeResultViewController.swift` fell from 11,934 to 11,338 lines, and the new `GenotypeResultDisplaySectionViewModel.swift` is 1,277 lines with a baseline entry.
- The Excel export now lives in `GenotypeViewportExportCoordinator`, which reads its controller through an `unowned` reference. New export logic belongs there, and every escaping closure on its path must capture the coordinator weakly. `Sources/LungfishGenotypeUI/AGENTS.md` records the rule and the anchors for Phase 4a.
- The GUI's CSV and TSV export path had no caller since the Excel export became the only GUI export, so it is deleted. `lungfish-cli genotype export` still writes CSV and TSV, and `--view-projection` still replays commands recorded earlier.
- The shared genotype rules live in LungfishIO, so the matrix, the Excel builder and the command line agree. They are `GenotypeLocusDenominator`, `GenotypeCatalogMatrixIdentity`, `GenotypeMatrixBaseProjection.logicalSampleRoster`, `ONTGenotypeCall.uniqueOccurrences` and `GenotypeMatrixTargetLocusAlias`.
- A command that the app streams into the Operations Panel writes each event line with `printEventLine` in `Sources/LungfishCLI/Output/CLIOutput.swift`, because `print` buffers on a pipe, and the CLI module guide says so. `workflow run` line-buffers its standard output once at its start instead. `RunSubcommand.engineFailureReason` and the Plugin Manager's pack observer and offline pack guidance moved into extension files, which keeps `RunSubcommand.swift` and `PluginManagerViewModel.swift` under their file-size baselines.

Testing and documentation:
