# Lungfish 2026.10.14

Channel: Preview

Previous versioned release: v2026.10.13

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release changes what a provenance record holds and how a record becomes a script, and it carries the fixes that the GUI walk of 2026.10.13 led to. Lungfish Genome Explorer (LGE) now writes records as schema version 2, which every 2026 release can still read, and it records the real versions of BBMap, bwa-mem2, vsearch, GATK, primalscheme3, EsViritu and Bracken where it recorded an error message, a citation number, another program's version or a shortened one. A shell, Python, Nextflow or Snakemake export now asks before the save panel when LGE cannot pin a step's tool version, runs each `lungfish-cli` step once and names exact conda builds. Opening a project, selecting a genotype result and viewing a FASTQ bundle or a reference no longer write into the project, switching genotype views no longer touches `annotations.json`, and a record that LGE rewrites survives a crash or an interrupted write on an ExFAT drive. In genotyping, a deleted built-in smart cohort stays deleted, the active cohort is marked, a click in the matrix or in Haplotype Calls takes the keyboard focus, and the first haplotype assignment save on a result with no saved annotations works. Kraken2 gains `lungfish-cli kraken2 classify`, and project search now finds Kraken2 results.

## Provenance records

**Schema version 2.** LGE writes every new record as schema version 2. Version 1 wrote 14 facts twice, under the main key and under an older name that early readers expected, and version 2 keeps only the main key. A script that reads records now needs `workflowName` for `name`, `options.explicit` for `parameters`, a step's `exitStatus` for `exitCode` and a file's `checksumSHA256` for `sha256`, and the `status` key stays. Paths are written with plain slashes, as in `@/Analyses/run`. A new record holds no process ID, names LGE's own program by its file name, such as `<external>/lungfish-cli`, where it named the install path, and holds the SHA-256 of the tool lock in force as `managedToolLockSHA256` beside the dependency set. A step can now name the step it ran under, the managed tool it ran and where its version came from. The File Formats appendix of the user manual shows a version 2 record.

**Earlier releases.** Every LGE release from 0.4.0-alpha.14 on, every 2026 release among them, reads a version 2 record with all of its facts and ignores the new fields, though it fills in its own process ID where the record holds none. The `lungfish-cli ops stats` of those releases counts no version 2 record, so on a project with records from this release it reports fewer completed runs and less total wall time than this release does. In this release `ops stats` reads each record through the reader the Provenance tab uses, so it also counts genotype result records, which it skipped before because their steps hold no start date. Records signed by earlier releases still verify.

**Run status, a correction.** The 2026.10.13 notes said that a record stores its run status. That holds for the records LGE writes through its standard record writer. The records of alignment (`.lungfishmsa`) and tree (`.lungfishtree`) bundles and the receipt of an Excel export come from older writers, and they store no status until a later release.

**Error logs.** Steps of a FASTQ processing recipe, human read scrubbing, and the EsViritu, Kraken2 and TaxTriage batch records now keep the first 2,048 and the last 8,192 characters of a long error log, as other records have since 2026.10.13, so a failed run keeps the error that tools print last. LGE also no longer shortens a log stored in a FASTQ dataset's metadata file when it reads that file and saves it again.

**12S reference bundles.** `fastq 12s-reference-bundle`, which Create 12S Reference runs, wrote a record for the bundle's metadata table inside the bundle and then a record of that record. The bundle now holds one record, which lists the table with its checksum, and a record file is never listed as an output.

**File options.** A file option recorded with a placeholder, such as `<workspace>/reads.fastq`, now reads, shows and exports as recorded. LGE used to put its working folder in front of it, so a Full Provenance (JSON) export wrote a path that never existed.

## Tool versions in records

Several tools recorded a version that was wrong in a way a reader of the record could not see. Each now records the version that ran.

| Tool | Where it is recorded | Before | Now |
|---|---|---|---|
| BBMap | Read mapping | micromamba's error line, naming the home folder, and an environment `bbmap` that does not exist | `40.02` in standard and PacBio mode, and the environment `bbtools` that it runs in |
| bwa-mem2 | Read mapping | `ERROR: unknown command '--version'` | `2.3`, read from its installed package |
| vsearch | Orient Reads | `10.7717` from its citation DOI, or zlib's `1.2.12` | `2.31.0` |
| GATK | GATK commands | `4.6.2` | `4.6.2.0` |
| primalscheme3 | Primer scheme design | `3.3.0` | `3.3.0+lge.5` |
| EsViritu | EsViritu runs | `3.14`, the Python version in its install path | `1.3.3` |
| Bracken | Kraken2 runs with a Bracken profile | `3.0.1` from its banner, or `1.0.0` or `unknown` | `3.1`, as the database install records it, marked as a source build |

With LGE's storage on a volume named `LGE 2.0`, the BBTools tools and EsViritu recorded `2.0`, and they now record their own versions. A tool that rejects the version check, such as bedGraphToBigWig or `medaka_variant`, now records no version where it recorded its error message.

**Where a version comes from.** FASTQ import steps, the pysam and minimap2 steps of ONT genotyping runs and Bracken steps now say whether LGE asked the tool for its version, took the version from the tool lock because the tool could not be asked, or built the tool from source. Mapping records of minimap2, bwa-mem2 and Bowtie2 now name the lock's exact package, such as `bioconda::minimap2=2.31=h6bd33b9_0`, where they named none, and eight plugin pack tools, iVar, LoFreq and Freyja among them, name the lock's package with its build. The `##source` line of a VCF that iVar calls now names `bioconda::ivar=1.4.4=hda5e58c_0` where it named `ivar`.

Known limit. A storage folder on a volume whose name has three words with a number in the middle, such as `Lab 2.0 Disk`, can still be read as a tool's version until a later release.

## The Provenance tab

**Loose files.** Selecting a loose file with a record beside it, such as a GFF3 with the record that `lungfish-cli` wrote next to it, showed "No provenance required" on the first selection, a defect present since 2026.9.9. The tab now shows the record on the first selection.

**Older record format.** A record in an older shape, a bare run or one of the shapes that early commands wrote, now says so. The tab labels it Older record format, where it read Complete or Incomplete before, and still shows every fact it holds. A fact that its shape never recorded, such as the exit status of the earliest records, reads Not recorded and no longer makes the record Incomplete. A fact the shape could hold and lacks still makes it Incomplete, with an Older record format warning after the gaps.

**Not recorded.** When a record lacked a fact such as its app version, operating system or dependency set, the tab used to fill it in from the Mac reading the record, so an old record could show the reading app's version. Such a fact now reads Not recorded, and so do a date the reader had to invent, a missing wall time or exit status, and a missing workflow version. The record that lineage builds for a reference bundle without one of its own takes no facts from the reading Mac either.

**Raw JSON.** The Raw JSON block cut a long record at 80 lines with no sign. It now says what it shows, for example "Showing the first 80 of 1,050 lines. Copy takes the whole record.", and it says the same of a record cut at 20,000 characters. A record past the display limits of 500 file rows or 200 paths in a step left the block empty with a message that no JSON was available. It now reads "This record is too large to show here. Choose Export > Full Provenance (JSON)… to save all of it." beside a Reveal in Finder button. When the block shows LGE's reading of a record instead of the file's own text, it says "Shows the decoded record, not the file.", and a file that begins with a UTF-8 byte order mark shows as its own text. Long lines now wrap at the block's width, where their ends were cut off. The Inspector's spinners also draw at the small size.

Known limit. Alignment and tree bundles still write their record in an older shape, so the tab shows Older record format for an alignment or tree made by this release, where 2026.10.13 showed Complete, and that record is never exported as a script. Methods Section and Full Provenance (JSON) still export it. The receipt of an Excel export is in the same shape. All three change in a later release.

## Exporting provenance

**The selected item.** File > Export > Provenance exported the record of the last document the viewer had loaded when the selected item, such as a README.md, showed only as a preview, so it could offer a GFF3's record for a README. It now exports the record of the item selected in the sidebar, or of the bundle in the viewer that contains it, and says "No Provenance Available" for a selected item without a record.

**Unpinned tools.** A shell, Python, Nextflow or Snakemake export promises that someone else can rebuild the tools a run used. Before the save panel opens, LGE now checks each step the script would run against its tool lock, the list of exact tool versions LGE installs. A step is unpinned when the version that ran is not in the lock, when no usable version was recorded, when LGE builds the tool from source, as it builds Bracken 3.1, or installs it in its own Python setup, as it does primalscheme3, or when a tool in a pipe ran in an environment the script does not write.

A sheet such as "Export a Nextflow pipeline with unpinned tools?" then names each such tool, its step and the reason in plain words, for example "Version 1.21 ran, but LGE installs version 1.24." Cancel is the default, so Return exports nothing, and Export Anyway… goes on to the save panel. The export then names each unpinned step in the script's header, beside the step and in the export's own record. Methods Section and Full Provenance (JSON) never show the sheet. A Kraken2 run with a Bracken profile always shows it, and no demo project needs it. On the command line, `lungfish-cli provenance export` refuses such a script with exit status 3, names each step and its reason and writes nothing, unless you add `--allow-unpinned`. The Exporting as Nextflow or Snakemake chapter of the user manual describes the sheet.

**Older record format.** A record in the Older record format is never exported as a script or pipeline, with or without the override, because LGE fills in facts that such records leave out, and neither is a record whose chain of earlier records includes one. LGE says so in an alert with only OK, and Methods Section and Full Provenance (JSON) still export such a record. The records of the two variant tracks in the Human Mapping and Variants (with results) demo are in that format, and so are the records of alignment and tree bundles, as the known limit under The Provenance tab says.

**Each command once.** A record of a `lungfish-cli` import lists the tools the import ran, such as clumpify, seqkit, bgzip and samtools, beside the import's own step. An exported script ran the import and then those tools again, some on a staging folder that no longer existed, so `run.sh` stopped at its second step. New records name the step each tool ran under, records from earlier releases are read through the staging folder they name, and a script now runs the `lungfish-cli` step once and lists the tools it ran as comments with their versions. Across the ten demo projects, 123 of 144 import records exported two or three commands before and export one now. A script also no longer lists an import's scratch files as inputs, and a Geneious or application export import made by this release exports its import once.

**Exact packages.** An export's environment files now name the lock's channel, package, version and build, such as `bioconda::minimap2=2.31=h6bd33b9_0`, when the version that ran is the lock's, and the recorded version without a build when it is not. An export never writes a version other than the one that ran. A plugin pack tool is named by its conda package, so the `phasing` environment exports `whatshap` and `gatk-core` exports `gatk4`, and when two steps ran different versions in one environment, each gets its own file, such as `envs/<name>_2.yaml`. The headers of `run.sh` and `reproduce.py`, `nextflow.config` and `config.yaml` say that the build part of a spec names the macOS arm64 build in the lock, which another platform can drop while keeping the version, and `run.sh` names the `lge-` environment to activate for each command.

**FASTQ metadata files.** Exporting the provenance of a FASTQ bundle's `<reads>.lungfish-meta.json` now uses the import record that lists the file. Before, the file was read as a record of its own, and the script made from it stopped with "Replay unavailable".

## Opening and viewing a project

Selecting, opening and viewing no longer change a result or a record in a project. Only hidden caches at the project root, such as the search index, still change, and no checksum covers them. The 2026.10.13 notes listed the writes that the GUI walk found, and this release removes them and two more.

**Genotype results.** The first selection of a haplotyped genotype result added the four built-in smart cohorts, Incomplete haplotypes, Needs review, Homozygous and Recombinants, to its `annotations.json` and wrote a record and a lock file for them. On a result annotated with `lungfish-cli genotype apply-annotations`, that write replaced the command's record of the file and left three more of its records with a checksum that no longer matched. The cohorts now show from memory and are saved with the first edit that saves the annotations, such as a note, a review status or a saved cohort. `genotype list-cohorts` and `genotype export-labkey` read the file, so they list the built-in cohorts only after that edit. The record of an Excel export now says that its annotations come from the window, and whether the bundle holds no `annotations.json`, the same file or a different one.

**Genotype view.** Switching between Haplotype Calls and Genotype Matrix saved the choice in `annotations.json` with an audit entry and a new record. The choice and the other view settings now live in a hidden `.genotype-viewstate.json` inside the result bundle, outside every checksum and record, written only when you change the view. A choice that an earlier release saved in `annotations.json` becomes the starting view. The locus order, the candidate row display, the thresholds and the haplotype definition set stay in `annotations.json` with a record, because they decide what an Excel export holds.

**Search index.** Opening a project rebuilt its search index and wrote a record, `.universal-search.db.lungfish-provenance.json`, beside it, and every update rewrote the record. The index is a cache, so LGE now writes no record for it. `lungfish-cli universal-search` still writes one when it builds or rebuilds the index.

**FASTQ bundles.** Viewing a FASTQ dataset with no saved statistics rewrote its `<reads>.lungfish-meta.json`, which the record of every demo FASTQ bundle covers with a checksum, so each view left that checksum out of date. LGE now keeps those statistics in memory for the session. Showing a FASTQ bundle in the Inspector no longer rewrites its `analyses-manifest.json` when an analysis it lists has been deleted. A Quality Report still rewrites the metadata file, with no record, until a later release.

**Reference bundles.** Viewing a reference bundle saved the viewer's place in the hidden `.viewstate.json` inside it whenever you left the bundle. LGE now writes the file only after you change the view.

## Genotyping

**Smart cohorts.** A built-in smart cohort that you delete now stays deleted. LGE records the deletion in `annotations.json`, and the record of the first save of the built-in cohorts names them. Restore Built-In Cohorts, below Save Current Filter… in the Inspector's Smart Cohorts section, brings back every missing built-in cohort in one recorded edit, and it is dimmed when none is missing. The active cohort now has a checkmark in that list and a `Cohort:` pill with its name in the filter bar, and a second click on the cohort or a click on the pill clears it. The pill had not reached the window since June 2026.

**Keyboard focus.** A click on a genotype matrix cell or a haplotype call selected it but left the keyboard focus in the sidebar, so the items of Selection > Genotype Call and Selection > Genotype Sample stayed dimmed, their shortcuts did nothing and the arrow keys moved through the sidebar. A click now gives the matrix or Haplotype Calls the focus, so Mark False Positive (⌥⌘P), Clear Review (⌥⌘R), Mark Sample Reviewed (⌘R) with its Undo, and Sample Detail… (⇧⌘O) work from the keyboard. Release 2026.10.11 had the same defect.

**Saving haplotype assignments.** On a genotype result with no saved annotations, the first Save Assignments in the manual haplotype editor had failed since July 2026, and so had Save in the alert that Export to Excel raises. LGE now saves the annotations shown in the window first, and the edit then goes through. A failed save now shows its message, with Retry and Reload, right under Save Assignments, and the detail pane brings it into view. The message used to sit below the visible part of the editor, so the draft stayed Unsaved with no word. When Save in the Export to Excel alert fails, the Inspector says under Export to Excel "Haplotype assignments were not saved. Use Retry or Reload in the editor, then export again." VoiceOver now announces a failed save in the MiSeq haplotype editor too, and LGE logs each failed save with the sample and the reason.

## Classification and search

**Kraken2 classify.** Kraken2 now has its own command, `lungfish-cli kraken2 classify`, which takes the same flags and runs the same code as `lungfish-cli conda classify`, the older spelling. A run started in the app still shows and records `conda classify` until a later release, and a run started as `kraken2 classify` records that spelling. The Running Kraken 2 chapter and the CLI reference now lead with the new spelling. The help for `--preset`, `--bracken-read-length` and `--bracken-threshold` now states each default once.

**Project search.** The sidebar search field never found a Kraken2 result that the app made, because the index knew result folders named `classification-…` and the app names a Kraken2 run's folder `kraken2-` and its date. Such folders are now indexed, and `type:kraken2` finds them, as do the words that worked before, such as `type:classification`. NAO-MGS and NVD results gain words of their own, such as `type:nao-mgs` and `type:nvd`, a renamed NAO-MGS or NVD bundle stays searchable, and a sample folder inside a Kraken2 batch is now a result of its own.

**CZ-ID batches.** Selecting a CZ-ID batch folder in the sidebar left the open viewer in place. It now clears the viewer with `Unsupported analysis: cz-id. Inspect or reveal <folder> from the sidebar.`, the message that an analysis without a viewer shows, and the Provenance tab follows that folder.

## The Operations Panel

**12S runs.** A clean 12S Amplicon Matching run or 12S reference build read Completed with Warnings, because the command printed its last line, the path it wrote, on its error stream, and the app reads any such line that is not progress as a warning. The five `fastq 12s-` commands now print that line on standard output, so a clean run reads Completed, and a real warning still reads Completed with Warnings.

**Error stream text.** For the runs that the app starts through `lungfish-cli` and follows event by event, such as tree inference, alignment actions, primer trimming and variant calling, plain text that the command prints on its error stream now appears in the row's log as information, where the row did not show it before. In those runs such text never marks a run Completed with Warnings. Only a warning that the command reports as an event does.

**Annotation projection warnings.** `msa annotate project`, which the app runs to project an annotation onto other rows, counted its warnings without reporting them, so the panel could not show that gaps split a projection into pieces. It now reports each warning, and the row reads Completed with Warnings. `msa annotate add` and `msa annotate edit` do the same.

**Variant calling and imports.** Variant calling, MAFFT alignment and the four imports of alignments, trees, Geneious exports and application exports now write the shared event format of the other `lungfish-cli` commands, and the app reads them through the same path. Their rows keep their labels and import the same files, and the summary lines of an import now appear in its row's log.

## Interrupted writes and external drives

**Rewriting a record.** When LGE rewrote or signed a provenance record, it moved the old record aside before the new one was in place and flushed nothing to the disk, so a crash or a pulled drive could leave the record's name empty. It now writes the new file beside the old one, flushes it to the disk, swaps the two in one step and flushes the folder, so the name always holds the whole old record or the whole new one. Bundle manifests, analysis metadata, mapping records, the receipt of LGE's installed tools and a genotype result's `annotations.json` with its record are written the same way.

**ExFAT drives.** Most external SSDs come formatted as ExFAT, where macOS cannot swap two files in one step, so an interrupted write there can leave a record's name empty with the old record beside it under another name. Opening the project now puts the newest such copy back, and the Provenance tab no longer shows another record from the same folder in its place. The receipt of LGE's installed tools is put back the same way when LGE reads it, so an interrupted write no longer makes LGE build a new receipt without its database and pipeline entries.

**Offline installs into a linked conda folder.** `lungfish-cli conda offline-install` now completes when LGE's conda folder reaches its real place through a link, such as storage moved to an external drive and linked back. Before, it installed and checked the environments, failed to write its record and removed the verified install again.

## Command line

**Import warnings and failures.** Without `--format json`, `import msa`, `import tree`, `import geneious` and `import application-export` printed no warning and gave no message when an import failed, only an exit status. They now print each warning as a `Warning:` line and a failure as an `Error:` line on standard error, and `--quiet` drops the warnings and keeps the failure.

**Event lines.** Every event line that a command prints under `--format json` now carries `"schemaVersion": 2`. A program that reads these lines should ignore an event name or key it does not know, as the app does, and `docs/formats/cli-events.md` describes the format. Five `msa` commands (`annotate edit`, `annotate delete`, `consensus`, `mask columns` and `trim columns`) and two `tree` commands (`export subtree` and `relabel`) now flush each event line, so a program that reads them through a pipe sees progress as it happens. `fastq platform --format json` now ends in one failed line when it fails after it starts.

## Help

The Getting Started and Settings pages of the in-app Help now name the bundle kinds LGE makes, such as `.lungfishref` reference bundles and `.lungfishfastq` read bundles, where they named a `.lungfishbundle` that LGE never creates. Getting Started now opens a project with File > Open Project Folder… (⌘O).

## For contributors

This release also carries Phase 2.5, which shipped no Preview of its own. `docs/plans/2026-10-10-phase-2-5.md`, `docs/plans/2026-10-10-phase-2-6.md` and `docs/reports/2026-10-10-gui-walk-preview-2026.10.13.md` record the lanes, the expert panels' rulings and the walk.

Tool identity:

- `AnalysisToolID` and `ManagedToolID` in `Sources/LungfishIO/Analysis/ToolIdentity.swift` keep the two id spaces apart. `AnalysisToolRegistry` describes 23 analysis kinds, with `buildDatabaseToken` and `outputStem`, and `ManagedToolVersionProbe` holds one probe for each of the 44 lock ids.
- The conformance suite runs through the probe table and fails on a missing probe executable, and `~/.lungfish` probes 44 of 44. `ManagedToolLock.bundledIdentity` is the SHA-256 of the lock file's own bytes, which new records carry.
- `scripts/ratchets/tool-identity.sh` counts analysis-id decisions (114), `tool(named:)` lookups (0) and unknown-version fallbacks (35), and each count may only fall. `AnalysesMigration`, which had no production caller, is deleted.
- `ProbeVersionText` holds the rules that the two Workflow version parsers share, and `VersionParserOutputPinTests` pins every tool the parsers probe in production on real output, with four known defects left for 2.7.

Provenance and durability:

- `DurableReplace` in Core stages a file as `.<name>.lungfish-stage-<UUID>` on the anchored folder, syncs it, swaps it in through the folder descriptor, syncs the folder and issues one `F_FULLFSYNC` per transaction. `NoFollowFileSystem` moved to Core with a `package` typealias in IO, and `ProvenanceWriter.swift` fell from 1,741 to 1,647 lines.
- A fault matrix runs every step of a write through the swap seam on APFS, on a real ExFAT image and under the simulation, and `exfat-tests.sh` runs every class named for durability under `--simulate`. `docs/contracts/EXTERNAL-VOLUMES.md` gives the rules.
- `docs/formats/provenance.md` gives the version 2 format and the reader rules, and `findProvenanceReading(for:)` returns a record with the shape that decoded it. About 20 rebuild sites now copy a step with `ProvenanceStep.with`, as `docs/contracts/RECORDING-PROVENANCE.md` requires, and `ProvenanceStderr` now lives in Core.
- `ProvenanceExportPinGate` and `ProvenanceExportPinGatePresenter` gate the four script formats in the CLI and the app, and `ProvenanceExportPlan.pinned` writes the specs. Of the 100 steps in the golden records, 34 are unpinned, and the CLI and the app refuse the same 20 restored golden records.
- One recapture changed 43 golden files and added 2 help files, and a checker compared each changed file key by key with the lanes' predictions, with every scientific payload byte-identical. The version 2 encoder accounts for 37 files and 3,245 keys. A new normalize rule masks the lock hash only where it equals the checkout's lock.

### CLI events, bundle kinds and documentation

- `CLIEventLine` decodes every event line with its `schemaVersion` and typed artifacts and leaves the `CLIEvent` enum unchanged, and `docs/formats/cli-events.md` holds the wire format and the version rule. `CLIEventLegacyNames` reads the private names of older CLIs in one dated table.
- `CLIEventContractTable` names what each of the 237 leaf commands writes for a machine reader, with 27 that emit events and 14 that print one of 10 older shapes, and its test fails on a leaf without a row.
- `BundleKindID` and `BundleKindRegistry` describe the 15 folder kinds, a parity freeze pins what eleven kind tables answer, and six of those tables now read the registry. The registry declares each kind's app state files, such as `.genotype-viewstate.json`, which no record covers.
- `docs/formats` gains specs for the bundle kinds, the reference bundle, the FASTQ bundle and the `Analyses/` layout, and `features.yaml` gains entries for the Provenance tab, the Operations Panel and smart cohorts, with its Kraken2 entry leading with `kraken2 classify`.

## Dependency versions

Dependency set 2026.2 and all managed tool, optional pack, pipeline, database, and bootstrap versions are unchanged from v2026.10.13. Bracken now records 3.1, the source build that LGE installs over the locked 1.0.0 package, and the lock still pins 1.0.0.
