# Lungfish 2026.10.20

Channel: Preview

Previous versioned release: v2026.10.19

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release moves more of Lungfish Genome Explorer (LGE) onto `lungfish-cli` on top of Preview 2026.10.19, so that the row of a run in the Operations Panel records the command that ran and Copy CLI Command copies it. Sequence export of FASTA, GenBank and FASTQ files and of reference bundles, region extraction from a reference bundle, reference import, the merge of reference bundles and GATK variant calling, which 2026.10.18 listed as running inside the app, now run the matching `lungfish-cli` command, and the row of each records that command. The TaxTriage launch, which 2026.10.18 also listed, now runs `lungfish-cli taxtriage run --project` from Tools > Classification > TaxTriage… in the same way. The release also lets Locate reopen a project that you renamed in Finder while it was open, shows No Project Open for downloads and imports that have no project, keeps the records of a renamed, moved or copied result true, and changes the words of several rows and records.

Ten hidden keys that kept an earlier route for one release are gone, and a value that you wrote with `defaults write` for any of them has no effect. They are `DatabaseBrowserGenomeRowRoute`, `DatabaseBrowserNucleotideRowRoute`, `DatabaseBrowserPathoplexusRowRoute`, `DatabaseBrowserSRARowRoute`, `InspectorDuplicateWorkflowRoute`, `ManagedToolsRoute`, `VariantOnlyReferenceDownloadRoute`, `ReadsLaunchRoute.assembly`, `ReadsLaunchRoute.ontImport` and `ReadsLaunchRoute.mapping`. Three hidden keys are new, each keeps an earlier route for one release, and a later release deletes them. They are `TaxTriageLaunchRoute`, `GATKVariantCallingRoute` and `BlastReadActionRoute`. Set one with `defaults write com.lungfish.browser.preview <key> legacy`, where `com.lungfish.browser.preview` is the identifier of this Preview, and delete it with `defaults delete com.lungfish.browser.preview <key>`.

The owner check list under Checks still to run blocks a Stable promotion until a walk with a person at the Mac has covered every row. This release removes the key steps from the rows that set the ten keys, keeps the other checks of those rows, and adds rows for the new behavior.

## Reads and downloads

**Map Reads, Reassemble and the ONT import.** The hidden keys `ReadsLaunchRoute.mapping`, `ReadsLaunchRoute.assembly` and `ReadsLaunchRoute.ontImport` are gone, and a value that you wrote with `defaults write` for any of them has no effect. Map Reads (Tools > Mapping) runs `lungfish-cli map`, Reassemble runs `lungfish-cli assemble`, and the ONT import runs `lungfish-cli fastq import-ont --format json`, as they did by default. The command that a Map Reads row records replays to the same bundle, and the row, the BAM and the record match the reference files that the tests keep.

**Database Browser downloads.** The hidden keys `DatabaseBrowserGenomeRowRoute`, `DatabaseBrowserNucleotideRowRoute`, `DatabaseBrowserPathoplexusRowRoute` and `DatabaseBrowserSRARowRoute` are gone, and a value that you wrote with `defaults write` for any of them has no effect. Every download from the Database Browser runs its `lungfish-cli fetch` command and records it. Genome rows run `fetch genome`, nucleotide and virus rows run `fetch ncbi --bundle`, Pathoplexus rows run `fetch pathoplexus`, and SRA rows run `fetch sra download --bundle`. The record of an SRA download now names the workflow `sra-fastq-download-bundle` and `lungfish-cli` as the run's tool, in place of `gui-sra-fastq-import`.

**Downloads with no project.** A download from the Database Browser with no project open now shows the sheet `No Project Open` over `Open or create a project before downloading genome assemblies.` and starts nothing. For the other searches the sentence ends `GenBank records.`, `virus records.`, `Pathoplexus records.` or `SRA runs.` The sheet opens on the browser's window with one OK button, adds no row to the Operations Panel and copies nothing to `~/Downloads/Lungfish Downloads`, and the browser stays open with its selection after you click OK. A selection of 51 or more records gets the same sheet at once, with no `Download N Records` question. In 2026.10.19 the download ran in the app, recorded no command, and copied the bundle into `Downloads/Lungfish Downloads` in your home folder without naming it on the row.

**SRA downloads.** Cancel in the Database Browser during the run metadata lookup now cancels the preparing row as well as closing the dialog. The row ends Cancelled with its View Log, the lookup stops and no import settings open. A run that you already confirmed keeps downloading. When the European Nucleotide Archive and NCBI both fail to answer the lookup, View Log now records `Could not detect SRA import settings.`, then the reason in one sentence that ends in a single period, then `Choose the settings manually.`, and the import settings still open. In 2026.10.19 Cancel in the Database Browser closed only that dialog, and the first line ended with a colon.

**Imports with no project.** With no project window open, the Import Center's NAO-MGS, primer scheme, NVD and CZ-ID imports now show the alert `No Project Open` over `Open or create a project before importing <thing>.`, such as `Open or create a project before importing NVD results.`, and start nothing. The NVD and CZ-ID result imports show the same words as a sheet on a project window that holds no project. Before, four ways to start them only beeped, and two more showed nothing when no window was open. Cancelling an import from File > Import Files... no longer ends in `Import Completed with Errors`, and a batch with a failure and a cancel counts only the failure.

**Import cancel.** A cancelled import of a multiple sequence alignment, a tree, a Geneious export, an application export or a BAM file now ends Cancelled inside 6 seconds, where the row failed with an alert before. A cancelled BAM import removes what it had written to the bundle's alignments folder. The Import Center's alignment import now runs `lungfish-cli import bam`, and its record names that command where it named an internal helper mode.

**Reference import.** Create Reference Bundle with annotations and the Import Center's reference import now run `lungfish-cli import fasta`, and Cancel ends the import inside 6 seconds. A standalone reference dropped on the sidebar imports through the same command, so its row shows the command and can be cancelled, and a failed drop shows the command's own message. A FASTA that a FASTQ operation writes is wrapped by the same command, which the bundle's record names, and Cancel on the operation stops the wrap. `import fasta` has a new option `--bundle-dir` that names the folder to build in, and giving it with `--output-dir` is refused at parse with exit status 64. An empty FASTA ends with exit status 3 and `No sequences were found in <file>`. `--annotations` with a compressed input is refused before anything is written, with exit status 3 and `--annotations needs an uncompressed input. Decompress <file> first.` With `--format json`, `import fasta` prints events, and it stops on SIGTERM with exit status 125.

**Sequence export.** Export Sequences… in the sidebar, whether it writes one file or one file for each of several reference bundles, now runs `lungfish-cli convert` when every selected item is a reference bundle or a FASTA, GenBank or FASTQ file, gzipped or not, so the Operations row shows the command to copy, including the compressor. An export that includes a document held in memory with no file, or a file that `convert` does not read, is still written in the app and records no command, and a later release records one. `convert` takes several input files and writes them to one output, and `--compress gzip` or `--compress zstd` writes the output compressed. A zstd export now also looks in `/opt/homebrew/bin` and `/usr/local/bin`, the two folders where Homebrew installs zstd. Before, it looked only in `/usr/bin` and failed on a Mac without one, because macOS does not ship zstd. This is a stopgap, and a later release makes zstd a managed tool.

**FASTQ ingest.** An in-place FASTQ ingest of a file outside a project now builds its output in the system temp folder when that folder is on the file's disk. A run that is killed leaves that folder until the app next starts, and the app then removes it once the run that made it is gone. On another disk, such as an ExFAT drive, the output is built in a hidden folder beside the file as before, and a killed run leaves that folder. The row reads `Recording the digests of the original and ingested files...` where it read `Recording the digest of the original file...`.

**Scratch folders.** At launch the app now removes the scratch folders that LGE left in the system temp folder after a quit, a crash or a cancelled run, once the process that made them is gone. It never removes a folder another user owns, a symbolic link, a folder without LGE's name and marker, a folder whose creating process is still running, a folder kept for debugging, or a folder that holds a run record of its own. It also removes the pbAA and Bracken scratch folders that a killed run leaves in the system temp folder. It looks only in the temp folder its own environment names, so a command-line run under another `TMPDIR` is never swept.

## Alignments, bundles and variants

**Mark Duplicates and variant-only references.** The hidden keys `InspectorDuplicateWorkflowRoute` and `VariantOnlyReferenceDownloadRoute` are gone, and a value that you wrote with `defaults write` for either has no effect. Mark Duplicates in Bundle Tracks runs `lungfish-cli bundle mark-duplicates` and Create Deduplicated Bundle runs `lungfish-cli bundle deduplicate-alignments`, as they did by default. The reference download of a variant-only bundle runs `lungfish-cli fetch genome <accession> --into-bundle`, as it did by default.

**Region extraction.** Extracting a region to a new bundle from a viewer that shows a reference bundle now runs `lungfish-cli extract sequence --bundle`. Its row in the Operations Panel records the command, and Cancel stops it before it publishes anything. A viewer that shows a document still builds the bundle in the app and records no command. Two region extractions given the same bundle name at the same time now keep both bundles, and the one that finishes second is saved under the next free name, such as `Name_1`. Before, it replaced the other. A region extracted with only spaces typed as its bundle name is now saved as `extracted_sequence`. Before, it was saved under the name `.lungfishref`, which Finder hides.

**Extract sequence on the command line.** `lungfish-cli extract sequence --bundle` builds a reference bundle of a region from a `.lungfishref` input. The new bundle keeps the source bundle's annotation and variant tracks in the region, `--samples` names each sample whose variant calls it keeps, and its record names `bgzip` and `samtools faidx` with their versions. `--bundle` never writes over its input, so an `-o` that is the source bundle, lies inside it or holds it is refused with exit status 3, and the bundle options (`--name`, `--samples`, `--no-samples`, `--feature-name`, `--feature-type`, `--strand`, `--concatenate-exons` and `--next-free-name`) are refused without `--bundle`. With `--format json`, `extract sequence` now prints event lines in place of the one JSON result that earlier releases printed, as `fetch ncbi` does. The `complete` line names the output, and the region, the sequence name, the span written, its length and the strand are in the run's record. Without `-o` the command still refuses with exit status 3, and the sentence now reads `--format json prints events on standard output, so the FASTA needs a file. Add -o <file>, or leave out --format json to print the FASTA.` The record of a region extracted from a reference bundle now names `lungfish extract sequence` and the command that ran as its workflow and tool, where earlier releases recorded `lungfish gui sequence extraction`.

**Bundle merge.** The new command `lungfish-cli bundle merge` merges two or more reference bundles into one new bundle, with events on `--format json`. It refuses, with exit status 3, a bundle that has a variant, signal or alignment track and two bundles that share a sequence name. Merge Into New Bundle… in the sidebar now runs it for reference bundles, so Cancel stops the merge before it publishes, the bundle appears under its name in one step, and the Operations row shows the command to copy.

**GATK variant calling.** The Call Variants dialog's GATK row now runs `lungfish-cli variants call --caller gatk` and records it, and its attach record names that command. `variants call --caller gatk` runs GATK HaplotypeCaller and attaches the VCF as a variant track under `variants/gatk/`, with `--emit-ref-confidence`, `--ploidy`, `--intervals`, `--pcr-indel-model`, `--stand-call-conf`, `--max-alternate-alleles` and `--pair-hmm-threads` as options of their own. Every `variants call` caller now stops on SIGTERM, records the cancel under `provenance/cancelled` and exits with status 125. The hidden key `GATKVariantCallingRoute` is new. `defaults write com.lungfish.browser.preview GATKVariantCallingRoute legacy` keeps the in-process route for this release, `defaults delete com.lungfish.browser.preview GATKVariantCallingRoute` returns to the command, and a later release deletes the key. A parity test compared the two routes on a stand-in GATK with the SARS-CoV-2 fixture and on real GATK 4.6.2.0 with a 300-base reference and forty reads. The routes differ in the recorded command, in where the recorded GATK version comes from (the installed GATK against the lock) and, between any two runs, in GATK's log clock and the track ID in the VCF's GATK header. A later GATK run in a bundle replaces the bundle's GATK execution record.

**Cancel in tree, alignment and primer actions.** Cancelling Primer Trim, a tree action (inference, reroot, extract subtree or relabel), Align with MAFFT, an MSA action or a platform label change now ends the row Cancelled with a record of the run, where it stopped the command at once and could leave partial output. Four cases stay as they were. `msa discriminating-sites` shares the runner of the MSA actions and is not converted. The four `msa annotate` actions never reach the cancel point. A cancel of `msa distance` on a large alignment cannot take effect after the alignment is read, so a kill at 6 seconds can still leave no record. A cancel that arrives after the write leaves a complete result under a row that reads `Cancelled by user`.

**Consensus and tracks.** A failed command shows its own reason in the Operations row instead of the system's generic message, and a stale alignment result names what changed. Remove Derived Alignment ends its row in the Operations Panel even when the window that started it has closed. Before, the row kept reading Running after the track was removed.

**Genotyping.** Annotation edits now encode, hash and write their `annotations.json` pair away from the main thread, one edit at a time in the order they were made. In the call evidence view and the sample detail sheet, the Swap H1 ↔ H2, Apply pending, Save and Restore Pipeline Call buttons stay enabled while an edit publishes, because absolute override requests are idempotent. The Save button of the haplotype editors waits while its own draft publishes, and the Mark Sample Reviewed command waits until an edit ends. The last line of the `genotype export-labkey` refusal for two smart cohorts that share a `cohort_id` now reads `To export, delete the cohorts named above in Lungfish, save each one you still need again from its filter, then export again. A delete removes every cohort with the same name and scope.`

**Primer design.** Copy CLI Command now gives a primer design a command and gives a PrimalScheme order from a filtered view a command. A replay of the recorded command to a bundle is proven for Primer3 on the real tool. For PrimalScheme3, Olivar and varVAMP, the recorded commands are proven to resolve to the dialog's options. A primer design run records a `lungfish-cli primers design <engine>` command, unless the dialog holds a setting that the command cannot say, and then the row records no command. `primers analysis export-order` reproduces a PrimalScheme view with `--hide-primer`, `--hide-pool`, `--hide-forward`, `--hide-reverse`, `--hide-amplicons`, `--hide-identity-dots`, `--hide-unassessed`, `--filter-compatibility` and `--min-compatibility`, and the compatibility filter option is proven by parse only.

## Tools and packs

**Update Tools, packs and databases.** The hidden key `ManagedToolsRoute` is gone, and a value that you wrote with `defaults write` for it has no effect. The Update Tools sheet runs `lungfish-cli tools update --apply`, the Plugin Manager's pack install runs `lungfish-cli conda install --pack`, and its database update runs `lungfish-cli conda db update`, as they did by default.

## Classifiers

**TaxTriage in the app.** Tools > Classification > TaxTriage… now runs `lungfish-cli taxtriage run --project`. The hidden key `TaxTriageLaunchRoute` takes `cli`, the default, or `legacy`. `defaults write com.lungfish.browser.preview TaxTriageLaunchRoute legacy` brings back the in-app route for this Preview, and a later release deletes the key and that route. Copy CLI Command on the row copies `lungfish-cli taxtriage run --input <bundle> ... --project <project> ... --format json`, and a row of several samples has a command with one `--input` for each sample and `--batch`. Running that command again makes a new `Analyses/taxtriage-batch-<timestamp>/` folder. The app's command carries `--negative-control` for a sample marked as a negative control. A result of the new route has the record that `lungfish-cli taxtriage run` writes, which keeps `top/` and names no file that the database build removed.

**TaxTriage and the command.** On the real TaxTriage engine, one sample run through the app's in-process route (the `legacy` value) and through `lungfish-cli taxtriage run` gave byte-identical organism reports and Kraken2 reports and the same kept-read alignments, and a second test run gave the same reports and alignments. The BAM headers differ only in the command lines of Lungfish's duplicate-marking step, which name each run's own folders. The CLI route also keeps TaxTriage's top report, which the app's old route deleted after a run, and two CLI runs gave byte-identical top reports.

**Kraken2 results.** After a single Kraken2 run opens its result, the Inspector follows it. Its Provenance tab shows the result, and the Operation Details in its Summary describe the result. After a Kraken2 batch run, the Operation Details describe the first sample, which the viewport shows. A Kraken2 compaction that is cut short no longer leaves a partial `.kraken.gz` under its name, and a trimmed FASTQ whose last write the disk refuses now stops with an error.

**Unreadable input.** `kraken2 classify` and `conda classify` on an input with no readable FASTQ or FASTA payload now refuse with exit status 3 and `Sequence input does not contain a readable FASTQ or FASTA payload: <path>`, before any folder exists. They exited with status 64 before. `esviritu detect` exited with status 3 already.

**Taxa collections.** The Extract button of a taxa collection now runs the new command `lungfish-cli extract taxa-collection`, and Copy CLI Command on its row replays the extraction. Clipboard and share extraction follow in a later release.

**NAO-MGS.** A NAO-MGS result imported before 2026-09-23 now lists its accessions, with their coverage shown as `coverage unavailable (reference not fetched)`, and extracts reads by taxon, and a failed taxon query ends with an error that names the taxon instead of an empty extraction.

**BLAST.** The NAO-MGS, assembly and FASTA selection BLAST actions now run `lungfish-cli blast submit`, so their rows show the command, Cancel stops the whole tool tree, and the result is saved with a copy of the query. The record names the digest of the query and where its sequences came from. The result of a NAO-MGS or FASTA search goes into a `blast-verifications` folder of the project. The hidden key `BlastReadActionRoute` is new. `defaults write com.lungfish.browser.preview BlastReadActionRoute legacy` restores the earlier in-process search for this release only, and `defaults delete com.lungfish.browser.preview BlastReadActionRoute` returns to the command.

## Viral Recon and Nextflow

**Docker.** When Docker has to start, the row of a Viral Recon or TaxTriage run now reads `Starting the pipeline...` once Docker is ready, where the Viral Recon row used to keep `Docker daemon ready` for the rest of the run.

## Records and the Provenance tab

**Copy Command.** Copy Command in Inspector > Provenance and the command rows beside it keep a recorded command whole when a later path in it also exists in the open project, and they move each path of it that exists here. Before this release, Copy Command gave a broken command for a record that another machine or folder wrote when its command started with an absolute tool path and named a later path that exists in the open project, and TaxTriage records were not the only ones.

**Shell steps.** In Inspector > Provenance, the Command row of a step that runs a shell script, such as the `gzip` step of a Kraken2 result, now keeps the program and shortens each path inside the script that lies in the project. Copy Command and the tooltip still carry the full command.

**Rename, move and copy.** A sidebar rename, move or copy of a result folder keeps its records true. When the app has a signing key in its environment, each signed record that the change rewrites is signed again and passes `lungfish-cli provenance verify`. When it has none, such a record loses its signature file and public key and reads unsigned, and `lungfish-cli provenance verify` on it prints `Signature artifact is missing` and ends with exit status 64, as it does for any unsigned record. A record whose signature had already failed stays as it was, so a result renamed by an earlier release still fails verify, since a rename cannot tell an old rename from an edit. A record that names a sibling folder such as `kraken2-batch-2` keeps that name when `kraken2-batch` is renamed, and a value that only holds the folder's path inside longer text, such as a `file://` URL, is left as it was. Duplicate names the copy of a plain folder `<name> copy` and a later copy `<name> copy 2`.

**Records of the database build.** After `build-db kraken2`, a raw output or result file that the build kept no longer carries `build-db kraken2` as its producer, so a sidebar copy of it keeps the record of the run that made it.

**Records of genotyping runs.** Haplotype definition records and run bundle manifests name the build of the Lungfish app that wrote them, `dev` for a build that is not a stamped Lungfish app, and never another program's build or `0`. An ONT MHC alignment command record keeps the last 65,536 bytes of each standard output and standard error log, cut to begin at a whole line.

## Projects and the sidebar

**Locate.** Locate now reopens a project whose folder you moved or renamed in Finder while the project was open, with write access and without the sheet that says the project may already be open. When the project folder goes, the sidebar shows `Project unavailable.` with a Locate… button. Before, LGE showed a sheet titled `“<name>” may already be open`, named its own process as the other session, and offered only Open Read-Only and Cancel, so the project stayed read-only until you quit LGE.

## Command line help

**New commands and options.** The commands `bundle merge`, `extract taxa-collection` and `blast submit` are new. `convert` takes several input files and the option `--compress`, `extract sequence` takes `--bundle` and the bundle options, `import fasta` takes `--bundle-dir`, and `variants call` takes `--caller gatk` with its own options. Each is described in the section of its area above.

## Known issues

Three known issues of 2026.10.19 are fixed. They are the `Docker daemon ready` line of a Viral Recon row, the Command row of a shell step in Inspector > Provenance that dropped the program, and the stale Inspector after a single Kraken2 run. The two TaxTriage limits now hold only under the `legacy` key or for results of earlier releases. The other known issues of 2026.10.19 still apply as below. The limits after the one about a Kraken2 batch run are new in this release.

Known limit. A cancelled or failed EsViritu run keeps its working files in its folder under Analyses. The notes of 2026.10.17 named a partial BAM and the trimmed reads among them and put them at about 15 GB for a sample of 25 million reads. If the Operations Panel lists the stopped run when you next open the project, Remove Partial Output… on its row deletes the folder after a confirmation.

Known limit. A large sample rich in one virus can take an EsViritu run several hours, and the run has no time limit, so it goes on until it ends or you cancel it. The rising count in the log shows that it goes on, and Cancel in the Operations Panel stops it.

Known limit. With the hidden key `TaxTriageLaunchRoute` set to `legacy`, the TaxTriage launch from the Tools > Classification menu runs in the app, and Copy CLI Command on its row copies a `lungfish-cli taxtriage` command whose `--output` is the app's own result folder, so running it writes into that folder again. Change `--output` to a new folder before you run it. A row for several samples offers no command. The default route runs `lungfish-cli taxtriage run --project` and has none of this. The `legacy` route and its key go in a later release.

Known limit. The record that the app wrote for a TaxTriage sample under the `legacy` key, and for every TaxTriage result made by 2026.10.19 or earlier, still names `count/`, `fastp/` and `top/` files that LGE removes after the database build, so some names in it point at files that are gone. Read a `count/`, `fastp/` or `top/` name in such a record as a file that the database build removed. The record at the top of such a run also names files in `filterkraken/`, `get/`, `map/`, `samtools/`, `mergedsubspecies/` and `mergedkrakenreport/` that the same cleanup removed, and they read the same way. The record of a run on the default route is the command's, which keeps `top/` and names no removed file. For a record that keeps the top report on an earlier result, run `lungfish-cli taxtriage run --project` in Terminal.

Known limit. A Viral Recon run keeps an unsigned copy of its record in its results folder on purpose, and the record in the run bundle holds the digest of that folder. `lungfish-cli provenance verify` throws on a record that has no signature file, so on the results folder it ends with exit status 64 and prints `Workflow execution failed: Signature artifact is missing` with the path of the missing `.lungfish-provenance.json.signature.json`. It does not say that the copy is unsigned on purpose or name the bundle. When the run had a signing key, `lungfish-cli provenance verify` on the run bundle prints `Signature valid`, so check the run there.

Known limit. A Viral Recon run into a results folder that an earlier run used can leave that run's files beside its own. Give each run a new results folder.

Known limit. When `lungfish-cli bam adopt-mapping` fails after it has attached a mapping, it still deletes the BAM that it moved into the bundle. A second adopt into the same bundle overwrites the bundle's shared `alignments/mapped/mapping-provenance.json`, so that record no longer describes the first track. Keep a copy of the mapping result until the command ends with exit status 0, and copy that `mapping-provenance.json` before a second adopt into the same bundle.

Known limit. A signing key does not sign every record yet. With `LUNGFISH_PROVENANCE_SIGNING_KEY` or `LUNGFISH_PROVENANCE_SIGNING_KEY_FILE` set, the records of `sequence annotate-orfs` and `sequence delete-track`, the log that Add Annotation appends to, and the record of a cancelled alignment workflow, consensus or read extraction stay unsigned, and a later release signs them. A run with no key that writes into a bundle whose record is signed leaves that record unsigned, on every route, so the record no longer shows that its earlier history was signed. A rename, move or copy of a result folder in the sidebar does the same when the app has no key. If your lab signs records, set the key for every run that writes into a signed bundle.

Known limit. After a Kraken2 batch run shows its first sample, the sidebar and the Inspector's Provenance tab stay on the item that was selected before the run. Click the batch's row in the sidebar to show the batch's own details.

Known limit. A download from the Database Browser needs a project. With no project open, the browser shows the `No Project Open` sheet and starts nothing, where 2026.10.19 downloaded the bundle into `Downloads/Lungfish Downloads` in your home folder. Open or create a project before you download.

Known limit. An export with zstd needs zstd on the Mac, because macOS does not ship it. Install it, for example with `brew install zstd`. The export looks for zstd only in `/usr/bin`, `/opt/homebrew/bin` and `/usr/local/bin`, and not in your PATH, and a later release makes zstd a managed tool. An export with gzip works on every Mac.

Known limit. The text of a sequence export from a GenBank file, a `.gz` file, FASTQ and a mixed selection has not been compared with the export of 2026.10.19. The comparison covers a FASTA file, a bundle written as GenBank, two FASTA files and a document held in memory, which the app still writes itself. A GenBank export is the first place to look for a difference, since the app's own GenBank writer keeps annotations that name no chromosome and `lungfish-cli convert` keeps only those that name the sequence. No run has shown whether this changes an export.

Known limit. The command that Copy CLI Command gives for a primer design writes into the project's `Analyses` folder and fails when the project has none. Create an empty `Analyses` folder in the project before you run it.

Known limit. The Import Center's metagenomics, NVD and CZ-ID imports still run through an internal helper mode of the app and not through a `lungfish-cli import` command of their own. A later release moves them.

Known limit. The command `primers analysis export-selection` for exporting the selected primers is not in this release, so that export has no command to copy yet. A later release adds it.

Known limit. A copy of a project that LGE has open, such as a Finder Duplicate or a backup put back in place, still shows the sheet that reads the project's name and `may already be open`, and the sheet names LGE until you quit LGE.

Known limit. A database that an older build adopted from a folder under a catalog name still shows the catalog's version label and no update in the Databases tab and in new classification records, because nothing checked that folder against that build. A later release marks such rows as unverified.

Known limit. When the integration-tier gate kills a test class at its time bound, its report can say `a case the log does not name` instead of the case that was running, because setting `NSUnbufferedIO=YES` for the run was not shown to bring the running case into the log through `swift test`.
