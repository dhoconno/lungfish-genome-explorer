# Lungfish 0.5.0-beta1

Previous release: v0.5.0-alpha35

## Beta Readiness Hardening

This beta moves Lungfish from the alpha channel into the first beta candidate
with a broad internal hardening pass rather than a narrow feature drop. The work
focused on making the application easier to reason about before beta testing:
stale development notes were removed or clarified, large implementation files
were split along clearer ownership boundaries, dead code and placeholder
surfaces were retired, and release-facing names were aligned around the beta
channel. The result should feel familiar to alpha users, but the codebase is now
less dependent on historical assumptions from earlier development phases.

Reproducibility and provenance were strengthened across the scientific workflows
that create, wrap, transform, import, export, or materialize data. CLI and GUI
paths now converge on the canonical `lungfish-cli` identity, durable replay
arguments, resolved options, runtime identity, and final published bundle paths.
FASTQ imports and transformations, classifier databases, extraction outputs,
sequence and variant exports, reference bundles, MSA and tree outputs, ONT
workflows, NAO-MGS and NVD imports, BAM and VCF ingestion, and workflow-run
bundles all received additional coverage so missing or partial provenance fails
closed instead of silently producing ambiguous scientific artifacts.

The bundle and project layers were also tightened. New and existing workflows
publish through staged outputs, atomic replacements, stronger manifest
validation, and rollback paths that keep incomplete artifacts out of projects.
Project locks, analysis manifests, attachment replacement, managed database
publishing, SQLite sidecars, bundle member path resolution, and legacy migration
paths were hardened so project state remains consistent when operations are
cancelled, fail midway, move between folders, or encounter older bundle layouts.

Operation handling is more predictable throughout the app. Cancellation now
propagates to subprocess trees for FASTQ work, primer trimming, SRA tooling,
variant calling, and network-backed searches; queued work is cancelled before it
can acquire execution slots; and UI updates are gated after cancellation. Several
background reads and long-running waits were moved off the main actor, large
tables use bounded rendering or windowing where appropriate, and stale or
incomplete UI panes were removed so the interface better reflects the operations
that are actually runnable.

The beta also expands and revises the user manual. The manual now gives fuller
context for foundations, FASTQ and read workflows, alignments, classification,
assembly, genotyping, workflows, provenance, CI use, and troubleshooting, with
accessibility review notes incorporated into the documentation set. This makes
the beta easier to evaluate as a whole product rather than as a collection of
individual workflow tools.

## Release Notes

This remains a prerelease build intended for beta validation. It is prepared for
distribution as a notarized Apple Silicon DMG and for publication to the
Sparkle beta update feed.
