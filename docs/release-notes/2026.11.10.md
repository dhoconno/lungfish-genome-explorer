# Lungfish 2026.11.10

Channel: Preview

Previous versioned release: v2026.11.9

Stable baseline: v2026.11.7

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview brings the counting half of the RNA-seq work to `lungfish-cli`. You can count bulk reads with salmon, export counts for DESeq2, edgeR and limma, import and sum single-cell results, plan STAR index builds and counting runs for a Linux machine, and import the counts such a run returns. It also corrects two results that Stable 2026.11.7 could get wrong without a word, one in Illumina amplicon genotyping and one in Extract Reads on an older TaxTriage result. No app window changes, so every new RNA-seq command runs in `lungfish-cli`.

## What works differently

- **Illumina amplicon genotyping keeps two samples with one file stem apart.** Two sample IDs that gave the same file name, such as `S-1` and `S--1`, or that differed only in letter case, such as `Sample_1` and `sample_1`, made the pair merge write one file for both. The first sample's genotype was then called from the second sample's reads, with no words. Each sample now gets its own file stem, and the second sample of such a pair takes `-2` after the stem. Sample IDs keep their spelling. If a batch held such a pair, run genotyping again on it with this version and use the new calls for the pair.
- **Extract Reads stops for a sample of an older TaxTriage result that may hold another sample's BAM.** A database built before 2026.11.6 can record a BAM of another name for a sample, such as `S1_2.bam` for S1, and Extract Reads wrote that file's reads under S1. The app and `lungfish-cli extract reads` now stop before they write a read, name the file and give the command that builds the database again. Run `lungfish-cli build-db taxtriage "<result folder>" --force`, then extract again. The other samples of the result extract as before. If you extracted reads from such a result with an older version, extract them again after the repair and compare. Opening the result in the app, in a project you can edit, also builds the database again when the result still holds its report files.

## What's new

- **Count bulk RNA-seq reads with salmon.** `lungfish-cli rnaseq index --set <id>` builds the salmon index of a reference set or reuses the one it built before, and `lungfish-cli rnaseq quant` counts each FASTQ bundle as one sample on that index. The result holds transcript counts and gene sums, and its record names the set, the index, salmon's version and every setting that changes counts. `quant` trims reads only when you pass `--trim`, and an import may have cut poly-G tails before that, so read the poly-G row of Known issues. The record of each count says what the import did with poly-G tails in its line Poly-G trimming at import, or Not recorded when the bundle holds no import record. An index build needs about 16.6 GB of memory and 64 GB of free disk. On a Mac with less, Lungfish refuses before it starts and says how to build the index on Linux. `rnaseq index` always gives salmon 8 threads and refuses `--threads` in words.
- **Export counts for DESeq2, edgeR and limma.** `lungfish-cli rnaseq export` writes `counts.tsv`, `genes.tsv`, `samples.tsv`, an R script for DESeq2, an R script for edgeR with limma voom and dream, and a record into a new folder. The results must come from one route and one reference set. You can name design columns, contrasts, a fold-change bar and a batch column, and correct the batch with ComBat-Seq or sva.
- **Import single-cell results.** `lungfish-cli import rnaseq` now also reads Cell Ranger outs and STARsolo run folders. It reads Matrix Market text, with or without gzip, and no HDF5 file. `--genome` picks one genome of a reference of two or more, such as hg19. With `--reference-set` and one `--not-host-bam <sample>=<path>` for each sample, the import also counts the set's not-host sequences (virus, bacterium or spike-in) in each cell and in the ambient pool, flags cells, and says how many cells have no flag computed.
- **Sum a single-cell result by sample and label.** `lungfish-cli rnaseq pseudobulk` writes a bulk result with one column for each sample and label of a table you give. The table has barcode and label columns, and a sample column for a result of two or more samples. A group under 10 cells is left out and said, and so are cells with no label.
- **Export a single-cell result for Seurat and Scanpy.** `lungfish-cli rnaseq export` takes a single-cell result by itself and writes one folder for each sample with its matrix, features and barcodes, beside `genes.tsv`, `samples.tsv`, `seurat.R` and `scanpy.py`. It refuses the design, contrast, batch, fold-change and non-default adjusted p-value options for such a result, so sum the cells with `rnaseq pseudobulk` and export that result to compare groups. An export of a pseudobulk result refuses a tested factor with a level that holds fewer than 3 animals, since a test that takes each cell for a replicate gives false discoveries.

More changes concern reference sets and the Linux route.

- **Reference sets keep their counting annotation.** `lungfish-cli rnaseq reference-set` now keeps `derived/genes.gtf` in every set it builds, the one GTF that STAR, STARsolo and featureCounts read. It also takes `--extra-mask <name>,<gtf>` to give an extra sequence its rRNA mask from a GTF. A set you built before still loads, counts with salmon and is never changed. A STAR route refuses it in words that name the rebuild.
- **Plan a STAR index for a Linux machine.** `lungfish-cli rnaseq index-plan` writes a new plan folder that runs STAR genomeGenerate with 8 threads on the set's genome, extras and counting annotation. It takes `--star 2.7.11b` (the default) or `2.7.3a`, the absolute `--staging-folder` on the Linux machine and the memory, CPUs and disk the job asks for. A genome with no measured figures needs all three, and the help names Macaca_fascicularis_6.0 as one that has them. After the run, `lungfish-cli rnaseq index-adopt` reads `run-record.json` from the returned folder and records each index file's staging path, size and SHA-256 under the storage root. The record also names the run that built the index and keeps a copy of that run record beside it. The files stay on the Linux machine and nothing copies them. A second adopt with other values is refused, and the words say what differs. `--tenx-filter mkgtf-3.0.0` or `gencode-2020-A` on `index-plan` and on `index-adopt` plans a STARsolo index on the genes that 10x list keeps, and a list that keeps no host gene is refused in words.
- **Plan counting runs for a Linux machine.** `lungfish-cli rnaseq quant --write-plan <folder>` writes one plan for each sample in place of counting here. A plan runs salmon on the index `rnaseq index` published for the set, or with `--chain` a STAR chain (STAR then salmon, STAR GeneCounts, or STAR then featureCounts) on the STAR index that `index-adopt` recorded. Give the reads as bundles, or list files already on the Linux machine with `--staged-reads` and `--samplesheet`, and name the `--staging-folder`. `--dry-run` makes every refusal and writes no folder.
- **Import the counts a Linux run returned.** `lungfish-cli import rnaseq --adopt <returned folder>` reads salmon counts, STAR GeneCounts (column 2, unstranded) or featureCounts as one result. A folder of samples gives one result, or nothing when any sample is refused. The plan fixed every setting, so `--adopt` takes no option that sets a count, and `--dry-run` checks everything and writes nothing. The record names the adapter Trim Galore chose for each sample and says it does not know what the import did with poly-G tails.
- **Plans for a CHTC batch carry reference files, a barcode list and a tool step.** The plan format, schema 2, now holds them, and the batch path writes the submit files `sample.sub` and `jobs.tsv` for such a plan. The plan pins the container image `lge-tools-43a3079b8fb1.sif` and its manifest of 713 tools.

## Things to know

- **The new commands run in `lungfish-cli` only.** The app has no window for them in this build.
- **`rnaseq quant` never builds an index.** Run `rnaseq index` first. STAR itself runs on the Linux machine, and the Mac plans the run and records its result.

## Known issues

Each row is open in this build. It says what can go wrong, who can meet it and what Lungfish already tells you.

- **Verify with BLAST can judge an imported EsViritu result by organism names.** The judge then reads the first word of a name, so a top hit named "Rotavirus C" can count as supporting "Rotavirus A". A native EsViritu result is judged by its tax ID and is not affected. A result judged by names shows a line that begins `Judged by organism names` under its summary. A result saved by an earlier version shows no such line.
- **Demultiplex Barcodes with Exact Bare Barcode has no chance floor.** On 150-base reads that carry none of your barcodes, each 8-base barcode still matches about 0.44% of the reads by chance, about 5% for 12 barcodes, and each barcode that matches becomes a sample file. The dialog says so when you pick the engine, and a run that makes sample files warns in its summary and its Operations row. Cutadapt, the default engine, has the floor.
- **A custom kit of very short barcodes defeats the chance floor.** When about half of all random read starts would match a barcode, as with a 384-sample plate of barcodes of 4 and 5 bases, the floor cannot tell a pool from a file with no barcode, and chance matches can become sample files. The summary says so, and the Operations row and the Log show the floor's own line.
- **The chance floor is a measured 1 in 1,000 for each barcode.** A 12-base kit built for the test that allows one error published a false sample in 3 of 147 real cuts, and the default Illumina kit in none of 147. A false sample holds about 0.4% of the reads, as a real small sample does. The window says that such a barcode can pass in about one run in 1,000 and tells you to check samples with few reads against your sample sheet.
- **Extract Reads can fit another sample's BAM to a sample.** It happens when no BAM path is recorded for a sample, the sample has no BAM of its own, and one file such as `S1_2.bam` or `S1.5.dedup.bam` belongs to another sample. The scan then gives that file to `S1`, and `S1` reads it.

Five more rows concern Viral Recon, trimming and the note for a known fault.

- **Trimming paired reads and Viral Recon can run out of memory and disk space on a large run.** Since version 2026.11.8 both put the reads in a fixed shuffled order before fastp, and the Lungfish helper `lungfish-cli` then holds about all of the reads in memory. Trimming used 3.20 GB at 4.8 million read pairs and 10.7 GB at 19.3 million, and Viral Recon used 11.1 GB at 19.3 million. Lungfish says 8 GB of memory is enough for viral genomes, so a run of about 20 million pairs on a Mac with 8 or 16 GB may become very slow or stop for lack of memory. This was not tried on such a Mac. The trim also needed 18.7 GB of free disk space, about 3.9 times the size of the uncompressed reads, and Lungfish checks neither memory nor disk space before either run. A run that finishes gives the right result. On a Mac with 16 GB or less, quit other apps before a large run or use a Mac with more memory, and free the disk space first.
- **Viral Recon on single-end Illumina reads lets fastp guess the adapter** from the head of the staged file. Whether that changes a result is not settled. The one single-end run measured gave one result in the file's order and with seeds 1 to 3.
- **A FASTQ import that uses Trim Galore for storage decides for itself whether to cut poly-G tails.** You reach it by picking Trim Galore as the Compression Tool or passing `--clumping-tool trim-galore`, and the default, BBTools, cuts nothing. On 2,000 synthetic reads of 100 bases that ended in 30 G, Trim Galore cut them to 70 bases with NextSeq and MiSeq read names alike. The import's provenance record keeps Trim Galore's own answer, and `rnaseq quant` repeats it in the line Poly-G trimming at import of its record. The import sheet does not say it.
- **A recipe that turns fastp's poly-G option off passes no flag to fastp.** fastp then decides from the instrument in the read name. Only a recipe you wrote yourself reaches this.
- **Viral Recon, Call Variants, trimmed reads, reads imported with a recipe and Demultiplex results show no note for a known fault.** The Inspector has no kind for them, so use the redo lines in the 2026.11.8 notes.

The limits in the 2026.11.8 and 2026.11.9 notes still apply, except the one on Illumina amplicon genotyping, which this version fixes.

### TaxTriage results

One more row concerns the BAM file that a result shows.

- **A TaxTriage result can show another sample's BAM with no warning.** In a TaxTriage result where a sample's own BAM file is missing, Lungfish can use another file in the minimap2 folder whose name fits the sample (for example `S1_2.bam` for sample S1). The alignment view, its coverage and the Inspector show that file with no warning, and it may hold another sample's reads. Extract Reads names the file, or refuses it when the database was built before 2026.11.6. Check the BAM line in the Inspector. If it is not the sample's own file, put that file back and run `lungfish-cli build-db taxtriage "<result folder>" --force`.
