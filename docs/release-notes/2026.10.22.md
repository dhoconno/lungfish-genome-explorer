# Lungfish 2026.10.22

Channel: Preview

Previous versioned release: v2026.10.21

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release is Preview 2026.10.22. It follows Preview 2026.10.21, and the sections below list what changed for a person who uses Lungfish Genome Explorer (LGE) or `lungfish-cli`. The changes fall into four themes. Cancels and failures are now reported more exactly, from a copy between projects to an export that finished just before Cancel. Records name what ran, which values a run resolved and which commands an exported script runs, and more of them are signed. Viewer images are drawn by a command from the bundle's files. Exports, classifier tables, variant tables and primer design commands carry the corrections listed under each heading.

The three hidden keys that 2026.10.21 added are gone. They are `ClassifierBlastRoute`, `RegionExtractionWithoutBundleRoute` and `CrossProjectCopyRoute`, and a value that you set for any of them has no effect. The BLAST Verify actions, the extraction of a region from a document and the copy of an item from another project now have one route each, the `lungfish-cli` command that was their default. A value left in your preferences is harmless, and `defaults delete com.lungfish.browser.preview <key>` removes it, where `com.lungfish.browser.preview` is the identifier of this Preview.

The owner check list under Checks still to run blocks a Stable promotion until a walk with a person at the Mac has covered every row.

## Reads and downloads

**Archives with an unsafe link.** Archive imports and database downloads now refuse an archive that holds a symbolic link pointing outside its folder, and the message names the link. This covers a Geneious archive, an application export archive, a CZ-ID ZIP, an NCBI Datasets download, an EsViritu database, an offline conda pack and a metagenomics database install.

**NAO-MGS import.** The NAO-MGS import now gives a sample no BAM and keeps its hits when samtools rejects one of the last few hundred reads of the sample while the BAM is built, and the log gives samtools' message. Before, such a sample got a BAM that held only the reads before the rejected one.

**Long-read bundles.** A bundle recorded as Oxford Nanopore or PacBio is now read as single reads by every FASTQ operation, `fastq deinterleave`, `fastq merge`, mapping, assembly, Kraken2, TaxTriage, Viral Recon and recipes, even when its read ids repeat, as the read set planner already read it, and an operation's output from such a bundle records single-end pairing.

**Joined FASTQ files.** A joined FASTQ file no longer glues a record onto the next header when a part lacks its final line break.

**MEGAHIT on Apple silicon.** On an Apple silicon Mac, a MEGAHIT assembly now runs on at most one thread, whatever the Threads setting says. The assembly dialog shows the line "On Apple silicon MEGAHIT runs on at most 1 thread, because more threads can crash it." under Threads when you choose MEGAHIT, and the run record and the bundle metadata name the thread count and the memory the run used.

**Viral Recon results folder.** A Viral Recon run into a results folder that already holds files now stops before it starts. The app names a new results folder for every run, so you meet the stop on the command line. `lungfish-cli workflow run nf-core/viralrecon` prints `--results-dir <path> already holds files. Name an empty or new folder.` and ends with exit status 3, and a `--dry-run` stops the same way. A run with `--resume` is not refused, because it continues into the folder its earlier run used. The command does not check that the folder is that run's, so give `--resume` only the folder of the run you resume. A command copied from an earlier run needs a new or empty `--results-dir` to run again.

## Alignments, bundles and variants

**Genotype names.** A sample name that is cut short beside the genotype rows ends a little further right.

**Tools that cannot start.** When a tool cannot be started, the error now reads Could not launch, then the tool's name in quotes, then the reason, where it showed the operating system's own message. This applies to the samtools steps of Mark Duplicates, whose error also names the failed stage `launch` where it named `markdup-pipeline`, to the samtools merge and index steps of the ONT barcode demultiplexing genotyping pipeline, to the Python renderer of a genotype workbook export, to the MAFFT alignment of discriminating sites, to the pair merge of the Illumina amplicon pipeline and to the bgzip or pigz step of a paired FASTQ import.

**Region extraction from a document.** The hidden key `RegionExtractionWithoutBundleRoute` is gone, and a value that you set for it has no effect. Extracting a region to a new bundle from a viewer that shows a document with no reference bundle always runs `lungfish-cli extract sequence`, as it did by default, and the earlier in-process route is removed. When Lungfish cannot write the copy of the document's sequence that the command reads, it now removes the folder it made for that copy in the project's `.tmp` folder, where earlier versions left the folder in place.

**Variant annotations.** At every import profile, Lungfish now splits SnpEff ANN and VEP CSQ annotations into their fields, so the High Impact filter and filters on ANN fields such as ANN_IMPACT find variants. A file imported before this release keeps its old rows until it is imported again.

**Coding features.** The variant table and the hover now use the genetic code that a coding feature names (`transl_table` or `genetic_code`). The variant table, the hover, the translation and both GFF3 exports now read a coding feature of a bundle in the frame its annotation file gives it, and both GFF3 exports keep the first phase of a coding feature of one or more segments, a GenBank codon start included.

**Variant bundles.** Showing a variant bundle no longer changes `variants/calls.db`. The bookmark table is added only when you star a variant, so a bundle you only look at keeps the bytes and the SHA-256 that its import record names.

**Empty files.** Export Sequences… of an empty file, or of a file that holds only white space, stops with Export Failed and the message `No sequences found in <file>.`, and writes nothing. `lungfish-cli convert` refuses such an input with the same words and writes nothing.

**GenBank feature keys.** GenBank files that Lungfish writes, from Export or from `lungfish-cli convert`, keep each feature's key and location as the source GenBank file had them, for example CDS, the partial markers `<` and `>` and `order()`, as long as the feature's type, ranges and strand are unchanged.

**Primer design commands.** The four primers design commands (primer3, primalscheme3, varvamp and olivar) take `--project` and `--name`, so a design writes a new analysis in the project and a second run writes another. Copy CLI Command of a primer design now gives `--project <project> --name=<name>` in place of `--output`, and it replays in a project with no Analyses folder. When the name is in use the command writes the first free `<name> 2`, `<name> 3` and so on and reports the path. A command that names `--output` still refuses a bundle that exists, and its words now point to `--project`.

**Primer order and selection exports.** The primer order and primer selection exports now run `lungfish-cli` behind their Operations rows, so Copy CLI Command replays an order, a Primer FASTA bundle or a reference amplicon export, a cancel leaves no folder behind, and the two commands take `--format json`. Copy CLI Command of an order spells each filled field with an equals sign, so a value that starts with a hyphen exports and replays.

**Olivar and varVAMP designs.** Olivar and varVAMP designs now save when the output path passes through `/tmp`, `/var` or a folder you linked, as Primer3 and PrimalScheme3 already did. The app's design dialog still asks for a project and an Analyses folder that are not links.

## Tools and packs

**Compression tools.** zstd export and `.zst` and `.xz` import now use tools that Lungfish manages and no longer need Homebrew. Lungfish adds zstd and xz to its Required Setup, so a Mac that updates is asked to install them once, and until then a zstd export and an import of a `.zst` or `.xz` file stop with a message that says so. A `.xz` import never worked on a Mac without `/usr/bin/xz`, which macOS does not ship, and now works.

## Classifiers

**The `ClassifierBlastRoute` key is gone.** A value that you set for the hidden key `ClassifierBlastRoute` has no effect. The BLAST Verify actions of the NVD, EsViritu, TaxTriage, 12S and Kraken2 results always run `lungfish-cli blast submit`, as they did by default. The earlier in-process search of these five actions is removed, and so is its key.

**Kraken2 taxonomy tables.** A Kraken2 taxonomy table of several samples gives each row's Clade % and Direct % as a percent of its own sample's reads, unclassified reads included, where it gave a percent of all the picked samples' reads. Each sample keeps its own unclassified row, and each sample's row counts the reads Kraken2 assigned to the root alone. A table of one sample is unchanged. Exporting a Kraken2 result whose database was built by an older version of Lungfish stops with a message, since that database may hold Bracken's estimates in place of Kraken2's read counts. Opening a Kraken2 result a second time leaves the bytes of `kraken2.sqlite` unchanged.

**Kraken2 table records.** The record of a Kraken2 taxonomy table export now names, for each sample in the table, the reference database as its classification result recorded it, with a name, a version and a digest, and gives the digest as unknown with the reason when the result records none. A table read from a batch also lists the batch manifest and each picked sample's classification result among its inputs. A table read from a database built for one run names that run's reference database from the `classification-result.json` beside it and lists that file among its inputs. A result that exists and cannot be read gets the digest as unknown with the reason that no readable `classification-result.json` was found.

**TaxTriage rows and Extract Reads.** A TaxTriage row no longer opens, searches or extracts another sample's reference. If its own sample has no reference accession for the organism, the alignment pane stays closed, BLAST Verify says that no reference accessions are available, and Extract Reads leaves the row out and says so. When no selected row has an accession, an alert titled "Nothing to extract" explains why. When only some selected rows are left out, the Extract Reads dialog still opens for the others and names the left-out rows in one line under its selection count, and that count now shows selected rows rather than samples.

## Records and the Provenance tab

**Mapping and GATK records.** Each adopted track and each GATK call into a bundle keeps its own run record, `<bam stem>.mapping-provenance.json` for an adopted mapping and `<track>.gatk-run.lungfish-provenance.json` for a GATK call, and older bundles still read. A failed `lungfish-cli bam adopt-mapping` returns the BAM and its index to the mapping folder and removes only the files that it made. Mapping records now list the `samtools coverage` and `samtools view` passes that made the summary rows, and an exported script names them in a comment and does not run them.

**More records sign.** With `LUNGFISH_PROVENANCE_SIGNING_KEY` or `LUNGFISH_PROVENANCE_SIGNING_KEY_FILE` set, more records now sign. They are the records of the commands blast submit (its failures), fastq demultiplex, fastq deacon ribo, `fetch ncbi`, import metadata, run, SRA download, `variants extract-sample` and `variants query`, the records of the app's sample metadata imports and their edits, VCF auto-ingest, FASTQ ingestion and operation outputs, workflow operation runs and the FASTA operation catalog, and the records of variant track attachments, workflow runs, VCF attaches, the app's other imports, builders and exports, and full-length genotyping. Without a key the records are the same as before.

**Who a record names.** A record of work that Lungfish Genome Explorer does in its own process now starts its command with Lungfish Genome Explorer, where older records started it with Lungfish.app, lungfish-app or lungfish-gui. Its tool name and tool identity read Lungfish Genome Explorer too, except for step names that keep their own words, such as those that start with `lungfish-app-action`. A record that carries a tool kind says gui for the app, and the FASTQ auto-bundle record said app before. A command copied from such a record shows the name in single quotes, since the name holds spaces, and it is no program to run in a terminal.

**Records that the command line writes.** A reference annotation or variant record that `lungfish-cli` writes now names `lungfish-cli` as its tool, where it named Lungfish Genome Explorer. This covers `sequence attach-track`, `sequence add-annotation`, `variants delete`, `variants import-sample-metadata`, `import` with annotations, `import geneious` and `primer-analysis`. A reference allele database record that `lungfish-cli haplotypes` writes when it creates, installs, saves or replaces a reference names `lungfish-cli` with kind cli, where it named Lungfish Genome Explorer with kind app. The record of `import fasta` with `--annotations` and the record of `import geneious` now name the command that was run, where they named `Lungfish.app annotation-import`, a command that does not exist. The bundle record of an annotation import and the variant records that the app writes now carry kind gui, where they carried cli. A record that the Haplotype Definitions window writes names Lungfish Genome Explorer with kind gui, starts its command with that name and holds no replay line.

**Exported scripts and app steps.** An exported script runs `lungfish-cli variants delete` for variants that you delete from the table, one variant or all of them, because a test shows that the command writes the same database bytes as the app, and the record names Lungfish Genome Explorer as what ran. Saving classifier-extracted reads to a file runs `lungfish-cli extract reads --by-classifier` in an exported script in the same way, except that a selection which carries a read-name allowlist, such as NAO-MGS rows, names its step and does not run it. The MSA annotation edits that the app records, Add annotation from an MSA selection and Apply annotation to selected rows, now read Lungfish Genome Explorer as their tool name, where they read `lungfish-gui msa annotation edit`.

**FASTQ bundle merge.** The record of a merge of FASTQ bundles now names its workflow `FASTQ bundle merge`, where it named `lungfish fastq merge`, which the pair merge of `lungfish-cli fastq merge` also records. Its command starts with Lungfish Genome Explorer, where it started with `lungfish-app`, and its kind reads gui.

**Primer records.** The records that a native primer inspection, a PrimalScheme3 design and a PrimalScheme3 allele label map write now keep a slash as typed, as the writer's records do, where they wrote it as `\/`. Nothing else in them changes.

**ONT haplotype definition snapshot.** The haplotype definition snapshot that the ONT barcode demultiplexing genotyping pipeline saves, `artifacts/haplotyping/haplotype-definition.json`, now reads 0644 under umask 022 like the other records, so the others on a project shared through a lab server can read it. It read 0600 before. A snapshot that an earlier release saved keeps 0600, and `chmod 644` on the file lets the others read it.

**Options and resolved values.** EsViritu and Kraken2 records no longer file the paired-end flag, the build's EsViritu release, the requested read format or the input layout scan as options you chose. They appear among the values the run resolved. Kraken2 records file a typed `--read-format auto` as auto, and EsViritu records name a typed `--read-format` and `--paired`, also for a run that fails. TaxTriage records no longer file the sequencing platform as an option you chose when a sample's bundle recorded it or you named none. It appears among the values the run resolved, with `platformSource` set to bundle or default. A platform you type with `--platform` stays an option you chose.

**Kraken2 database digest.** A Kraken2 record names the database digest only when the folder's install receipt backs it, with the size of every file that digest covers. Otherwise it records no digest and says why.

**EsViritu build-db records.** In the record beside a BAM or BAM index of `build-db esviritu`, the move, the `_temp` removal and the run step list only that file's inputs and name the folder record that holds them whole. Other BAMs' fixmate and sort stages are gone. Older records read as written. `build-db` no longer writes read counts it did not measure. A failed count or a failed duplicate marking leaves the row as parsed, and the summary says how many rows were left uncounted.

**Provenance lookups.** A record above the project root that lists a project file as produced is no longer found for that file, because it lies outside the project and a moved or shared project never carried it. A record with a workflow name that lies directly in a shared folder (the temp, home, Downloads, Desktop or Documents folder) and lists a file in a subfolder is no longer found, so the Provenance tab reads Missing and the `provenance` command of `lungfish-cli` finds none. Outside a project, a lineage link whose recorded checksum differs from the record's output, and a link from an input recorded with no checksum, are no longer lineage. A link whose checksum matches stays, and nothing inside a project moves.

**Renamed and moved records.** The Command row, Copy Command and the mapping Document tab show a moved or renamed result folder's command in the folder where the record is now. An exported shell or Python script now needs `OUTDIR` set to a new folder, writes every output there, checks each input's SHA-256 before it runs, and does not write into the result folder it came from, even after that folder was renamed, moved or duplicated, except where the record's relocation maps nothing (see Known issues).

**Steps that ran inside the app.** On the Provenance tab, a step that ran inside the app, such as a merge of FASTQ bundles, keeps its recorded words in the Command row with the note "This step ran inside the app and has no command to run in Terminal." Its Copy Command is turned off, and Copy Step still copies the step. Copy CLI Command in the Operations Panel appears only for a `lungfish-cli` command.

**Genotype workbook receipts.** A genotype workbook's receipt names `lungfish-cli` as its tool and the command that wrote it as its workflow (for example `lungfish genotype export-pivot-xlsx` or `lungfish fastq genotype-cohort`), and keeps the request's own workflow name as `requestWorkflowName`.

## Projects and the sidebar

**Copy between projects.** The hidden key `CrossProjectCopyRoute` is gone, and a value that you set for it has no effect. A project item dropped on the sidebar from another project always runs `lungfish-cli project copy-item`, as it did by default, and the earlier in-app copy is removed.

**Cancelling a copy.** Cancel now stops a copy between two projects on one disk formatted APFS, as a Mac's own disk is, within moments, whatever the size of an item that carries no provenance record. The copy takes Cancel while it checks the item's files and before it copies them. For a very large item that carries a provenance record, Cancel can still take several seconds.

## Viewer exports

**Viewer images.** File > Export > Image (PNG)… and Image (PDF)… now run `lungfish-cli bundle export-graphic` when the viewer shows a genome bundle, and the row of the export in the Operations Panel records that command, so Copy CLI Command copies it. The command also takes `--regions-file` with a BED file and writes one image for each region. The image is now drawn from the bundle's files and is no longer captured from the screen. It shows the region the viewer shows and draws the bundle's sequence, annotation, variant and read tracks from the bundle's files, but it is not a copy of the screen. Its track heights, spacing, colours, fonts and edges differ from the viewer's, its read track is 200 points high and holds at most 75 rows of reads where the viewer can show more, and anything it leaves out for a limit is named in its record. The sequence track differs in five ways. The image turns coloured blocks into a grey bar at 300 bases a point where the viewer waits until 500, it outlines that bar where the viewer draws a thin line, it colours a block by the most common base of its bin where the viewer fills one block for each run of one base, it leaves a half point gap between bases, and it writes each letter in bold sized to its cell where the viewer writes a fixed 12 point letter. A PDF image of a bundle holds no creation or modification date, so running its command again on the same Mac and macOS build writes the same file. If a PDF keeps those dates, its record says so. The image follows the light or dark appearance of the app when you export, and the command draws light unless you pass `--theme dark`. The Scope menu reads Tracks, Ruler and Tracks, and Selected Region. The annotation table is no longer part of the image, and the table's own export still writes it. The Export Successful alert no longer appears, and the finished row names the file. When the viewer shows anything else, such as a classifier result, an alignment, a tree or a PDF, the export still captures the whole pane as before, with the one scope Full Viewer Pane, and records no command. A document that is not a bundle also keeps Tracks and Selected Region as captures.

**Variant table exports.** An export of the Variants tab now fills Gene / Protein, Consequence and AA Change for each exported variant that lies in a coding feature, in Selected Rows and All Matching Rows alike, including a variant outside the part of the genome that the viewer has cached. In 2026.10.21 those cells were blank for such a variant, and the table on screen still works them out only for the part of the genome that the viewer has cached. The export reads every coding feature of the bundle that overlaps the exported variants, so a variant's cells equal the table's once the view shows it. With a filter or sort on one of these columns, All Matching Rows keeps, drops and orders each variant by the values its cells show. If one annotation track holds at least 50,000 annotations in a span of the exported variants, the export stops with a message that names the track and the span, and writes no file. The command recorded by an earlier export still works these cells out from the part of the genome that it names.

**Export buttons.** The Export button of NVD and EsViritu is disabled until a sample is picked, the Export button of NAO-MGS and NVD is disabled while a result shows its cached rows, and a missing database found before the save panel opens now ends in an alert in the app's words. A disabled Export button of a NAO-MGS or NVD result says "Export is ready once this result finishes opening." while the result's database file is in its folder and still opening.

**GFF3 export.** A GFF3 export of a bundle keeps each feature's ID from the imported file, gives a feature imported without one an ID from its row (`lungfish-row-12`), names each Parent by an ID in the same file and leaves out Lungfish's internal keys, so two exports of one bundle are the same file.

**XLSX export.** An exported XLSX is byte-stable on one Mac and one `/usr/bin/zip`, so two exports of one table are equal and a replay there regenerates the recorded digest.

**Cancel after an export.** A Cancel that lands just after an export wrote its file now leaves the row Completed, with the file's link and the detail Finished before Cancel took effect, where it used to read Cancelled by user and drop the link. An export that does not report its own completion still reads Cancelled by user in that case.

## Command line help

**The compress flag.** Twenty `fastq` subcommands now refuse `--compress`. They are adapter-trim, contaminant-filter, deduplicate, entropy-filter, error-correct, fixed-trim, interleave, length-filter, orient, primer-remove, qc-summary, quality-trim, repair, reverse-complement, search-motif, search-text, sequence-filter, subsample, translate and trim. Each prints `--compress is not supported by fastq <subcommand>. Remove it to write plain output.` and exits with status 64 before it writes a file, and its help no longer lists the flag. Before, they accepted the flag and recorded `compress` as true, but the flag changed nothing in the output. `fastq merge`, `fastq materialize` and `fastq scrub-human` still write gzip with `--compress`. A script that passed `--compress` to one of the 20, and a command copied from the argv of an earlier record, must drop it. `fastq trim` still writes gzip when the output name ends in `.gz`.

**Cancelling a command.** A rare cancel can no longer end `lungfish-cli` by SIGBUS.

## Known issues

This release closes seven known limits of 2026.10.21 and narrows or rewrites nine. It closes the limits about a Viral Recon run into a results folder that an earlier run used, the zstd lookup in Homebrew folders, the primer design command that needs an `Analyses` folder, `lungfish-cli fastq translate --compress`, an export from a NAO-MGS result that opens from its cached rows, two GFF3 exports with different IDs and a SnpEff ANN annotation kept as one value. It narrows or rewrites the limits about adopt-mapping and GATK records, the signing key, MEGAHIT, the empty `.seq` export, GenBank feature keys, the XLSX replay of an annotation table, records written before this release, the Document tab of a renamed mapping result and the cancel of a copy between projects. The other known issues of 2026.10.21 still apply as below. Each one ends with the Phase 3 task that covers it, with the words Phase 3 candidate when no plan row names one, or with the words No task applies for a fact about records or bundles that are already written. The limits after the one about cancelling a copy between projects are new in this release.

Known limit. A cancelled or failed EsViritu run keeps its working files in its folder under Analyses. The notes of 2026.10.17 named a partial BAM and the trimmed reads among them and put them at about 15 GB for a sample of 25 million reads. If the Operations Panel lists the stopped run when you next open the project, Remove Partial Output… on its row deletes the folder after a confirmation. This is a Phase 3 candidate.

Known limit. A large sample rich in one virus can take an EsViritu run several hours, and the run has no time limit, so it goes on until it ends or you cancel it. The rising count in the log shows that it goes on, and Cancel in the Operations Panel stops it. This is a Phase 3 candidate.

Known limit. The record that the app wrote for every TaxTriage result made by 2026.10.19 or earlier, or by 2026.10.20 with the `legacy` key set, still names `count/`, `fastp/` and `top/` files that LGE removes after the database build, so some names in it point at files that are gone. Read a `count/`, `fastp/` or `top/` name in such a record as a file that the database build removed. The record at the top of such a run also names files in `filterkraken/`, `get/`, `map/`, `samtools/`, `mergedsubspecies/` and `mergedkrakenreport/` that the same cleanup removed, and they read the same way. The record of a run made by this release is the command's, which keeps `top/` and names no removed file. For a record that keeps the top report on an earlier result, run `lungfish-cli taxtriage run --project` in Terminal. No task applies, since the records are already written.

Known limit. A Viral Recon run keeps an unsigned copy of its record in its results folder on purpose, and the record in the run bundle holds the digest of that folder. `lungfish-cli provenance verify` throws on a record that has no signature file, so on the results folder it ends with exit status 64 and prints `Workflow execution failed: Signature artifact is missing` with the path of the missing `.lungfish-provenance.json.signature.json`. It does not say that the copy is unsigned on purpose or name the bundle. When the run had a signing key, `lungfish-cli provenance verify` on the run bundle prints `Signature valid`, so check the run there. This is a Phase 3 candidate.

Known limit. A bundle that took two or more `bam adopt-mapping` or GATK runs before this release kept only the last one's mapping record or GATK run record. Lungfish shows no such record for the earlier tracks, and their attach records still name the files they used. No task applies, since the bundles are already written.

Known limit. A signing key does not sign every record. With `LUNGFISH_PROVENANCE_SIGNING_KEY` or `LUNGFISH_PROVENANCE_SIGNING_KEY_FILE` set, these records still stay unsigned. They are the records that the ENA FASTA download, `lungfish-cli fetch` and the Savont clustering pipeline write under a staged file name, the receipts of a metagenomics database install, the records of `lungfish-cli bam adopt-mapping` and of a GATK call into a bundle, the inner Primer3 records of a primer design bundle, the records that a copy between projects, a native project copy, an attachment import and the rehydration of an imported record rewrite, and the log that an annotation import appends to. A run with no key that writes into a record or a log whose record is signed leaves it unsigned on every route, and it never reads as tampered. The new record states the provider, key fingerprint, covered digest and signing time of the signature it removed, and an older build that rewrites such a record or appends to the log drops that entry. If your lab signs records, set the key for every run that writes into a signed bundle. Phase 3d covers this.

Known limit. After a Kraken2 batch run shows its first sample, the sidebar and the Inspector's Provenance tab stay on the item that was selected before the run. Click the batch's row in the sidebar to show the batch's own details. This is a Phase 3 candidate.

Known limit. A download from the Database Browser needs a project. With no project open, the browser shows the `No Project Open` sheet and starts nothing, where 2026.10.19 downloaded the bundle into `Downloads/Lungfish Downloads` in your home folder. Open or create a project before you download. This is a Phase 3 candidate.

Known limit. MEGAHIT 1.2.9, the assembler Lungfish ships, can end a run on Apple silicon in its own graph code, with a segmentation fault (exit -11) or an abort (exit -6). Lungfish runs it on one thread and without the hardware-accelerated core. In 40 test runs of a small SARS-CoV-2 sample at one thread, none ended that way and all 40 wrote the same contig file. At two threads 1 of 40 runs ended with a segmentation fault and the 39 that finished wrote 16 different contig files. In 37 of them the contigs were the same 12 as at one thread in another order, and in 2 they were different. An earlier test saw 2 of 20 runs at two threads end that way. These counts are too few to show that one thread is safer, so the cap rests on the repeatable result. Counts above two threads were not tested. If an assembly ends that way, run it again, or assemble the reads with SPAdes or SKESA, and keep the crash report from `~/Library/Logs/DiagnosticReports` if you report the problem. This is a Phase 3 candidate.

Known limit. A copy of a project that LGE has open, such as a Finder Duplicate or a backup put back in place, still shows the sheet that reads the project's name and `may already be open`, and the sheet names LGE until you quit LGE. This is a Phase 3 candidate.

Known limit. LGE cannot check a database that shows Unverified where it is, so Update downloads the whole database again. This is a Phase 3 candidate.

Known limit. When the integration-tier gate kills a test class at its time bound, its report names the XCTest case that was running. If the running test is a Swift Testing function, the report still says `a case the log does not name`, because the gate reads the start lines of XCTest cases only. This is a Phase 3 candidate.

Known limit. A CZ-ID import that you cancel while it converts the report can leave a half-written bundle. LGE gives the command 6 seconds to stop, and a conversion that outlives them is ended by force, which can leave a half-written `.lungfishtax` bundle in the project's `Classifications` folder. Importing the same report again then stops with `Classification bundle already exists`, so remove that bundle first. This is a Phase 3 candidate.
