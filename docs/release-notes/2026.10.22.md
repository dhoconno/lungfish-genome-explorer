# Lungfish 2026.10.22

Channel: Preview

Previous versioned release: v2026.10.21

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release is Preview 2026.10.22. It follows Preview 2026.10.21, and the sections below list what changed for a person who uses Lungfish Genome Explorer (LGE) or `lungfish-cli`.

The three hidden keys that 2026.10.21 added are gone. They are `ClassifierBlastRoute`, `RegionExtractionWithoutBundleRoute` and `CrossProjectCopyRoute`, and a value that you set for any of them has no effect. The BLAST Verify actions, the extraction of a region from a document and the copy of an item from another project now have one route each, the `lungfish-cli` command that was their default. A value left in your preferences is harmless, and `defaults delete com.lungfish.browser.preview <key>` removes it, where `com.lungfish.browser.preview` is the identifier of this Preview.

The owner check list under Checks still to run blocks a Stable promotion until a walk with a person at the Mac has covered every row.

## Reads and downloads

**Archives with an unsafe link.** Archive imports and database downloads now refuse an archive that holds a symbolic link pointing outside its folder, and the message names the link. This covers a Geneious archive, an application export archive, a CZ-ID ZIP, an NCBI Datasets download, an EsViritu database, an offline conda pack and a metagenomics database install.

**NAO-MGS import.** The NAO-MGS import now gives a sample no BAM and keeps its hits when samtools rejects one of the last few hundred reads of the sample while the BAM is built, and the log gives samtools' message. Before, such a sample got a BAM that held only the reads before the rejected one.

**Result imports.** The Import Center now runs `lungfish-cli import kraken2`, `import esviritu`, `import taxtriage`, `import nao-mgs` or `import nvd` for a result, and the row shows the command with `--format json`. The app no longer carries a helper mode for these imports. Cancel ends the import as Cancelled inside 6 seconds, removes only the folder that its own run began, so another import in the same Imports folder stays whole, and records the cancel. The record of each import names the sample ids of the result, with an Illumina `_S<n>_L<n>` tail cut from a NAO-MGS id, and a digest of the source result. The combined TaxTriage report `all.odr.txt` is no sample, so a TaxTriage record does not name it.

**BAM, CZ-ID, alignment and tree imports.** The Import Center runs `lungfish-cli import cz-id` for a CZ-ID result, and a cancelled CZ-ID import ends Cancelled inside 6 seconds. A new BAM import record names `lungfish-cli import bam`, a command that you can run. Older records keep the old helper command, and an export lists that step as an in-app step and does not replay it. The app no longer has its BAM helper mode. `lungfish-cli import bam` into a plain folder prints progress events with `--format json`. A cancelled `lungfish-cli import msa` or `import tree` never leaves a part of a bundle in the project, because the bundle is written aside and moved into place in one step.

**VCF import.** The Import Center imports a VCF with `lungfish-cli import vcf` in one process at every size and profile. A compressed VCF of 1 GB or more, with 128 or more contigs, or at the Ultra Low Memory profile no longer splits by chromosome into child processes, and the import profile you choose still sets its memory use. A compressed VCF whose header lists more than 512 contigs, or that has records on a contig its header does not list, now imports every record. The earlier split by chromosome skipped those records, so a track built from such a file by an earlier version lacks them, and importing the file again with the replace choice adds them. A cancelled VCF import ends Cancelled inside 6 seconds. Copy CLI Command copies the exact command, `--resume` and `--materialize` included, and each of those two refuses a track that is already finished. The VCF import helper is gone.

**Translate.** `lungfish-cli fastq translate` numbers the mates of an interleaved pair that share a read id with `.1` and `.2`, and its help says what the frame labels mean. Only interleaved and mixed inputs change. The FASTA ids of two adjacent mates that share a read id gain `.1` and `.2` right after the id, so the ids are unique. A single-end file, a pair named with `/1` and `/2`, a long-read bundle and a mixed file recorded as single-end keep every byte.

## Alignments, bundles and variants

**Tools that cannot start.** When a tool cannot be started, the error now reads Could not launch, then the tool's name in quotes, then the reason, where it showed the operating system's own message. This applies to the samtools steps of Mark Duplicates, whose error also names the failed stage `launch` where it named `markdup-pipeline`, to the samtools merge and index steps of the ONT barcode demultiplexing genotyping pipeline, to the Python renderer of a genotype workbook export, to the MAFFT alignment of discriminating sites, to the pair merge of the Illumina amplicon pipeline and to the bgzip or pigz step of a paired FASTQ import.

**Region extraction from a document.** The hidden key `RegionExtractionWithoutBundleRoute` is gone, and a value that you set for it has no effect. Extracting a region to a new bundle from a viewer that shows a document with no reference bundle always runs `lungfish-cli extract sequence`, as it did by default, and the earlier in-process route is removed. When Lungfish cannot write the copy of the document's sequence that the command reads, it now removes the folder it made for that copy in the project's `.tmp` folder, where earlier versions left the folder in place.

**Export Sequences….** Export Sequences… in the sidebar now runs `lungfish-cli convert` for an open document or a project sequence too, so the Operations row shows the command. It runs the command on a copy that the app saves in the project's `.tmp` folder, or in the system temporary folder when no project is in reach or the project cannot be written. A file that Lungfish cannot read by name, such as a `.seq` or `.txt` file, is copied as FASTA first. In 2026.10.20 an export that included a document held in memory with no file, or such a file, was written in the app and recorded no command.

**GenBank files.** GenBank files that Lungfish writes, from Export Sequences… or from `lungfish-cli convert`, no longer hold the internal qualifiers `/_lf_raw_feature_type` and `/_lf_raw_genbank_location` under each feature. Earlier releases wrote them when the source was a GenBank file.

**Primer design.** The PCR Primer Design dialog runs Primer3, PrimalScheme3 and varVAMP designs through `lungfish-cli primers design`, so a design can be cancelled like any other command, the row shows the command's progress, and Copy CLI Command gives the command that ran. The row text is unchanged. A blank assay rule now records `primer3-default`. A failed `lungfish-cli primers design primer3`, `primalscheme3` or `varvamp` now exits with status 64 after its failed event, where it exited with status 1. An existing `--output` is now refused with status 3, and a cancel now ends the command with status 125. An Olivar design still runs inside the app, and `olivar` still exits with status 1 on failure. A replay of the recorded command to a bundle is proven on the real tool for Primer3, PrimalScheme3 and varVAMP. For Olivar the recorded command is proven to resolve to the dialog's options.

**AI Haplotyping.** The AI Haplotyping row records `lungfish-cli genotype ai-haplotyping` with the provider and model that it resolved. If the bundle changes before the run starts, the row records the command that the run used, and the log says so. The API key reaches no row, log, sheet or record. The recorded command replays through the CLI with the key in its environment and sends the same provider request. The run itself stays inside the app.

**Bundle merge records.** The record of a reference bundle made by Merge Into New Bundle… or by `lungfish-cli bundle merge` now names `lungfish-cli bundle merge` and the arguments that the merge process started with, where it named `lungfish-app` and a command that nothing can run. The Provenance tab shows that command, Copy Command copies it, and a project replay export now lists the merge step. The record of a merged FASTQ bundle is unchanged and still names `lungfish-app`. Bundles merged before this release keep their old record.

**Mapping result counts.** Mapping results against references with many sequences, such as SILVA, now list only the reference sequences that have alignments, and the bar above the list says how many, for example 94 of 905,628. A new result records how many sequences the reference holds and how many it left out. Results made by earlier versions show as before.

**Map Reads on a plain FASTA reference.** A Map Reads run on a plain FASTA reference no longer shows `Preparing reference mapping viewer...` or moves its bar back, since such a run makes no viewer bundle.

**Opening large references and mapping results.** Opening a reference or a mapping result decodes its manifest once, off the main thread, and runs one large decode at a time. It also builds the sequence index and the chromosome name index once, off the main thread, and the viewer and its data provider share them. The loading toast of a reference open that another selection replaced is hidden.

**Sorting and lookups in large references.** Sorting a long sequence list by name or by chromosome builds each sort key once, and the annotation search builds its alias groups on the first lookup and only for a bundle that has tracks. A bundle reads the `.fai` file of its genome once and finds a chromosome by name through one index. A genome that is replaced on disk while its bundle is open is read with the index that was loaded first, so open the bundle again to see the replacement.

**Smaller manifests.** A new reference bundle's `manifest.json` no longer stores a browser summary that Lungfish can build from its sequences, so the manifest of a large reference such as SILVA SSU NR99 is smaller. Opening such a bundle in the viewer builds the summary in memory, off the main thread, and writes nothing into the project. Older bundles are unchanged until their next save, and `lungfish-cli project migrate` reports a manifest that stores no summary as current when Lungfish can build the summary again.

## Tools and packs

**Unverified databases.** A database that LGE has not checked against a catalog build now shows Unverified in place of a version and offers an update, and new classification records give it no version. Such a database is a folder an older build adopted under a catalog name, a database downloaded by v0.5.0-beta26 or earlier, or one that LGE finished from a staged copy after an interrupted update. Records made earlier keep the version they recorded. `lungfish-cli tools update --include-databases` plans an update for it too.

## Classifiers

**BLAST Verify.** The BLAST Verify actions of the NVD, EsViritu, TaxTriage, 12S and Kraken2 results now run `lungfish-cli blast submit`, so each row shows the command to copy and Cancel stops the whole tool tree. The record of a search names the SHA-256 of its query and the result or bundle that it came from. A failed NVD or EsViritu search leaves a `failed` record beside the query copy. With no project open, the NVD and EsViritu actions show the alert `No Project Open` over `Open or create a project before running BLAST.` and start nothing.

**BLAST Verify rows that extract reads.** The EsViritu row appears at once with `Extracting reads for selected accessions…`, Cancel stops the BAM extraction and the search, and the command shows once the reads are in. The TaxTriage and 12S rows also appear at once. Cancel stops the BAM extraction of a TaxTriage search or the export of a 12S search and then the search, and the command shows once the reads or sequences are in. The record of a TaxTriage search names the tax ID and the accessions, and the record of a 12S search names the bundle. The record of a TaxTriage search names the sample whose BAM it searched, a re-run from the results drawer searches the same BAM, and a request from the organism table with no sample picked records none.

**Kraken2 BLAST Verify.** A cancel during the read lookup ends the row as Cancelled with no search. The search keeps NCBI `nt`, and its record names the database, the taxon, and the count and seed of the read draw. The search is saved in the `blast-verifications` folder of the result, where reopening the result shows it again beside older saved verifications.

**The `ClassifierBlastRoute` key is gone.** A value that you set for the hidden key `ClassifierBlastRoute` has no effect. The BLAST Verify actions of the NVD, EsViritu, TaxTriage, 12S and Kraken2 results always run `lungfish-cli blast submit`, as they did by default. The earlier in-process search of these five actions is removed, and so is its key.

**Extraction.** Copy CLI Command now replays a clipboard or share extraction from the classifier extraction sheet, which runs `lungfish-cli extract reads --by-classifier` into a scratch file and then copies it. A taxa collection extraction picks reads the same way as the other classifiers, and `lungfish-cli extract reads --by-classifier --tool kraken2` takes `--taxon-scope exact` for the reads classified to a taxon itself. `lungfish-cli conda extract` is gone, and its notice already named `extract reads --by-classifier --tool kraken2`.

**Extract Reads sheet.** When the BAM file of a sample is missing or is a link to a file outside the result folder, the Extract Reads sheet shows the whole reason, shows no read count and turns off its main button, which reads Create Bundle, Save, Copy or Share by destination. Any other failed read-count estimate no longer shows a count of 0.

## Records and the Provenance tab

**Mapping and GATK records.** Each adopted track and each GATK call into a bundle keeps its own run record, `<bam stem>.mapping-provenance.json` for an adopted mapping and `<track>.gatk-run.lungfish-provenance.json` for a GATK call, and older bundles still read. A failed `lungfish-cli bam adopt-mapping` returns the BAM and its index to the mapping folder and removes only the files that it made. Mapping records now list the `samtools coverage` and `samtools view` passes that made the summary rows, and an exported script names them in a comment and does not run them.

**More records sign.** With `LUNGFISH_PROVENANCE_SIGNING_KEY` or `LUNGFISH_PROVENANCE_SIGNING_KEY_FILE` set, more records now sign. They are the records of the commands blast submit (its failures), fastq demultiplex, fastq deacon ribo, `fetch ncbi`, import metadata, project migration, run, SRA download, `variants extract-sample` and `variants query`, the records of the app's sample metadata imports and their edits, VCF auto-ingest, FASTQ ingestion and operation outputs, workflow operation runs and the FASTA operation catalog, and the records of variant track attachments, workflow runs, VCF attaches, the app's other imports, builders and exports, and full-length genotyping. Without a key the records are the same as before.

**Who a record names.** A record of work that Lungfish Genome Explorer does in its own process now starts its command with Lungfish Genome Explorer, where older records started it with Lungfish.app, lungfish-app or lungfish-gui. Its tool name and tool identity read Lungfish Genome Explorer too, except for step names that keep their own words, such as those that start with `lungfish-app-action`. A record that carries a tool kind says gui for the app, and the FASTQ auto-bundle record said app before. A command copied from such a record shows the name in single quotes, since the name holds spaces, and it is no program to run in a terminal.

**Records that the command line writes.** A reference annotation or variant record that `lungfish-cli` writes now names `lungfish-cli` as its tool, where it named Lungfish Genome Explorer. This covers `sequence attach-track`, `sequence add-annotation`, `variants delete`, `variants import-sample-metadata`, `import` with annotations, `import geneious` and `primer-analysis`. A reference allele database record that `lungfish-cli haplotypes` writes when it creates, installs, saves or replaces a reference names `lungfish-cli` with kind cli, where it named Lungfish Genome Explorer with kind app. The record of `import fasta` with `--annotations` and the record of `import geneious` now name the command that was run, where they named `lungfish-cli annotation-import`, a command that does not exist. The bundle record of an annotation import and the variant records that the app writes now carry kind gui, where they carried cli. A record that the Haplotype Definitions window writes names Lungfish Genome Explorer with kind gui, starts its command with that name and holds no replay line.

**Exported scripts and app steps.** An exported script runs `lungfish-cli variants delete` for variants that you delete from the table, one variant or all of them, because a test shows that the command writes the same database bytes as the app, and the record names Lungfish Genome Explorer as what ran. Saving classifier-extracted reads to a file runs `lungfish-cli extract reads --by-classifier` in an exported script in the same way, except that a selection which carries a read-name allowlist, such as NAO-MGS rows, names its step and does not run it. The MSA annotation edits that the app records, Add annotation from an MSA selection and Apply annotation to selected rows, now read Lungfish Genome Explorer as their tool name, where they read `lungfish-gui msa annotation edit`.

**FASTQ bundle merge.** The record of a merge of FASTQ bundles now names its workflow `FASTQ bundle merge`, where it named `lungfish fastq merge`, which the pair merge of `lungfish-cli fastq merge` also records. Its command starts with Lungfish Genome Explorer, where it started with `lungfish-app`, and its kind reads gui.

**Primer records.** The records that a native primer inspection, a PrimalScheme3 design and a PrimalScheme3 allele label map write now keep a slash as typed, as the writer's records do, where they wrote it as `\/`. Nothing else in them changes.

**ONT haplotype definition snapshot.** The haplotype definition snapshot that the ONT barcode demultiplexing genotyping pipeline saves, `artifacts/haplotyping/haplotype-definition.json`, now reads 0644 under umask 022 like the other records, so the others on a project shared through a lab server can read it. It read 0600 before. A snapshot that an earlier release saved keeps 0600, and `chmod 644` on the file lets the others read it.

**Copy Step, Copy Command and Copy All Steps.** In a mapping result's Inspector, each command in Run Settings now expands to its full length without drawing over the rows below. Copy Step, Copy Command and Copy All Steps copy steps as plain text from a step's copy button, its context menu, its VoiceOver actions or Command-C. Each Lineage step on the Provenance tab offers the same three commands from its context menu and its VoiceOver actions, and Command-C copies a focused step.

**Commands after a rename.** After a rename or Duplicate, a step's Command row and Copy Command on the Provenance tab name the renamed folder, and the note beside the Command row says where the command ran and where the record is now. Copy Step and the tooltip keep the command as it ran. A command's tool reads by its name on every Mac, whatever its storage root. The mapping Document tab shows each command with project paths relative to the project, and Copy Command copies it whole. Records are unchanged.

**Signed records.** With `LUNGFISH_PROVENANCE_SIGNING_KEY` or `LUNGFISH_PROVENANCE_SIGNING_KEY_FILE` set, the records of `sequence annotate-orfs` and `sequence delete-annotation-track` and the log that Add Annotation appends to now sign. So do the records of a cancelled alignment workflow, consensus or read extraction and the file record of a read extraction, and a consensus published as a FASTA file keeps a signed record. A later run takes a cancelled record's signature files with the record. The log's signature covers the whole file as it is at the write. A record, or the Add Annotation log, that a later run without a signing key rewrites now states the provider, key fingerprint, covered digest and signing time of the signature it removed, under `priorSignatures`.

**Record modes.** Records written by `lungfish-cli` now read 0644 under umask 022 like the records the app writes, so a project shared through a lab server can be read by the others on it. Files that are private on purpose, such as markers, workbook state, export staging, the operation history and the cleanup receipts, keep 0600.

**Lineage walks.** The Lineage walk of the Provenance tab now stops when you select another item, and the walks of one project share one index of its record files, so a later walk does not read every record file again. A provenance export is no longer cut short when a walk is cancelled.

**EsViritu records.** The record beside each EsViritu BAM and BAI file now keeps only the steps of its own sample. The record beside the database keeps every step that has no outputs, so it still lists every read count of the run, and the record of the batch keeps the whole run. Older records read as written.

## Projects and the sidebar

**Copy between projects.** The hidden key `CrossProjectCopyRoute` is gone, and a value that you set for it has no effect. A project item dropped on the sidebar from another project always runs `lungfish-cli project copy-item`, as it did by default, and the earlier in-app copy is removed.

**New Folder and Copy Path.** New Folder… is enabled when you right-click an empty part of the sidebar in an open project, and Cmd-Shift-N works with nothing selected while the sidebar has focus. Copy Path copies one path per line when several rows are selected, and the context menu then reads Copy 2 Paths.

**Copy Name.** Copy Name, in the sidebar's context menu and in Selection > Sidebar Item, copies the names of the selected items, one per line. Command-C does the same while the sidebar has focus. With several rows selected the context menu counts them, so three rows read Copy 3 Names, and the Selection menu keeps Copy Name.

**View state saves.** Panning and zooming in a large reference or mapping result no longer makes the sidebar and the project search read the project again after each pause. On a project stored on an exFAT, SMB or NFS volume the search can still read the bundle again after a save.

## Known issues

Five known limits of 2026.10.20 are closed and three are narrower. The limit about the hidden key `TaxTriageLaunchRoute` went with the key. The limit about the Import Center's metagenomics, NVD and CZ-ID imports is closed, because those imports now run `lungfish-cli import` commands. The limit about the missing `primers analysis export-selection` command is answered, because the command exists. The limit about the text of a sequence export is closed, because Export Sequences… now runs `lungfish-cli convert` for every selection and tests pin the text of a GenBank file, a `.gz` file, FASTQ and a mixed selection. The limit about the records of earlier TaxTriage results now names the releases that wrote them. The limit about the integration-tier gate is narrower, because the gate was shown to name the XCTest case that a killed class was running. The limit about records that stay unsigned now names only the records that still stay unsigned. The limit about a database that an older build adopted is closed, because the Databases tab now shows such a database as Unverified, and a new limit says what an update costs. The other known issues of 2026.10.20 still apply as below. The limits after the one about the integration-tier gate are new in this release.

Known limit. A cancelled or failed EsViritu run keeps its working files in its folder under Analyses. The notes of 2026.10.17 named a partial BAM and the trimmed reads among them and put them at about 15 GB for a sample of 25 million reads. If the Operations Panel lists the stopped run when you next open the project, Remove Partial Output… on its row deletes the folder after a confirmation.

Known limit. A large sample rich in one virus can take an EsViritu run several hours, and the run has no time limit, so it goes on until it ends or you cancel it. The rising count in the log shows that it goes on, and Cancel in the Operations Panel stops it.

Known limit. The record that the app wrote for every TaxTriage result made by 2026.10.19 or earlier, or by 2026.10.20 with the `legacy` key set, still names `count/`, `fastp/` and `top/` files that LGE removes after the database build, so some names in it point at files that are gone. Read a `count/`, `fastp/` or `top/` name in such a record as a file that the database build removed. The record at the top of such a run also names files in `filterkraken/`, `get/`, `map/`, `samtools/`, `mergedsubspecies/` and `mergedkrakenreport/` that the same cleanup removed, and they read the same way. The record of a run made by this release is the command's, which keeps `top/` and names no removed file.
