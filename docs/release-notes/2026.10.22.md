# Lungfish 2026.10.22

Channel: Preview

Previous versioned release: v2026.10.21

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

In this Preview, cancels and failures are reported more exactly, from a copy between projects to an export that finished just before you clicked Cancel. Viewer images are now drawn from the bundle's files, and records name what ran, which values a run worked out for itself and which commands an exported script runs. Exports, classifier tables, variant tables and primer design also carry a number of corrections.

## What's new

### Reads and downloads

Exports to zstd and imports of `.zst` and `.xz` files now use tools that Lungfish manages, so they no longer need Homebrew. An `.xz` import never worked on a Mac without `/usr/bin/xz`, which macOS does not ship, and now it does. Lungfish adds zstd and xz to its Required Setup (see Updating).

### Variants, annotations and primers

- **Genetic codes.** The variant table and the hover now use the genetic code that a coding feature names (`transl_table` or `genetic_code`). The variant table, the hover, the translation and both GFF3 exports also read a coding feature of a bundle in the reading frame that its annotation file gives it, which is the phase in GFF3 and the codon start in GenBank.
- **SnpEff and VEP annotations.** Lungfish now splits SnpEff ANN and VEP CSQ annotations into their fields at every import profile, so the High Impact filter and filters on ANN fields such as ANN_IMPACT find variants.
- **Primer design commands.** The Primer3, PrimalScheme3, varVAMP and Olivar design commands of `lungfish-cli` take `--project` and `--name`, so each design writes a new analysis in the project. Copy CLI Command of a primer design now gives these options, and the command replays in a project with no Analyses folder.
- **Primer order and selection exports.** These exports now run `lungfish-cli` behind their rows in the Operations Panel, so Copy CLI Command replays them and a cancel leaves no folder behind. A replay of a Primer FASTA bundle or reference amplicon export stops until you name a new output folder.

### Viewer images

When the viewer shows a genome bundle, File > Export > Image (PNG)… and Image (PDF)… now run `lungfish-cli bundle export-graphic`, so Copy CLI Command on the export's row in the Operations Panel copies the command. The command also takes a BED file with `--regions-file` and writes one image for each region.

### Records and the Provenance tab

- **More records are signed.** When your lab sets `LUNGFISH_PROVENANCE_SIGNING_KEY` or `LUNGFISH_PROVENANCE_SIGNING_KEY_FILE`, more records are now signed, among them those of SRA downloads, sample metadata imports and edits, FASTQ ingestion, workflow runs, VCF attaches and full-length genotyping. Without a key the records are the same as before.
- **One record for each mapping and GATK call.** Each adopted mapping track and each GATK call into a bundle now keeps its own run record, and older bundles still read.
- **Kraken2 table records.** The record of a Kraken2 taxonomy table export now names the reference database of each sample as that sample's classification result recorded it, with a name, a version and a digest. When the result records no digest, the record says unknown and gives the reason.

## What works differently

### Reads and downloads

- **Archives with an unsafe link.** Archive imports and database downloads now refuse an archive that holds a symbolic link pointing outside its folder, and the message names the link. This covers Geneious archives, application export archives, CZ-ID ZIP files, NCBI Datasets downloads, EsViritu databases, offline conda packs and metagenomics database installs.
- **Long reads.** A bundle recorded as Oxford Nanopore or PacBio is now read as single-end reads, not as read pairs, by every FASTQ operation, mapping, assembly, Kraken2, TaxTriage, Viral Recon and recipes, even when some of its read ids repeat. A file with no recorded platform is not covered (see Things to know).
- **NAO-MGS import.** When samtools rejects one of the last few hundred reads of a sample while its BAM is built, the import now gives that sample no BAM, keeps its hits and puts samtools' message in the log. The sample's record has no step that says why, and for a large sample the log may say only that a pipe broke. Before, such a sample got a BAM that held only the reads before the rejected one.
- **MEGAHIT on Apple silicon.** Because more threads can crash it, a MEGAHIT assembly on an Apple silicon Mac now runs on at most one thread, whatever the Threads setting says, and the assembly dialog says so under Threads. The run record and the bundle metadata name the thread count and the memory the run used.
- **The `--compress` option.** Twenty `fastq` commands of `lungfish-cli`, among them `fastq trim`, `fastq subsample` and `fastq deduplicate`, now refuse `--compress`, which never changed their output. Drop it from any script that passes it to one of them. `fastq merge`, `fastq materialize` and `fastq scrub-human` still write gzip with `--compress`.

### Classifiers

- **BLAST Verify.** The BLAST Verify actions of NVD, EsViritu, TaxTriage, 12S and Kraken2 results always run `lungfish-cli blast submit`, as they already did by default.
- **Kraken2 tables of several samples.** Each row's Clade % and Direct % is now a percent of its own sample's reads, unclassified reads included, where before it was a percent of all the picked samples' reads. Each sample keeps its own unclassified row, and a table of one sample is unchanged.
- **Kraken2 exports from older results.** Exporting a Kraken2 result stops with a message when an older version of Lungfish built the result's own database (not the reference database), since that database may hold Bracken's estimates in place of Kraken2's read counts.
- **TaxTriage rows.** A TaxTriage row no longer opens, searches or extracts another sample's reference. When the row's own sample has no reference accession for the organism, the alignment pane stays closed, and Extract Reads leaves the row out, names it under the selection count and opens for the other rows. If no selected row has an accession, an alert titled Nothing to extract explains why.
- **Export buttons.** The Export button of NVD and EsViritu results is disabled until a sample is picked, and that of NAO-MGS and NVD results is disabled until the result finishes opening.

### Variants, annotations and primers

- **Variant table exports.** An export of the Variants tab now fills Gene / Protein, Consequence and AA Change for each exported variant that lies in a coding feature, also outside the part of the genome that the viewer has cached, where 2026.10.21 left those cells blank. The table on screen still fills them only for the part of the genome that the viewer has cached. If one annotation track holds at least 50,000 annotations in the span of the exported variants, the export stops with a message that names the track and the span, and writes no file.
- **Empty files.** Export Sequences… of an empty file, or of one that holds only white space, stops with Export Failed and writes nothing.
- **GenBank and GFF3 exports.** GenBank files that Lungfish writes keep each feature's key and location as the source GenBank file had them, such as CDS and the partial markers `<` and `>`, as long as the feature's type, ranges and strand are unchanged. Other features, such as those from a GFF3 or BED source, still print the key in lower case, for example cds. A GFF3 export keeps each feature's ID from the imported file and gives a feature that came without one an ID from its row, so two exports of one bundle are the same file. A feature with two parents, or an attribute with a list of values such as Dbxref, is written as one value with encoded commas.

### Viewer images

An image of a genome bundle is now drawn from the bundle's files and is no longer captured from the screen. It shows the region that the viewer shows and draws the sequence, annotation, variant and read tracks, but it leaves out a signal track, and its track heights, spacing, colours and fonts differ from the viewer's. Its read track is 200 points high and holds at most 75 rows of reads where the viewer can show more, so in deep coverage the image can show fewer reads than the viewer. Its record names anything that it leaves out for a limit, and the record and the Operations log both name a signal track. In the sequence track the image turns coloured blocks into a grey bar at 300 bases a point, where the viewer waits until 500.

The image follows the app's light or dark appearance when you export. The Scope menu reads Tracks, Ruler and Tracks, and Selected Region, and the annotation table is no longer part of the image, so use the table's own export for it. The Export Successful alert no longer appears, and the finished row in the Operations Panel names the file. When the viewer shows anything else, such as a classifier result, an alignment, a tree or a PDF, the export still captures the whole pane as before.

### Records and the Provenance tab

- **Steps that ran inside the app.** On the Provenance tab, such a step, for example a merge of FASTQ bundles, keeps its recorded words in the Command row with a note that it has no command to run in Terminal. Its Copy Command is turned off, Copy Step still copies the step, and Copy CLI Command in the Operations Panel appears only for a `lungfish-cli` command.
- **Who a record names.** A record of work done inside the app now names Lungfish Genome Explorer, where older ones named Lungfish.app, lungfish-app or lungfish-gui. An annotation or variant record that `lungfish-cli` writes now names `lungfish-cli` as its tool.
- **Options and resolved values.** EsViritu, Kraken2 and TaxTriage records no longer list values that the run worked out for itself, such as the paired-end flag or a sequencing platform read from the bundle, as options that you chose. They now appear among the values the run resolved, and a platform that you type stays an option that you chose. A script that reads only a record's options does not see them.
- **Renamed and moved results.** The Command row, Copy Command and the Document tab of a mapping result show the command of a moved or renamed result folder in the folder where it is now. An exported shell or Python script now needs `OUTDIR` set to a new folder, writes every output there, checks each input's SHA-256 before it runs and does not write into the result folder it came from, except where the record cannot be mapped to the new place, such as after a Move that also renames. Snakemake and Nextflow exports do not take `OUTDIR`.

### Projects

- **Hidden settings removed.** The three hidden settings that 2026.10.21 added are gone, and a value left set for any of them has no effect.
- **Cancelling a copy between projects.** Cancel now stops a copy between two projects on one APFS disk, as a Mac's own disk is, within moments, whatever the size of an item that carries no provenance record. For a very large item that carries a provenance record, Cancel can still take several seconds.
- **Cancel just after an export.** A Cancel that lands just after an export wrote its file now leaves the row Completed, with the file's link and the detail Finished before Cancel took effect. The Haplotype definition, genotype, 12S amplicon and provenance report exports still read Cancelled by user in that case, as does an analysis run that had just finished.

## Things to know

### Reads and downloads

- **Downloads need a project.** With no project open, the Database Browser shows a No Project Open sheet and downloads nothing. Open or create a project before you download.
- **MEGAHIT crashes.** MEGAHIT can end a run on Apple silicon with a segmentation fault (exit -11) or an abort (exit -6). Run the assembly again or use SPAdes or SKESA, and keep the crash report from `~/Library/Logs/DiagnosticReports` if you report the problem.
- **Cancelled CZ-ID imports.** A CZ-ID import cancelled while it converts the report can leave a half-written `.lungfishtax` bundle in the project's Classifications folder. Remove that bundle before you import the same report again, or the import stops with Classification bundle already exists.
- **Long reads with no recorded platform.** A FASTQ file copied out of its bundle without its metadata and handed to a tool with no bundle named, and a derived bundle whose parent bundle can no longer be found, carry no recorded platform. Oxford Nanopore or PacBio reads in them that repeat an id can still be read as pairs, so run long reads from a bundle that records its platform.
- **Database archives with an absolute link.** An archive whose symbolic link has an absolute target is refused even when the target lies inside the folder. It is not known whether the official Kraken2 and EsViritu database archives hold such a link, and an archive that does fails to install.

### Classifiers

- **Stopped EsViritu runs.** A cancelled or failed EsViritu run keeps its working files in its folder under Analyses, which can reach about 15 GB for a sample of 25 million reads. If the Operations Panel lists the stopped run when you next open the project, choose Remove Partial Output… on its row to delete the folder.
- **Long EsViritu runs.** A large sample rich in one virus can take an EsViritu run several hours, and the run has no time limit, so it goes on until it ends or you cancel it. The rising count in its log shows that it is still going, and Cancel in the Operations Panel stops it.
- **Kraken2 batches.** After a Kraken2 batch run shows its first sample, the sidebar and the Provenance tab stay on the item that you had selected before. Click the batch's row in the sidebar to see its own details.
- **Kraken2 table records with an unknown database.** A table exported from a result folder that holds several samples and no batch manifest records each sample's database name, version and digest as unknown. When the manifest exists but a sample has no classification result, only that sample's digest is unknown. A digest appears only when the database folder's install receipt backs it.
- **TaxTriage rows without an accession.** Extract Reads can leave a row out even though its sample's BAM holds reads for that organism, for example when a mapping file was missing as the database was built. A database built again with the file present gives the row its accession. A row with an organism id and no stored accession can also match another organism of the same sample by a similar name and open that organism's reference.

### Variants and annotations

- **Variant files imported earlier.** A variant file imported before this release keeps its old rows, so the High Impact filter can run slower and its chips show no count. Import the file again to split its annotations into fields.
- **Annotation tracks imported earlier.** A coding feature of several segments in a bundle imported before this release is still read from its first base, so its Consequence and AA Change can be wrong when its first segment has a phase of 1 or 2. Import its annotation track again to read it in its own frame. A coding feature of one segment is read in its own frame without a new import, unless it is on the reverse strand and was cut at the end of its sequence. A reverse-strand coding feature that runs past the end of its sequence in the annotation file is stored cut at that end and the length cut is not recorded, so the AA Change of its variants can number residues from the cut.
- **Extracted regions carry no annotations.** A region extracted to a new bundle from a sequence of the project keeps none of the sequence's annotations, and the bundle's record does not say so.

### Records, exports and projects

- **Cancelled copies across disks.** Cancelling a copy between projects on two disks, or on a disk that is not APFS such as an ExFAT drive, can leave a staging folder as large as the item in the hidden `.tmp` folder of the project you copied into. Lungfish moves it to the Trash within 4 hours while that project is open, or you can move it with File > Manage Project Storage…, and then empty the Trash.
- **Records shared on a lab server.** Records that an earlier `lungfish-cli` wrote, and an ONT haplotype definition snapshot that an earlier release saved, keep mode 0600, so others cannot read them. Run `chmod 644` on such a file in Terminal, or for every record of a project run `find <project folder> -name '*.lungfish-provenance.json' -exec chmod 644 {} +`.
- **Signed records.** A signing key does not sign every record, and a run with no key that writes into a signed record leaves it unsigned. If your lab signs records, set the key for every run that writes into a signed bundle.
- **Viewer export folders.** A viewer export keeps a full copy of its inputs in a hidden `.lungfish-export-inputs` folder beside the export, so it takes about twice the disk space. Keep that folder if you may want to replay the export, because deleting it breaks a replay.
- **Older bundles with several mappings or GATK calls.** A bundle that took two or more adopted mappings or GATK calls before this release kept only the last one's run record. Lungfish shows no run record for the earlier tracks, and their attach records still name the files they used.

## Updating

Choose Check for Updates… in the app menu, and Sparkle offers this release, installs it and relaunches the app. This release adds zstd 1.5.7 and xz 5.8.3 to the Required Setup, so a Mac that updates asks you once to install them. Until you do, a zstd export and an import of a `.zst` or `.xz` file stop with a message that says so.
