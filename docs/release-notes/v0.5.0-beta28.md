# Lungfish 0.5.0-beta28

Previous release: v0.5.0-beta27

This beta makes Kraken2/Bracken abundance profiling database-aware, preserves
useful Kraken classifications when downstream profiling degrades, and
strengthens replayable provenance for single-sample and batch analyses.

## In-place recovery — build 4021

This authorized in-place recovery replaces the original beta28 DMG and Sparkle
item while keeping the marketing version at `0.5.0-beta28`. Sparkle build 4021
supersedes the original build 4020. The immutable `v0.5.0-beta28` tag remains at
its original commit; exact replacement-source and artifact provenance is
attached to the GitHub release.

Build 4021 fixes Kraken2 read extraction from indexes stored on ExFAT volumes.
Completed beta28 indexes were valid and fully checkpointed, but retained SQLite
WAL mode and could fail their first read-only query with a disk I/O error on
filesystems without compatible shared-memory locking. Lungfish now opens legacy
self-contained indexes without changing their bytes, while still honoring any
nonempty WAL that may contain committed data. New indexes are checked,
finalized in portable DELETE journal mode, and published without WAL or
shared-memory sidecars. Query failures can no longer return partial read-ID sets
as successful results. Classification output-directory setup failures now fail
closed when their required provenance record cannot be saved, preserving both
the primary setup error and the secondary provenance failure instead of
suppressing the latter.

## Resolve rRNA profile rank from database identity

Automatic profiling now uses genus for stable SILVA and Greengenes catalog
identities or recipes and species for ordinary Kraken databases; explicit
supported ranks remain unchanged. Lungfish uses a fixed resolved read length of
150 bases and a configurable minimum-read threshold that defaults to 10,
verifies that the Kraken report contains the selected rank, and requires a
readable, regular, non-empty
`database150mers.kmer_distrib` before launching Bracken. Bracken version
detection uses its supported `-v` interface, and requested mode plus resolved
rank are visible in CLI output and provenance.

## Keep valid Kraken results when Bracken cannot finish

Profiling now has explicit completed and degraded outcomes. Unsupported or
absent ranks, missing distributions, unavailable tools, nonzero exits, absent
output, and parse or merge failures retain the valid Kraken report, read
classifications and index, result sidecar, and scientific evidence while
withholding failed Bracken artifacts. The CLI prints retained outputs, explains
the degradation, writes provenance, and exits nonzero; the app surfaces warning
completion instead of deleting useful results.

## Make batch outcomes honest and replayable

Classification batches persist per-sample `ok`, `degraded`, or `failed` status,
requested and resolved ranks, completed, degraded, and failed outcome counts,
and messages in schema-compatible manifests and summaries. Batch-root
provenance rolls up child evidence plus the final summary, manifest, and SQLite
artifacts. Replay scripts pin exact per-sample options and fail closed unless
the database directory, recorded installation receipt, digest, final path,
receipt status, and registry mapping still agree. Cancellation and setup or
publication failures retain batch directories and independent root evidence for
diagnosis.

## Strengthen provenance and release confidence

Classification provenance now begins before validation, removes stale
success-looking outputs, preserves durable lineage when GUI or CLI inputs are
materialized, records requested, default, and resolved options plus runtime
identity, and writes honest failure envelopes for validation, pipeline,
cancellation, and publication errors. CLI failure provenance attaches database
reference descriptors only from complete, matching installation receipts;
relative replay inputs are rehydrated to durable absolute sources. Focused
cross-layer and broader classification and provenance regression suites cover
completed, degraded, failed, replay, batch, and compatibility paths.

The app, embedded command-line tool, Help Book, and managed-tool metadata now
report `0.5.0-beta28`. This remains a signed and notarized Apple Silicon beta
DMG, published through the Sparkle beta feed with the legacy alpha bridge so
older installations can discover the update.
