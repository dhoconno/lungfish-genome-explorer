# Lungfish 2026.11.2

Channel: Preview

Previous versioned release: v2026.11.1

Stable baseline: v2026.10.29

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview brings the work since Preview 2026.11.1. A FASTA list no longer shows a GC percent for a protein record, and a TaxTriage export now reads Not checked where a negative control was only partly checked, so read What works differently before you compare with old results. When NCBI is not taking new searches, BLAST now says so.

## What works differently

### FASTA lists

- **A protein record in a FASTA list no longer shows a GC percent.** Before, its G, C, A and T letters were counted as if they were bases, so its row showed a GC percent and the GC Content card above the list counted them too. Now its GC cell reads a dash, and hovering over the dash or VoiceOver says why. The GC Content card counts only the nucleotide records, and when a list holds protein records a "Protein records, not in GC Content" card says how many.

### TaxTriage

- **A negative control that was only partly checked now reads Not checked.** When the pipeline skipped a step of a negative control after an error, or two sample names became the same name once spaces and symbols were removed so that the results kept only one of them, the organism matrix and the results table now say Not checked, not No or a blank cell, for an organism that no negative control lists. The viewer and the batch report say what happened and what to try. Export a result again to correct an earlier file.

### Reads in the viewer

- **Opening another reference returns the read filters to their defaults.** Before, the Minimum alignment confidence and the other read filters you set in the Inspector for one reference stayed set for the next one, so its reads could show pale and its depth could change under a filter you set elsewhere. Now opening another reference returns the Minimum alignment confidence, the consensus quality limits, the duplicate, secondary and supplementary toggles and the read group filter to their defaults. Selecting the same reference again keeps them.

### BLAST Verify

- **Verify with BLAST in the Kraken 2 viewer now asks NCBI for core_nt.** Before, it asked for nt, and NCBI was already searching core_nt when Lungfish asked for nt, so no result changes. `lungfish-cli blast verify` now asks for core_nt too. A check you saved earlier keeps the nt it was made with. When NCBI reports that it searched a different database than the one a search asked for, the BLAST results pane and `lungfish-cli blast verify` now say so. The saved result of a check and the provenance record of an exported table now keep the database and the BLAST version NCBI reports. A Not specific summary no longer shows two periods in a row.

## What's new

### BLAST searches

- **When NCBI is not taking new searches, the Operations row and the BLAST pane now say so and give the time Lungfish sends the search again.** Before, they said only that the search was being sent. You can keep working. In a narrow Operations Panel the row may cut off the time, so hold the pointer over the row to read all of it.

### Sidebar and Inspector

- **After you import a Kraken 2 classification, the Inspector no longer jumps to its Document tab or opens by itself.** It now behaves as it does after you import EsViritu, TaxTriage, NAO-MGS and NVD results.
- **View > Show Sidebar now opens the sidebar at a normal width.** Before, if Lungfish opened in a narrow window with the sidebar hidden and you then enlarged the window with Zoom, the command could open the sidebar so thin that you had to drag its edge to see it.

## Things to know

### BLAST Verify

- **Without NCBI Taxonomy.** Verify with BLAST on an EsViritu result that Lungfish cannot look up in NCBI Taxonomy, such as an imported result or a computer without it installed, judges each read by organism names alone, so a read can count for or against the row by a name it shares with another virus. The BLAST pane says so and tells you to install NCBI Taxonomy in the Databases tab of the Plugin Manager and run Verify with BLAST… again. A result saved by an earlier version shows no such line, so send the row again to see how it was judged.
- **Reads tied at one score.** A read tied at one score counts as supporting when any record tied with it is in the row's species. NCBI returns a sample of the tied records and a run can miss the best record itself, so a read can show 100% on one run and 99.3% on the next. A read tied with many records outside your species can still read Unsupported on a run whose sample holds none from it.
- **A search under way.** While a Kraken 2 or FASTA list BLAST search is running, the BLAST pane keeps showing that search, naming its sample or sequences, even when you pick another row, so that row's own saved result is hidden. It is not lost. It shows again after the search ends, when you pick the row again.
- **A FASTA list.** A FASTA list you open again shows no BLAST search until you pick the same sequences you sent. The Operations Panel shows the search while it waits.
- **A Kraken 2 check saved by an earlier version.** Its record keeps nt, so a replay of that record still asks NCBI for nt. NCBI searches core_nt for it, as before, so the result is the same, and the BLAST results pane says that NCBI searched core_nt, not the nt the search asked for.

### Other limits

- **FASTQ drawer.** The Demux tab saves a plan with the dataset, but demultiplexing runs from the FASTQ operations dialog with the settings you give it there. Detect Barcodes cannot search Illumina, Element, Ultima or MGI kits and says so. For barcodes inside the reads, use Demultiplex Barcodes with a Custom Definition. Lungfish cannot yet split reads by the index written in each read's header line, as in an Undetermined file from bcl2fastq.
- **FASTA lists.** A protein whose letters are all also nucleotide codes, such as MKTAYGHSSRV, is still read as DNA and still shows a GC percent.
- **Status bar.** It still cuts a long message in the middle, and its text cannot be selected or copied.
- **Mapping results.** If the BAM file of a mapping result has been moved or deleted, the result still opens with the totals saved when the mapping ran, an empty contig list and a warning that the alignment could not be measured. Put the file back or run the mapping again to see the reads.
- **Earlier notes.** The limits in the 2026.10.29 notes still apply, apart from the known issues about mixed FASTQ files, imported TaxTriage results and TaxTriage negative controls, the sentence about reads tied at one score and the sentences about a search that stops after about 10 minutes.
