# Lungfish 0.5.0-alpha3

This alpha makes ONT amplicon genotyping usable outside the development
machine. It adds the first project-bundle workflow for ONT genotype reports,
improves project import/deletion behavior, and cleans up the reports and
sidebar surfaces that new users will see first.

Changes since v0.5.0-alpha2:

## ONT Genotyping

- Added the new `lungfish fastq ont-barcode-genotype` CLI workflow for ONT
  barcode runs. It maps reads to a species-specific MiSeq allele reference,
  retains exact full-amplicon matches with indels allowed but mismatches
  rejected, demultiplexes retained mapped reads by Fluidigm barcode definitions,
  and writes genotype count tables.
- Replaced the previous GUI ONT Genotyping operation with this retained-read
  workflow. The operation now accepts selected `.lungfishfastq` bundles, a
  project `.lungfishref` reference, and barcode definitions from either the
  project or the filesystem.
- Filesystem barcode definition files selected in the workflow dialog are
  copied into the project before the run so the workflow can be reproduced from
  project contents.
- Added pinned report-preparation dependencies, including `openpyxl`, to the
  managed Third-Party Tools pack used by release builds.

## Genotyping Result Bundles

- Added `.lungfishgenotype` bundles for ONT genotype results. These bundles
  keep the Excel workbook, CSV summaries, run statistics, logs, and provenance
  together instead of exposing a loose analysis folder as the user-facing result.
- The sidebar recognizes `.lungfishgenotype` bundles under Analyses and opens
  the primary Excel workbook in the viewport.
- Intermediate BAM and CSV files remain available inside the bundle for
  reproducibility, but the main user-facing output is the workbook.

## Excel Reports

- Reformatted the ONT genotype workbook to match the Illumina comparison
  layout more closely, including haplotype placeholder rows and loci grouped in
  the expected order.
- Removed unassigned and zero-read-only allele rows from the main workbook
  output so reports focus on alleles detected in at least one demultiplexed
  sample.
- Limited sample columns in the first worksheet to demultiplexed samples with
  retained exact-match reads instead of every barcode bundle in the project.
- Replaced fragile formulas with explicit subtotal, observation, total, and
  average values so workbooks open cleanly in Excel.

## Project Imports, Deletion, And Provenance

- ONT `fastq_pass` folders and other source bundles can be imported repeatedly
  without colliding with stale companion sidecar files from earlier imports.
- Deleting project items now checks for dependent descendants and warns when
  provenance would be broken. The confirmation dialog can show the full list of
  affected objects and can move dependent analyses to the Trash with the
  selected item.
- Project-root provenance staging folders are hidden from the sidebar. Bundle
  provenance remains stored inside the relevant result bundle and visible from
  the provenance surfaces.

## Sidebar And UI Polish

- Fixed bundle display regressions after ONT import so newly imported
  `.lungfishfastq` bundles show their data when selected.
- Kept ordinary project CSV, TSV, text, and other document files visible in the
  sidebar and routed through QuickLook-style preview instead of genomic document
  loading.
- Replaced clashing red destructive-action styling with the app's warmer
  danger color while preserving conventional sequence/base colors.

## Known Alpha Notes

- The ONT genotyping workflow is designed for the retained-read exact-match
  strategy validated on the barcode08 test data. Other species and reference
  panels should be checked against known genotyping expectations before routine
  use.
- Haplotype labels in the Excel workbook are placeholders unless a population-
  specific haplotype definition is provided by the analysis context.
- Missing provenance remains a release-blocking defect for new scientific
  outputs; older project data may still need backfill when opened.
