# Lungfish 2026.9.8

Channel: Preview

Previous versioned release: v2026.9.7

Stable baseline: v2026.9.4

Dependency set: 2026.2

Lungfish 2026.9.8 is a fixes release covering the MAFFT multiple sequence
alignment viewport and the FASTA paths beside it. Six reported problems are
addressed. Most of them had causes that were not what the symptom suggested,
which is worth knowing if you reported one of them.

## Aligning only the sequences you selected

Selecting a few sequences and running MAFFT used to do one of two different
things without telling you. Launched from the viewport, it quietly aligned only
your selection. Launched from the Tools menu, it aligned every sequence in the
file. Nothing on screen said which had happened.

The alignment dialog now asks, showing both counts:

    Sequences to align
    ( ) All sequences (5)
    (o) Selected sequences (3)

It defaults to your selection when you reached it by selecting sequences. Where
there is no real choice to make, it states in one line what it is about to do
instead of offering a control you cannot change.

The command line gained a matching repeatable `--sequence` option. Names
resolve the way you would expect: a full FASTA header, a bare accession such as
`MT192765.1`, or the label shown in the alignment all work. A name that matches
more than one record is reported rather than silently pulling in both, since
that would change your tree. Subsetting is recorded in the bundle's command
provenance, so a subset run reproduces itself.

Realigning sequences that already contain gaps now warns. MAFFT treats a gap as
a residue, so realigning an existing alignment produces unreliable results.

## Extracting selected sequences to a new bundle

The action existed but was called "Create Bundle…", which is not what anyone
searches for. It now reads "Extract to New Bundle…" in the sequence list, and
"Extract Selection to New Bundle…" in the alignment viewer, where the unit is a
rectangular block rather than whole sequences.

The reference-bundle viewer's sequence list was single-selection, so there was
no selection to extract from. It now supports multiple selection and offers the
same action. Clicking a single sequence still navigates to it.

## Exporting an alignment

Right-clicking an alignment, in the viewer or the sidebar, now offers
"Export Alignment…". You choose a destination and whether gaps are kept:

- Save as Bundle, producing an alignment bundle with gaps preserved, or a
  reference bundle with them removed
- Save to File, in aligned FASTA, PHYLIP, NEXUS, Clustal, Stockholm, A2M or A3M
- Copy to Clipboard

Whether gaps survive is the choice that decides if you are exporting an
alignment or a set of sequences, so it is asked directly rather than implied.
The clipboard option disables itself with an explanation for alignments too
large to carry, rather than failing after you commit.

## The bottom drawer is no longer painted over

Opening an alignment could leave the Annotations, Variants and Samples drawer
partly covered by alignment rows. Eleven separate paths were revealing that
drawer underneath an installed alignment viewer. All of them now respect the
viewer that owns the window.

## Readable sequence names

The sequence-name column was a fixed width, so longer identifiers truncated
with no way to widen them. Drag the divider at its right edge to resize between
160 and 640 points. Double-click the divider to fit the longest visible name.
The width is remembered. Names now truncate in the middle rather than the end,
so accession suffixes stay visible, and hovering shows the full name.

## Controls that did nothing

Three dead surfaces are gone from the alignment Inspector and drawer. The
Assistant tab appeared even with AI services switched off, where selecting it
raised an alert and left an empty pane; it now appears only once a provider is
configured. The Analysis tab asked you to import a BAM file, which an alignment
bundle never has. The drawer's Variants and Samples tabs offered sample
metadata actions that operated on nothing.

"Run Operation…" returned to the alignment viewer's menu, where its handler
existed but was never connected. BLAST and MAFFT stay absent from that menu
deliberately: BLAST would search gapped sequence, and realigning an alignment
is a different operation from aligning sequences.
