# Lungfish 2026.9.40

Channel: Preview

Previous versioned release: v2026.9.39

Stable baseline: v2026.9.28

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This release is the result of a top-to-bottom review of Lungfish Genome Explorer (LGE) by a panel of specialist reviewers, followed by a round of fixes. It is a large update. Most of the changes make LGE safer with your data, more accurate in the numbers it reports, and quicker to respond. The sections below describe what you will notice.

## Your data is safer

Several actions could quietly change or remove data that you meant to keep. They no longer do.

- Deleting a variant track no longer removes the read alignments stored in the same reference.
- Importing a FASTQ file with the same name as an existing sample now keeps both instead of replacing the older one.
- Building a phylogenetic tree or aligning sequences no longer deletes shared scratch files or earlier results.
- FASTQ files are no longer trimmed or have their quality scores rounded unless you ask for it. Quality rounding (binning) is now off by default.
- Editing or deleting an annotation from the Inspector now saves to disk, and the annotation table updates straight away.
- If a restore fails, LGE keeps its backup copy.

## More accurate results

A scientific review checked what LGE calculates against what the underlying tools and published methods expect.

- Variant calling for viral samples now uses the settings the tool authors recommend. Allele frequency and depth thresholds that you set are now actually applied.
- iVar receives the correct gene structure for genomes with overlapping or frame-shifted genes, such as SARS-CoV-2 ORF1ab, and duplicate variant records are removed.
- Unique-read counts are no longer capped at 100,000, and the mapping rate now counts reads rather than alignment records.
- Extracting a gene now respects its strand and its exons, and translations honour the gene's reading frame and genetic code.
- Subsampling paired reads that are stored in one file keeps mates together.

## Viewing deep sequencing data

When a region has very deep coverage, LGE shows a sample of the reads so the viewer stays responsive. It used to take the same fraction everywhere in view, which could make shallow areas next to a deep amplicon look nearly empty.

LGE now caps how deep the stack of reads gets instead. Regions shallower than the cap show every read, and only deeper regions are sampled. The default cap is 500x. You can change it with **Maximum displayed depth** in the Inspector's Reads settings, by dragging the slider or typing a number. A note above the reads says when sampling is active. Coverage, depth and consensus always use every read.

## Easier controls

Every slider in LGE now has a box next to it where you can type an exact number, and all sliders share the same look.

## EsViritu virus detection

- A paired-end sample stored as one interleaved file now runs as paired reads. Before, it ran as single-end reads and was labelled that way.
- A file that mixes read pairs with merged reads, such as the output of the VSP2 recipe, runs as single-end reads. The wizard labels it clearly and the run record notes why.
- The command that **Copy CLI Command** gives you now reproduces the pairing choice exactly.

## MHC genotyping

These changes affect results. LGE recalculates saved haplotype analyses automatically, so some haplotype calls in existing projects may change when you open them.

- **Homozygous animals are called correctly.** An animal carrying two copies of the same haplotype, such as MHC-DQ M2/M2, was sometimes reported as two different haplotypes because the two share an allele. A haplotype now counts only when it has evidence that no other haplotype explains.
- **Look-alike haplotypes are flagged.** Where two haplotype definitions are identical at a locus, such as MHC-DP M4 and M7, LGE reports both names together (for example "M1 / M4|M7") and marks the call for review instead of guessing. `lungfish-cli haplotypes validate` now warns about identical definitions.
- **Percentages mean the same thing everywhere.** Every "percent of locus" number, in the genotype matrix, the haplotype evidence panel, the haplotype caller and the Excel export, now divides by the sample's reads at that allele's own locus. Before, some views pooled several loci and could disagree, so an allele could pass a threshold in one place and fail it in another.
- **"Min %" filters by reads for every allele.** It used to count how many animals carried a new allele, which could hide a real allele seen in only one animal. It now uses that animal's share of reads, like it does for known alleles. A separate **Seen in ≥ N% of animals** control filters by how common an allele is, and it is off by default.
- **Duplicate reference sequences are merged.** If a custom reference contains identical sequences, reads were split between them unevenly. LGE now treats them as one group with all of the group's reads, and lists every name in the new `ambiguous_with` column.
- **Long-read calls show small insertions and deletions.** Full-length Nanopore results keep calling a match "known" when it only differs by small insertions or deletions, which are common sequencing errors. The new `indel_bases` column shows how many there were, and `review_flag` marks those calls for a closer look.
- **Excel comments keep your notes exactly.** Comments on the Filtered sheet now contain only the note you wrote. The evidence numbers moved to their own column, "Evidence (display / raw support)".

## Reliability

- If another task is already changing the same reference, a new task now tells you and does not start, instead of running at the same time and risking a conflict.
- Cancelling an operation always finishes the cancellation. If a task cannot stop right away, it is marked cancelled after a short wait and its reference stays protected until the task really ends.
- **Cancel Operations and Quit** now quits.
- Selecting an annotation no longer starts a stuck background task.
- Projects kept on the Desktop, in Documents or in Downloads no longer freeze saving steps when macOS has not granted LGE access to the whole folder.
- The sidebar catches up on file changes it missed when you switch back to LGE.
- Many slow steps now run in the background, so the window keeps responding while LGE reads large files.

## Command line

- `lungfish-cli import vcf` can now add variants to an existing reference by pointing `--output-dir` at the reference bundle. Imports started from the window record this command, so **Copy CLI Command** works for them again.
- `lungfish-cli esviritu detect` gains `--read-format`, which detects interleaved input automatically.
- Copied commands for Kraken2 and FASTQ operations can be pasted into a terminal and run as is.

## Documentation

The user manual's screenshots and illustrations moved to a separate repository that is pinned to each release, so the main download of the source code is much smaller. Finished engineering notes were removed.

## Licences

The bundled third-party notices now point to the exact versions LGE ships, and state that LGE uses zstd under its BSD licence.

## Dependency versions

Dependency set 2026.2 and all managed tool, optional pack, pipeline, database, and bootstrap pins are unchanged from v2026.9.39.
