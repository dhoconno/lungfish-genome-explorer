# Lungfish 2026.11.15

Channel: Preview

Previous versioned release: v2026.11.13

Stable baseline: v2026.11.7

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview shows the cells of a single-cell result on a map. You import the coordinates and clusters that your own tool made, or you run `lungfish-cli rnaseq cell-map compute` to cluster the cells and draw a UMAP. The map opens from the sidebar. It colours the cells by cluster, sample, totals or one gene, and it lets you select cells and pseudobulk them with a record of how the cells were chosen. This Preview also fixes the Seurat script of an export of a result with two or more samples, which joined samples whose ids share a first part.

## What works differently

- **The Seurat script of an export keeps samples apart.** Before, `seurat.R` named each cell `<sample>_<barcode>` and let Seurat read the sample from the text before the first underscore. A result with samples such as `cov_10` and `cov_11` then got one identity, `cov`, in `orig.ident` and in the default `Idents`, so `SplitObject(split.by = "orig.ident")` or a quality plot by identity treated two samples as one. The object's `sample` column and LGE's own numbers were right. Now `orig.ident` and `Idents` hold the sample ids in the order of `samples.tsv`, and `meta.data` has a `barcode` column. Exports that Previews 2026.11.10 to 2026.11.13 made from a result with two or more samples have the fault, so export again with this version. Stable 2026.11.7 never had this script.
- **The summary of a single-cell result ends with one new line.** It names Import Embedding… and the two commands that make a cell map, and it leaves this result as it is. The rest of the view reads as in Preview 2026.11.13.

## What's new

- **Cell maps.** A cell map is a new result that holds the coordinates of your cells for one or more embeddings, such as UMAP, t-SNE or PCA, and one or more sets of labels, such as clusters. It names the single-cell result it came from, and nothing is written inside that result. Select a cell map in the sidebar and it opens in its own view. The view draws the cells and shows the embedding's name and how many cells it draws. Each count, legend bound and gene value it shows is a number that `lungfish-cli` wrote into the cell map, and the view counts nothing itself.
- **Import Embedding… in Tools > RNA-seq.** Choose a single-cell result, then the coordinate files, and the cluster files if you have them. It reads LGE's own table form, which the Seurat and Scanpy scripts of an export now write at their end, and the `projection.csv` and `clusters.csv` of 10x's analysis. It pairs each barcode with a cell of the result exactly as you gave it, writes a new cell map next to the result and keeps your files. When no barcode is found as given but some would be after dropping or adding `-1`, it refuses and says how many, and a checkbox lets you choose that. It refuses barcodes that the result does not hold, with their count and the first 10, unless you tell it to leave them out. An embedding that was computed on other counts than the result's, such as 10x's analysis of Cell Ranger counts, needs the checkbox that says so, and the result and the view then say "computed on other counts". The row ends as Completed once the new cell map loads and the embedding opens, and the Operations row records `lungfish-cli rnaseq cell-map import`.
- **Colour, embedding and gene.** The Embedding pop-up switches between the embeddings of a cell map. The Colour by pop-up colours the cells by a set of labels such as clusters, by sample, by each cell's UMIs or genes, by the not-host columns when the result has them, or by one gene. Gene… finds a gene, and a row under the list chooses normalised or raw UMIs. The legend shows the lowest and highest value and the unit. A normalised value is log(1 + 10,000 × the gene's UMIs ÷ the cell's Gene Expression UMIs), the value of Seurat's `NormalizeData` with a scale factor of 10,000, to within the last bit of a 32-bit float. Cells with no UMIs of the gene are drawn first in light grey. A legend of labels lists each label with its cell count.
- **Select cells and pseudobulk them.** Drag a lasso to select cells, Shift-drag to add more and Option-drag to take cells away, or click a legend row to select the cells of that label. Selection also works from the keyboard. The view says how many cells are selected, and selecting writes nothing. Save Selection as Labels Table… and Pseudobulk Selected Cells… run `lungfish-cli rnaseq cell-map select` and then `lungfish-cli rnaseq pseudobulk`, and each Operations row records its command. A selection and the rest become two labels of one table, and cells that the embedding leaves out stay unlabelled and are counted. A group is one sample and one label, so animals never pool, and the smallest group of Pseudobulk RNA-seq Cells… still applies. The pseudobulk result records the cell map and the table that chose the cells, each by its sha256. One function decides the highlight, the count on screen and the cells that the command selects, so a point on the edge of a lasso is placed the same way in the app and on the command line.

Four more changes belong to the view, the command and the pack.

- **Three plain sentences stay on screen.** Under a UMAP or t-SNE the view says that the method places cells with similar counts near each other on a flat picture, that only near neighbours mean something, and that the distance between groups far apart, the size of a group and the space between groups carry no meaning. A PCA or an unrecorded method gets a neutral caption without that claim. Beside clusters that LGE computed, the view says that clusters come from a graph of each cell's nearest neighbours and not from the picture, so one cluster can look split and two can look joined. It also says that a cluster number is a name and not a rank, that another run can number the same groups differently, and that naming a cluster is the analyst's call.
- **`lungfish-cli rnaseq cell-map compute` clusters the cells and draws a UMAP.** `lungfish-cli rnaseq cell-map compute RESULT --output NEW` runs a pinned Scanpy 1.11.5 route on the Mac with normalisation, variable genes, PCA, exact nearest neighbours, Leiden clustering and a UMAP. It checks its table and writes a new cell map next to the result. The app has no compute pane in this Preview, so you run it as a command and open the new cell map from the sidebar. These are Scanpy's clusters and not Cell Ranger's. On two 10x test sets the route cut the cells into 15 and 22 groups where Cell Ranger's graph clustering gave 7 and 11, so name the tool when you report them. `--seed` offers only 0, and the route uses one thread unless `--threads` says otherwise. The number of clusters is one seed's answer. On the 1,222-cell test set, seeds 2, 8 and 9 give 14 clusters where seed 0 gives 15. A run that would need more than 40% of the Mac's memory is refused before it starts, and the words say how many cells that Mac can compute at the depth of your result.
- **The Single-Cell Analysis pack.** The pack shows as a card in Plugin Manager (about 800 MB, with Install All), among the optional packs of the Welcome window, and in About > Acknowledgements, which lists its two GPL licences. `lungfish-cli conda install --pack single-cell` installs it too. It holds Scanpy, python-igraph, leidenalg and umap-learn in one environment, and python-igraph and leidenalg run as separate programs that the app does not link. Only `rnaseq cell-map compute` uses the pack until the app has a compute pane, and nothing installs by itself.
- **PHATE and MIOFlow.** Their status in LGE is `not offered: Yale non-commercial licence`. Your own PHATE coordinates can still be imported, and the view then says what PHATE draws. This Preview reads no `.h5ad` or `.rds` file, names no cell groups for you and does not integrate samples.

## Things to know

- **No second Mac has run `compute`.** It has run on one Mac, so nothing here says that another Mac gives the same clusters or the same number of them.
- **A joined selection is view-only.** A selection that joins two lassos, a lasso with a label or a pick by samples is highlighted and counted, but Save Selection as Labels Table… and Pseudobulk Selected Cells… stay off for it, since `rnaseq cell-map select` takes one polygon or the labels of one set.
- **The Import Embedding dialog closes when you press Run.** After a refusal its words show in an alert, and each retry starts from an empty pane, so 10x's files on a STARsolo result take two rounds.
- **An import can draw no cell.** When every barcode is left out with the skip option, the file holds only its header, or a label set labels no cell, the import still writes a cell map and does not refuse.
- **A label set with a few thousand labels slows the view** when you choose it, since the format sets no limit on labels in a set. How long a map of 1,000,000 cells takes to open is not measured.

Four more limits concern the gene list, compute, the pack and the command line.

- **The gene list.** The arrow keys do not move from the search field into the offered genes, and Return takes the first one.
- **Compute.** The help of `rnaseq cell-map compute` says `--threads` defaults to auto while the route uses one thread. The command shows one step line and then nothing until it ends, which took 409 s for 152,425 cells. The Source line of a computed embedding names the tool and its version and not the seed or the thread count.
- **The pack.** Reinstall of the Single-Cell Analysis pack rebuilds its environment four times, once for each of its four tools.
- **A pair of files on the command line.** `rnaseq pseudobulk --cell-map` records the cell map it is given. When it is not the one that the `--labels` table came from, the record says so with no refusal. The app builds both from one map.

The limits in the 2026.11.13 notes still apply, and so do the earlier limits that those notes keep.

## Known issues

No known issue is open in this build beyond the limits above.

## Updating

Choose Check for Updates… in the app menu to install this release. The Single-Cell Analysis pack of about 800 MB is optional and installs only when you ask, from Plugin Manager or with `lungfish-cli conda install --pack single-cell`.
