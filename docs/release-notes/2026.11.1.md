# Lungfish 2026.11.1

Channel: Preview

Previous versioned release: v2026.10.29

Stable baseline: v2026.10.29

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview brings the work since Stable 2026.10.29. Some numbers and files change, so read What works differently before you compare with old results. A BLAST search that NCBI holds for a long time no longer fails, and many beeps became messages.

## What works differently

### Reads and read pairs

- **A FASTQ file that holds read pairs together with merged or single reads is read in full before it is paired.** With 50,000 or more pairs, unrelated reads could be paired without a warning. This now holds for `fastq deinterleave`, `map`, `assemble` and the classifiers. To check a file, run `fastq deinterleave` on it without `--unpaired`. A mixed file stops with its counts and writes nothing, so split it again with `--unpaired`. Rerun any Kraken 2, TaxTriage, EsViritu, Viral Recon, mapping, assembly or FASTQ operation made from it, or from R1 and R2 files an earlier version split from it, since its read counts, pair flags or contigs can be wrong. Your imported reads are whole, so nothing needs importing again for this.
- **Read pairs named like SRR123.1.1 and SRR123.1.2 are now recognized as pairs.** That is what `fastq-dump --readids` writes. Before, Lungfish ran them as single reads, so a Kraken 2 total was about double the number of pairs, a map showed no paired reads, and a third file of unpaired reads was left out with a warning and not stored. Now Kraken 2 counts each pair once, a map marks the pairs as properly paired, and the third file joins when you import the run again. Run again any analysis of such a sample made with an earlier version, because an old result does not change until you do. Pairs whose names differ only by _1 and _2 run as single reads, also in a file you declare interleaved.
- **Illumina Amplicon Merge keeps only merged reads.** It drops every pair that does not overlap, and its description on the Import FASTQ sheet now says so. When an import dropped pairs, the Operation Log gets one warning line for each sample and the row ends as Completed with Warnings.
- **NAO-MGS could count a read pair's second mate at the first base of a reference without placing it,** so Unique Reads read low and the mate was missing from the read panels. This is fixed for new imports. A result imported by an earlier build keeps its old numbers, and Lungfish cannot correct it, so import its original results file again, which makes a second result beside the old one, then remove the old result. A result's record names the version that imported it. An import now stops and names the sample when its alignment file cannot be written. A results file row whose quality scores or alignment string (CIGAR) do not match the length of its bases, or whose alignment string reads NA, still stops the import. The message names the sample and not the row.

### Unique Reads and exports

- **Unique Reads showed 1 for rows that were never counted.** A dash now means "not counted". EsViritu results need nothing redone. EsViritu and NVD exports now write Unique Reads right after Read Count (Mapped Reads in NVD), empty where the table shows a dash, and NVD also writes Aln Length. Columns after them move right, so a script that reads these files by column number needs updating. Kraken 2 and CZ ID have no unique read count, since Kraken 2 does not align reads and Lungfish holds only CZ ID's report.

### TaxTriage

- **A TaxTriage result says when a negative control cannot be read as clean.** If a control failed, cannot be found in the results, or had a step that the pipeline skipped after an error and left it with no results, the viewer shows a note above the table. The organism matrix and the results table say Not checked where they said No or left the cell blank. The batch report says the same in words and tells you what to do. A control whose name has a space or a symbol, such as NTC 1 or Water (blank), now keeps its flag, where before the batch report said none were found in it. With the negative control unticked, a matrix or batch report said No for its organisms. To correct a result you made earlier, open it in this version, export the organism matrix, the results table and the batch report again, and replace the old files. If the batch report says a control failed, run that control again. If its folder holds a report at its top and sample folders beside it, build its database again with `lungfish-cli build-db taxtriage FOLDER --force`. A new run stops before it starts when two sample names become the same once spaces and symbols are removed, such as A (1) and A_1, and asks you to rename one.
- **An imported TaxTriage run keeps its negative controls.** Importing a run now keeps which samples were negative controls, the run's settings and its database name. A run imported with an earlier version did not keep the controls. That result now reads Not recorded and says so above its table, so import the run's folder again with this version to get them back. A matrix, table or batch report exported from an older import may say No for contamination and show default settings such as Illumina and 0.0 seconds, so export it again from the new import. If you no longer have the run's folder, check its controls another way before you rely on those results.

### BLAST Verify

- **BLAST Verify now asks NCBI for up to 500 records per read, not 5, when it judges by species.** A read that matches your organism perfectly no longer reads Unsupported because its first five matches happened to be lab vectors. When every supporting read also matches other records equally well, such as a vector, the row now reads Not specific instead of Supported, because the reads fit your organism and cannot tell it from those records. A saved result keeps its old badge, so send the row again to get the new reading.
- **A verdict showed under the wrong sample's row.** Verify with BLAST could leave one sample's verdict showing under another sample's row of the same taxon. The pane now shows that row's own search, or nothing when it has none, and a verdict that arrives after you picked another row names its sample.

### Files you open or save

- **A reference whose sequence file changed after import.** If the sequence file inside a reference bundle was replaced by a shorter one, Copy, Export FASTA, the viewer and figures could use fewer bases than the reference has, and nothing said so. They now stop and say why. This only follows a change made by hand inside a bundle.
- **A genotype comment or review added during a workbook update is kept.** In the genotype matrix, a comment or review you add while Lungfish is still updating that result's workbook is now kept if you close the window, open another item or switch projects before the update ends, and it is saved right after. If you quit during the update, Lungfish waits up to 15 seconds for it. If the comment or review is still not saved, Lungfish says so and lets you choose Quit Anyway, which discards it, or Don't Quit, so the update can finish. If no Lungfish window is open when you quit, a comment or review that is still waiting is discarded without a question.

## What's new

### BLAST searches that NCBI holds for a long time

- **A BLAST search stuck at NCBI no longer fails or holds up your work.** It waits on its row in the Operations Panel (Operations > Show Operations Panel), and its result comes back on its own, on the row it was sent from. The search stays at NCBI when you quit, and closing a project window no longer asks about it or stops it. A search that is still waiting, or ended with no result, shows where it stands on its row and in the BLAST pane. The quit and close warning for a search that is not saved yet says the search is lost and to start it again.
- **A search sent from a FASTA list shows as waiting when you pick the same sequences again,** also after you leave the list and after you reopen Lungfish. A late answer lands there while those sequences stay picked.

### Failures explain themselves

- **Commands that used to beep now say what is missing and what to try.** A few commands that need a window still beep when no window exists, and some result viewers keep their beeps.
- **Failed runs and saves name the sample.** A Map Reads run that fails tells you in an alert which sample failed and why, even with the Operations Panel closed. A Map Reads batch shows its one alert when the whole batch has run. A metadata edit that cannot be saved says so and stays unsaved, and Clone Metadata names the samples it could not copy to.
- **Files and results that cannot be opened say what is wrong.** This covers a preview, a FASTQ dataset (only its first file is checked), an assembly, a reference bundle, a mapping result, an alignment and a FASTA list selection with an unreadable file, and most also say what to try. A FASTQ dataset or an assembly no longer opens with stored numbers over an error or an empty table.
- **Leaving a result takes its viewer away.** After an MHC reference bundle, the MHC viewer no longer stays on screen behind or over the next result, and after an alignment its details no longer stay in the Inspector. After a Kraken 2, EsViritu, TaxTriage or CZ ID result the Inspector can still describe the MHC bundle until you select something else. The roles you mark for discriminating sites are lost when you open a different alignment or close the window.
- **Long messages in the status bar can be read.** Hold the pointer over one for a moment to read all of it, including the file name and the reason.

### Other changes

- **A result dragged to another project arrives with its record.** A TaxTriage, Kraken 2, EsViritu, NVD or NAO-MGS result now copies with its provenance record, and each file is checked against the original. A refused copy names the file. A result whose files were changed after its record by a person, another program or an older version that left no note is refused. The original is never changed.
- **Reassemble in a copied or renamed project uses the reads inside that project.** If the reads have changed since the assembly, or cannot be read now, Reassemble says so and stops, and an older assembly with no stored checksum asks first. Genotype results in a copied project read the copy's own haplotype definitions.
- **A used-up AI quota says so.** An OpenAI account with no credits no longer shows "Rate limited". Settings > AI Services, the AI Assistant and `lungfish-cli genotype ai-haplotyping` now say the quota is used up, with OpenAI's own words and billing link, and a haplotyping run no longer retries when only credits help. Anthropic's monthly spend cap and Gemini's daily quota read the same way. This answers GitHub issue 35.
- **A FASTA list comes back as you left it.** Opening one sequence from a FASTA list and coming back finds the list with its filter, sort, selection and scroll position.
- **A protein cut by the end of a sequence says so.** Lungfish says how many bases it could read, for example 20 of 30, in the Inspector, on the translation track and in the hover text, and a protein you copy from it says so in its FASTA header.

## Things to know

### BLAST Verify

- **Without NCBI Taxonomy.** Verify with BLAST on an EsViritu result that Lungfish cannot look up in NCBI Taxonomy, such as an imported result or a computer without NCBI Taxonomy installed, judges each read by organism names alone, so a read can count for or against the row by a name it shares with another virus. The BLAST pane now says so under the summary and tells you to install NCBI Taxonomy in the Databases tab of the Plugin Manager and run Verify with BLAST… again. A result saved by an earlier version shows no such line, so send the row again to see how it was judged.
- **Reads tied at one score.** A read tied at one score counts as supporting when any record tied with it is in the row's species. NCBI returns a sample of the tied records and a run can miss the best record itself, so a read can show 100% on one run and 99.3% on the next. A read tied with many records outside your species can still read Unsupported on a run whose sample holds none from it. The saved result shows the best score and how many records tied.
- **A FASTA list.** A FASTA list you open again shows no BLAST search until you pick the same sequences you sent. The Operations Panel shows the search while it waits. If you pick other sequences while a BLAST search from a list is still being sent, the pane keeps showing that search until you click a row again.

### TaxTriage

- **Negative controls.** A negative control that has results and also had a step that the pipeline skipped after an error is read from the results it has, so the organism matrix and the results table still say No, or leave the cell blank, for an organism it does not list. The viewer and the batch report say that such a control may be incomplete. Read them before you rely on a No.
- **Sample names.** The organism matrix and the results table do not say when two sample names became one name in a result made earlier. The sample that was left out has no column there, and if the two are negative controls, an organism that only the left-out control held reads No. The viewer and the batch report say it.

### Other limits

- **FASTQ drawer.** The Demux tab of the FASTQ drawer saves a plan with the dataset, but demultiplexing runs from the FASTQ operations dialog with the settings you give it there.
- **Status bar.** The status bar still cuts a long message in the middle on the screen, and its text cannot be selected or copied.
- **Mapping results.** If the BAM file of a mapping result has been moved or deleted, the result still opens. The summary line keeps the totals saved when the mapping ran, the contig list stays empty and a warning says the alignment could not be measured. Put the file back or run the mapping again to see the reads.
- **Earlier notes.** The limits in the 2026.10.29 notes still apply, apart from the known issues about mixed FASTQ files, imported TaxTriage results and TaxTriage negative controls, the sentence about reads tied at one score and the sentences about a search that stops after about 10 minutes.
