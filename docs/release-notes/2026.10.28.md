# Lungfish 2026.10.28

Channel: Preview

Previous versioned release: v2026.10.27

Stable baseline: v2026.10.27

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview fixes read extraction and alignment counts that were wrong in Stable 2026.10.27, lifts the fixed time limits that were left, puts plain words on failure alerts, and records the database behind EsViritu and TaxTriage runs. Some numbers and files change, so read What works differently before you compare with old results.

## What's new

### Failures explain themselves

- **Failure alerts name the step and the next thing to try.** Alerts from the Import Center, the Inspector, the genotype and assembly views, sequence and table export, project opening and migration, annotation edits, primer exports and FASTQ barcode detection now say which step failed, what happened and what to try next. A message the app wrote about your own input, such as a BAM file opened as a document, a sample sheet with a missing column or a bundle that is read-only, stays in view with the next step beside it. The technical error is under Show Details.
- **A database archive that cannot be installed says why.** When it holds a link that leaves its own folder, the alert names the link, says that nothing was installed and says what to try. A ZIP dropped on the sidebar that holds such a link says the same. The official Kraken2 viral and EsViritu archives hold no such link and install as before.
- **A NAO-MGS result whose alignment file is missing says so.** The read panels name the file and tell you to import the same NAO-MGS results file again. They used to stay blank.

### Time limits

- **Analysis steps no longer stop at a fixed time.** Kraken2, Bracken, the mappers, read extraction, variant calling, human read removal, MAFFT alignment, assembly, the FASTQ tools, FASTQ import with its clumping, compression and Trim Galore steps, demultiplexing, BAM import, filtering, duplicate marking and indexing, primer trimming, read orientation, Savont clustering, ONT genotyping, Freyja, the database builds and the FASTA and VCF clean-up steps run until they end or you press Cancel, which stops them at once. Savont used to stop after 2 hours and Freyja after 24. Short version, header and index checks, tool installs, database downloads, network requests and the barcode scout over a small sample of reads keep their own fixed limits.
- **`--time-limit` stops any one analysis step that runs too long, when you want that.** `lungfish-cli kraken2 classify`, `map`, `assemble`, `align mafft`, `extract reads`, `fastq scrub-human`, `variants call` and `variants phase` take `--time-limit <minutes>`, which stops any single analysis step of the run that goes past that many minutes. The run record says the limit you gave, and a stop by a limit tells you to run again without it or with a longer time. A GATK run now applies the limit it records, where it recorded a limit and ran without one.

### Records that name their database

- **EsViritu and TaxTriage records name their database.** The record and the Provenance tab give the database release and the checksum Lungfish took when it installed the database, as Kraken2 records already did. A database you installed by hand shows as unpinned. An NVD or CZ-ID import names the database versions its result states, and every other import says that its result names no database, so cite the run that made it. Records written before this release stay as they were.

### Viewers

- **12S results, primer analyses and primer orders open through one viewer host.** They look as before. Leaving a 12S result now takes its Detail tab and its result and sample blocks out of the Inspector, where they stayed beside the next result's summary. A primer analysis or primer order hides the ruler, header, status bar, gene tabs and annotation drawer of the reference under it, and View > Show Drawer does nothing while one is showing.
- **NAO-MGS results open through the same host.** Opening a text, PDF or image file after a NAO-MGS result no longer leaves that result's summary in the Inspector.

## What works differently

### Reads you extract

- **NVD Unique Reads counts each read once.** A BAM with secondary or supplementary alignments made the column count a read more than once. On our small test file a count of 7 became 5. An NVD result imported before this release keeps the Unique Reads it stored, so import it again to get the corrected number.
- **Extract Reads writes each read once.** From an EsViritu, TaxTriage, NVD or NAO-MGS row, an extraction wrote a read more than once when its alignment file held secondary or supplementary alignments. For an EsViritu, TaxTriage or NVD row it now writes each read once, matching Unique Reads. We have not checked this for a NAO-MGS row. In our test data no EsViritu extraction changes. One TaxTriage row writes 983 reads where it wrote 993, and two others write the same number of reads, each with a full-length read where a fragment was written before. Extract Reads from an NVD result imported before this release can write fewer reads than the older Unique Reads it shows, until you import the result again.
- **Extract Reads keeps both mates.** A pair that a run mapped as two single reads, as happens with reads downloaded from SRA, lost one mate in an extraction. Both mates are now kept when you extract from an EsViritu or TaxTriage result, by read ID from a BAM, from a region of the alignment viewer, and for selected reads by name from an alignment, which is the fallback when the original FASTQ files are not kept. Before, an extraction could come out a few reads short of the count shown, on our test data 1 to 5 reads and up to a third of a small selection, and nothing said so. Extract again to get the missing mates.
- **NAO-MGS reads are stored on the right strand.** Extract Reads from a NAO-MGS result wrote about half its reads reverse-complemented, and the reads view and the BAM file in the result folder showed those reads on the wrong strand as well. A result you import with this release writes each read as it was sequenced, and `lungfish-cli markdup --force` keeps the BAM files of a NAO-MGS result, where it replaced them with empty ones.
- **Older NAO-MGS results are refused, not extracted.** A NAO-MGS result imported before this release stored the reads that map to the reverse strand the wrong way round, so those reads came out reverse-complemented when extracted and showed as false mismatches in the read panels, although counts and read IDs were right. The read panels now say so, and Extract Reads and the command line refuse with the same words and write nothing. Import the same NAO-MGS results file again in the Import Center, under NAO-MGS Results. The new result takes the name with -2 added, and the old one stays in the project until you remove it.

### Alignment counts

- **Mapped counts say what they count.** When an alignment's statistics hold no read counts, the Inspector and the mapping header label the numbers as alignments, since a read that aligned in more than one place counts once for each place. When the total number of reads is unknown, the header shows no percentage and says so, where it showed `N / N reads mapped (100.0%)`. The Inspector shows Not recorded for a track that holds no counts, where it showed 0.
- **The command line says the same.** `lungfish-cli bundle list` and `bundle info` label alignment counts, and `bundle info --format json` adds a `mapped_read_count_basis` entry beside `manifest` and `path`, with one word for each alignment track, `reads`, `alignments` or `manifest` (the manifest's own copy), that says what that track's `mapped_read_count` counts. `lungfish-cli import bam` into a plain folder now counts reads the way the app does, so a BAM with supplementary alignments reports its reads and not its alignment records.

## Things to know

### Limits you may meet

- **NAO-MGS.** Older results need their results file again, and an import made with another minimum identity can give other counts. The note about a missing alignment file appears once Lungfish has tried to rebuild the file from the reads stored in the result. For results imported by recent versions that takes a few seconds, and an older result that still holds its reads is rebuilt first, which can take longer on a large result. Extract Reads and BLAST Verify keep their own words for a missing file.
- **Extract counts.** The count shown for a region or a selection in the alignment viewer is the number of alignment records. The file can hold fewer reads, one fewer for each selected record that has no sequence and for each extra record of one read that carries the same mate flag as another record of it, which is written once.
- **Time limits.** Only the commands named above offer `--time-limit`, and the app has no field for one, so press Cancel to end any other run.
- **Database names.** A NAO-MGS import states no database or pipeline version, an NVD import records the BLAST and STAT database versions its result states and no database name, date or checksum, and no import carries a checksum.

### Counts, alerts and earlier notes

- **Alignment counts.** When samtools gives no per-read counts, as with a samtools before 1.9 or a file it cannot read, the numbers are alignments, labelled as such, and the import says to run it again. A count taken from a bundle's manifest shows as alignments in the header, even when it is a read count.
- **Failure alerts.** Some alerts still show the technical error as their text, mostly the extraction and blocking alerts of the viewer.
- **Earlier notes.** The limits in the 2026.10.27 notes still apply, apart from the fixed time limits and the NVD Unique Reads count, which this release changes.
