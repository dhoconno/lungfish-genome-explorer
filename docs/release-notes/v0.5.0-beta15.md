# Lungfish 0.5.0-beta15

Previous release: v0.5.0-beta14

## ONT reads can now be imported from unmapped BAM files

Lungfish now accepts unmapped BAM files anywhere the app or
`lungfish-cli import fastq` accepts Oxford Nanopore read input. This is meant
to be a simple compatibility layer: Lungfish converts each BAM into a
temporary compressed FASTQ and then sends those reads through the same import
or processing recipe used for ordinary ONT FASTQ input. BAM inputs are treated
as single-end ONT sources and cannot be supplied as one half of a read pair.

The conversion does not weaken traceability. Import provenance identifies the
original BAM, records the managed conversion and compression tools with their
versions and arguments, and describes the final stored FASTQ bundle rather
than leaving provenance pointed at temporary files. Temporary conversion
workspaces are removed after a successful import and cleaned up on failure.

## Repeated PacBio barcode sample names are resolved before demultiplexing

ONT imports that use PacBio barcode sample sheets can now contain the same
sample name more than once. A name that appears only once remains unchanged.
When a name is repeated, every occurrence is numbered in sample-sheet order:
for example, two rows named `AnimalA` become `AnimalA_1` and `AnimalA_2`, with
additional copies continuing as `_3`, `_4`, and so on.

Lungfish determines these names before it creates the demultiplexing output
directory or begins the expensive read-processing work. It also checks for
case-insensitive filesystem collisions and conflicts between generated names
and explicit sample names. If the sheet cannot be resolved safely, the import
now stops immediately with a focused error instead of failing after a long
demultiplexing run.

## Candidate-only MHC results open in the native genotype matrix

Some valid full-length MHC analyses contain provisional or novel candidate
sequences but no conventional named genotype calls. Those bundles previously
looked empty to the app because the standard call summary had no rows, so
Lungfish opened `current.xlsx` instead of the interactive genotype viewport.

Lungfish now recognizes the bundle's reviewable genotype-row catalog as native
matrix content. Candidate-only analyses therefore open directly in the Matrix
view, where provisional `_nov` rows, read support, annotations, comments, and
manual review tools remain available. This routing change does not alter the
scientific calls or workbook: genuinely empty legacy bundles still fall back
to Excel, and analyses with computed haplotypes retain their existing Outline
behavior.

## Reliability and compatibility

The new import and display paths share existing workflow and viewport code
instead of introducing parallel processing logic. Regression coverage now
includes BAM-to-FASTQ materialization and provenance, successful and failed
cleanup, duplicate sample-name numbering and collision checks, candidate-only
matrix routing, legacy Excel fallback, and the existing known/candidate matrix
projection rules.

## Notes

This remains a beta prerelease. It is packaged as a signed and notarized Apple
Silicon DMG and published through the Sparkle beta update feed for testing.
