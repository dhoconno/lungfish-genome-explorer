# Lungfish 0.5.0-alpha12

## Highlights

This release is a focused overhaul of the 12S amplicon results viewport, plus a
count-time improvement to how cross-species identical-sequence reads are
counted. The 12S surface now matches the sort, filter, copy, multi-sample, and
inspection conventions used elsewhere in the app.

### 12S viewport

- The per-row detail moved out of a cramped split pane into a dedicated
  Inspector Detail tab. The results list is now full width, and selecting a
  species shows its exact reads, reference targets, per-sample evidence, and
  alternate matches in the Inspector.
- Every column in the 12S list now sorts and filters the same way the other
  list views do, including per-column filter menus.
- The list now defaults to sorting by number of reads, descending, and species
  with zero reads across the shown samples are hidden.
- Right-clicking a row offers Copy Name, Copy Sequence (for unresolved
  sequences), Copy Sequences as FASTA, and Copy Rows as TSV. Selecting a single
  species also offers Learn More (opens the NCBI Taxonomy page) and View Photo
  (opens the species Wikipedia page).
- The Inspector Detail tab can show the reference sequences that match the
  selected species, with per-sequence copy and Copy All as FASTA.

### 12S multi-sample comparison

- When several samples are profiled together, the viewport gains a sample
  picker and per-sample comparison columns: each selected sample can show its
  read count and its percentage of that sample's total 12S reads, alongside a
  new percentage-of-sample column.
- Sample metadata can be imported from CSV or TSV and attached as per-sample
  columns that sort and filter like any other column, reusing the shared
  metadata importer.

### Cross-species read assignment

- When a read's 12S sequence is identical across more than one species, the
  matching step now assigns it to the more abundant candidate species rather
  than leaving it unresolved, deciding per sample so one sample's abundance
  never claims another sample's reads. The reads that move are tracked as a
  distinct, audited channel and recorded in the result bundle, and a species
  that loses all of its reads to a more abundant relative stays visible rather
  than disappearing.
- The behavior is configurable from the CLI with
  `--ambiguity-resolution strict|conservative`. The default, `strict`, assigns
  on any nonzero abundance lead. `conservative` requires the winner to have at
  least twice the runner-up and at least ten reads.

## Notes

- The 12S result bundle adds an optional reassignments table. Older bundles load
  unchanged.
- This release was validated by the full automated test suite.
