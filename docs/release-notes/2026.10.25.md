# Lungfish 2026.10.25

Channel: Preview

Previous versioned release: v2026.10.24

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview fixes results that were wrong, empty or silent. A ZIP of reads dropped on the sidebar now adds the reads, and a refused ZIP says why. Extract works in a renamed or copied project. A TaxTriage row with no recorded reference no longer opens another organism's reads. A pooled map of paired bundles keeps the pairs. Some analysis steps no longer stop at a time limit you did not choose. Some numbers differ from earlier builds, and the section What works differently says which and why.

## What's new

### Importing

- **A dropped ZIP adds its reads.** Drag a ZIP that holds one read bundle onto the sidebar and the bundle now appears in the project's Imports folder. Before, the row in the Operations Panel ended Completed and the reads were gone.
- **A refused ZIP says why.** A ZIP that Lungfish cannot import opens a sheet titled `Could not import <archive name>` that gives the reason and what to try, such as dropping one ZIP for each bundle. Several refused ZIPs in one drop share one sheet, titled with the count, that lists each archive with its reason. The project stays as it was.

### Mapping

- **Pooled paired bundles keep their pairs.** When you map several bundles of read pairs in one pooled run, each pair now stays inside its own bundle, whether a bundle holds its pairs in one interleaved file or in an R1 and an R2 file. Before, a pooled run mapped every read as a single read.
- **A pool that cannot keep its pairs stops first.** A pool that mixes read pairs with single reads, Oxford Nanopore or PacBio reads with short reads, or interleaved pairs with R1 and R2 files stops before anything is mapped. The message names the inputs and says to map them apart. For interleaved pairs with R1 and R2 files it also says to join the inputs first with Merge Into New Bundle and map that bundle.
- **`--paired` names what it cannot bind.** `lungfish-cli map --paired` binds exactly two files as the R1 and R2 reads of one sample. With any other number of files it now stops with exit code 3 and lists them, where it used to pool them as single reads without a word.

### Classification and Extract

- **Extract uses the result's own folder.** Extract on a Kraken2 result now reads from and writes into the result's own folder. A result you renamed, moved inside a project or copied with its project extracts where you expect, and the command in the Operations Panel names those folders. In a copied project, Extract and BLAST verification read the FASTQ from the copy when it holds the reads. Before, they read the original project's reads, or failed when the original was gone.
- **Missing reads say what to try.** When Extract, BLAST verification or `lungfish-cli` cannot find a Kraken2 result's reads, the message now reads `The FASTQ reads this Kraken2 result was made from could not be found or read. Put their files or bundle back in the same place in this project, or where the run recorded them, then open this result again and try again. Or run the classification again in this project.`
- **CZ-ID Extract says why it does nothing.** Extract in the Collections drawer of a CZ-ID result used to do nothing. It now opens an alert titled Could not extract reads that says CZ-ID imports do not include per-read source IDs, and to classify the sample's FASTQ in Lungfish and extract from that result.
- **A TaxTriage row with no reference opens nothing else.** When a TaxTriage report gave no reference for an organism, Lungfish used to pick another organism with a similar name, so HPV type 1 could open the alignments and reads of type 16. It now takes a reference only when the name matches exactly. Such a row shows `No reference was recorded for this organism in this sample.` in the action bar, and Extract leaves it out and names it.
- **The Inspector forgets the last result.** The Inspector's Summary no longer shows the details block of a NAO-MGS or NVD result, for NAO-MGS its Sample, Virus Hits and Top Taxon rows, above the next Kraken2, EsViritu or TaxTriage result you open.

### Exports and figures

- **Mismatch marks in a mapping image.** An image exported from a mapping result with File > Export > Image (PNG)… now shows the mismatch marks the viewer shows, so a variant column in the reads shows in the image. The note under the reads counts every read not drawn, including reads cut off by the track height. A window too wide to draw reads (more than 2 bases to a point) now gets a line that says so and names a window that would draw them.

### Viewers

- **A tree keeps the window on the screen.** Selecting a tree or a subtree no longer makes the main window taller than the screen. The window keeps its size.
- **The annotation table says when it could not be built.** When a bundle's annotation database is missing or damaged, the annotation table used to show nothing and read 0 annotations. It now reads `The annotation table could not be built for <bundle name>, because its annotation database is missing or cannot be read. Reopen the bundle, and if this repeats, import its annotations again.`

### Long runs

- **Some analysis steps run as long as they need.** A tool run with `lungfish-cli conda run` and the mapping summary used to stop after one hour, GATK variant calling and the ONT genotyping filter after 24 hours, and trimming, deduplicating, subsampling or scrubbing a FASTQ with the bundled tools after five minutes. They now run as long as they need, and Cancel still stops them.
- **A stop at a limit says so.** When a step stops at a time limit of its own, the message names the tool, says how long the limit was and that the time limit stopped it, and says that no setting changes the limit yet, so you can try a smaller input or report it.

### Plans for a Linux machine

- **Plan reads that already sit on the Linux machine.** When the reads are in the staging folder on the Linux machine, add `--staged-reads <list>` to `lungfish-cli import fastq --write-plan <folder> --staging-folder <path> --samplesheet <sheet>`. The Mac never opens or copies those reads. The sample sheet's r1 and r2 columns name each read by its absolute path on the Linux machine. The list is a tab-separated file with the columns file, bytes and sha256 (a fingerprint of the file's contents), which you make on that machine with the short command that `--help` shows. Each job checks every read against its size and SHA-256 before any step runs. Add `--platform`, such as `--platform illumina`, because the app cannot read the reads to infer it. A name that is no platform is refused with `Unknown platform '<name>'.` and the list of valid names, and nothing is written.
- **The README says which files to copy.** Step 1 of the HTCondor pool instructions in `README.txt` now says to copy or link the source of each file in `staging-files.json` that has one, and to leave a file already in `shared/` with the listed size where it is, because its name starts with its SHA-256 and the jobs of other batches may be reading it. Before, the step said to copy every listed file, which read literally copies over those shared files. The README of a batch with staged reads names the folders that hold the reads.
- **Plans for wastewater samples ask for more disk.** Unless the sample sheet's request_disk column gives it, a plan asks the pool for disk that covers the image, the databases and the job's working files, with a quarter to spare. The working files are the size of a sample's reads times a factor that depends on the preset of the recipe. The factor for the wastewater metagenomics preset rises from 10.61 to 12.14, because the largest sample we ran needed 12.13 times the size of its reads. For that 14.8 GB sample the request rises from 188 GiB to about 214 GiB. A plan with another preset, or none, takes the same factor, and the VSP2 target enrichment preset keeps its smaller 5.03.

## What works differently

### Results that show different numbers

- **EsViritu and TaxTriage Reads and Unique Reads count each read once.** They used to count every alignment record of a read, so a read that aligned in two places, or was split into two pieces, counted twice. They now count a read at its primary alignment only, which for EsViritu matches the read count in EsViritu's own table. A number drops only where a read had a second alignment, for example in a virus with repeated ends. In our test data no EsViritu number changes and three TaxTriage rows drop by 1 to 10 reads, for example 993 reads become 983. The number of reads that Extract writes now equals Unique Reads.
- **A pooled map of paired bundles reports pairs.** For two bundles of four pairs each, the pooled BAM now reports 16 reads paired in sequencing, as the two bundles mapped one by one do. It reported none.
- **An exported mapping image no longer drops reads at its left edge.** An image used to leave out every read that began before the first base shown, or on it, and the note under the reads counted them as `max 75 rows` even with rows free. Those reads are now drawn, as in the viewer, and the live view with Limit visible rows on places them too.
- **A GFF3 export keeps Notes and list attributes.** An export from a bundle left out every feature's Note, and wrote a feature's several parents and cross-references as one escaped value. It now writes each Note, and writes Parent, Alias, Dbxref, Ontology_term and Derives_from as lists such as `Parent=mRNA1,mRNA2`, which other tools read as separate items. The menu item is File > Export > Annotations (GFF3)…

## Things to know

### If you repeat earlier work

- **Databases.** A classifier database built with an earlier release keeps the counts it stored until you build it again.
- **Files and images.** Export a GFF3 file or a mapping image again to get the Notes, the lists and the reads at the left edge. Map a pool of paired bundles again to get its pairs, and run Extract again on a result you renamed or copied.

### Limits of these changes

- **Old counts stay.** NVD results are not changed in this release, and their Unique Reads can still count a read more than once.
- **Copied results without their reads.** A Kraken2 result copied into another project without its reads still reads them from the place the run recorded while that place exists, and says to put the bundle back when it does not.
- **Some steps keep a limit.** kraken2 stops at 2 hours, Bracken at 1 hour, the human-read filter of a scrub at 2 hours, a recipe's deduplication step at 1 hour, and the mappers, MAFFT and assembly at up to 24 hours.
- **Images in the base tier.** An image of a mapping result a few bases wide still leaves out the base letters and draws a mismatch in the base's colour.

### Smaller limits

- **GFF3 commas.** An item of Parent, Alias, Dbxref, Ontology_term or Derives_from that itself holds a comma is written as two items.
- **One annotation database missing.** If only one of a bundle's annotation databases is missing, the table shows the tracks that opened and does not mention the missing one.
- **A TaxTriage row with no reference.** BLAST Verify stays on for it and answers with words after the click.

### Known limits

- **No reads, a Failed row.** When none of the ticked taxa has a read in a sample, Extract writes no bundle and the row ends Failed under an alert titled Taxonomy Extraction Failed, although nothing went wrong.
- **Cancel does not ask.** Cancel in the Operations Panel stops a run at once, so a click on a row that moved under the pointer can stop the wrong run.
- **A taken assembly name.** An assembly whose output name already exists is refused with `Output assembly bundle already exists` and the path, and Lungfish offers no free name.
- **A region has no annotations.** A region extracted from a bundle becomes a new bundle with no annotation track. Its sequence and coordinates are right, and the source bundle keeps every annotation.

### Everything else

The limits under Things to know in the 2026.10.24 notes still apply, except where a change above says otherwise.
