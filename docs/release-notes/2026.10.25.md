# Lungfish 2026.10.25

Channel: Preview

Previous versioned release: v2026.10.24

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview fixes results that were wrong, empty or silent. Mapping tables, mapped read counts and the statistics of Nanopore and demultiplexed reads now show measured numbers, and What works differently says which numbers moved and why.

## What's new

### Importing

- **A dropped ZIP adds its reads.** Drag a ZIP that holds one read bundle onto the sidebar and the bundle appears in Imports. Before, the row ended Completed and the reads were gone. A ZIP that Lungfish cannot import opens a sheet titled `Could not import <archive name>` that gives the reason and what to try.
- **A Nanopore run folder imports.** The ONT Run Folder card takes the run folder MinKNOW writes, its fastq_pass folder or one barcode folder, and refuses any other folder with words that say what to choose.

### Mapping and assembly

- **A pool that cannot keep its pairs stops first.** A pool that mixes pairs with single reads, long reads with short reads, or interleaved pairs with R1 and R2 files stops before mapping and says to map them apart. `lungfish-cli map --paired` with other than two files stops with exit code 3 and lists them.
- **Generate Consensus saves into the project.** Save as Bundle puts the bundle in Reference Sequences with no file dialog, and Save to File… opens in your project.
- **Reassemble again takes the next free name.** A second Reassemble on the same reads takes a name such as `HG002.chrM_assembly-2` in place of stopping, and its row log says why. A failed assembly shows an alert that names it and says to choose View Log on its row.

### Classification and Extract

- **Extract uses the result's own folder.** Extract on a Kraken2 result reads from and writes into the result's own folder, so a result you renamed, moved or copied extracts where you expect. A copy made in Finder opens with full access, and one named like `X.lungfish copy` opens from the Welcome window with no working-directory question. In a copy, Extract and BLAST read the copy's reads, and when it lacks them Lungfish says which and never reads another project's files. BLAST on a sample whose classification record is missing now says so, where it did nothing.
- **Extract says when it has nothing to extract.** When no ticked taxon has a read in the sample, an alert titled No reads to extract says so. In a CZ-ID result an alert says to classify the sample's FASTQ in Lungfish and extract from that result.
- **Extract is dimmed until you tick a taxon.** In the taxa collections drawer, Extract is dimmed with a hint until a taxon is ticked, and VoiceOver reads Extract ticked taxa in the collection.
- **A TaxTriage row with no reference opens nothing else.** Lungfish used to pick another organism with a similar name, so HPV type 1 could open the reads of type 16. It takes a reference only on an exact name match, and Extract leaves such a row out and names it.
- **The Inspector forgets the last result.** The Summary no longer shows a NAO-MGS or NVD details block above the next result.

### Exports and figures

- **Mapping images show the Depth track and name their range.** An image of a mapping view draws the Depth track above the reads in the scale you chose, and every exported image starts with a line naming its contig, range and length.
- **Mismatch marks in a mapping image.** File > Export > Image (PNG)… shows the mismatch marks the viewer shows, and the note under the reads counts every read not drawn, including those cut off by the track height. A window too wide to draw reads says so.
- **Small export fixes.** Export as CSV and TSV of a classifier result opens in the project that holds it, and Escape answers Cancel on the unpinned tools question of a provenance shell script, as Return does.

### Viewers

- **A tree keeps the window on the screen.** Selecting a tree or a subtree no longer makes the window taller than the screen.
- **A reference at full width draws at once.** A reference wider than the sequence fetch cap (500 Kb unless you changed it) read Fetching sequence… for good while the app kept a core busy.
- **Show Drawer opens the annotation list you are looking at.** It acts on a reference you have just opened and on a mapping result, reads 0 annotations for a reference with none, and shows Building annotation index only while one is being built.
- **The annotation table says when it could not be built.** A missing or damaged annotation database now gets a sentence that says to reopen the bundle or import its annotations again.
- **Smart Cohorts delete buttons name their cohort.** Each says which cohort it removes, to VoiceOver and in its tooltip.

### Long runs

- **Some analysis steps run as long as they need.** `lungfish-cli conda run` and the mapping summary stopped after one hour, GATK variant calling and the ONT genotyping filter after 24 hours, and trimming, deduplicating, subsampling or scrubbing a FASTQ with the bundled tools after five minutes. They run as long as they need, Cancel still stops them, and a stop at a limit of its own names the tool and the limit.

### Plans for a Linux machine

- **Plan reads that already sit on the Linux machine.** Add `--staged-reads <list>` to `lungfish-cli import fastq --write-plan` and the Mac never opens or copies those reads. The sample sheet names each read by its absolute path there, the list holds file, bytes and sha256, and each job checks every read first. Add `--platform`, since the app cannot infer it.
- **The README says which files to copy.** It says to copy or link each listed file that has a source, and to leave a file already in `shared/` where it is.
- **Plans for wastewater samples ask for more disk.** The factor for the wastewater metagenomics preset rises from 10.61 to 12.14, because the largest sample we ran needed 12.13 times the size of its reads, so a 14.8 GB sample requests about 214 GiB where it requested 188 GiB.

## What works differently

### Counts and depth

- **EsViritu and TaxTriage Reads and Unique Reads count each read once.** They counted every alignment record, so a read that aligned in two places counted twice. They now count a read at its primary alignment only, which matches EsViritu's own table, and Extract writes as many reads as Unique Reads. In our test data no EsViritu number changes and three TaxTriage rows drop by 1 to 10 reads, for example 993 reads become 983.
- **An EsViritu virus row measures its whole genome.** RPKMF and Coverage on a summary row now describe the whole genome, and RPKMF matches EsViritu's own assembly summary. A segmented virus such as influenza could read several times too high. In one test sample High Island virus moves from RPKMF 6.9 to 1.2 and from Coverage 2.5x to 0.4x, and the confidence badge, which reads the same Coverage, can drop for a virus with only some segments found. Segment rows and exports are unchanged.
- **Copy Row and Export write one identity.** For a one-contig virus they agree to the last digit, where they differed in the 16th.
- **The mapping contig table shows measured numbers.** Mapped Reads counts each read once, as the mapping's own summary does, and Mean Depth, Coverage Breadth, Median MAPQ and Mean Identity no longer read 0.0 where the record holds real values. For one test mapping Mapped Reads moves from 172,596 to 172,166 and Mean Depth from 0.0 to 84.6.- **Mapped read counts count reads.** Total Mapped and Total Unmapped in the Inspector and the Mapped Reads of `bundle info` and `bundle list` counted alignment records, so a read that aligned in two places counted twice and Total Unmapped left out unplaced reads. For the same mapping Total Mapped moves from 172,596 to 172,166 and Total Unmapped reads 576. Earlier bundles are right when opened, and `bundle info --format json` no longer carries the cached browser summary of a bundle with alignment tracks.

### Pairs, images and exports

- **A pooled map of paired bundles keeps its pairs.** Each pair stays inside its own bundle. For two bundles of four pairs, the pooled BAM reports 16 reads paired in sequencing, as the bundles mapped one by one do. It reported none.
- **Extracted pairs stay pairs.** Reads that a taxa collection extracts from an interleaved sample were recorded as single reads, so later mapping and assembly lost the mates. They are recorded as pairs, the counts do not change, and the folder no longer keeps a record for the plain file that storing replaced.
- **An exported mapping image keeps reads at its left edge.** It left out every read that began before the first base shown, or on it, and counted them as `max 75 rows`. They are drawn as in the viewer, and the live view with Limit visible rows on places them too.
- **A GFF3 export keeps Notes and lists.** It left out every Note and wrote several parents as one escaped value. It now writes each Note and lists such as `Parent=mRNA1,mRNA2` for Parent, Alias, Dbxref, Ontology_term and Derives_from. The source column holds a dot where it held Lungfish, since Lungfish does not keep an imported feature's source, and a feature with only an ID gets no Name. The menu item is File > Export > Annotations (GFF3)…

### Statistics and records

- **Nanopore statistics are measured.** A barcode showed a base count estimated from compressed file size, 383,349 for reads that hold 1,735,173 bases, and 0 for lengths, N50, GC and quality. They are measured from the reads, and a chunk with no final newline, once counted one read short, is counted right.
- **Demultiplexed bundles show counted statistics.** They could show GC 0%, Mean Q 0, Q20 and Q30 0%, and unassigned reads Median 0 and N50 0, because no route counted them. Every route does now, and the median of an even count is the lower middle length, as in imports, so it can move down one step against an older bundle. Reads with no scores, such as FASTA, read No quality scores.
- **The Wall Time of a Linux run is the run's own.** An adopted Linux run read Wall Time under a second, the Mac's adopt time. It reads Wall Time (Linux run) with the run's time, and the tab shows only Loading provenance… while it reads a record.

## Things to know

### If you repeat earlier work

- **Databases.** A classifier database built with an earlier release keeps the counts it stored until you build it again.
- **Files and images.** Export a GFF3 file or a mapping image, copy a mapping table, map a pool of paired bundles and run Extract on a renamed or copied result again to get the new output.

### Limits of these changes

- **Old counts and bundles.** NVD results are not changed, and their Unique Reads can still count a read more than once. Nanopore bundles imported earlier are measured again when opened, and their old numbers stay in project search until you import them again. An older demultiplexed bundle is counted when you first open it in each session, several minutes for many gigabytes, with a message that shows the reads counted so far.
- **Some steps keep a limit.** kraken2 stops at 2 hours, Bracken at 1 hour, the human-read filter of a scrub at 2 hours, a recipe's deduplication step at 1 hour, and the mappers, MAFFT and assembly at up to 24 hours.
- **Images.** An image a few bases wide still leaves out base letters. Above 1,000 bases per point an image leaves the Depth track out and says so, and several alignment tracks get one Depth track each. A reference wider than the cap shows a plain line and no bases.
- **Same-named reads.** Extract and BLAST on a result made in another project read the open project's reads of the same name and place and do not compare them with the originals. After you import reads again, BLAST Matching Reads needs the result reopened, and Extract does not.
- **Mapping numbers.** A mapping you renamed, some made by earlier releases and every filtered track have no saved numbers, so the contig table stays empty while Lungfish measures and the summary bar says Measuring, longer for a large mapping. A failure names the track and what to try. A table copied before can hold 0.0 in four columns. The Inspector's Per-Chromosome list counts alignments and says so, so its rows can add up to more than Total Mapped. A bundle whose statistics lack flagstat read lines keeps alignment counts.

### Smaller limits

- **GFF3.** A list item that holds a comma is written as two items. An imported file's source column is not kept, and a feature named by another attribute, such as gene_name, still gets a Name.
- **One annotation database missing.** If only one of a bundle's annotation databases is missing, the table shows the tracks that opened and does not mention it.
- **Pairs and TaxTriage.** BLAST Verify stays on for a row with no reference and answers after the click. A file that holds pairs and single reads is still recorded as single reads with roles. A taxa extraction's per-file record is retired with the plain file, and the folder's record keeps the command, result and Kraken2 inputs.
- **Renamed open projects.** If you rename an open project in Finder and make a new folder with the old name, Lungfish lets you open the renamed project a second time for editing, so close the first window first.
- **Other commands.** A mapping opened outside a project still asks where to save a consensus bundle. `lungfish-cli assemble --reference-bundle` still refuses an output bundle that exists. A record with no Linux run step shows one Wall Time row.

### Known limits

- **A zero-read Extract ends Failed.** The alert says No reads to extract, and the row in the Operations Panel ends Failed with the same sentence, although nothing went wrong.
- **Cancel does not ask.** Cancel in the Operations Panel stops a run at once, so a click on a row that moved under the pointer can stop the wrong run.
- **A region has no annotations.** A region extracted from a bundle becomes a new bundle with no annotation track. Its sequence and coordinates are right.

### Everything else

The limits in the 2026.10.24 notes still apply, except where a change above says otherwise.
