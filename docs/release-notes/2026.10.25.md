# Lungfish 2026.10.25

Channel: Preview

Previous versioned release: v2026.10.24

Stable baseline: v2026.9.78

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview fixes wrong, empty and silent results.

## What's new

### Importing

- **A dropped ZIP adds its reads.** A ZIP of one read bundle, dropped on the sidebar, adds the bundle to Imports, where the row once ended Completed with no reads. A ZIP that Lungfish Genome Explorer (LGE) cannot import opens a sheet titled `Could not import <archive name>` with the reason and what to try.
- **A Nanopore run folder imports.** The ONT Run Folder card takes the run folder MinKNOW writes, its fastq_pass folder or one barcode folder, and refuses a folder of other reads, such as Illumina, with words that say what to choose.

### Mapping and assembly

- **A pool that cannot keep its pairs stops first.** Pools that mix pairs with single reads, long reads with short reads, or interleaved pairs with R1 and R2 files stop before mapping and say to map them apart. `lungfish-cli map --paired` with other than two files exits 3 and lists them.
- **Generate Consensus saves into the project.** Save as Bundle adds the bundle to Reference Sequences with no file dialog, and Save to File… opens in your project.
- **Reassemble again takes the next free name.** A second Reassemble on the same reads takes a name such as `HG002.chrM_assembly-2` instead of stopping. A failed assembly shows an alert that names it and says to choose View Log on its row.

### Classification and Extract

- **Extract uses the result's own folder.** Extract on a Kraken2 result reads from and writes into its own folder, so a renamed, moved or copied result extracts where you expect. A Finder copy opens with full access and no working-directory question. In a copy, Extract and BLAST read the copy's reads, and when it lacks them LGE says which and never reads another project's files. BLAST with no classification record now says so.
- **Extract and BLAST stop when the reads no longer match.** After Replace in Import FASTQ put other reads under the same names, both used them and said nothing. Extract now checks every read it extracts, and BLAST every read it sends, against the name and length Kraken2 recorded, and both stop with words when a read is missing or differs in length. Both also say when a read file's size changed but its reads are all there.
- **Extract says when it has nothing to extract.** In the taxa collections drawer Extract is dimmed, with a hint, until a taxon is ticked, and VoiceOver reads Extract ticked taxa in the collection. An alert titled No reads to extract says so when no ticked taxon has a read in the sample, and in a CZ-ID result an alert says to classify the sample's FASTQ in LGE and extract from that result.
- **A TaxTriage row with no reference opens nothing else.** LGE used to pick another organism with a similar name, so HPV type 1 could open the reads of type 16. A reference is now taken only on an exact name match, and Extract leaves such a row out and names it.

### Viewers

- **A reference at full width draws at once.** A reference wider than the sequence fetch cap (500 Kb unless you changed it) read Fetching sequence... for good while the app kept a core busy.
- **Show Drawer opens the annotation list you are looking at.** It acts on a reference you have just opened and on a mapping result, reads 0 annotations for a reference with none, and shows Building annotation index only while one is being built. A missing or damaged annotation database gets a sentence that says what to do.

### Long runs and Linux plans

- **Long steps are not cut off.** `lungfish-cli conda run` and the mapping summary stopped after one hour, GATK variant calling and the ONT genotyping filter after 24 hours, and trimming, deduplicating, subsampling or scrubbing a FASTQ with the bundled tools after five minutes. Cancel still stops them, and a stop at a limit of its own names the tool and the limit.
- **Linux plans.** Add `--staged-reads <list>` to `lungfish-cli import fastq --write-plan` for reads that already sit on the Linux machine, and the Mac never opens or copies them. The plan then needs `--platform`, since the app cannot infer it. The wastewater metagenomics preset now asks for 12.14 times the size of the reads in disk, up from 10.61, because the largest sample we ran needed 12.13 times, so a 14.8 GB sample requests about 214 GiB where it requested 188 GiB.

## What works differently

### Importing and processing reads

- **Scores are read as Phred+33.** The shipped Preview 2026.10.24 let BBTools guess the encoding in most imports and every BBTools step, so a short read with a score of about Q55 or more, such as Element UltraQ, quality-filtered or short PacBio HiFi reads, could make a step fail, hang or store every later score 31 too low with no warning, and a step that passes reads through capped scores at Q50. Import such reads again and repeat BBTools steps on them from the original files.
- **Scores are stored in steps of five on every platform.** A score never moves across Q10, Q20 or Q30, so the Q20 and Q30 percentages stay as sequenced, but it can move by up to 2 inside a step, and every score of Q35 and above is stored as Q37, so a HiFi read set shows a mean quality of about 37. Earlier releases stored 0 to 10 as 8 and 18 and 19 as 22, so in one test file the Q20 share read 85% where the reads held 45%. Choose None (keep every score) for Quality Binning to keep every score.
- **Two more score faults are fixed.** With Optimize storage on, None stored every score above Q50 as Q50, and it now keeps scores up to Q93. A FASTQ file whose first read holds only scores of Q31 or above, such as a short PacBio HiFi amplicon kept with None (keep every score), no longer shows its mean quality, Q20 and Q30 too low, and files LGE writes from it keep their scores. If you imported such a file with None, import it again from the original files.
- **Demultiplex Barcodes works with the built-in Illumina kits.** With TruSeq or Nextera XT it stopped with "Adapter sequence is empty". These kits find an index written into the read itself. Reads that an Illumina instrument has already split keep their index only in the read name, which Demultiplex Barcodes does not read. A kit with two indexes, TruSeq HT or Nextera XT, runs at Both Ends, the default, and 5' End or 3' End stops with words, since there it would count chance matches as pairs.
- **Old Phred+64 files are refused.** LGE stores Phred+33 only, so an import of a file in the old Phred+64 encoding (Illumina pipelines 1.3 to 1.7, before about 2011) stops with words that say how to convert it. A modern file refused this way already has Phred+33 scores, so do not convert it and report it.

### Counts and depth

- **EsViritu and TaxTriage Reads and Unique Reads count each read once.** They counted every alignment record, so a read that aligned in two places counted twice. They now count a read at its primary alignment only, and Extract writes as many reads as Unique Reads. In our test data no EsViritu number changes and three TaxTriage rows drop by 1 to 10 reads, for example 993 to 983.
- **An EsViritu virus row measures its whole genome.** RPKMF and Coverage on a summary row now describe the whole genome, and RPKMF matches EsViritu's own assembly summary, where a segmented virus such as influenza could read several times too high. In one test sample High Island virus moves from RPKMF 6.9 to 1.2 and Coverage 2.5x to 0.4x. The confidence badge reads the same Coverage and can drop for a virus with only some segments found. Segment rows and exports are unchanged.
- **Copy Row and Export write one identity.** For a one-contig virus they agree to the last digit, where they differed in the 16th.
- **The mapping contig table shows measured numbers.** Mapped Reads counts each read once and Mean Depth, Coverage Breadth, Median MAPQ and Mean Identity no longer read 0.0 where the record holds real values. For one test mapping Mapped Reads moves from 172,596 to 172,166 and Mean Depth from 0.0 to 84.6.
- **Mapped read counts count reads.** Total Mapped and Total Unmapped in the Inspector and the Mapped Reads of `bundle info` and `bundle list` counted alignment records, so a read that aligned twice counted twice and Total Unmapped left out unplaced reads. For the same mapping Total Mapped moves from 172,596 to 172,166 and Total Unmapped reads 576. Earlier bundles are right when opened.

### Pairs, images and exports

- **A pooled map of paired bundles keeps its pairs.** For two bundles of four pairs, the pooled BAM reports 16 reads paired in sequencing. It reported none.
- **Extracted pairs stay pairs.** Reads that a taxa collection extracts from an interleaved sample were recorded as single reads, so later mapping and assembly lost the mates. They are now recorded as pairs, and the counts do not change.
- **An exported mapping image is complete.** File > Export > Image (PNG)… of a mapping view left out every read that began before the first base shown, or on it, and counted them as `max 75 rows`. It now draws them as the viewer does, adds the Depth track in the scale you chose, the viewer's mismatch marks and a line naming its contig, range and length, and counts every read not drawn, including those cut off by the track height. A window too wide to draw reads says so.
- **A GFF3 export keeps Notes and lists.** It left out every Note and wrote several parents as one escaped value. It now writes each Note and lists such as `Parent=mRNA1,mRNA2` for Parent, Alias, Dbxref, Ontology_term and Derives_from. The source column holds a dot where it held Lungfish, since LGE does not keep an imported feature's source, and a feature with only an ID gets no Name.

### Statistics and records

- **Nanopore statistics are measured.** A barcode showed a base count estimated from compressed file size, 383,349 for reads that hold 1,735,173 bases, and 0 for lengths, N50, GC and quality. They are measured from the reads, and a chunk with no final newline, once counted one read short, is counted right.
- **Demultiplexed bundles show counted statistics.** They could show GC 0%, Mean Q 0, Q20 and Q30 0%, and unassigned reads Median 0 and N50 0. Every route counts them now, and the median of an even count is the lower middle length, so it can move down one step against an older bundle.
- **The Wall Time of a Linux run is the run's own.** An adopted Linux run read Wall Time under a second. It reads Wall Time (Linux run) with the run's time.

## Things to know

### If you repeat earlier work

- **Databases.** A classifier database built with an earlier release keeps the counts it stored until you build it again.
- **Files and images.** Export a GFF3 file or a mapping image, copy a mapping table, map a pool of paired bundles and run Extract on a renamed or copied result again to get the new output.

### Limits of these changes

- **Old counts and bundles.** NVD results are not changed, and their Unique Reads can still count a read more than once. Nanopore bundles imported earlier are measured again when opened, and their old numbers stay in project search until you import them again. An older demultiplexed bundle is counted when you first open it in each session, several minutes for many gigabytes.
- **Some steps keep a limit.** kraken2 stops at 2 hours, Bracken at 1 hour, the human-read filter of a scrub at 2 hours, a recipe's deduplication step at 1 hour, and the mappers, MAFFT and assembly at up to 24 hours.
- **Images.** An image zoomed in to single bases still leaves out base letters. Above 1,000 bases per point an image leaves the Depth track out and says so, and several alignment tracks get one Depth track each. A reference wider than the cap shows a plain line and no bases.
- **Same-named reads.** Extract and BLAST compare read names and lengths, not bases or scores, so a change that keeps each length is not refused, and a result made before this release records no file sizes. A result made in another project reads the open project's reads of the same name and place.
- **Mapping numbers.** A mapping you renamed, some made by earlier releases and every filtered track have no saved numbers, so the contig table stays empty while LGE measures and the summary bar says Measuring. A table copied before can hold 0.0 in four columns. The Inspector's Per-Chromosome list counts alignments and says so, so its rows can add up to more than Total Mapped. A bundle whose statistics lack flagstat read lines keeps alignment counts.

### Smaller limits

- **GFF3.** A list item that holds a comma is written as two items, and a feature named by another attribute, such as gene_name, still gets a Name.
- **One annotation database missing.** If only one of a bundle's annotation databases is missing, the table shows the tracks that opened and says nothing of it.
- **Pairs and TaxTriage.** BLAST Verify stays on for a row with no reference and answers after the click. A file that holds pairs and single reads is still recorded as single reads with roles. A taxa extraction's per-file record is retired with the plain file.
- **Renamed open projects.** If you rename an open project in Finder and make a new folder with the old name, LGE lets you open the renamed project a second time for editing, so close the first window first.
- **Other commands.** A mapping opened outside a project still asks where to save a consensus bundle. `lungfish-cli assemble --reference-bundle` still refuses an output bundle that exists.

### Known limits

- **IDT for Illumina UD Indexes is off.** Its built-in table holds 24 of the kit's 96 pairs, so it stops with words until the sequences are checked. Choose Custom Definition and enter the i7 and i5 sequences from your index sheet. A custom list that gives one sequence two names also stops, where the first name took every read.
- **A zero-read Extract ends Failed.** The alert titled No reads to extract gives a sentence, and the row in the Operations Panel ends Failed with that sentence, although nothing went wrong.
- **Cancel does not ask.** Cancel in the Operations Panel stops a run at once, so a click on a row that moved under the pointer can stop the wrong run.
- **A region has no annotations.** A region extracted from a bundle becomes a new bundle with no annotation track.
- **Quality scores.** Any BBTools step stores a base called at Q0 or Q1 as Q2 with no change to a Q20 or Q30 figure. Merge stores scores above Q50 as Q50 in pairs it cannot merge, and BBMap writes alignment base qualities above Q50 as Q50. Binning cannot be undone once the original files are gone, and in-place imports of downloaded files and single-file imports offer no choice, so use the Import FASTQ sheet or `lungfish-cli import fastq --quality-binning none` to keep every score. Only imports refuse Phred+64, and a Phred+64 file trimmed to no score below Q6 is not caught.

The limits in the 2026.10.24 notes still apply, except where a change above says otherwise.
