# Lungfish 2026.11.17

Channel: Preview

Previous versioned release: v2026.11.16

Stable baseline: v2026.11.14

Dependency set: 2026.2

Preview builds are under rapid iterative development. Features may be incomplete, change quickly, or require additional feedback.

This Preview fixes the three faults that the 2026.11.16 notes list under Things to know, where two loose read files were paired by position with no check that they are mates. It also fixes faults that could give a wrong number, lose what you typed or stop the app, in TaxTriage, NAO-MGS and markdup counts, Verify with BLAST…, quality figures, the Inspector's depth, genotyping reruns, variant filters, annotations, Demultiplex Barcodes, memory use, run records and the FASTQ drawer. A result made by an earlier version stays as it was, except an older TaxTriage result, which is counted again the first time it opens in a project you can edit, and many now show a warning that says what to do.

## What works differently

### Two read files given as a pair

- **`lungfish-cli fastq ingest --pair` checks that the two files are mates.** Before, it paired the reads by position, so a second file in another order gave mismatched mates with no message. Now files with different read counts or reads out of order by their names stop before anything is staged, with a message that starts `Paired FASTQ mates` and exit code 3.
- **`lungfish-cli fastq ribodetector` and `lungfish-cli fastq deacon-ribo` check two read files before the tool starts,** with the same kinds of message and exit code 3. Two FASTA files are checked the same way, and a file that is neither FASTQ nor FASTA by its name, such as one that ends .bz2, is refused. A `.lungfishfastq` bundle is not checked here, since Lungfish Genome Explorer (LGE) checked its mates when it was imported.
- **12S matching now puts a bundle pair's warning in the result.** A pair inside a bundle whose read names carry no mate number is still paired by position, and the warning that only a progress line showed now sits in the result. Two read files given to `lungfish-cli fastq 12s-match` are two samples of single reads, not a pair.

### Metagenomics

- **TaxTriage keeps the top folder of an older result.** Opening or rebuilding an older TaxTriage result deleted its folder named top, so a sample whose rows came only from it could not be counted again. Now the folder stays, and a result that lost it opens with every sample's rows, where it showed `Build failed`. When a rebuild keeps some samples' rows without counting them again, a line above the table names those samples, and an export of such a sample is refused in words.
- **A TaxTriage row that sums several strains counts on every strain.** Before, Unique Reads, Extract Reads and BLAST Verify used the first strain's references only. LGE counts an older result again the first time you open it in a project you can edit, while its report files are still in the result folder.
- **NAO-MGS Unique Reads keep a mate that two pairs share.** Before, the import counted a read as a PCR duplicate when it shared its place, strand and length with a read of a different pair. An earlier import keeps its counts until you import its results file again.
- **`lungfish-cli markdup` counts reads, not alignment records.** A BAM with 2 primary reads, 1 secondary and 1 supplementary record reads `Total reads: 2, duplicates: 1`, where earlier builds read 4 and 1. The markdup step of `lungfish-cli build-db` counts the same way.
- **Verify with BLAST… no longer counts a read for a row because of a name in another species's record.** With NCBI Taxonomy installed, a new check no longer takes a best match such as Woolly monkey hepatitis B virus on a Hepatitis B virus row, and a row under a catch-all species such as "Human rhinovirus sp." no longer counts its unrelated neighbours. Without NCBI Taxonomy, a check saves the hits, reads Not judged and says how to install it.

### Quality figures and depth

- **Fluidigm reads read "No quality scores".** Their reads are built from sequence counts, so no instrument measured their scores. The dashboard, the Inspector, the read table and the Assembly dialog no longer show or use those scores, also for datasets made from such reads. Merge Into New Bundle…, read-ID extraction and Extract Reads from their alignment refuse them in words.
- **A FASTQ operation's new dataset shows the figures of the reads it stores.** Before, its Mean Q and charts described the reads before LGE stored them, and storing raises every score of 0 or 1 to 2. A read with no scores now has an empty Mean Q cell in the read table, where it showed 0.0.
- **Merge Overlapping Pairs keeps the measured scores.** Before, the app's merge wrote one read with Q40 on every base for each unique sequence, and unmerged mates lost their pairs. Now it writes bbmerge's merged reads with their scores, then the pairs that did not merge with the sequencer's scores and names.
- **The Inspector shows the measured depth of a one-sequence alignment.** "Mean Depth" is the figure samtools measured, as in the mapping table. Before, "Est. Coverage" assumed a read length of 150 bp, which for long reads could be off by a large factor.

### Demultiplexing and genotyping

- **A run from the Demux tab uses what the tab shows.** Before, a plan run used the kit's barcode sequences and the default Min Overlap and Allow Indels. Now it runs the sequence typed in a kit row, searches at the tab's Min Overlap and allows no indels when Allow Indels is off. A one-index kit row with two different typed sequences, or a Sequence cell that holds another barcode's sequence, stops in words.
- **A search too large to finish stops before it starts.** A run whose Cutadapt search lines pass 6,000 now stops in words. Before, such a run could sit at `[ 10%] Running cutadapt demultiplexing...` for hours or days, and a very large 5' Distance or 3' Distance could crash the app or use up its memory.
- **Genotyping reuses a saved sample only when its files are unchanged.** A full-length ONT MHC rerun that reuses earlier results now reuses a sample only when every output is the file its checkpoint recorded, and never a checkpoint of an earlier build. Before, a reused sample could hold files that a later run, stopped part way, had overwritten.

### Variants and annotations

- **Typed impact and gene filters read every key the file holds.** Before, a typed `impact=HIGH` in a file with both CSQ_IMPACT and ANN_IMPACT counted one tool's variants. A typed `gene=` read one gene key only, so with CSQ and ANN annotations, or a GENE key beside them, it counted one source's variants, and in a file whose only gene key is SYMBOL it counted none. Filter again. The High Impact table now also finds a key written in another case.
- **GenBank export spells feature keys as INSDC does,** such as CDS, mRNA and ncRNA. Files exported before 2026.11.17 from GFF3, BED or an edited annotation spell them in lower case, so export them again.

### Annotation tracks

- **The annotation drawer names tracks it cannot show.**
- **Exports name an annotation track they cannot read.** Before, GFF3 and GenBank export, the drawer's table export, extraction into a new bundle and iVar variant calling left out a track whose annotation file was missing or unreadable, with no word, so iVar's calls could lack codon and amino-acid changes. Each now names the track, as Go to Gene… does. Import those annotations again, then redo the step.
- **Extraction into a new bundle keeps every annotation.** Before, it could leave out an annotation that shared its name, type and exact position with another, such as two modification sites on one codon. Extract the region again.
- **GFF3 and GTF import keeps every feature.** Before, it dropped a feature that shared its name, type and position with another, such as an exon that two transcripts share, so the track's count, its exports and bundles extracted or merged from it lacked it too. Import the file again, then remove the old track.
- **A GTF transcript or CDS now joins its exons.** Before, Concatenate Exons (remove introns) and Copy as FASTA gave a GTF transcript with its introns, and Copy Translation gave one exon's piece of a GTF CDS, with no word. Attach the GTF file again, then extract or copy again.

### What you type

- **The FASTQ drawer now keeps what you type when you select another dataset, close the project window or quit LGE.** Sample names, kits, the demultiplexing plan and primer-trim settings are saved with the dataset, as Save does. If they cannot be saved, a message says why, and on quit you can choose Don't Quit to keep them in the drawer.

### Views remember where you left them

Leave a result or bundle and come back, in the same session or after you quit and reopen the app. It opens as you left it (the place and zoom, the selected row, the sort, the filters and the sample you chose).

These keep their view in 2026.11.17:
- Mapping results, references and MHC references (the place, zoom, selected contig or sequence, list or focus view, and annotation colours).
- Kraken2, EsViritu and CZ ID, TaxTriage, NAO-MGS and NVD, and 12S (the filter, sort, selected row, samples and layout).
- Genotype (the view mode, layout, cell colours and percent bases).
- RNA-seq results and cell maps.
- FASTQ datasets, assemblies and FASTA collections. Alignments and trees.

**Saved on this Mac only.** Views are saved outside your project and never in your files. A copied or shared project opens at its starting view.

**Changed data.** If a bundle's data changed since your last visit, it opens at its starting view or keeps only what still fits. One line says what was not restored, for example "The data changed since your last visit, so the view was reset."

### Old results that now show a warning

A result made by Preview 2026.11.16 or an earlier build shows a warning line in the Inspector and above the viewer, with what to do, when it is one of these.

- **A loose pair from 2026.11.16.** A FASTQ file that `fastq ingest --pair` made from two loose files, and the reads that `fastq ribodetector` or `fastq deacon-ribo` kept from them, carry the warnings of the other loose-pair routes.
- **TaxTriage, NAO-MGS, EsViritu, NVD and Kraken2 results.** Each says that a saved Verify with BLAST… badge could count a read by a name in another species's record. A TaxTriage result also says that its counts used one strain's references, and one that an earlier version rebuilt with its own cleanup says that its top folder was deleted. A NAO-MGS result says that Unique Reads can read low.
- **Fluidigm datasets.** Before, Fluidigm datasets and datasets made from them showed Mean Q 40, Q20 and Q30 of 100 percent, a read table Mean Q of 40.0 and flat quality charts. After the update they read "No quality scores", except a dataset made by Merge Into New Bundle… that put other reads ahead of them, whose figures still count them as Q40. The Assembly dialog may have preselected Nano HQ from any of them. Read no quality figure from these datasets or from any dataset made from them.
- **Annotation results.** A reference given a GFF3 or GTF track, a bundle extracted from a reference and iVar calls made with no annotation file name the fault above that can touch them. An older GTF track also warns you when you extract or copy as FASTA.

These show one too.

- **A run started from the Demux tab.** If you changed the tab's sequences, Min Overlap or Allow Indels, demultiplex again from the tab.
- **A trimmed FASTQ dataset.** If its reads held scores of 0 or 1, its Mean Q and quality charts can read a little lower than the stored reads, while Q20 and Q30 are not changed. Run the trim again to measure the stored reads. A dataset of another FASTQ operation, or of a trim that named its adapter or turned adapter trimming off, can read low the same way with no warning.
- **A Merge Overlapping Pairs dataset.** It holds one copy of each read sequence with Q40 on every base, and later steps counted each copy once, though each stands for several reads. Merge the original pairs again, and redo the work that used the merged reads.
- **A record that an import replaced or an ingest dropped.** A 12S, TaxTriage, EsViritu, Kraken2 or NAO-MGS result after a sample metadata import, and an extracted FASTQ file ingested in place. Run the analysis or the extraction again, or import a NAO-MGS results file again.
- **A genotype result that reused a saved sample.** Run the genotyping again without reusing earlier results.

## Things to know

The limits in the 2026.11.15 notes still apply, and so do the earlier limits that those notes keep.

- **Some old results of the loose-pair routes show no warning.** Whether the Inspector finds the record that `fastq ingest --pair`, `fastq ribodetector` and `fastq deacon-ribo` write beside a loose FASTQ file was not checked. The record of a 12S result does not name its read files, so a 12S result made by an earlier version from a pair inside a bundle shows none. If you made a result from two loose files with one of these routes, run it again with this version.
- **A bundle pair with no mate numbers still runs in 12S matching.** It is paired by position, and the warning in the result is the only sign. If an earlier version imported that bundle from two files out of step, its species counts can be wrong. Import the original files again with this version, which checks that the reads are mates.
- **An older merge with other reads ahead of Fluidigm reads still counts Q40.** A dataset that Merge Into New Bundle… made before this version keeps a Mean Q that counts the written Q40. No figure is right for such a mix, so read no quality figure from it.

### View memory

- **Restored contig.** A mapping result that comes back with a contig selected loads that contig's alignment evidence only when you click the row. Until you click the selected row, the consensus row and Extract show "Click the selected row in the list to load its alignment evidence." Click the selected row once.
- **The changed-data line.** It can cover the top of the tracks until you leave the bundle. In a mapping result it shows under the ruler, and only once you click a contig row.
- **No Reset View yet.** To return a view to its start, undo your changes by hand, and the view is no longer kept. View > Reset View Settings to Defaults still resets colours and track height in every bundle, but it does not reset most views.
