# Lungfish 2026.10.29

Channel: Stable

Previous versioned release: v2026.10.28

Stable baseline: v2026.10.27

Dependency set: 2026.2

This Stable release brings the work since Stable 2026.10.27, which is Preview 2026.10.28 and the changes made after it. A NAO-MGS share that was doubled for paired-end reads and a NAO-MGS BLAST check that could not show a better match are now right, Verify with BLAST… no longer counts a close relative in the same species against a row, read extraction and alignment counts that were wrong are fixed, failure alerts say what to try, saved BLAST results come back, and the classifier viewers share one set of buttons. Some numbers and files change, so read What works differently before you compare with old results.

## What works differently

### NAO-MGS shares and BLAST checks

- **A paired-end NAO-MGS share is no longer doubled.** Since v0.4.0-alpha.1, a paired-end NAO-MGS result showed each virus's share of its sample's hits at about twice its true value, so a share could pass 100%. Open a result again for the right share, with no new import, and do not reuse a share you noted before. Hits and Unique Reads count each mate of a read pair as one read.
- **NAO-MGS Verify with BLAST… searches all of NCBI's core_nt database.** From v0.4.0-alpha.1 to Preview 2026.10.28 it searched only the taxon's own records, so a badge could read Supported when another organism matched better. A best match in another organism, such as the host, now contradicts the taxon, and the badge can read Mixed or Unsupported. Run Verify with BLAST… again on any NAO-MGS call you rely on.
- **Verify with BLAST… judges a row at species level.** A best match filed under another name in the same species counted as contradicting, so a correct call could read Mixed or Unsupported. On one Human rotavirus A row, seven reads at 100% identity read 5 supporting and 2 contradicting. Such a read now supports in NAO-MGS, EsViritu, TaxTriage, NVD and Kraken2 results. Run Verify with BLAST… again on any row that read Mixed or Unsupported.
- **Verify with BLAST… reads both mates of a read pair.** EsViritu and TaxTriage ignored the second mate with no word, so a row could read Inconclusive with `No significant hit` when the second mate matched at 100%, and a dropped match to another organism could leave a badge at Supported. Both mates are now judged and the pair counts once, as in `1 supporting, 0 contradicting (1 fragment, 2 reads)`. A pair whose mates match different organisms counts as neither and shows in the conflicting count. Run it again on any EsViritu or TaxTriage row from paired-end reads.
- **EsViritu Verify with BLAST… uses only the row's own sample.** In an EsViritu batch it could take its reads from another sample's alignment file when the row's own sample had none. It now reads only the row's own sample. We have not checked whether the table's right-click menu could reach the old case.

### Saved BLAST results and the table you export

- **A saved BLAST result comes back.** In NAO-MGS, EsViritu, TaxTriage and NVD a saved result comes back when you return to its row, and the BLAST Results pane stays as you left it. A row shows only the search sent from that row, in that result and sample, and a row with no search leaves the pane as it was, so read which taxon the pane names. In the Assembly and 12S viewers a result comes back when you select the same contigs, in any order, or open Unresolved in 12S with the same sequences showing, and the pane opens by itself.
- **The BLAST table you export says what each read means for the row.** Verdict says only whether a read's alignment passed the quality thresholds, so a read that contradicts the row can read `verified`. The new Queried Taxon and Taxon Check columns at the end say what the read means for the row, and a BLAST of a contig or a sequence leaves Queried Taxon empty and Taxon Check at `no taxon queried`. A table exported by an earlier version lacks them, so export it again before you rely on it.
- **BLAST rows in Operations.** A finished BLAST row now gives the pane's counts, where it said `1/1 verified`. Lungfish asks NCBI about a running search once a minute, so a finished search can take up to a minute to appear.
- **A 12S result replaced on disk.** Export now stops and says so when the open 12S result was replaced on disk, and so does BLAST when the result's sequences are no longer the ones on screen, so no wrong sequence goes to NCBI. The Unresolved tab now says so when its sequences cannot be read, since an empty table there does not mean the result has none.
- **A moved, renamed or copied assembly result reads its own folder.** BLAST Contig, Copy FASTA, saved BLAST results and the Inspector's run details read the folder the assembly was first made in. BLAST Contig did nothing and said nothing if that folder was gone, and in a copied project a contig of the same name was read from the original folder, so the sequence sent to NCBI or copied could differ from the one on screen, with no word. Every action now reads the result on screen, with no new import, and Extract, Export FASTA, Create Bundle and Run Operation say so and do not run when its contigs file cannot be read. If you ran BLAST Contig or Copy FASTA on a copied or moved assembly with an earlier version, run it again. This goes back to at least v2026.9.78.
- **An assembly result that changes on disk while it is open.** If an assembly's contigs file was replaced while the result was open, for example by a Finder Replace or a sync folder, the table kept the old rows, and BLAST Contig, Copy FASTA, Export, Extract, Create Bundle and Run Operation could use other bases than the contig on screen, with no word. They now stop and say why, and nothing goes to NCBI. Select another item in the sidebar and then the result again. An index file left beside a replaced contigs file no longer gives wrong bases or lengths, an assembly refuses a folder that holds a finished assembly instead of overwriting it, and a search saved on the old contigs no longer comes back on a new contig of that name. If you replaced a contigs file in an assembly with an earlier version, repeat any BLAST, export or bundle you made from that result. This goes back to at least v2026.9.78.

### Reads you extract

- **Unique Reads and Extract Reads count each read once.** A BAM with secondary or supplementary alignments made NVD Unique Reads, and an extraction from an EsViritu, TaxTriage, NVD or NAO-MGS row, count a read more than once, and on our small test file a count of 7 became 5. EsViritu, TaxTriage and NVD rows now write each read once, matching Unique Reads, and we have not checked this for a NAO-MGS row. In our test data no EsViritu extraction changes and one TaxTriage row writes 983 reads where it wrote 993. An NVD result imported with Stable 2026.10.27 or earlier keeps the Unique Reads it stored and can extract fewer reads than it shows, so import it again.
- **Extract Reads keeps both mates.** A pair that a run mapped as two single reads lost one mate in an extraction, so it could come out a few reads short of the count shown, on our test data 1 to 5 reads and up to a third of a small selection, with no word. Both mates are now kept when you extract from an EsViritu or TaxTriage result, by read ID from a BAM, from a region of the alignment viewer, and for selected reads by name. Extract again to get the missing mates.
- **NAO-MGS reads are stored on the right strand.** Extract Reads from a NAO-MGS result wrote about half its reads reverse-complemented, and the reads view and the BAM file showed them on the wrong strand too. A result imported with 2026.10.28 or later writes each read as it was sequenced, and `lungfish-cli markdup --force` keeps the BAM files of a NAO-MGS result, where it replaced them with empty ones.
- **Older NAO-MGS results are refused, not extracted.** A NAO-MGS result imported with Stable 2026.10.27 or earlier gave reverse-complemented reads when extracted and false mismatches in the read panels, although counts and read IDs were right. The read panels now say so, and Extract Reads and the command line refuse with the same words and write nothing. Import the same NAO-MGS results file again in the Import Center, under NAO-MGS Results.

### Alignment counts

- **Alignment counts say what they count.** When an alignment's statistics hold no read counts, as with a samtools before 1.9 or a file it cannot read, the Inspector and the mapping header label the numbers as alignments and the import says to run it again. A count taken from a bundle's manifest also shows as alignments, even when it is a read count. When the total number of reads is unknown, the header shows no percentage, where it showed `N / N reads mapped (100.0%)`, and the Inspector shows Not recorded for a track with no counts, not 0. `lungfish-cli import bam` into a plain folder now counts reads the way the app does, so a BAM with supplementary alignments reports its reads and not its alignment records.

## What's new

### Failures explain themselves

- **Failure alerts name the step and the next thing to try,** with the technical error under Show Details. Some alerts still show the technical error as their text.

### The classifier viewers

- **NAO-MGS, EsViritu, NVD, TaxTriage and Kraken2 share one action bar** with Verify with BLAST…, Export, Extract Reads… and BLAST Results.

### Time limits

- **Analysis steps no longer stop at a fixed time.** They run until they end or you press Cancel, and some commands take `--time-limit <minutes>`.

### Records that name their database

- **EsViritu and TaxTriage records name their database,** and a database installed by hand shows as unpinned. An NVD or CZ-ID import names the database versions its result states, and every other import says its result names no database, so cite the run that made it. Records written before 2026.10.28 stay as they were.

## Things to know

### Limits you may meet

- **BLAST Verify.** It judges at species level when the NCBI Taxonomy database is installed, and for an EsViritu row the EsViritu database too, so it cannot tell strains, genotypes or host groups apart. A SARS-CoV-2 row is judged at Betacoronavirus pandemicum, which includes SARS-CoV-1 (about 80% identical) and the SARS-related viruses of bats and other hosts. Influenza A, Influenza B and Norovirus norwalkense are judged along the line from the strain up to the species and its names, so a record named otherwise can count as another organism. Without those databases, a best match in another virus of the same species counts as contradicting, and an EsViritu row is judged by names, so a record of another species with the same first word can count as supporting. A read tied at one score counts as supporting when any of the five records NCBI returns for it is in the row's species, and the row shows a conflicting count. NCBI can return a different five on another run, so the same reads can read Supported once and Unsupported the next time. A large row is sampled read by read, so some pairs send one mate, and a virus cannot be told from a lab vector built from it. Look at each read's best match in the saved result before you rely on a badge. A search still in NCBI's queue after about 10 minutes stops and gives its request ID. About half of our test searches stopped this way, and those we followed finished at NCBI hours later. Lungfish cannot read a finished search back or badge it, so send the row again later, or open it on NCBI's site. NAO-MGS checks can also take longer than before. In the Assembly and 12S viewers a saved result comes back only for exactly the contigs or sequences that were searched, and no list of past searches exists there, so note which ones you sent.
- **NAO-MGS.** An import made with another minimum identity can give other counts. The note about a missing alignment file appears once Lungfish has tried to rebuild the file from the reads stored in the result, which takes a few seconds for a recent import and can take longer for a large older result. A window that the note stretched before the update can still open wider than your screen, so choose Window > Zoom once.
- **Extract counts.** The count shown for a region or a selection in the alignment viewer is the number of alignment records, so the file can hold fewer reads, one fewer for each selected record with no sequence and for each extra record of a read that repeats another record's mate flag.
- **Time limits.** Only `lungfish-cli kraken2 classify`, `map`, `assemble`, `align mafft`, `extract reads`, `fastq scrub-human`, `variants call` and `variants phase` take `--time-limit <minutes>`, which stops a step that runs past it, and the app has no field for one, so press Cancel to end any other run.
- **Database names.** A NAO-MGS import states no database or pipeline version, an NVD import records the BLAST and STAT database versions its result states and no database name, date or checksum, and no import carries a checksum.
- **12S results.** The screen does not refresh by itself when a 12S result is replaced. It keeps the old numbers until you select another item in the sidebar and then the result again, and the same steps clear the message that Export and BLAST show. Export also stops when the result was written again with the same numbers. An assembly's table does not refresh by itself either, and the same two steps clear it.
- **A BLAST search saved before you rename an assembly result.** A saved search goes with the result's name, so after you rename the result in the sidebar the earlier search stays on disk and does not come back. A search saved after the rename does, and renaming the result back brings the earlier one back.
- **Earlier notes.** The limits in the 2026.10.27 notes still apply, apart from the fixed time limits and the NVD Unique Reads count, which this release changes.
