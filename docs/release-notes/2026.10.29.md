# Lungfish 2026.10.29

Channel: Stable

Previous versioned release: v2026.10.28

Stable baseline: v2026.10.27

Dependency set: 2026.2

This Stable release brings the work since Stable 2026.10.27, which is Preview 2026.10.28 and the changes made after it. A NAO-MGS share that was doubled for paired-end reads and a NAO-MGS BLAST check that could not show a better match are now right, Verify with BLAST… no longer counts a close relative in the same species against a row, read extraction and alignment counts that were wrong are fixed, failure alerts say what to try, and the classifier viewers share one set of buttons. Some numbers and files change, so read What works differently before you compare with old results.

## What works differently

### NAO-MGS shares and BLAST checks

- **A paired-end NAO-MGS share is no longer doubled.** Since v0.4.0-alpha.1, a NAO-MGS result from paired-end reads showed each virus's share of its sample's hits at about twice its true value, so a share could pass 100%. Shares are now correct for results made before and after this release, and you only need to open a result again to see them right, with no new import. Do not reuse a share you noted from an earlier version for paired-end reads. Hits and Unique Reads count each mate of a read pair as one read, and hovering a column header in the NAO-MGS table now says what the column counts.
- **NAO-MGS Verify with BLAST… searches all of NCBI's core_nt database.** In every version from v0.4.0-alpha.1 to Preview 2026.10.28 it searched only records of the taxon being checked, so no read could contradict the taxon and the badge could read Supported when another organism matched better. A read whose best match is another organism, such as the host, now counts as contradicting the taxon, and the badge can read Mixed or Unsupported. The EsViritu, TaxTriage, Kraken2 and NVD checks searched everything already. Run Verify with BLAST… again on any NAO-MGS call from an earlier version that you rely on.
- **Verify with BLAST… judges a row at species level.** A read whose best match was filed under another name in the same species, such as Rotavirus A for a Human rotavirus A row or Canine respiratory coronavirus for a Human coronavirus OC43 row, counted as contradicting, so a correct call could read Mixed or Unsupported. On one Human rotavirus A row, seven reads at 100% identity read 5 supporting and 2 contradicting. Such a read now counts as supporting in NAO-MGS, EsViritu, TaxTriage, NVD and Kraken2 results. Run Verify with BLAST… again on any row that read Mixed or Unsupported, since a saved result keeps the badge it was given.
- **EsViritu Verify with BLAST… uses only the row's own sample.** In an EsViritu batch it could take its reads from another sample's alignment file when the row's own sample had none. It now reads only the row's own sample. We have not checked whether the table's right-click menu could reach the old case.

### Reads you extract

- **NVD Unique Reads counts each read once.** A BAM with secondary or supplementary alignments made the column count a read more than once. On our small test file a count of 7 became 5. An NVD result imported with Stable 2026.10.27 or earlier keeps the Unique Reads it stored, so import it again to get the corrected number.
- **Extract Reads writes each read once.** From an EsViritu, TaxTriage, NVD or NAO-MGS row, an extraction wrote a read more than once when its alignment file held secondary or supplementary alignments. EsViritu, TaxTriage and NVD rows now write each read once, matching Unique Reads, and we have not checked this for a NAO-MGS row. In our test data no EsViritu extraction changes and one TaxTriage row writes 983 reads where it wrote 993. From an NVD result imported with Stable 2026.10.27 or earlier, an extraction can write fewer reads than the older Unique Reads it shows until you import the result again.
- **Extract Reads keeps both mates.** A pair that a run mapped as two single reads, as happens with reads downloaded from SRA, lost one mate in an extraction. Both mates are now kept when you extract from an EsViritu or TaxTriage result, by read ID from a BAM, from a region of the alignment viewer, and for selected reads by name from an alignment. Before, an extraction could come out a few reads short of the count shown, on our test data 1 to 5 reads and up to a third of a small selection, and nothing said so. Extract again to get the missing mates.
- **NAO-MGS reads are stored on the right strand.** Extract Reads from a NAO-MGS result wrote about half its reads reverse-complemented, and the reads view and the BAM file in the result folder showed those reads on the wrong strand as well. A result imported with 2026.10.28 or later writes each read as it was sequenced, and `lungfish-cli markdup --force` keeps the BAM files of a NAO-MGS result, where it replaced them with empty ones.
- **Older NAO-MGS results are refused, not extracted.** A NAO-MGS result imported with Stable 2026.10.27 or earlier stored the reads that map to the reverse strand the wrong way round, so those reads came out reverse-complemented when extracted and showed as false mismatches in the read panels, although counts and read IDs were right. The read panels now say so, and Extract Reads and the command line refuse with the same words and write nothing. Import the same NAO-MGS results file again in the Import Center, under NAO-MGS Results. The new result takes the name with -2 added, and the old one stays in the project until you remove it.

### Alignment counts

- **Mapped counts say what they count.** When an alignment's statistics hold no read counts, the Inspector and the mapping header label the numbers as alignments, since a read that aligned in more than one place counts once for each place. When the total number of reads is unknown, the header shows no percentage and says so, where it showed `N / N reads mapped (100.0%)`. The Inspector shows Not recorded for a track that holds no counts, where it showed 0.
- **The command line says the same.** `lungfish-cli bundle list` and `bundle info` label alignment counts, and `bundle info --format json` adds a `mapped_read_count_basis` entry that says what each alignment track's `mapped_read_count` counts. `lungfish-cli import bam` into a plain folder now counts reads the way the app does, so a BAM with supplementary alignments reports its reads and not its alignment records.

## What's new

### Failures explain themselves

- **Failure alerts name the step and the next thing to try.** Alerts from the Import Center, the Inspector, the genotype and assembly views, sequence and table export, project opening and migration, annotation edits, primer exports and FASTQ barcode detection now say which step failed, what happened and what to try next. A message the app wrote about your own input, such as a BAM file opened as a document, a sample sheet with a missing column or a bundle that is read-only, stays in view with the next step beside it. The technical error is under Show Details.
- **A NAO-MGS, NVD or CZ-ID result that cannot be opened says which one.** The alert names the result and says what to try next, such as importing it again for a missing file or an older layout, and the technical error is under Show Details.
- **Verify with BLAST… says why it cannot start.** When NAO-MGS cannot start BLAST or cannot read the reads for it, or an EsViritu result records no alignment file for the sample, the results below the table say why instead of an alert. The refusals for an NVD contig without its sequence and for a Kraken2 result without its reads name the button Verify with BLAST….
- **A database archive that cannot be installed says why.** When it holds a link that leaves its own folder, the alert names the link, says that nothing was installed and says what to try. A ZIP dropped on the sidebar that holds such a link says the same. The official Kraken2 viral and EsViritu archives hold no such link and install as before.
- **A NAO-MGS result whose alignment file is missing says so.** The read panels name the file and tell you to import the same NAO-MGS results file again. They used to stay blank.

### The classifier viewers

- **NAO-MGS, EsViritu, NVD, TaxTriage, Kraken2 and CZ-ID results open through one viewer host,** as 12S results and primer analyses do. Opening a FASTQ bundle or a 12S result afterwards no longer leaves the run details or summary of an EsViritu, NVD, TaxTriage or Kraken2 result in the Inspector. Opening a text, PDF or image file after a NAO-MGS result no longer leaves that result's summary there either.
- **NAO-MGS, EsViritu, NVD, TaxTriage and Kraken2 share one action bar.** It shows Verify with BLAST…, Export, Extract Reads… and BLAST Results, and the right-click menus use the same words. BLAST Results shows or hides the BLAST results below the table, and a greyed button says why it is greyed, for example "Select one or more rows to extract their reads." The buttons carry the same names for VoiceOver, and the in-app Help page on classification review names them.
- **Kraken2 menus use the shared row words.** The row and sunburst menus say Verify with BLAST… and Copy Name, and list Open Taxonomy on NCBI, Open GenBank Record and Search PubMed directly, with no Look Up on NCBI submenu, which the EsViritu table menu still has.
- **CZ-ID results show the same bar with BLAST and Extract dimmed.** A CZ-ID import holds no read IDs, so Extract Reads… and Verify with BLAST… stay dimmed with the reason as their tip, in the bar and in the sunburst chart's menu, and the BLAST Results button is not shown. A Kraken2 result copied from a project without its reads dims the same two chart items, as its table menu already did.
- **12S results, primer analyses and primer orders open through the same host.** They look as before. Leaving a 12S result now takes its Detail tab and its result and sample blocks out of the Inspector. A primer analysis or primer order hides the ruler, header, status bar, gene tabs and annotation drawer of the reference under it, and View > Show Drawer does nothing while one is showing.

### Time limits

- **Analysis steps no longer stop at a fixed time.** Kraken2, Bracken, the mappers, read extraction, variant calling, human read removal, MAFFT alignment, assembly, the FASTQ tools, FASTQ import, demultiplexing, BAM import and filtering, duplicate marking, primer trimming, read orientation, Savont clustering, ONT genotyping, Freyja, the database builds and the FASTA and VCF clean-up steps run until they end or you press Cancel, which stops them at once. Savont used to stop after 2 hours and Freyja after 24. Short version, header and index checks, tool installs, database downloads, network requests and the barcode scout over a small sample of reads keep their own fixed limits.
- **`--time-limit` stops any one analysis step that runs too long, when you want that.** `lungfish-cli kraken2 classify`, `map`, `assemble`, `align mafft`, `extract reads`, `fastq scrub-human`, `variants call` and `variants phase` take `--time-limit <minutes>`, which stops any single analysis step of the run that goes past that many minutes. The run record says the limit you gave, and a stop by a limit tells you to run again without it or with a longer time. A GATK run now applies the limit it records, where it recorded a limit and ran without one.

### Records that name their database

- **EsViritu and TaxTriage records name their database.** The record and the Provenance tab give the database release and the checksum Lungfish took when it installed the database, as Kraken2 records already did. A database you installed by hand shows as unpinned. An NVD or CZ-ID import names the database versions its result states, and every other import says that its result names no database, so cite the run that made it. Records written before 2026.10.28 stay as they were.

## Things to know

### Limits you may meet

- **BLAST Verify.** It judges a row at species level when the NCBI Taxonomy database is installed, and for an EsViritu row the EsViritu database too. So it cannot tell strains, genotypes or host groups apart. A SARS-CoV-2 row is judged at its species, Betacoronavirus pandemicum, which includes SARS-CoV-1 and the SARS-related viruses of bats and other hosts, even though SARS-CoV-2 and SARS-CoV-1 are only about 80% identical across the genome. For Influenza A, Influenza B and Norovirus norwalkense, which have too many strains to list, it checks the line from the strain up to the species and the names on it, so a record named otherwise can count as another organism. Without those databases, a best match that is another virus of the same species, such as Bovine coronavirus for Human coronavirus OC43, counts as contradicting, and an EsViritu row is judged by names, so a record of another species that starts with the same word, such as a Rotavirus C record for a Rotavirus A call, can count as supporting. A read tied at one score between species counts by the record NCBI lists first. Look at each read's best match in the saved result before you rely on a badge. NAO-MGS Verify with BLAST… can also take longer than before, because the search is no longer limited to the taxon, and a search still in NCBI's queue after 10 minutes stops with its request ID, so you can look for it on NCBI's site.
- **NAO-MGS.** Older results need their results file again, and an import made with another minimum identity can give other counts. The note about a missing alignment file appears once Lungfish has tried to rebuild the file from the reads stored in the result. For results imported by recent versions that takes a few seconds, and an older result that still holds its reads is rebuilt first, which can take longer on a large result. Extract Reads and Verify with BLAST… keep their own words for a missing file.
- **Extract counts.** The count shown for a region or a selection in the alignment viewer is the number of alignment records. The file can hold fewer reads, one fewer for each selected record that has no sequence and for each extra record of one read that carries the same mate flag as another record of it, which is written once.
- **Time limits.** Only the commands named above offer `--time-limit`, and the app has no field for one, so press Cancel to end any other run.
- **Database names.** A NAO-MGS import states no database or pipeline version, an NVD import records the BLAST and STAT database versions its result states and no database name, date or checksum, and no import carries a checksum.

### Counts, alerts and earlier notes

- **Alignment counts.** When samtools gives no per-read counts, as with a samtools before 1.9 or a file it cannot read, the numbers are alignments, labelled as such, and the import says to run it again. A count taken from a bundle's manifest shows as alignments in the header, even when it is a read count.
- **Failure alerts.** Some alerts still show the technical error as their text.
- **Earlier notes.** The limits in the 2026.10.27 notes still apply, apart from the fixed time limits and the NVD Unique Reads count, which this release changes.
