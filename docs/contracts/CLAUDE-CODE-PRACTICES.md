# Claude Code best practices in LGE

The owner directed on 2026-10-18 that the best practices page of Claude Code,
https://code.claude.com/docs/en/best-practices, is checked weekly and that its practices are incorporated into the
contracts and the expert plans. This contract holds the weekly check and the decisions that come from it. Its practice
ids, BP01 and on, are the ids of `/Users/dho/lungfish-phase-records/best-practices/2026-10-18-check.md`, the first
check.

## Basis of a rule

A rule of `docs/contracts/RUNNING-A-PHASE-SESSION.md` rests on a measurement in its Evidence tables. A rule that comes
from the page rests on the page, and it has the basis `page` until a session of the monitor measures it. The monitor
then keeps, changes or removes the rule as the End-of-session duty of that contract sets. A measurement that
contradicts the page wins, and the Decisions and trials table records it.

## Weekly check

| Step | What the monitor does |
|---|---|
| Due | At its first run of a session, which is checkpoint 0 of a phase session and the single end run of a short one, the monitor reads the newest date in the file names under `/Users/dho/lungfish-phase-records/best-practices/`. The check is due when that date is more than 7 days before today |
| Hash | One call runs `curl -sL --fail --proto '=https' --proto-redir '=https' --max-time 30 -o SCR/llm/bp-page.md https://code.claude.com/docs/en/best-practices.md`, and one call runs `shasum -a 256 SCR/llm/bp-page.md`. A hash equal to the one in the newest `*-page.md` or `*-unchanged.md` writes `<today>-unchanged.md` with the date and the hash, deletes the download and ends the check |
| Diff | A new hash sends the monitor through the downloaded text and the newest `*-page.md`. It writes `<today>-diff.md` with the hash before and after and the added, removed and changed practices, each with its section, its status in our contracts (holds, part, contradicts or lacks) with file and line, and an exact proposal. A new outline goes to `<today>-page.md`, written in the monitor's own words. A change of wording only writes `<today>-unchanged.md` with the new hash. The monitor deletes the download in both cases |
| Reach | The monitor reads the page and at most three pages that the newest `*-page.md` lists as read before |
| Cost | A current hash costs two calls and no reading. A changed page costs one read of the new text, 36,520 bytes today, and of the newest outline, and the log entry shows it under role llm |
| Report | The monitor puts one numbered action at the top of `SCR/llm/actions.md` with the path of the diff and the counts. The manager lists each added or changed practice under the owner direction of the next plan, in the form of rows O10 and O11 of `docs/plans/2026-10-17-phase-2-12.md`, and hands it to the expert it concerns. The QA and QC expert takes verification, hooks and permissions, the ARCH expert takes file size and layout, and the SWIFT expert takes process and security-sensitive command forms. A proposal that changes a recorded decision goes to a vote, as `docs/contracts/EXPERT-PANEL.md` sets under Rulings and disputes |
| Land | The monitor changes a contract only at its last checkpoint and only for a proposal that the owner or the panel accepted. Each row it adds has the basis `page` |
| Failure | A download that fails writes `<today>-unreachable.md` with the exit code, and the next checkpoint tries again |
