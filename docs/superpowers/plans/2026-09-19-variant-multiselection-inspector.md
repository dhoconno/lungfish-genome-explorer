# Variant multi-selection Inspector

## Intent and diagnosis (Astra)
User needs meaningful Inspector content when several variant table rows are selected. Current tableViewSelectionDidChange returns unless selection count equals one, leaving stale single-variant details and editable annotation fields. Preserve the recent single-selection/no-navigation behavior and full Inspector/table parity.

## Bounded design
Single selection retains current rich detail. Multiple selected rows show a read-only Variant Selection summary: selected row count, unique variant count (track ID + row ID), track/chromosome/type breakdown, and an expandable lazy list of selected variants with their resolved table fields and retained INFO/FORMAT values. Genotype selection preserves sample identity; several samples of one variant must not masquerade as several variants. Do not average allele frequencies or aggregate unrelated genotype counts. Clear stale single-annotation editing controls. Empty selection clears details. No viewport movement or synthetic genomic interval selection.

## Implementation ownership
Own Inspector VariantSection.swift (or focused new multi-selection view file), InspectorViewController+Notifications.swift observer registration in InspectorViewController.swift, notification constants, drawer delegate declarations and tableViewSelectionDidChange, controller delegate bridge. Coordinate minimal hunks in AnnotationTableDrawerView.swift and ViewerViewController+AnnotationDrawer.swift with export/zoom owners. No changes to hover or export service.

1. Define immutable entry payload in app layer containing SearchResult, [VariantInspectorField], optional genotype sample name. Stable entry identity includes track+variant row+sample when present, safe fallback coordinates for nil IDs.
2. New scoped notification variantSelectionChanged with entries payload for MULTI/EMPTY path; preserve existing variantSelected single path and viewer-originated callers. Default noop delegate method for arrays. Sender is drawer; do not route arrays through singular handlers or make own drawer reselect first row. Observer respects same window scoping.
3. Drawer maps selected row indexes in displayed order. Calls captures rows; Genotypes captures exact sample and resolves parent by full track+row identity. Zero/multi invokes new method. Single retains didHighlightVariant. Context menu Show in Inspector should respect selected rows when multi-selected (coordinate export owner); context clicking an unselected row uses that single row. Avoid introducing navigation.
4. Controller multi/empty handler clears viewer selectedAnnotation and posts annotation deselection without auto variant notification, then posts rich array event. Inspector clears old annotation SelectionSection state and selects new entries; selectItem tab for nonempty, avoid forced tab on empty. Multi entry model cancels/bump existing async load generation so old single DB result cannot reappear. Single select/clear resets multi entries.
5. UI Variant Selection summary and lazy expandable per-entry details, copy selection action. Use already resolved table strings and raw retained info values; no per-row DB fetch storm. Labels distinguish selected genotype rows from unique variants. Keep all entries accessible (scroll/lazy), long values wrap/selectable. Hide single editable annotation section because no single target. Single behavior unchanged.
6. Selection changes due local filtering/hiding/query replacement must update Inspector to actual surviving selection, including zero; suppress intermediate reload events then publish once after restoration. Do not reintroduce sort-triggered navigation or selection echo. Scope this to relevant Calls restoration paths; don't redesign query engine.

Tests run by sole Sol Medium builder, not implementation worker. Preserve previous 158 passing baseline and all uncommitted work. No scientific output or provenance changes in this slice.
