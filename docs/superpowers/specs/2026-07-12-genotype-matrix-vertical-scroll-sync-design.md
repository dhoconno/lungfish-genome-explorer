# Genotype matrix vertical-scroll synchronization

## Goal

Keep the pinned genotype metadata panel and the per-sample matrix panel aligned
to the same visible row while either panel is scrolled vertically. Horizontal
scrolling remains independent in the per-sample matrix.

## Current behavior and cause

`GenotypeComparisonMatrixView` has two `NSScrollView` instances:

- `pinnedScrollView` contains the genotype, locus, and summary columns.
- `scrollView` contains the sample-value matrix.

The view observes bounds changes only from `scrollView.contentView` and copies
that Y offset to `pinnedScrollView`. A wheel gesture over the pinned panel can
therefore change only its own offset, leaving the two tables on different rows.

## Design

Register the same bounds-change observer for both content views. The handler
identifies the scroll view that originated the notification, then copies only
its Y offset to the other scroll view. A shared reentrancy guard suppresses the
notification generated by the programmatic update, so this works in either
direction without a loop.

The helper preserves each destination content view's X offset. This keeps the
sample panel's horizontal position untouched and continues to hide the pinned
panel's horizontal scrolling.

## Error handling

The handler ignores unrelated notifications, already-synchronized offsets, and
programmatic synchronization notifications. It does not alter selection,
filtering, row heights, or sort state.

## Verification

Add a regression test that constructs the comparison matrix with enough rows to
scroll, then verifies both directions:

1. Moving the sample matrix vertically moves the pinned panel to the same Y
   offset.
2. Moving the pinned panel vertically moves the sample matrix to the same Y
   offset.
3. The sample matrix's X offset is preserved when vertical synchronization
   occurs.

Run the focused genotype viewport tests and relevant UI build/test coverage.
