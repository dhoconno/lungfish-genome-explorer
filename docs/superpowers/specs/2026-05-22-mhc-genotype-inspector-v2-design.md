# MHC Genotype Inspector v2 Design

> Successor to `2026-05-21-lungfishgenotype-viewport-inspector-design.md`. v1 shipped a five-lens display-only viewport reading `.lungfishgenotype` bundles. v2 polishes the display, introduces a haplotype tape primitive, adds analyst annotations (highlights, comments, overrides) persisted in a bundle sidecar, supports both small (MCM, 7 haplotypes) and large (Rhesus, hundreds) reference haplotype sets, and supports populations with no reference set via a manual-haplotyping mode. The Inspector stays in the right sidebar across all of LGE; the two-panel viewport carries the data surface, reusing the shared `TwoPaneTrackedSplitCoordinator` already used by classifier viewports.

## Context

The Wisconsin O'Connor lab and WNPRC Genomics Services produce MHC genotyping workbooks for nonhuman primate cohorts (Mauritian cynomolgus / Mafa / MCM, Indian rhesus / Mamu / MAMU, pig-tailed / Mane / MANE). The current delivery format is an Excel workbook generated by a Jupyter notebook ([`mhc_genotyper_for_github.ipynb`](https://lab.wisc.edu/), supplied by the user). The workbook fuses three audiences (analyst, consumer, generator) onto one dense sheet and forces consumers to read 192-sample plates with manual filtering.

v1 of this work landed a native viewport that renders the bundle with five lenses (Analyst, Haplotypes, Anchors, Consumer, Artifacts), a comparison-matrix table, highlight colors, sample-metadata import, and Excel export. v2 reorganizes around three lenses, introduces a haplotype tape primitive that preserves block-coherence visually, adds a Smart Cohort predicate-and-saved-filter system modelled on `VariantSmartFilter`, and adds a sidecar annotation layer so analysts can override calls, attach status, color, and comments without touching pipeline output.

## Users

**Analyst** (single-digit headcount, expert) — reviews every call against read evidence on a 192-sample plate; annotates cells; overrides specific calls when the pipeline mis-called or under-called a haplotype. Lives in the Review lens for hours. Wants a queue-driven workflow (Needs Review cohort) with keyboard-only progression and an audit trail.

**Consumer** (many, varying expertise) — breeding coordinators, immunology PIs, scientific writers. Open the bundle for a few minutes and leave with haplotype calls for a cohort. Almost never want read counts. Want a clean printable summary.

**Generator** (the bench scientist who ran the pipeline) — glances at the bundle to confirm the run is shippable. Spot-checks QC distribution; opens the Audit lens if anything looks wrong. Five-second job; lives at the cohort summary altitude.

## Scope and non-goals

**In scope for v2:**
- Native viewport using the existing two-panel `TrackedDividerSplitView` + `TwoPaneTrackedSplitCoordinator` infrastructure (the same controllers used by `EsVirituResultViewController`, `TaxTriageResultViewController`, `NaoMgsResultViewController`, `NvdResultViewController`, `AssemblyResultViewController`, `ReferenceBundleViewportController`).
- Three lenses: Summary, Review, Audit. Replaces v1's five.
- Three view modes for Summary's Panel A: Outline, Cards, Matrix.
- Haplotype tape primitive: two stacked strips of N swatches per sample (H1 on top, H2 on bottom; one column per locus).
- Block-status glyph vocabulary (block coherent / regional recombinant / atypical).
- Per-haplotype color tokens (`HaplotypeColorToken`), backed by semantic system colors with optional palette overrides; per-haplotype glyph channel for non-color accessibility.
- Smart Cohort predicate language + saved-filter library, modelled on `VariantSmartFilter`. Bundle-scope and user-scope saved cohorts.
- Quick-filter bar with text search and pill toggles.
- Sort key + direction.
- Run-level QC strip at the viewport top (click-to-filter) and a Cohort Summary in Panel B (Summary lens).
- Call evidence in Panel B (Review lens): diagnostic-allele table, locus coverage bar, run neighbors.
- Annotation sidecar (`annotations.json` next to the bundle artifacts): highlights, comments, call overrides, status flags, smart cohort definitions. Versioned with a change log.
- Override flow in the Inspector Selection tab: status flag, override picker (whitelist for known reference sets, free-text for populations with no reference set), reason chip vocabulary, free-text rationale, audit trail.
- Manual-haplotype assignment mode for populations without a `GenotypeHaplotypeDefinitionSet`: analyst defines a label, picks the diagnostic alleles by clicking into the per-genotype matrix, and the new "manual" definition writes into the sidecar (does not modify the built-in registry).
- Three dropout-threshold modes (absolute reads, % of sample reads, % of locus reads), all OR-evaluated, configurable per bundle in the Audit lens with sensible defaults.
- Configurable card density (Compact / Comfortable / Roomy) with automatic-density rules tied to cohort size.
- Polished Excel workbook export that matches the Budde 2010 / O'Connor lab convention (M1–M7 conditional formatting, freeze panes, header strip).
- Accessibility: glyph channel paired with every color; VoiceOver labels for every cell; high-contrast and increased-contrast colors via system color sources.
- CLI parity for the headless flows: list samples, list cohorts, apply an annotation patch, export workbook.

**Deferred to v3 (out of scope):**
- Plate-position contamination view (96/384-well plate map with adjacency analysis).
- KIR-specific UI (gene-content vs allelic presentation).
- Collaboration (multi-author annotations, merge/conflict).
- LabKey direct ingestion of overrides.
- Per-call evidence pileup viewer (BAM/SAM region).
- Workbook round-trip from an analyst-edited workbook back into the inspector.

## Architecture

### Modules

The work touches every Lungfish module:

- **LungfishCore** — extend `HaplotypeColorToken`, add `GenotypeAnnotationLayer` value types, add `Notifications` constants.
- **LungfishIO** — add `GenotypeAnnotationSidecar` reader/writer (lives next to the bundle, peer to the existing `genotype-result.json`). Extend `BuiltInGenotypeHaplotypeDefinitions` with explicit `colorTokenIndex` per haplotype and a `manualAssignment` placeholder set. Add `GenotypeCohortSmartFilter` (the predicate model, modelled on `VariantSmartFilter`).
- **LungfishWorkflow** — no change; the pipeline still produces the bundle.
- **LungfishApp** — the viewport, inspector sections, view-mode/lens controls, and the wiring.
- **LungfishCLI** — `lungfish genotype list-samples`, `lungfish genotype list-cohorts`, `lungfish genotype apply-annotations`, `lungfish genotype export-xlsx`.

### Two-panel composition by lens

The Inspector right sidebar uses the existing tab model: `bundle`, `selectedItem`, `view`, `analysis`, `ai`, `fastqMetadata`, `resultSummary`, `provenance`. The genotype viewport drives which tab is active by lens (mirroring the convention used by other viewports).

| Lens | Panel A | Panel B | Inspector active tab |
|---|---|---|---|
| Summary | Cohort (Outline / Cards / Matrix) | Cohort Summary list | `bundle` (the "Document" tab) |
| Review | Needs Review queue (Outline-style tape, current sample expanded inline) | Call Evidence (diagnostic alleles, locus coverage, run neighbors) | `selectedItem` (the "Selection" tab) |
| Audit | Provenance graph + artifact list | Configuration (dropout thresholds, smart cohort editor, palette overrides, manual definition import/export) | `provenance` |

Layout uses the existing enum (renamed `ResultPanelLayout`), with three options: `aLeading` (Panel A left), `aTrailing` (Panel A right), `aOver` (Panel A on top). User-selectable in the Inspector Document section; persists per bundle in the annotation sidecar.

### Viewport top strip

A thin row above Panel A inside the viewport: `192 samples · ● 154 OK · ● 22 low · ● 11 review · ● 5 error`. The non-OK dots are dotted-underlined and click-to-filter (each click sets the QC predicate of the active filter to that single status; click again to clear). This strip is the same across all three lenses; only its filter scope changes (in Review, clicking "5 error" narrows the Needs Review queue further).

## Lens behavior

### Summary lens (default for new bundles)

- Panel A's view mode (Outline / Cards / Matrix) is user-controlled via a `Picker` in the Inspector Document section. The choice persists per bundle in the annotation sidecar.
  - **Outline** — one row per sample with the haplotype tape (see below). Best for ≤500 sample scans.
  - **Cards** — one card per sample with the tape inside the card body, animal id, comments excerpt. Auto-densifies to Compact when filtered set > N (default 30, configurable).
  - **Matrix** — repurposes the existing `GenotypeComparisonMatrixView`. Two render modes: "Normal" (per-cell labels) and "Fit" (per-cell swatches at 4pt, label hover). The Normal radio remains the default. The new Fit toggle lives at the top of the Matrix viewport (reuses the existing matrix's filter row).
- Panel B carries a `GenotypeCohortSummaryPanelView` with: QC distribution, Errors breakdown, Block coherence breakdown, Read budget (median / min / max / below-threshold count), and Annotation counts. All sections are collapsible. No hero numbers, no histograms, no AI-style CTAs.

### Review lens

- Panel A is a queue. By default the Needs Review smart cohort is active; the analyst can apply any other smart cohort. The queue uses the same Outline tape primitive at queue density (~18pt total row height).
- The currently selected sample expands inline to show its 14 locus-slot calls (one row per `(locus, slot)`).
- Panel B is `GenotypeCallEvidenceView`. Three sub-sections, stacked: diagnostic alleles table, locus coverage bar, run neighbors. All show data for the call selected in Panel A's expansion.
- The Inspector Selection tab carries the override controls (see Annotation flow below).
- Keyboard: `Down` next sample, `Up` previous sample, `Right` descend into expanded call list, `Left` ascend, `Space` toggle disclosure, `⌘R` mark reviewed and auto-advance, `⌘K` mark confirmed and auto-advance, `⌘⇧F` flag needs-review, `⌘⇧O` open override sheet, `⌘⌃1`..`⌘⌃7` apply haplotype-token highlight, `⌘'` add comment, `⌘Z`/`⌘⇧Z` undo/redo.

### Audit lens

- Panel A: pipeline provenance graph (already exists, just hosted in this panel for the Audit lens) plus the artifact list (workbook, long summary CSV, sample summary CSV, stats JSON, provenance, sidecar).
- Panel B: configuration. Specifically:
  - Dropout thresholds (three modes, see below).
  - Smart cohort editor (list, edit predicate, add, delete, star/unstar; user-scope vs bundle-scope toggle).
  - Palette override (per-token override for the eight haplotype color tokens; for non-MCM reference sets the palette can be expanded; for manual definitions the analyst picks).
  - Manual haplotype definitions for this bundle (import, export, edit).
  - Bundle defaults: default view mode, default sort, default panel layout.

## Haplotype tape primitive

`GenotypeHaplotypeTapeView` is an `NSView` whose render contract:

- Input: an ordered list of `(locus, h1: Call, h2: Call)` where `Call = { tokenIndex: Int, label: String, kind: .reference | .manual | .recombinant | .err | .empty, isOverridden: Bool }`. The number of loci is set by the active `GenotypeHaplotypeDefinitionSet` (7 for MCM/MAMU/MANE MHC; the structure scales to any N).
- Layout: two horizontal strips stacked, total height 22pt (Outline default), 18pt (Review queue), 10pt (Matrix Fit). Each locus column has equal width; locus header labels are drawn outside the tape by the host view.
- Drawing per swatch:
  - Fill from `HaplotypeColorToken[tokenIndex].fillColor` (or `.darkFillColor` in Dark Mode).
  - If `.recombinant`, fill with a diagonal stripe pattern of the two component tokens.
  - If `.err`, fill with a semantic error pattern (cross-hatch on `secondaryLabelColor`).
  - If `.empty`, fill with `tertiaryLabelColor` muted.
  - If `isOverridden`, overlay a diagonal hatch at low opacity (the "overridden" texture).
  - A small glyph (the token's `glyph`) is drawn centered when the swatch is ≥18pt wide; below that, the glyph is hidden and the user relies on color + system accessibility settings.
  - Color is never the sole carrier: each token has a unique glyph; in Increased Contrast mode the glyph becomes the primary signal.
- Accessibility:
  - The tape view is one accessibility group per row, with children one element per swatch.
  - Each swatch's accessibility label: "{sample} {locus} {h1|h2} {tokenName} {qc}", plus "overridden" if applicable. The label never says "red" or "blue".
  - VoiceOver-rotor: tape acts as a table for navigation.

### Reference-set scaling: small (MCM) vs large (Rhesus)

The MCM reference set defines 7 haplotypes (M1–M7) with the canonical color palette. Rhesus defines many dozens (the notebook's `indian_rhesus['MHC_A_HAPLOTYPES']` has 24+ A haplotypes; B has 31+; DRB has 32+). The tape primitive scales as follows:

- `HaplotypeColorToken` exposes a static palette of 8 explicit tokens (M1–M7 plus M0 for "absent" or the special-case A1_063 marker), but the registry supports an arbitrary number via a deterministic `assignedToken(for: haplotypeName)` function that hashes the haplotype's name and the active definition set's name into one of N palette slots. For MCM the canonical mapping is preserved by name (`M1A` → token index 1, `M2A` → 2, etc.); for non-MCM sets the hash provides a stable, repeatable colour assignment without claiming biological meaning.
- For populations with >7 distinct haplotypes at a single locus, the palette extends from the 8 canonical tokens to a 16-token extended palette (additional tokens distinguishable by glyph + lightness step), and beyond 16 the tape transitions to a Rhesus-mode rendering where the swatch displays the haplotype's name as text inside the strip (small Inter font), color-coded only by category (class I A / class I B / class II DR / DQ / DP). The analyst's primary signal at Rhesus scale becomes the label, not the color.
- The Inspector Document section's palette panel lets the analyst manually pin a specific haplotype to a specific token if the auto-assignment is unhelpful.

### Manual-haplotype mode (populations with no reference set)

When the bundle's species has no `GenotypeHaplotypeDefinitionSet` in the built-in registry, the inspector enters Manual mode automatically:

- Panel A in Summary still shows samples, but the tape is collapsed to a placeholder ("Haplotype not assigned") per locus until the analyst manually assigns.
- The Audit lens's Panel B exposes a `GenotypeManualHaplotypingPanelView`:
  - Lists the loci defined by the species CSV.
  - For each locus, lists the unique genotype strings observed across all samples in the cohort with their per-sample read counts and a "samples sharing this genotype" count.
  - The analyst groups genotypes into haplotypes: select 1+ genotypes, click "Create haplotype...", enter a label, pick a color token (or auto-assign), confirm.
  - Once one haplotype is defined the tape begins to show that haplotype's colored swatch on samples that match.
  - All manual definitions are stored in the annotation sidecar (`manualHaplotypeAssignments`). They are scoped to this bundle only and never written to the built-in registry.
- The Review lens's evidence pane shows the manual definitions as "diagnostic alleles" alongside any auto-discovered shared genotypes.
- A bundle can mix automatic and manual: a species with a partial reference set can have analyst-added haplotypes for additional loci.
- "Export Manual Definitions" writes a JSON document the lab can submit upstream for inclusion in the built-in registry.

## Annotation sidecar

A single file: `<bundle>/annotations.json`. Peer to `genotype-result.json` inside the `.lungfishgenotype` bundle directory.

### Why JSON, not SQLite

The codebase has a SQLite-backed `AnnotationDatabase` (`Sources/LungfishIO/Bundles/AnnotationDatabase.swift`) used for sequence-level annotations (GFF3, BED). It is not a good fit for genotype annotations because:

1. `AnnotationDatabase` is structured around chromosome coordinates and per-feature attributes (chromosome, start, end, blockCount, blockSizes…). Genotype annotations are keyed on sample × locus × slot, not genome coordinates.
2. The genotype sidecar carries a small bounded set of records (overrides, comments, highlights — typically dozens per bundle, not thousands). SQLite's value proposition (range queries on millions of rows) is mismatched.
3. JSON is human-readable, diff-friendly, easily versioned in git, easily exported and re-imported, easily reviewed by a non-engineer.
4. The smart cohort predicate language is a recursive ADT that serializes naturally to JSON; representing it in SQL tables adds an indirection.
5. The audit log is naturally append-only and easily browsed in text form.

SQLite remains the right answer for sequence-coordinate annotations and stays untouched. Read-only access is safe across multiple LGE windows; writes are serialized by a per-bundle in-process lock. The pipeline never writes this file; the inspector is its sole author.

User-scope smart cohorts (the ones the user wants across all bundles) live in `~/Library/Application Support/Lungfish/genotype-smart-cohorts.json` and have the same `GenotypeCohortSmartFilter` schema. User-scope cohorts are merged into the bundle's cohort list at display time; they cannot be edited from the bundle inspector (a small "Edit in Settings…" button opens the user-scope list).

### Schema versioning

`schemaVersion = 1` for v2. Future revisions either preserve compatibility (add fields, never remove) or bump the version and provide an importer. Unknown fields are preserved on round-trip (the sidecar reader uses `JSONSerialization` with passthrough for unknown keys at the document and entry level).

### Audit log

Every mutation appends one entry to `auditLog`. Entries are immutable. The log is the source of truth for "who changed what when" and the Provenance tab surfaces it as a unified timeline with the pipeline's own provenance graph.

## Annotation flow (Review lens)

1. Analyst selects a sample in the Needs Review queue (Panel A).
2. Panel B populates with the evidence for the call flagged on that sample (or, if no call is flagged, the first call by locus order).
3. Inspector Selection tab populates with:
   - **Call identity**: `H22C112 / MHC-A / H2`.
   - **Status flag** (radio): unflagged, needs-review, reviewed, confirmed. The current value persists to `sampleStatusFlags` (or `callStatusFlags` for call-level).
   - **Override card**: shows the original pipeline call as a colored swatch + label. An "Override to" picker — for MCM/MAMU/MANE the picker is a strict whitelist drawn from the active definition set's haplotype names (plus `A1_063` and `—` for "no haplotype"); for populations using manual mode, the picker is a free-text autocompleting input with the manual definitions list. A "Reason" chip row (Dropout / Contamination / Novel / Mis-call / Confirmed as called). A free-text rationale textarea. Save / Cancel.
   - **Highlight palette**: 8 named swatches; one is "none". Clicking applies a fill highlight to the currently-selected cell. Border-only highlights are accessed via a small "Border" toggle.
   - **Comments**: a chronological list of `cellComments` + `sampleNotes` for the selected sample/call, with the pipeline's auto-comment ("Called M2A from 02_M2_G_02_06_156bp 198 reads…") rendered as a non-editable entry pinned at the bottom. New comment input.
4. Saving an override:
   - Validates the override target against the active definition set (whitelist) or against the manual definitions for the bundle. Free-text overrides are blocked for MCM/MAMU/MANE.
   - Writes the `CallOverride` and the `AnnotationAuditEntry` to the sidecar.
   - Triggers a redraw: the tape swatch keeps its original fill but gains the diagonal hatch overlay (Outline/Cards) or a small pencil corner glyph (Matrix). The call label flips to the override target.
   - Hover/click on an overridden swatch surfaces a tooltip with the original call, the override target, the reason, the rationale, the author, the timestamp.
5. Undo / redo: every annotation action is undoable via the standard `NSUndoManager` chain of the window's first responder. Multi-action undo groups are coalesced when the user does several related actions within 5s (e.g. flag + highlight + override).

## Quick-filter bar

A row above the cohort list inside Panel A (Summary and Review lenses):

- `NSSearchField` for free-text matching against `animalId`, `gsId`, and all `cellComments`/`sampleNotes` text.
- A horizontal `NSStackView` of pill toggles for the common filters: "Has errors", "Homozygous", "Recombinant", "Bw6+", "Has comments", "Duplicate". Pills are user-configurable via a "+ More…" overflow which shows the smart-cohort predicate library.
- Active filters below the bar as removable chips (Mail-style search tokens). One chip per active predicate.
- A "Save as Smart Cohort…" link below the chips when the active filter has at least one predicate. Clicking opens a sheet to name the cohort and choose bundle vs user scope.

Filtering is a stable operation: changing filters preserves sample selection (the selected sample is kept in view if it still matches; otherwise selection moves to the nearest match).

## Sort

The Inspector Document section exposes a `Sort by` dropdown + `Ascending/Descending` toggle. Keys:
- Animal ID (default)
- GS ID
- Total reads
- % unmapped (descending)
- QC status (review > low > ok)
- Haplotype at locus X (analyst picks the locus from a submenu)
- Has comments (samples with comments first)

Sort is a view-only setting; the underlying sample order is preserved. No drag-to-reorder for samples — that's the Excel anti-pattern. For a custom display order, analysts use a smart cohort with explicit `animalIdIn` ordered list, or apply a tag and sort by tag.

## Dropout thresholds (three modes, OR'd)

Audit lens Panel B exposes a `DropoutCriteriaEditor`:

- **Absolute reads**: integer ≥ 0, default 50. Any diagnostic allele below this is "low support".
- **% of sample reads**: double in [0, 1], default unset. Any diagnostic allele whose read count is below this fraction of the sample's total mapped reads is "low support".
- **% of locus reads**: double in [0, 1], default 0.05 (5%). Any diagnostic allele whose read count is below this fraction of the locus's total mapped reads in that sample is "low support".

Any of the three (or any combination) can be active; "low support" is the OR. The dropout settings persist in the sidecar's `settings` block. The Needs Review smart cohort uses these settings; changing them updates the cohort count in real time.

The defaults are conservative; the labs may set their own. The user's CLAUDE.md memory will be updated to note the canonical defaults.

## Excel export

`GenotypeViewportExcelExportService` already exists. v2 extends it to produce a workbook visually compatible with the Budde 2010 / O'Connor lab convention:

- Sheet 1 (`<run-name>_pivot`): the polished workbook. Header rows 1–19 (Animal ID, GS ID, mapped read count, total reads, % unmapped, 14 haplotype rows for the 7 MHC loci × 2 slots). Row 20 = comments. Row 21+ = genotype × sample read counts grouped by locus (Mafa-F, Mafa-G, Mafa-AG, Mafa-A major/minor, Mafa-70, Mafa-E, Mafa-B, Mafa-DRB, Mafa-DQA/DQB, Mafa-DPA/DPB), with the conditional-format rules from the notebook regenerated.
- Sheet 2 (`<run-name>_overrides`): if any overrides exist in the sidecar, one row per override with sample, locus, slot, original, override, reason, author, timestamp.
- Sheet 3 (`<run-name>_audit`): the audit log.

Overrides are applied to the haplotype rows by default; the original pipeline call is preserved in a cell comment (`xlsx`'s threaded comment) on the same cell. This makes the workbook self-describing.

Font choice: SF Mono Regular 10pt for monospace columns; Inter Regular 11pt for headers. Both fonts are widely available; if the receiver's system lacks them the xlsx renderer falls back to the system default and the format degrades to the default Excel font.

## CLI parity

Subcommands under `lungfish genotype …`:
- `list-samples <bundle>` — prints animal id, gs id, qc status, total reads, top calls per locus.
- `list-cohorts <bundle>` — prints smart cohorts with counts.

## Polish and accessibility

- **Typography**: Inter Regular 11–13pt for body and panel labels; Space Grotesk Semibold 16–17pt for inspector section headers; IBM Plex Mono Regular 11pt for animal/GS ids, allele names, and shell-output style content. System fonts (SF / SF Mono) for menu items and toolbar.
- **Spacing**: 8pt baseline grid throughout. Inspector section padding 16pt vertical / 12pt horizontal. Panel B section spacing 12pt. Quick-filter bar padding 8pt vertical / 10pt horizontal.
- **Accent color**: Lungfish Orange `#D47B3A` (light) / `#E8A06A` (dark) for accents, focus rings, selected-row left edge, primary buttons. Used sparingly — never on data swatches.
- **Focus rings**: system focus ring (`NSFocusRingTypeDefault`); no custom rings.
- **Hover states**: row hover at 4% darken; cells do not hover-highlight on their own.
- **Dark Mode**: every haplotype color token has a `darkFillColor` variant. Increased Contrast settings increase the saturation of swatch fills and force the glyph to display.
- **VoiceOver**: every cell announces sample, locus, slot, haplotype, qc status, override state, in that order. Block-status glyphs announce as "block coherent", "regional recombinant", "atypical". No color names.
- **Differentiate without color**: glyphs are always available; in the "Differentiate Without Color" system setting the glyph becomes mandatory and the color drops to a low-saturation tint.

## Performance

- Smart cohort predicates evaluate over the cohort (max ~192 samples × 14 calls = 2688 cells) in O(cohort) per predicate. Cached per cohort + sidecar version. No concern at the design level.
- Outline view uses `NSTableView` with `NSViewBasedTableView` reuse identifiers (already established pattern in the codebase). 192 rows is trivial.
- Cards view uses an `NSCollectionView` with cell reuse. At Compact density a 192-sample cohort renders in <33ms on M1.
- Matrix view's existing `GenotypeComparisonMatrixView` handles 192 sample columns via column virtualization; the Fit mode reduces column width but not column count.
- The annotation sidecar is read once on bundle open, kept in memory as an `@Observable` value, and written atomically (write-to-temp + rename) on each save.

## Migration from v1

The v1 viewport (5 lenses) is replaced wholesale, not augmented. Specifically:
- `GenotypeResultViewportLens` collapses 5 → 3. Code that references `Lens.haplotypes` / `Lens.anchors` is removed or rewritten to use Summary's Outline or Review.
- `GenotypeResultPanelLayout` is renamed to `ResultPanelLayout` and lifted to `Sources/LungfishApp/Views/Layout/`. The existing genotype-only file is updated to re-export the name and re-route to the shared type.
- `GenotypeResultHighlightStyle` and `GenotypeResultHighlightTarget` evolve to include a `slot: HaplotypeSlot` and to migrate from per-cell to per-(sample, locus, slot). Existing highlights in any sidecars in the wild — none expected, since v1 had no sidecar — are dropped.
- `GenotypeViewportExcelExportService` keeps its existing API; the conditional-format logic is extended.
- The MVP's `GenotypeComparisonMatrixView` continues to back the Matrix view mode and is the place the Fit toggle is added.
- Built-in haplotype definitions in `BuiltInGenotypeHaplotypeDefinitions.swift` are extended with `colorTokenIndex` per haplotype; the existing M1–M7 → token-1..7 mapping is preserved by name.

## Provenance and pipeline interaction

This is a display + annotation feature. The pipeline never writes `annotations.json`; the inspector is its only author. The bundle's pipeline output (`genotype-result.json`, sample/long summary CSVs, stats JSON, the original Excel workbook) is never modified. Overrides are applied at display and at export time; the pipeline's view of the world is unchanged.

If a future workflow operation reads `annotations.json` to drive a re-run, that operation must write full Lungfish provenance and must preserve the final stored payload paths (per the existing CLAUDE.md "Provenance" rule in v1 spec).

## Open issues

- The Rhesus hash-to-palette assignment is deterministic but visually noisy when many haplotypes appear per cohort. The palette-pinning UI in the Inspector mitigates but does not eliminate this. We may revisit with a categorical-palette generator (HCL space, perceptually uniform) in a future iteration.
- The manual-haplotype mode's "shared genotypes" list can be very long for cohorts without a reference set (hundreds of unique genotypes per locus). The current design lists them in read-count-descending order with a search field; we'll iterate after first lab feedback.
- Excel export of overrides as "primary value, original as comment" is a convention choice. Alternative: original value, override in a comment. We choose primary=override because the workbook's audience is consumers reading the call, not analysts reading the pipeline output. Open to flipping after first review.
