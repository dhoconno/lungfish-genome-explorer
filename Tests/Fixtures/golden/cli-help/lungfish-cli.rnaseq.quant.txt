OVERVIEW: Count bulk RNA-seq reads in a project with salmon

Each FASTQ bundle is one sample. Lungfish runs salmon quant with selective
alignment and library type A on the set's own index, which lungfish-cli rnaseq
index builds, and never builds one itself. Reads are not trimmed unless you
pass --trim, which runs Trim Galore with poly-G trimming off unless you pass
--poly-g-trimming on. Duplicates are kept.

The result holds transcript counts and gene sums through the set's transcript
table, in unit estimated, and its record names the set, the index's hashes,
salmon's version and every setting that changes counts. --threads is recorded
and changes no count.

With --write-plan the command writes a plan folder for a run on a Linux machine
in place of counting here, one plan a sample, and writes no result in a
project. Each plan runs salmon on the index this Mac published for the set, or
with --chain a STAR chain on the STAR index an earlier Linux run built. A run
you adopt as a result takes a true --executor-manifest, the manifest of the
executor you built, since the plan pins it.

USAGE: lungfish-cli rnaseq quant [<options>] [<bundles> ...] --set <set>

ARGUMENTS:
  <bundles>               FASTQ bundles, one sample each. A plan of staged
                          reads names none

OPTIONS:
  --project <project>     The project the result is written in, required unless
                          --write-plan is given
  --name <name>           The result's name (default: RNA-seq counts)
  --set <set>             The id of a reference set under the storage root
  --k <k>                 k-mer length of the index, an odd number up to 31
                          (default: 31)
  --decoys <decoys>       genome (the default) for the index with the genome as
                          decoys, or none (default: genome)
  --trim                  Trim the reads with Trim Galore before salmon
                          (default: not trimmed)
  --poly-g-trimming <poly-g-trimming>
                          With --trim: on passes --poly_g to Trim Galore, off
                          (the default) --no_poly_g
  --storage-root <storage-root>
                          Managed storage root (default: the configured
                          location)
  --write-plan <folder>   Write a plan folder for a run on a Linux machine to
                          this new folder in place of counting here
        The folder is the submit folder of one batch, as import fastq
        --write-plan writes it, with one plan a sample. Each plan runs Trim
        Galore (with --trim) and then the chain --chain names. Each plan pins
        its index file by file and never builds one. Nothing runs here and
        nothing is submitted, so --project is not used. A run you adopt as a
        result takes the manifest of the executor you built with
        --executor-manifest, since the plan pins it.
  --chain <chain>         With --write-plan, what each plan runs after trimming
                          (default: salmon) (values: salmon, star-salmon,
                          star-salmon-errormodel, star-2.7.11b-genecounts,
                          star-2.7.3a-genecounts, star-2.7.11b-featurecounts)
        salmon counts the reads with salmon on the index this Mac published for
        the set, so run lungfish-cli rnaseq index first. star-salmon maps with
        STAR 2.7.11b --quantMode TranscriptomeSAM GeneCounts and counts STAR's
        transcriptome alignments with salmon -a, and star-salmon-errormodel
        adds salmon's --errorModel. star-2.7.11b-genecounts and
        star-2.7.3a-genecounts count genes with STAR's GeneCounts, and
        star-2.7.11b-featurecounts counts exons with featureCounts on STAR's
        alignments. Each STAR chain pins the STAR index of its version that an
        earlier run built on the Linux machine and left in the staging folder.
        Plan that index with lungfish-cli rnaseq index-plan --star <version>,
        run it, and record it with lungfish-cli rnaseq index-adopt. --k and
        --decoys pick a salmon index, so a STAR chain takes neither.
  --staged-reads <file>   A tab-separated list of reads already in the staging
                          folder, with each read's absolute path, size in bytes
                          and SHA-256, for --write-plan with --samplesheet
        The sample sheet's r1 and r2 name each read by its absolute path in the
        staging folder, and Lungfish reads none of them. The list's first line
        names the columns file, bytes and sha256, separated by tabs. The
        sheet's optional model column names the instrument.
  --samplesheet <file>    A comma-separated sample sheet with sample, r1 and r2
                          columns, for --staged-reads
  --staging-folder <path> The absolute path of the folder on the Linux machine
                          that holds the image, the executor, the index and the
                          reads
  --executor-manifest <file>
                          The manifest.json beside the Linux lungfish-executor
                          (default: the app's). A run you adopt as a result
                          takes the one you built
  --image <file>          The image.json of the container image the jobs run in
                          (default: the app's)
  --image-tool-manifest <file>
                          The image's tool manifest, the file image.json pins
                          (default: the app's)
  --request-memory-mib <request-memory-mib>
                          Memory each job asks for, in MiB. Optional for
                          Macaca_fascicularis_6.0
  --request-cpus <request-cpus>
                          CPUs each job asks for, and the threads of salmon and
                          STAR (default: 8). Optional for
                          Macaca_fascicularis_6.0
  --request-disk-gib <request-disk-gib>
                          Disk each job asks for, in GiB. Optional for
                          Macaca_fascicularis_6.0
  --job-requirements <job-requirements>
                          The machines the jobs may run on, as one HTCondor
                          requirements expression
  --dry-run               With --write-plan, make every refusal of the run and
                          write no folder
  --format <format>       Output format (values: text, json, tsv; default: text)
  -v, --verbose           Increase output verbosity (can be repeated: -v, -vv,
                          -vvv)
  -q, --quiet             Suppress non-essential output (errors only)
  --progress              Show progress bar (default: auto-detect TTY)
  --no-progress           Disable progress bar
  --debug                 Enable debug output with detailed logging
  --log-file <log-file>   Write detailed logs to file
  --no-color              Disable colored output
  -t, --threads <threads> Number of threads to use (default: auto)
  --version               Show the version.
  -h, --help              Show help information.
