OVERVIEW: Import bulk RNA-seq counts into a project

USAGE: lungfish-cli import rnaseq [<options>] <input-paths> ... --project <project> --name <name>

ARGUMENTS:
  <input-paths>           salmon quant folders, one count table of genes by
                          samples, or Cell Ranger outs and STARsolo run folders

OPTIONS:
  --project <project>     Lungfish project directory to import into
  --name <name>           Name of the RNA-seq result
  --tx2gene <tx2gene>     Transcript-to-gene table for gene sums of salmon
                          folders
  --samples <samples>     Sample sheet (sample, run, animal, species, origin,
                          group)
  --unit <unit>           Unit of a count table: reads, pairs, umis or estimated
  --genome <genome>       Gene id prefix of one genome of a single-cell
                          reference of two or more, such as hg19 (repeat for
                          each genome)
  --reference-set <reference-set>
                          Reference set folder whose not-host sequences a
                          single-cell import counts in each cell and in the
                          ambient pool
  --not-host-bam <not-host-bam>
                          A sample's sorted, indexed BAM as <sample>=<path>,
                          one for each sample with --reference-set (repeat)
  --adopt                 Adopt the counts a Linux run of lungfish-executor
                          returned, as one result
        The one input names the returned plan folder, which holds plan.json,
        run-record.json and the run's count files, or a returned batch folder,
        which holds one such folder a sample as <sample>/. The counts are
        salmon's, STAR GeneCounts' column 2 (unstranded) or featureCounts'
        table, as the plan's route names. A STARsolo plan of rnaseq solo-plan
        gives the filtered matrix of Solo.out/Gene as one single-cell result. A
        batch gives one result of all its samples, and when any sample is
        refused nothing is imported. The genes are those of the reference set
        the plan names, in the storage root, and a STAR or featureCounts table
        counted on another GTF is refused. The plan fixed every setting, so no
        option that sets a count is taken with --adopt. A refused adopt writes
        nothing.
  --dry-run               With --adopt, run every check and read and write
                          nothing
  --storage-root <storage-root>
                          With --adopt, the storage root that holds the plan's
                          reference set (default: the configured location)
  --format <format>       Output format (values: text, json, tsv; default: text)
  -v, --verbose           Increase output verbosity (can be repeated: -v, -vv,
                          -vvv)
  -q, --quiet             Suppress non-essential output (errors only)
  --progress              Show progress bar (default: auto-detect TTY)
  --no-progress           Disable progress bar
  --debug                 Enable debug output with detailed logging
  --log-file <log-file>   Write detailed logs to file
  --no-color              Disable colored output
  -t, --threads <threads> Number of threads to use (default: auto)
  --version               Show the version.
  -h, --help              Show help information.
