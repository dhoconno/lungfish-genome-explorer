OVERVIEW: Batch-import FASTQ files or unmapped ONT BAM into a Lungfish project

USAGE: lungfish-cli import fastq [<options>] [<input> ...]

ARGUMENTS:
  <input>                 Directory containing sequencing reads, FASTQ paths,
                          or unmapped ONT BAM paths

OPTIONS:
  --samplesheet <samplesheet>
                          CSV sample sheet with sample,r1,r2 columns and
                          optional metadata columns
  -p, --project <project> Path to .lungfish project directory, required unless
                          --write-plan is given
  --platform <platform>   Sequencing platform: auto, illumina, ont, pacbio,
                          element, mgi, ultima, unknown (default: auto)
        auto infers each sample's platform from its read headers (and a BAM
        file's @RG PL) and prints the evidence. Reads whose platform cannot be
        inferred are recorded as unknown, never as Illumina. A given value is
        recorded as given, even when the reads suggest another platform.
  --pairing <pairing>     Read pairing: auto, single, paired, interleaved
                          (default: auto)
        auto and paired match R1/R2 files by name, inside one folder first.
        Mates in two folders pair only when no other listed file has either
        name. When one does, a warning names the files. They also join a run's
        file named for the run alone, such as SRR1.fastq beside SRR1_1.fastq
        and SRR1_2.fastq, to that pair as unpaired reads, by the same folder
        rule, when the first reads of the pair are named as mates, the first
        read of that file is not from their fragment, and no two adjacent reads
        among the first 1,000 of that file are mates. Otherwise the import
        skips that file and a warning says why. The import fails the sample
        when two adjacent reads later in that file are mates. For any other
        file with no mate file, they read its records and record interleaved
        mates when every record is followed by its mate, otherwise single-end.
        single imports every file as its own single-end sample, even when a
        mate is detected. interleaved imports every file on its own and records
        it as interleaved mates.
  --quality-binning <quality-binning>
                          Quality binning: illumina4 (7 quality levels, the
                          default), eightLevel (~21 quality levels), none
        Every import bins quality scores with illumina4 on every platform
        unless this option or the recipe names another value. Binning saves
        space and is lossy. The original scores cannot be recovered once the
        original files are removed. Pass --quality-binning none to keep every
        score as the reads have it.
  --compression <compression>
                          Compression level: fast, balanced, maximum (default:
                          balanced)
  --recipe <recipe>       Processing recipe: illumina-amplicon-merge,
                          illumina-paired-cleanup, vsp2-target-enrichment,
                          wastewater-metagenomics, vsp2, wgs, hifi, or none
                          (default: none)
        illumina-amplicon-merge: Illumina Amplicon Merge
        illumina-paired-cleanup: Illumina paired-end cleanup (Remove duplicate
        reads on, Remove ribosomal RNA reads off)
        vsp2-target-enrichment: VSP2 target enrichment, a preset of
        illumina-paired-cleanup (Remove duplicate reads on, Remove ribosomal
        RNA reads off)
        wastewater-metagenomics: Wastewater metagenomics, a preset of
        illumina-paired-cleanup (Remove duplicate reads on, Remove ribosomal
        RNA reads on)
        vsp2: alias of vsp2-target-enrichment
        wgs: the built-in Illumina whole-genome recipe
        hifi: the built-in PacBio HiFi recipe
  --remove-duplicates/--no-remove-duplicates
                          Remove duplicate reads. Replaces the recipe's setting.
  --remove-ribosomal-rna/--no-remove-ribosomal-rna
                          Remove ribosomal RNA reads. Replaces the recipe's
                          setting.
        Removal is final for a stored import. Only a reimport from the raw
        files brings the removed reads back.
  --no-optimize-storage   Skip read reordering for storage optimization
  --clumping-tool <clumping-tool>
                          Storage optimization tool: auto, bbtools,
                          trim-galore, none (default: platform-specific)
  --write-plan <folder>   Write a CHTC submit folder to this new folder in
                          place of importing
        The folder holds run.dag, sample.sub, lge-job.sh, logs/, one plan
        folder per sample named by its sample, each sample's plan.tar under
        staging/, and staging-files.json, which lists each file the jobs read
        from the staging folder with its size, its SHA-256 and the file on this
        Mac to copy there. No file is imported and nothing is submitted, so
        --project is not needed. A sample sheet's request_disk column gives a
        sample's disk request in GB.
  --executor-manifest <file>
                          The manifest.json beside the Linux lungfish-executor,
                          which states its SHA-256, size and build
        Required with --write-plan. This build of the app holds no Linux
        executor yet, so you name the manifest of one you built.
  --image <file>          The image.json of the container image the jobs run
                          in, which states the image's file name, SHA-256 and
                          size and its tool manifest's SHA-256 and size
        Required with --write-plan. This build of the app holds no image record
        yet, so you name the one written when the image was built.
  --image-tool-manifest <file>
                          The image's tool manifest, the file image.json pins
        Required with --write-plan. The plan pins each tool it runs from this
        file.
  --staging-folder <path> The absolute path of the group's staging folder on
                          CHTC that the jobs read from
        Required with --write-plan. The image is in images/, each executor and
        database copy in shared/ under a name that starts with its SHA-256, and
        each sample's plan tar, reads and result in batches/<submit folder
        name>/<sample>/.
  --plan-database <id=file>
                          A database a recipe step reads, as <id>=<index file>,
                          for --write-plan
        Repeat it for each database the recipe reads.
  --log-dir <log-dir>     Directory for per-sample log files
  --dry-run               List detected pairs without importing
  --force                 Reimport samples even if bundle already exists
        A bundle that an earlier sample of the same import wrote is never
        replaced, and no sample writes a bundle that an earlier sample of the
        same import failed to write.
  --name <name>           Override the output bundle name. Only valid when
                          exactly one sample is detected.
  --recursive             Recursively scan directories for FASTQ files
  --clumpify-heap-gb <clumpify-heap-gb>
                          Java heap for BBTools clumpify in GB, from 1 up to
                          this host's physical memory (default: 35 percent of
                          this host's physical memory, lowered to its free
                          memory less 8 GB when that is smaller, from 4 up to
                          31)
  --format <format>       Output format (values: text, json, tsv; default: text)
  -v, --verbose           Increase output verbosity (can be repeated: -v, -vv,
                          -vvv)
  -q, --quiet             Suppress non-essential output (errors only)
  --progress              Show progress bar (default: auto-detect TTY)
  --no-progress           Disable progress bar
  --debug                 Enable debug output with detailed logging
  --log-file <log-file>   Write detailed logs to file
  --no-color              Disable colored output
  -t, --threads <threads> Number of threads to use (default: auto)
  --version               Show the version.
  -h, --help              Show help information.
