OVERVIEW: Write the reads of a FASTQ bundle as one FASTQ file with provenance

A bundle with one FASTQ file is copied. A bundle of several source files is
joined in manifest order, and
a .gz output joins gzip inputs byte for byte. A derived bundle holds a recipe
and no reads, so it needs
--materialize-derived to write the reads it stands for. The record is written
beside the output.

Examples:
  lungfish-cli fastq export reads Sample.lungfishfastq -o Sample.fastq.gz
  lungfish-cli fastq export reads Subset.lungfishfastq --materialize-derived -o
Subset.fastq.gz

USAGE: lungfish-cli fastq export reads [<options>] <bundle-path> --output <output>

ARGUMENTS:
  <bundle-path>           The FASTQ bundle (.lungfishfastq) the sidebar shows

OPTIONS:
  --materialize-derived   Write the reads a derived bundle stands for. A
                          derived bundle needs it
  -o, --output <output>   The file to write. An existing file is refused
                          without --force
  --force                 Overwrite an existing output file
  --format <format>       Output format (values: text, json, tsv; default: text)
  -v, --verbose           Increase output verbosity (can be repeated: -v, -vv,
                          -vvv)
  -q, --quiet             Suppress non-essential output (errors only)
  --progress              Show progress bar (default: auto-detect TTY)
  --no-progress           Disable progress bar
  --debug                 Enable debug output with detailed logging
  --log-file <log-file>   Write detailed logs to file
  --no-color              Disable colored output
  -t, --threads <threads> Number of threads to use (default: auto)
  --version               Show the version.
  -h, --help              Show help information.
