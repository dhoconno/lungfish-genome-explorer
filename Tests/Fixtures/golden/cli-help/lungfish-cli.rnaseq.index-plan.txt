OVERVIEW: Write a plan folder that builds the STAR index of a reference set on
a Linux machine

The plan runs STAR --runMode genomeGenerate with 8 threads on the set's genome,
each extra and its counting GTF, derived/genes.gtf. Each index file stays in
the staging folder on the Linux machine as a staged output, and index-adopt
then records where each file sits and its SHA-256 for later plans. A set built
before the counting GTF has none, so rebuild it first.

A genome with no measured figures needs --request-memory-mib, --request-cpus
and --request-disk-gib, taken from STAR's own peak memory and the job's disk on
a small run. A run that index-adopt will read takes the manifest of the
executor you built with --executor-manifest, since the plan pins it.

USAGE: lungfish-cli rnaseq index-plan [<options>] --set <set> --output <output> --staging-folder <staging-folder>

OPTIONS:
  --set <set>             The id of a reference set under the storage root, or
                          the path of a set folder
  --star <star>           The STAR build the image runs: 2.7.11b (the default)
                          or 2.7.3a (default: 2.7.11b)
  --output <output>       The new plan folder to write. It must not exist
  --staging-folder <staging-folder>
                          The absolute path of the folder on the Linux machine
                          that holds the image and the executor and keeps the
                          index
  --executor-manifest <executor-manifest>
                          The manifest.json beside the Linux lungfish-executor
                          (default: the app's)
  --image <image>         The image.json of the container image (default: the
                          app's)
  --image-tool-manifest <image-tool-manifest>
                          The image's tool manifest, the file image.json pins
                          (default: the app's)
  --request-memory-mib <request-memory-mib>
                          Memory the job asks for, in MiB. Optional for
                          Macaca_fascicularis_6.0
  --request-cpus <request-cpus>
                          CPUs the job asks for. Optional for
                          Macaca_fascicularis_6.0
  --request-disk-gib <request-disk-gib>
                          Disk the job asks for, in GiB. Optional for
                          Macaca_fascicularis_6.0
  --job-requirements <job-requirements>
                          The machines the job may run on, as one HTCondor
                          requirements expression
  --storage-root <storage-root>
                          Managed storage root that --set names a set under
                          (default: the configured location)
  --format <format>       Output format (values: text, json, tsv; default: text)
  -v, --verbose           Increase output verbosity (can be repeated: -v, -vv,
                          -vvv)
  -q, --quiet             Suppress non-essential output (errors only)
  --progress              Show progress bar (default: auto-detect TTY)
  --no-progress           Disable progress bar
  --debug                 Enable debug output with detailed logging
  --log-file <log-file>   Write detailed logs to file
  --no-color              Disable colored output
  -t, --threads <threads> Number of threads to use (default: auto)
  --version               Show the version.
  -h, --help              Show help information.
