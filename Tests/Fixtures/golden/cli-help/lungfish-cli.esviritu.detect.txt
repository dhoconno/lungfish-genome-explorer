OVERVIEW: Run EsViritu viral detection on FASTQ files

USAGE: lungfish-cli esviritu detect <options>

OPTIONS:
  -i, --input <input>     Input FASTQ file(s) or .lungfishfastq bundle(s).
                          Provide two files for paired-end.
  -s, --sample <sample>   Sample name for output file prefixes (required
                          without --batch)
  --db <db>               Path to EsViritu database directory (default:
                          auto-detect)
  -o, --output <output>   Output directory (default: ./esviritu-<sample>)
  --project <project>     The .lungfish project the run belongs to. The result
                          lands in its Analyses/esviritu-batch-<timestamp>/
                          folder with one folder per sample, where the app's
                          EsViritu runs put it
        Each sample folder is named after the sample, made safe for a folder
        name, and EsViritu names its tables after that folder. The result gets
        the batch summary, the batch manifest and esviritu.sqlite, and each
        source bundle records the run. Not with --output.
  --batch                 Group the inputs into samples by their file names, as
                          the app's EsViritu dialog does, and run each sample
                          into its own folder of one batch result
        Each sample's read layout is planned from its files, so --batch takes
        --read-format auto and no --sample. A batch completes while one sample
        completes, and each failed sample is a warning. Give --output or
        --project.
  --paired                Input files are paired-end reads
  --read-format <read-format>
                          Read layout: auto, unpaired, paired, or interleaved.
                          (values: auto, unpaired, paired, interleaved;
                          default: auto)
        auto (default) plans a single input, a file or a .lungfishfastq bundle.
        Separate R1 and R2 files run as a pair, strictly alternating R1/R2
        records run as interleaved, and single-end reads run as unpaired. A
        sample that mixes pairs with merged or orphan reads runs as unpaired on
        one file that holds every read, and the output says why. Several files
        of single reads are joined into one file. Two files run as unpaired
        unless --paired is given.
  --recursive             When an input is a directory, include eligible FASTQ
                          files in subfolders
  --no-qc                 Skip quality filtering (fastp)
  --extra-args <extra-args>
                          Additional EsViritu arguments passed verbatim
  --format <format>       Output format: text, json, tsv (default: text)
                          (values: text, json, tsv; default: text)
  -v, --verbose           Increase output verbosity (can be repeated: -v, -vv,
                          -vvv)
  -q, --quiet             Suppress non-essential output (errors only)
  --progress              Show progress bar (default: auto-detect TTY)
  --no-progress           Disable progress bar
  --debug                 Enable debug output with detailed logging
  --log-file <log-file>   Write detailed logs to file
  --no-color              Disable colored output
  -t, --threads <threads> Number of threads to use (default: auto)
  --version               Show the version.
  -h, --help              Show help information.
